# 端末のファイルのリンクとドロップ（ブラウザ版）

ふつうの端末では、出力の中のファイルのパスを Ctrl＋クリックで開けて、ファイルをドラッグ＆ドロップするとそのパスが入力されます。
ブラウザ版の Sodashitsu はブラウザの中で動くので、**ブラウザはサーバのマシンのファイルを直接開けず、ドロップされたファイルの元のパスも
（ほとんどのブラウザでは）知ることができません**。そこで、サーバ（pane のマシンの `soda serve`）越しに同じ使い勝手を作っています。

端末版（引数なしの `soda`）は対象外です——外側の端末（Windows Terminal・iTerm2 等）がリンクとドロップを扱います。

## 何が起きるか

| 操作 | ブラウザがサーバと**同じマシン** | ブラウザがサーバと**別のマシン** |
| --- | --- | --- |
| パスのリンクを Ctrl（macOS は Cmd）＋クリック | サーバのマシンの既定のアプリで開く | ブラウザのダウンロードになる（開くのはブラウザのダウンロードの一覧から） |
| ファイルを pane へドロップ | 元のパスが分かれば、そのパスを貼る（分からなければ右と同じ） | サーバへ送って置き、置いた先のパスを貼る |

- どちらの場合も、ブラウザの既定の動作（落としたファイルをそのタブで開く・ダウンロードする）は起きません。pane の外（サイドバー等）へ
  落としても、何も起きないだけで画面はそのままです。
- 貼られるパスは、ふつうの端末と同じく、空白等を含むときは引用符で包まれ（Linux・macOS は `'…'`、Windows は `"…"`）、後ろに空白が 1 つ付きます。
  複数のファイルを落とすと、空白で区切って並びます。
- 送っている間にその pane へ打ったキーは、パスが貼られた後に届きます（最長 20 秒で先に流れます）。
- ファイルでないドロップ（選択した文字のドラッグ）は、その文字を貼り付けます。

## リンクになるもの

- 出力の中の、**サーバに実在する**ファイル・フォルダのパス。絶対パス・`~/…`・相対パス（その pane の今の場所から解きます）・Windows の
  `C:\…`。後ろの行番号・列（`src/a.ts:12:3`・`src/a.ts(12,3)`）はリンクの一部になります（開くときは使いません）。
  `git diff` の見出しの `a/…`・`b/…` は、外したパスでも探します。
- OSC 8 のリンクで、行き先が `file:` のもの（`ls --hyperlink` 等）。URI のホスト名が空・`localhost`・サーバのホスト名のものだけです
  （pane の中の `ssh` の先で出たリンクは、サーバの同じパスのファイルとして開かないよう、リンクとして扱いません）。
- 空白を含むパスは、出力の文字からは拾えません（OSC 8 のリンクなら開けます）。
- 相対パスは「その pane の今の場所」から解くので、別のディレクトリを基準に出力されたパス（下位のディレクトリで動いたビルドの出力等）はリンクになりません。

下線と指のカーソルは、URL のリンクと同じく Ctrl（macOS は Cmd）を押している間だけ出ます。実在するかはポインタを重ねたときにサーバへ確かめるので、
少し遅れて出ることがあります。

## 同じマシンかどうかの決め方

設定（`prefix+s` の「端末」→「ファイルのリンクとドロップ」。**このブラウザだけの設定**）で選びます。

- **自動**（既定）: サーバが、接続の両端のアドレスから判定します。`http://127.0.0.1:…`・`http://localhost:…` で開いたブラウザや、同じマシンの
  LAN の名前で開いたブラウザは「同じマシン」になります。
- **同じマシンとして扱う** / **別のマシンとして扱う**: 判定を上書きします。

**自動の判定が当たらない構成**があります。サーバに届いた接続のアドレスしか見ないので、`ssh -L` のポート転送・コンテナ（Dev Container・Docker）の
ポートの公開・WSL2 の `localhost` の転送・同じマシンの上のリバースプロキシの後ろでは、別のマシンのブラウザも「同じマシン」に見えます。

- そのとき、リンクは「サーバのマシンのアプリで開く」になりますが、サーバに開く手段（下の表）が無ければ自動でダウンロードに切り替わります。
  コンテナ・画面の無いサーバではこちらになるので、たいていはそのままで困りません。
- サーバに画面があってアプリが開いてしまう（手元の画面には出ない）ときは、「別のマシンとして扱う」を選びます。
- ドロップは、同じマシンと判定されていても、元のパスがサーバで実在して大きさも合うときだけそのパスを使うので、転送の後ろでも
  まちがったパスは貼りません（送る側へ回ります）。

保存した SSH のマシン（`docs/machines.md`）の pane は、設定に関わらず常に「別のマシン」として扱います（ファイルはそのマシンとやりとりします）。

### サーバのマシンでファイルを開く手段

| サーバの OS | 使うコマンド |
| --- | --- |
| Windows | `explorer.exe` |
| macOS | `open` |
| WSL | `wslview`（`wslu`。入っていれば Windows の既定のアプリで開く） |
| Linux | `xdg-open`（`DISPLAY` か `WAYLAND_DISPLAY` があるときだけ） |

どれも無ければ「開く手段が無い」として、ダウンロードになります。開くと実行になる種類のファイル（Windows の `.exe`・`.bat`・`.lnk` と `PATHEXT` の
拡張子、macOS の `.app`・`.command` と拡張子の無い実行できるファイル、Linux の `.desktop`・`.AppImage` 等。WSL は Windows の一覧も見ます）は、
サーバのマシンでは開きません（端末の出力は pane のプログラムが自由に書けるので、クリックだけで実行まで進めないため）。シンボリックリンクは
辿った先の名前で判定します。拡張子の一覧での判定なので、既定のアプリの割り当てによっては漏れがありえます——信用できない出力のリンクは
開かないでください。Windows の UNC のパス（`\\host\share\…`）で始まるものは、リンクにしません。

## ドロップで元のパスを渡せる条件

ブラウザは安全のため、落とされたファイルの**元のパスをページに渡しません**（Chrome・Edge は OS からのドラッグでは常に渡しません）。
元のパスを貼れるのは、次のすべてを満たすときだけです。

1. ブラウザがサーバと同じマシンとして扱われている。
2. ドラッグ元が `file:` の URI を一緒に渡している（ブラウザ・ドラッグ元のアプリによります）。
3. そのパスがサーバで実在し、ファイルなら大きさがドロップされたものと同じ。

満たさないときは、同じマシンでも**サーバへ送ったコピーのパス**が貼られます。コピーなので、pane のプログラムがそのファイルを書き換えても、
元のファイルは変わりません。

## 送ったファイルの置き場所

`<状態ディレクトリ>/dropped-files/soda-drop-<時刻>-<乱数>/<元の名前>` に置きます（既定の状態ディレクトリは Linux・macOS で
`${XDG_STATE_HOME:-~/.local/state}/sodashitsu`、Windows で `%LOCALAPPDATA%\sodashitsu`。名前付き session は `sessions/<名前>/` の下）。

- 名前は元のファイル名のままです（パスの区切り・制御文字・Windows で使えない文字は `_` に替えます）。
- Linux・macOS ではディレクトリは 0700、ファイルは 0600 です。
- **24 時間たつと消えます**。数が 200・合計が 2 GiB を超えたときも、古いものから消えます。残したいファイルは、pane で別の場所へ `cp`・`mv` してください。
- 送っている途中で接続が切れた・やめたときは、書きかけを消します。

## 上限

- fish では、`'` と `\` の両方を含むパスの引用が正しく読まれないことがあります（元のパスを貼るときだけ。送ったファイルの名前には `\` が残りません）。
- 1 つのファイルは 256 MB まで（送る・ダウンロードするの両方）。
- フォルダは送れません（ブラウザが中身を渡さないため）。フォルダのリンクは、同じマシンならファイルマネージャで開き、別のマシンでは開けません。
- ダウンロードは、ブラウザのメモリに全体を受け取ってから保存します。

## 安全について

- `file.*` の要求は、ログイン済みの接続だけが送れます。ログインした利用者は pane のシェルで同じファイルを読み書きできるので、読める・書ける範囲は
  サーバの利用者の権限のままです（置き場所はサーバが決め、ブラウザは選べません）。
- ダウンロードしたファイルは、この画面と同じオリジンのページとしては開きません（HTML・SVG を開いてこの画面の権限で動かさせないため）。
- サーバが返したパスに制御文字が含まれるときは貼りません（中継先のマシンが返すパスも信用しません）。

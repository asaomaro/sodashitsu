# エージェントの fork（会話を引き継いだエージェントを、もう 1 つ起こす）

動いている Claude Code のエージェントを、**ここまでの会話の記憶を持ったまま**、別の pane にもう 1 つ起こします。別の案を並べて試したいとき、同じ調査をやり直させずに済みます。リポジトリの fork（GitHub の上の写し）ではなく、**会話（セッション）の fork** です。

- 起こす先は、**同じフォルダの新しい pane**、または**新しい worktree（新しいブランチ）の workspace**。
- 元のエージェントは止まらず、そのまま続きます。元の会話の記録は書き換わりません。
- どこから枝分かれしたかは、連携のグラフに**見るだけの線**（`fork`）で出ます（画面は PR2。このページの「グラフ」）。
- 使い方: `sodactl agent fork`（このページの「`sodactl`」）。画面のメニューは、画面の PR で足します。

## 使える条件

次のすべてが要ります。外れると、`fork_unavailable`（理由の種類つき）で断り、何も作りません。

| 条件 | 外れたときの理由 |
| :- | :- |
| その pane に Claude Code のエージェントが検出されている | `no_agent` |
| Claude Code である（今は Claude Code だけ。Codex などは対象外） | `not_claude` |
| 会話の id が分かる（**フックの報告**〔`SessionStart`〕で知る。設定の「エージェント連携」でフックを入れて、エージェントを起動し直すと使える） | `no_session_id` |
| 会話の id が UUID の形（名前・パス・引数に化ける値は通さない） | `bad_session_id` |
| 前面がシェルだけの pane を作れる（POSIX 系のシェル。fish・pwsh などと Windows のサーバは使えない） | `unsupported_shell` |
| 新しい worktree で fork するとき、元の pane が git のリポジトリの中にある | `not_a_git_repository` |

会話の id は、**サーバが pane の記録（フックの報告）から引きます**。プロセスの引数・記録のファイルの更新時刻から推すことはしません（別の会話を fork してしまうため）。ブラウザ・`sodactl` から、会話の id・起動するコマンドは送れません（余計な項目は `invalid_params` で断ります）。

### フックの matcher を更新する必要があります

以前の版が入れたフックは、`SessionStart` の matcher が `startup|resume` で、**fork と `/clear` の後の新しい会話の id を拾えません**。この版から `startup|resume|fork|clear|compact` に広げました（`compact` は id が変わらない再報告）。空の matcher にはしていません（知らない種類を黙って拾わないため）。

導入済みの方は、設定の「エージェント連携」に **「更新が必要」** と出ます。［更新］を押して入れ直し、Claude Code を起動し直してください。matcher が期待の値を含んでいる（`""`＝全部を含む）ときは、「更新が必要」と出ません。**利用者のフックと同じエントリに入っている自分のフックは、［更新］でも matcher を直しません**（同じエントリの matcher を変えると、利用者のフックの動きも変わるため）。その場合は、自分のフックを別のエントリに分けて、`startup|resume|fork|clear|compact` にしてください。入れ直すまでは:

- fork したエージェントの会話の id が分からないので、**fork を重ねる（孫の fork）ことと、fork の後のサーバ再起動での再開は、効きません**。
- **`/clear` の後は、pane の会話の id が古い（消した会話の）ままです**。この状態で再起動すると、消した会話が再開され、fork するとその会話を引きます。これは fork に限らない、以前からの不具合で、matcher の更新で直ります。

## 同じフォルダで fork する

元の pane を分割して（広いほうの辺の向き。場所は元の pane の「いまの場所」）、新しい pane で `claude --resume <会話の id> --fork-session` を起動します。サーバは、起動のコマンドを打ち込むところまでを行って、**新しい pane の id を返します**。その後の検知・手が空くのを待つこと・グラフの注記は裏で続き、進み具合は `agent.fork_progress` のできごとで配ります。

- 作ったばかりの pane は、シェルが入力を受けられるのを待ってから打ち込みます（前面がシェルだけと判定され、かつ出力が 300 ms 静まるまで。出力が一度も無いときは最低 2 秒待つ。上限 15 秒。切れたら `fork_shell_not_ready` で止めて pane は残します。待つ間に pane を閉じられたら `fork_failed`）。先頭の Ctrl-C は送りません（打ちかけが無く、シェルの準備前だと打鍵ごと捨てるため）。
- 起動の直前に、元の pane の会話の id を**読み直します**。シェルの準備の間に `/clear` などで会話が替わっていれば、替わった後の会話を fork します。会話の id が無くなっていたら止めます（新しい pane は閉じます）。
- 新しいエージェントの名前は `<元の名前>-fork`（使われていれば `-fork-2`…）。元に名前が無ければ `fork-<pane id の先頭>`。
- 同じ pane の fork が進行中のとき、もう一度押すと `fork_in_progress`。

## 新しい worktree で fork する

`--worktree <ブランチ>`（画面ではダイアログ）。元の pane の**リポジトリの根**の `HEAD` から新しいブランチを切り、`~/.sodashitsu/worktrees/<リポジトリ名>/<ブランチ名の slug>` に worktree を作り、その workspace を開いて、そこで fork します。

- **ブランチ名が既にあれば断ります**（`fork_branch_exists`。既存のブランチの先端から始めると、会話が見ているコミットとずれるため）。
- **まだコミットしていない変更・`.gitignore` されたファイル（`.env`・`node_modules`・成果物）は付いてきません**（新しい checkout のため）。確定の前の画面（`agent.fork_preview`）に、変更の数を出します（`git status --porcelain` の行数。2 秒で数えられなければ出しません）。
- 元の pane がリポジトリのサブフォルダにいても、新しい workspace は worktree の**根**で開きます。

### 最初の知らせ

会話の中の絶対のパスは、**元のフォルダを指したまま**です。そのままだと、新しいエージェントが元のフォルダのファイルを書き換えかねません。そこで、起動後に 1 回、次の趣旨の知らせを pane に打ち込みます（利用者に見える形）:

> このセッションは、fork されました。作業フォルダは `<新しいフォルダ>` です。元のフォルダ `<元のフォルダ>` のファイルは、変更しないでください。

- **送らない選択**ができます（`--no-note`・ダイアログのチェック）。
- 送るのは「送る予定」として持ち、**エージェントの手が空いた（idle）時点で**です。ただし、idle は確認の画面が描かれる前の読み込みの画面でも成り立つので、**入力欄が出ている証拠**も待ちます: 画面の末尾に入力欄（`❯`）の行があり、確認の文言（`esc to cancel`・`enter to confirm`）が無いこと、または元と違う会話の id が報告されたこと（フックは確認の後に走ります）。確認に Enter が届かないためです。
- 初めてのフォルダの信頼の確認などで止まっている間（`blocked`）は送らず、利用者が答えて手が空いた後に送ります。待つ上限は**手順全体で 10 分**（手が空く・入力欄を確かめるのを繰り返しても、延びません）。切れたら送らず `timed_out`。実機では、信頼済みのリポジトリの worktree は確認が出ませんでした（普通の新しいフォルダでは出ます）。
- 状態は `noteStatus`: `off`（送らない選択・同じフォルダ）／`pending`（手が空いたら送る）／`sent`／`skipped`（理由つき）／`timed_out`。
- フォルダのパスに制御文字・改行・行の区切り（U+2028/2029）・双方向の制御・ゼロ幅の文字・バッククォート・1000 文字を超える長さがあるときは、**知らせを送りません**（`skipped`）。fork 自体は行います。

## 引き継がれるもの・引き継がれないもの

- 引き継がれる: 会話、モデル。
- **引き継がれない: 権限のモード（新しい会話は `default`）、追加したフォルダ（`--add-dir`）。** 必要なら fork した側で指定し直してください。
- 長い会話の fork は、最初のターンで複製した文脈をすべて送るので、**起動に時間と費用がかかります**。
- 元のエージェントが作業中（ツール実行中）のとき、fork は**その時点の記録の写し**です（実行中のツールの結果は持ちません）。

## 失敗したとき

手順の途中で失敗したとき、何が残ったかをメッセージと `agent.fork_progress`（`failed`）の `created` に載せます。

| 失敗の段階 | 残るもの |
| :- | :- |
| 確かめ（pane・エージェント・会話の id・シェル・ブランチ名） | 何も作らない |
| pane を足せない／worktree を作れない | 作った分（worktree は残る。パスを知らせる） |
| worktree はできたが workspace を開けない | worktree が残る |
| シェルが入力を受けられない | pane／workspace・worktree が残る |
| 起動の直前に元のエージェントが入れ替わった・居なくなった（会話の id が無くなった） | 同じフォルダ: 新しい pane は閉じる。worktree: workspace・worktree は残す |
| 起動のコマンドを打ち込めなかった | 同じフォルダ: 新しい pane は閉じる。worktree: 残す |
| 同じフォルダの fork で、場所を引き継げなかった（元の場所が使えず、別のフォルダになる） | 新しい pane は閉じる（止める） |
| 打ち込んだが、エージェントが検出されない／すぐ終わった | 閉じない（利用者が画面で理由を見る）。画面の末尾から理由を拾う: `No conversation found`（記録が見つからない。`CLAUDE_CONFIG_DIR` が違うか、親の Claude Code の環境変数〔`CLAUDE_CODE_*`〕の引き継ぎ）・`unknown option`（古い Claude Code。`--fork-session` に対応していない）・`command not found` |

サーバの再起動・`soda handoff` の途中では、裏の続き（検知・注記・最初の知らせ）は失われます（打ち込み済みの Claude Code は動き続けます）。

## `sodactl`

```
sodactl agent fork <target> [--worktree <ブランチ>] [--no-note] [--no-wait] [--timeout <ms>] [--json]
```

`<target>` は pane の id か、エージェントの名前（`agent rename`／`agent start` で付けたもの）。**既定で最後まで待ちます**（進み具合が `done`／`failed` になるまで。待ちの上限は既定 11 分、最初の知らせの待ちを含む）。`--no-wait` は、起動のコマンドを打ち込んだところで返します。`--no-note` は `--worktree` と一緒に使います。結果（`--json`）:

```json
{"paneId":"…","workspaceId":"…","name":"src-fork","target":"worktree","worktreePath":"…","noteStatus":"sent","annotated":true,"stage":"done"}
```

失敗は終了コード 1（stderr に JSON）。途中で失敗したときは、メッセージに残したもの（pane・worktree）を含めます。自分の pane のエージェントを fork することもできます。

## グラフ

fork した pane のノードに、元のノードを指す**注記**（`forkedFrom`）を付けます（`sodactl graph show --json` のノードに出ます）。新しい線の種類ではなく、**見るだけ**です: 指示は流れず、設定を持たず、線の上限に数えません。

- fork には、エージェントが起動したエージェントに付く自動の監督の線・承認の代理の線を**付けません**。
- 元のノードが無くなったら（pane を閉じた・ノードを外した）、注記は外れます。ノードの鍵を選び直す（`rekey_node`）と、注記も新しい鍵へ付け替わります。
- 古い版のサーバは、注記を知らずに読み飛ばします（グラフのファイルは読めます）。その版が保存し直すと、注記は消えます（線が見えなくなるだけ）。
- 手元のノードの上限でノードが足せないときは、注記なしで成功します（`annotated: false`）。

## 安全と限界

- `agent.fork` は `/ws` の認証済みの接続から使えます（`agent.start` と同じ）。ログイン不要の `pane.sock` には載せません。
- 会話の id の出どころはフックの報告で、**同じ OS の利用者のプログラムが偽の報告を送れば、その利用者の別の会話を fork させることができます**。同じ利用者のプログラムを信頼する、という今の前提の中です。確定の前の画面には、会話の id の先頭 8 文字を出します（取り違えに気づけるように）。
- fork した会話の記録は、その利用者の `~/.claude` に残ります（worktree を消しても残ります）。
- Claude Code だけ。フックが要る。別のマシンの pane は対象外（記録はそのマシンにあるため）。端末版（`soda`）の画面にメニューはなく、`sodactl` を使います。
- Claude Code の版の下限は確かめていません。会話の id で別のフォルダから fork できるのは Claude Code 2.1.223 以降で、それより古い版では、`unknown option` や `No conversation found` の理由が出ます。
- **親の Claude Code の環境変数を引き継いだ pane では fork できません**。`soda serve` を Claude Code の pane の中から起動すると、子の pane に `CLAUDE_CODE_*`（例: `CLAUDE_CODE_CHILD_SESSION`）が入り、`claude --resume --fork-session` の会話が保存されず、`No conversation found` になります（確かめた例）。`soda` を別の端末（Claude Code の外）から起動し直してください。

# 船長の専用端末と停止

船長は対話用PTYを使います。通常の作業一覧から隠しても、端末を非対話実行に切り替えたり、会話・利用データを消したりしません。サーバが保存する `Workspace.assistant` の所有ペインと、そのペインが属するタブ・ワークスペースが一致した場合だけを専用端末として扱います。同じワークスペースに追加された別のペインは通常の作業対象です。通常画面の表示はこの判定を用い、専用の端末窓は元のスナップショットから接続します。

通常の稼働エージェント件数には専用船長を含めません。利用状況、費用の分析、履歴、保存済みの連携グラフの参照は維持します。表示を隠すことで実使用量を過少集計することはありません。所有情報は既存の保存・復元を使い、追加の名前推測で判定しません。

認証済みの `assistant.stop` は `deviceId` と現在の `instanceId` を必要とします。停止直前にも所有ペイン・個体・端末を照合し、置き換わった個体を閉じません。停止中は `assistant.get` が `stopping` を返し、重複停止は同じ処理を待ちます。送信や再起動は許可しません。ペインが一覧から消えただけでは停止完了とせず、PTYの終了通知と状態の保存が完了してから成功を返します。終了確認は最大10秒です。終了の確認中である記録を端末を閉じる前にディスクへ保存し、終了通知と状態保存の成功後だけ消します。保存できなければ端末を閉じません。確認できなかった場合はエラーと停止中の状態を維持し、サーバ側のセッション管理を再生成しても有効化操作ではこの記録を消せません。自動再起動もしません。

停止が成功した後は、明示的な `assistant.ensure` の `activate:true` で新しい専用端末を開始できます。元のワークスペースに別の作業ペインが残っていれば、それを閉じずに所有情報だけを解放し、新しい専用ワークスペースを作ります。アシスタント表示の無効化に伴う既存の「待機状態になるまで待つ」処理とは別です。

生成端末で状態遷移・終了の未確認・置換・同居ペインを検証しています。この変更だけで実Windowsの船長CLIの起動・停止を検証済みとするものではありません。

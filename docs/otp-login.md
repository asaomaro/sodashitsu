# 追加ログイン手段

Web版で認証した状態から、設定の「追加ログイン手段」を開きます。通常のトークン認証も引き続き使えます。二段階認証ではなく、トークンの代わりに使える追加ログイン手段です。

## 使い切りコード

「使い切りコードを発行」で12桁のコードを表示します。別のブラウザのログイン画面で「ログイン方法 → 使い切りコード」を選び、入力します。

有効期間は5分、使用は1回です。発行し直すと前のコードは失効し、「コードを失効」で取り消せます。コードはメモリにハッシュのみ保持し、サーバの再起動・handoffでも失効します。

## 認証アプリ

1. 設定で登録名を入力し、「認証アプリを登録」を押します。
2. 認証アプリで登録用QRを読み取ります。QRを読めない場合は「QRを読めない場合」の手動登録キーを使います。
3. アプリに表示された6桁コードを入力し、「登録を確定」を押します。確認前はログインに使えません。登録作業は5分で期限切れになります。
4. 別のブラウザで「ログイン方法 → 認証アプリ」を選び、新しいコードを入力します。

[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)のTOTP、SHA-1・6桁・30秒に対応します。前後1ステップの時刻差を許容しますが、同じステップのコードは1回限りです。登録確認に使ったコードも再使用できないため、ログインには次のコードを使います。

最大8件登録でき、設定の「登録を削除」で失効できます。登録キーはQR生成ライブラリでブラウザ内に描画し、外部のQR生成サービスへ送信しません。キーは登録時だけ表示し、登録済み一覧からは取得できません。

## 保存と失効

登録情報はサーバのstateDir内の `otp-auth.json` に保存します。共有秘密鍵と使用済みステップを保持するため、このファイルをトークンと同じ認証情報として扱います。ファイル権限は0600（WindowsではOS側のユーザー権限）です。受け付けたステップはログイン前に保存し、再起動後も再使用を拒否します。

登録と使い切りコードは現在のトークンに紐付きます。`soda token reset` でトークンを作り直すと、既存のセッションと追加ログイン手段は失効します。認証アプリの登録をやり直してください。処理中に認証が失効した要求から、新しいコードやセッションを発行しません。

ログインには通常のOrigin/Host検査と、接続元ごとの失敗制限（1分5回・1時間20回）を適用します。追加コードの検証はサーバ全体で1分20回までです。設定の取得・変更には認証が必要で、変更時にもOriginを確認します。

HTTPは通常の `/api/login` に `{ "token": "コード", "method": "otp" }` または `"totp"` を送ります。トークン認証は既存の `{ "token": "トークン" }` のままです。認証済み設定の受け口は `/api/login-settings` です。追加手段の設定UIとQR表示はWeb版で提供します。

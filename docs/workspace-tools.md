# 標準のファイル・Gitビュー

ワークスペースのPJフォルダを設定すると、プラグインの導入なしでファイルツリー、ファイル表示・編集、Gitグラフ、Git差分が利用できます。対象は接続先サーバのPJフォルダで、Sodashitsuの起動フォルダには依存しません。

## ブラウザ版

- タブを追加して「開発（標準）」を選ぶと、ツリー・ファイル表示・Gitグラフ／差分をまとめた作業画面が開きます。作業画面への切替で同じタブの端末を使えます。モバイルでは上部ボタンで各機能を切り替えます。
- タブ行の「ビューを追加」はタブ全体への追加です。種類と配置を選んで確定します。
- ファイル・GitビューはPJフォルダの情報を扱うため、タブ側の候補に表示します。ペイン側には、そのペインの情報を扱うプラグインビューを表示します。浮いた窓も情報の対象と独立して選べます。
- ツリーはフォルダを展開できます。ファイル名検索と「内容をGrep」を切り替え、大文字小文字の区別を選べます。Grepは文字列の一致検索です。結果を選ぶとファイル表示で該当行へ移動します。表示ビューが無ければ同じ対象範囲に閲覧用の浮いた窓を開きます。
- ファイル表示の「編集」でテキストを編集し、「保存」またはCtrl+S（macOSはCmd+S）で保存します。未保存の別ファイルへの移動は確認します。未保存の編集は同じブラウザ内で保持し、窓を開き直すと復元します。ページを閉じる・再読み込みすると失われます（ブラウザの離脱確認が出ます）。
- Gitグラフは枝の記号とコミット・参照名を表示します。コミットを選ぶと、そのコミットの差分を開きます。Git差分では作業中／ステージ済み、ファイル、完全なコミットSHAを指定できます。未追跡ファイルはファイルを選ぶと内容を追加行として表示します。コミットやステージなどのGit変更操作は提供しません。
- 追加ビューの登録・配置は保存されます。タブのビュー一覧の×で登録を削除します。

## 端末版

左右・上下の配置を選んだビューは端末と並べて表示します。浮いた窓はfloatを選んだ場合だけ開きます。ビューをクリックして操作し、Escまたはprefixで端末へ戻ります。

サイドバーのワークスペースを右クリックし「PJフォルダを設定…」を選びます。現在の設定を編集してEnterで確定し、空欄で確定すると解除します。接続先サーバ側に存在する絶対パスを指定してください。

タブ行の `[ビュー＋]`、ペインヘッダーの `[+]`、タブ／ペインの右クリック「ビューを追加…」から、種類と配置を選べます。端末版では標準機能をリサイズ可能なウィンドウで操作します。登録済みの標準ビューは「表示ウィンドウ…」から開き直せます。新規タブの名前入力でTabを押すとターミナル／開発を切り替えます（PJ設定が必要）。

| 操作 | キー |
|---|---|
| 一覧の選択・ファイル／フォルダを開く・コミットの差分 | 上下・Enter |
| ファイル名検索 | `/` →検索語→Enter |
| 内容のGrep | Ctrl+G→検索語→Enter |
| パスを指定してファイルを開く | `p`→相対パス→Enter |
| 編集・保存 | `e`・Ctrl+S |
| 編集中の改行・移動・貼り付け | Enter・矢印・通常の貼り付け |
| 編集から閲覧へ戻る | Esc |
| ファイル一覧・再読込 | `f`・`r` |
| ステージ済み差分切替 | `s` |
| 差分のファイル・コミット指定 | `d`→相対パス、`c`→完全なSHA |
| 閉じる | Esc（未保存時は警告後、もう一度Escで破棄） |
| 窓のリサイズ・移動 | Alt+矢印・Alt+Shift+矢印 |

## 範囲と上限

ファイルの閲覧・編集は512 KiB以下のUTF-8テキストです。バイナリ・複数ハードリンク・Git管理ファイル・PJの外を指すリンクは開けません。編集はリンクを含まない実体の相対パスで行います。保存前に読込時のハッシュと現在の内容を比較し、エージェントや別画面が変更していれば拒否します。保存は一時ファイルから置換し、最終確認後と置換の間に外部プロセスが変更する競合は完全には防げません。

検索は名前／内容とも最大100件、訪問5000項目、深さ24、約5秒までです。`.git`・`node_modules`・リンクは検索を省きます。大きいファイル・読めないファイルは内容検索を省きます。Gitignore全体を解釈する検索ではないため、他の生成物は検索対象になります。上限に達したら検索語を絞ってください。フォルダ一覧は2000項目までです。

Gitグラフは直近150コミット、Git出力は1 MiB、コマンドは8秒までです。PJがリポジトリのサブフォルダなら、履歴・変更の対象をそのフォルダに限定します。Gitの導入が必要です。PJ設定が変わったときはWebでは内容をリセットし、端末版では窓を開き直します。

APIは認証済みの `workspace.tools`。`operation` は `list/read/write/search/git-log/git-status/git-diff`。書込みには`content/version`、検索には`query`と任意の`grep/caseSensitive`、画面からの要求には`expectedFolder`を渡してPJ設定の変更を検出します。ログイン不要のpane.sockには公開していません。

## Webと端末の描画

標準ビューはWeb用と端末用のビュー定義を持ちます。ビューの登録・配置・PJフォルダは共通ですが、Webはファイルツリー/編集画面とSVGのGit接続図、端末はネイティブの一覧/編集画面と罫線・文字によるGit表示を使います。WebのGit接続図は色付きの線とコミット点を表示し、コミットをクリックするとその差分を開きます。端末のGitグラフはコミット点と接続線を色分けし、差分は追加を緑、削除を赤、ハンクをシアンで表示します。

「Statusline」はPJフォルダなしでも追加できる標準ビューです。ペインのヘッダー「ビューを追加」ではそのペイン、タブ行の「ビューを追加」ではそのタブのアクティブなペインを参照します。上下の帯・上下パネル・フロートに配置できます。状態・エージェント・モデル・コンテキスト量・トークン・コスト・アカウントの利用制限を、取得できる範囲で表示します。取得できないモデル/コンテキストは「—」です。焦点・状態の変更と定期更新で表示を更新します。Webと端末は同じ標準のテキスト表示を利用します。

標準ファイル/Gitビューは端末クライアントが直接描画するため、Web用と端末用で表示枠の上限を二重に消費しません。

## 閉じる・畳む

ビューの×は表示と保存済みの登録を削除します。畳む操作は登録を維持し、トレイから再展開できます。削除だけの上段リストは表示しません。準備中/停止中のビューも、Webと端末のタブ右クリックメニュー「ビューを削除: …」から削除できます。ペイン内プログラムが出した、タブビューとして登録していない表示を閉じる操作は従来どおりです。

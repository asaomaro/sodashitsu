# エージェントの利用状況（トークン・コスト・コンテキスト）

起動しているエージェントの利用状況を、**記録（会話の記録のファイル）から読んで**出します。**Claude Code** と **Codex** の、`sodactl agent usage`・方式 `agent.usage`・ブラウザの**ダッシュボード**（3 つ目の画面。下の「ダッシュボード」）と、**pane の情報**（その pane のセッションの窓。下の「pane の情報」）まで。Copilot CLI は、これから（別の PR）です。調査と、決めたことの理由は `.aidev/works/20261010-agent-usage/`（`research.md`・`decisions.md`）。

## 使い方

```
sodactl agent usage              # 取れる全部
sodactl agent usage <target>     # pane の id か、エージェントの名前
sodactl agent usage --json
```

出るもの（種類 `claude`）:

| 項目 | 中身 |
| :- | :- |
| モデル | 記録の最後の主の応答のモデル名 |
| トークン | 入力（キャッシュの読み書きを含む）・出力。**数え方の印**（下）つき |
| コスト | **記録の会計の行（`cost-state`）があるときだけ**。その行の時点の値（それ以後の分は含まない） |
| コンテキスト | 最後の主の応答の入力側のトークン数。**窓の大きさが分かるときだけ率**（下） |
| 更新 | 記録の最後の応答の時刻 |
| 内訳 | 主のエージェントと、サブエージェント（記録に残る分） |

取れない項目は「—」（`--json` では項目が無い）。**0 とは違います**。

## Codex

pane の Codex の会話は、`pane.agentSession`（引数・最初の入力の時刻・終了の文言などで、サーバが記録で検算して付けたもの。Codex の複数 pane の仕組み。`docs/verification.md` の会話の再開）の id だけを使います。記録（`$CODEX_HOME/sessions/YYYY/MM/DD/rollout-…-<id>.jsonl`。既定 `~/.codex`）の探し方は、その検算と同じ部品（新しい日付のフォルダから・上限つき・時間切れつき・リンクを辿らない）です。

| 項目 | 中身 |
| :- | :- |
| トークン | 記録の最後の `token_count` の累計（`total_token_usage`。`cumulative`）。`input` はキャッシュでない分、`cacheRead` はキャッシュの読み（Codex の `input_tokens` は、キャッシュの読みを含む）。`total` は記録の値 |
| モデル | 最後の `turn_context` の `model` |
| コンテキスト | 最後の呼び出しの `total_tokens` ÷ `model_context_window`。**Codex 自身の「残り」の式と違う可能性があります**（Codex は窓の有効な割合〔`effective_context_window_percent`〕や、予約を引くことがあります）。目安として読んでください |
| コスト | **記録に無い**ので、出ません（「—」） |
| 更新 | その `token_count` の行の時刻 |

- **続きから読みます**: 初回は記録の末尾の 256 KB（足りなければ 4 倍ずつ、16 MiB まで）を逆から見て、最後の `token_count` と `turn_context` を探します（`turn_context` はターンごとで、長いターンの後は遠い。実機で、52 MB の記録の最後のものが末尾から 8.7 MB にあり、約 30 ms で読めた）。16 MiB の中に `turn_context` が無ければ、モデルは「—」です。以後は前回の位置から（1 回 1 MiB まで）。大きな記録を、毎回全部は読みません。まだ `token_count` が無い（始まったばかりの）会話は、「無い」（`null`）です。
- **アカウント全体の制限の枠**: `sessions` の下の**いちばん新しい記録**の、最後の `rate_limits` です。pane との対応が無くても出ます（その記録を作った道具〔`originator`〕は見ません。枠は、どの道具の会話でも同じ）。探し方は総当たりしません: 新しい日付のフォルダから（14 日まで）、更新の新しい 4 件までを見て、結果を 10 秒覚えます。
  - 枠のラベルは `window_minutes` から: 300→「5 時間」、10080→「週」、ほかは「N 分」。`primary`・`secondary` の、ある方だけが出ます（アカウントによっては `secondary` が `null` で、週の枠だけ）。プラン（`plan_type`）も出ます。
  - **制限の枠は、`limit_id` が無いか `codex` の行だけ**使います。モデルごとの別枠（`codex_other` など）の行は、Codex の枠として出さず、次の記録（その中の前の行）へ進みます。
  - 取得の時刻（`asOf`）は、その行の時刻です。**リセットの時刻を過ぎた枠は、古い印**（`stale`。次の値を待っています）。
  - 複数の `CODEX_HOME` を使い分けていても、サーバが見るのはサーバの環境の `CODEX_HOME`（無ければ `~/.codex`）の 1 つだけです。
  - 古い日付のフォルダにだけある、長く動いている会話の枠は、見ません。
  - 候補は、日付のフォルダごとに**名前（＝作られた時刻）の新しい順の 12 件**です（更新の時刻ではない）。1 日に 12 件を超える会話がある日に、朝に始めて今も動いている会話は候補に入らず、枠が古く出ることがあります（その pane が開いていて、その記録が新しければ、そちらが勝ちます）。
  - 末尾が 16 MiB を超える改行の無い 1 行（書き途中の巨大な行）のとき、毎回その窓を読み直します（書き終われば元に戻ります）。
  - 初回の読みは、窓の中の行を文字にしてから絞るので、巨大な記録で 数十 ms 主スレッドを占めます（実測で最大でも約 80 ms。初回と、大きく増えたときだけ）。
- **制限の枠**はダッシュボードの上部に出ます（包みを入れていない Claude Code の分は「まだ値がありません」）。

## ダッシュボード（画面）

ブラウザの**サイドバーの上の切り替え**（基本画面／グラフ／**利用状況**。畳んだサイドバーでは「利」。ボタンの `title`・読み上げの名前は「利用状況（ダッシュボード）」）で開く、3 つ目の画面です（画面の中の見出しは「ダッシュボード」）。**見るだけ**です（数字を出すだけで、エージェントには何も送りません）。

- **上部: アカウントの利用枠**。種類（Claude Code・Codex…）ごと・枠（5 時間・週…）ごとの使用率の棒と数字、リセットまでの時間（「あと 2 時間 10 分でリセット」）、値の時刻（「3 分前」）。**値が無いときは、小さく「まだ値がありません」**（Claude Code の枠は、設定の「利用状況（ステータスライン）」で包みを入れると出ます。Codex の枠は記録から出ます）。リセットの時刻を過ぎた枠は、率を出さず「リセット済み（次の値を待っています）」と薄く出します。
- **一覧**: 起動しているエージェント 1 つが 1 行です（エージェントの居ない pane は出ません）。状態・種類・名前・モデル・場所（workspace／tab・作業フォルダ・ブランチ）・サブエージェントの数・トークン・コスト・コンテキスト・最後の動き。
  - **トークン**は、**数え方の印**（累計／記録分〔記録に残る分。確定した累計ではない〕）と、読み込み中・一部の印つき。**コスト**は、時点つき（記録の会計の行の時点「N 分前の時点」・報告の見積り）。無いものは「—」です（0 とは書きません）。
  - **コンテキスト**は、率が分かるとき棒と数字、分からないときはトークン数だけ。棒は数字を併記します（色だけに頼りません）。
  - **古い値**（更新が 1 分より前・更新が止まった）は薄く出し、時刻（「N 分前」）を添えます。
- **並べ替え**（状態・コスト・トークン・名前）と、**種類の絞り込み**。並べ替えはブラウザに覚えます。
- **行を押す（Enter）と、その pane へ移ります**（基本画面に切り替えて、その workspace・tab・pane を選びます）。行へは ↑↓・Home・End で移ります。`Esc` か `prefix`+`a` で基本画面へ戻ります。
- **別のマシン**: 画面が向いているマシン（サイドバーで選んだもの）の pane だけを出します。別のマシンへ切り替えれば、そのマシンの分が出ます（そのマシンのサーバが読みます）。そのサーバが古く、利用状況に対応していないときは、その旨を出します。
- **端末へのキーは届きません**: ダッシュボードの画面が出ている間、基本画面の端末は見えない（`inert`）ので、キー入力は端末へ送られません（グラフの画面と同じ決まり）。`prefix` の二度押し・分割・閉じる操作などは食います。画面を切り替えても、端末（PTY）の大きさは変わりません。
- **様式**: クラシックは端末らしい表（罫線の行）、モダンは行がカード（角の丸い面）。色は画面のテーマの色です。
- **1 列の画面（モバイル）**: 重ねる全画面のダイアログです（行は縦のカード・押せる部品は 44px）。入口は、pane のピッカー（上部の workspace／tab の表示を押して開く）の一番下の「ダッシュボード」です（全体のメニューには足していません。クラシックの基本画面の見た目を変えないため）。行を押すと、ダイアログを閉じてその pane へ移ります。

### 更新の配信

ダッシュボードが**見えている間だけ**、サーバが 5 秒おきに利用状況を確かめ（記録が変わっていなければ読みません）、変わった分を `agent.usage_changed` で、**見ている接続にだけ**送ります。

- ブラウザは、ダッシュボードが見えていて・タブが前面で・接続が開いている間だけ `agent.usage_watch {on: true}` を送ります。見えなくなる・別の画面へ移る・タブが裏へ回るで `on: false`。接続が切れたら、サーバの印も消えます（開き直したら送り直します）。見ている接続が 1 つも居なければ、サーバは確かめません（タイマーも止まります）。
- 画面に出る間隔は 5 秒＋記録の書き込みの遅れ。**エージェントが動いていない間は、値は変わりません**（古い値は薄く出ます）。
- 配るのは `agent.usage` の答えと同じ形（数字・モデル名・時刻・ラベルだけ）の差分です。`pane.sock` には載せません。`sodactl` など画面を持たないクライアントには、頼まれない限り送りません。

## pane の情報（そのセッションの利用状況の窓）

pane 1 つの、エージェントのセッションの利用状況を、pane の近くの小さな窓に出します（ダッシュボードの 1 行を、もう少し詳しく）。

- **開き方**: モダンでは pane の隅の［情報］（分割と最大化の間。エージェントの居る pane だけ）。**クラシックでは隅のボタンを出しません**（配置は今のまま）。どちらでも、pane の右クリックのメニューの「利用状況…」（グラフのノードのメニューにもあります）と、キー **`prefix+shift+u`**（操作 `show_usage`。設定の「キー」で変えられます。もう一度で閉じます）から開けます。エージェントの居ない pane では、ボタン・メニューの項目・キーとも働きません。1 列の画面（モバイル）は、pane のピッカーの各エージェントの行の［利用状況］から、全面のダイアログで開きます。
- **閉じ方**: `Esc`・窓の外を押す・［情報］（またはキー）をもう一度。閉じると端末へフォーカスが戻ります（外を押したときは、押した先）。
- **位置**: その pane の箱の中に収まるときは右上（端末の文字をできるだけ隠さない）。pane が小さいとき・基本画面が見えないとき（グラフのノードのメニューから開いたとき）は、画面の中央です。
- **中身**: 種類・名前・状態・モデル／トークン（入力・出力・キャッシュ読み・キャッシュ書き・推論。基準の印〔累計／記録分／文脈内〕。主とサブエージェントの内訳があれば）・コスト（時点・見積り。無ければ「—」）・コンテキスト（率と窓の大きさ、または `N tok`）・更新（「N 分前」。1 分より前は「古い」。読み込み中・一部・更新停止）／会話の id の先頭 8 文字・作業フォルダ・ブランチ・サブエージェントの数（1 件以上なら一覧を開く入口）／その種類のアカウントの枠（ダッシュボードと同じ形）と［ダッシュボードを開く］。数字の整形と古い値の扱いは、ダッシュボードと同じ部品です。
- **「いまの状態になってから」**: 状態（作業中・待機中など）が変わってからの時間です（エージェントが検知された時刻ではありません。検出の時刻はプロトコルに無い）。
- **配信**: 窓が開いている間だけ、サーバへ利用状況の配信を頼みます（ダッシュボードと同じ仕組みで、どちらかが見えていれば配られ、両方が閉じれば止まります）。窓が閉じている間は、サーバは利用状況を確かめません。
- 端末版（`soda`）には窓がありません（`prefix+shift+u` は「ブラウザで開けます」と知らせます。`sodactl agent usage` で見られます）。

## 数え方の印（確定した累計とは言いません）

- **累計**（`cumulative`）: Claude Code が記録の区切り（`/clear`・終了・再開）に書く会計の行（`cost-state`。未文書）の累計に、その行より後の記録の分を足したもの。コストも、この行の値です。
- **記録に残る分**（`transcript`）: 記録の応答の `usage` を、応答の id ごとに 1 回数えた合計（サブエージェントの記録を含む）。**会計の累計より小さく出ます**（調査で、出力トークンが 1/3〜1/9 になる例を確かめました。記録に残らない呼び出し・消えたサブエージェントの記録などが理由と考えられますが、確かめていません）。下限として読んでください。
- **一部**: 大きな記録（64 MiB 超）は末尾の 64 MiB だけを読みます（初めの分は含まれません）。サブエージェントの記録が 256 を超えたときも「一部」です。
- **読み込み中**: 大きな記録は、背景で何回かに分けて読みます。もう一度呼ぶと増えます。

## ステータスラインの包み（Claude Code。制限の枠とコスト。PR2）

制限（5 時間・週）の使用率とリセットの時刻、いま動いているセッションのコスト・コンテキストの使用率は、記録に出ません。**Claude Code のステータスライン**の入力にだけあります。そこで、設定の「エージェント連携」の項目 **「利用状況（ステータスライン）」** で、ステータスラインの設定を、**元の表示をそのまま返す小さな包み**（`soda-statusline.cjs`）に替えられます。**フックの［導入］とは別の項目**です（フックを入れただけでは、ステータスラインは変えません。押したときだけ書き換えます）。

### 何を送るか・送らないもの
- 送る（`agent-report.sock` へ、数字と id だけの 1 行）: コスト（`cost.total_cost_usd`。見積り）・コンテキストの使用率と窓の大きさ・いま文脈にあるトークン数・制限の枠（5 時間・週。組織の枠があればそれも。使用率とリセットの時刻）・モデルの id と表示名・会話の id（UUID）・報告したエージェントの pid（#128 の確かめ用）・設定のフォルダの一方向の印と（別の設定のフォルダを使うときだけ）フォルダの末尾の名前。
- **送らない**: セッションの名前（`session_name`）・作業フォルダ・会話の記録の場所・リポジトリの情報・会話の中身・設定のフォルダの場所そのもの。
- 送れなくても（ソケットが無い・遅い・失敗）、**表示は元のとおり**です（200 ms ほどで諦めます。元のコマンドの出力・終了コードをそのまま返します）。
- **包みの費用**: 起動に Node を 1 つ余計に動かします（測定: 元が数 ms のとき、直接 約 1 ms → 包み経由 約 45〜60 ms。うち Node の起動 約 30 ms・送り 約 10 ms）。送りは、入力を読んだ直後に始め、元のコマンドと並べて動かします。元が速くても、送りの終わりを最大 200 ms だけ待ちます（普通は数 ms〜十数 ms）。元のコマンドが重いほど、割合は小さくなります。
- Claude Code は、ステータスラインのコマンドの標準入力を閉じます（公式の例が、`cat` で全部読む形のため）。包みは、閉じられなくても 3 秒で読むのをやめて動かします。

### 入れ方・外し方
- **導入**: `statusLine` が無ければ、包みだけを入れます（元は「無い」と控えます）。あれば、元の `statusLine`（`type`・`command`・`padding`・`refreshInterval`）を**控えて**、`command` だけを包みに替えます（`padding`・`refreshInterval` は元のまま）。包みは、元のコマンドを、**シェルを通して**（Claude Code と同じ）動かします。
- **元の控え**は 2 か所: 横のファイル（`~/.claude/hooks/soda-statusline.orig.json`。0600）と、包みの command の引数（base64url。元のオブジェクトと、**元の値の文字列そのもの**）。**包みは引数を先に読む**ので、横のファイルが消えても、設定のファイルだけで元を再現でき、外すと元の書式のまま戻ります。引数が 8 KiB を超える元は、値の文字列を（それでも超えるなら元のオブジェクトも）引数に載せず、横のファイルだけに頼ります（そのとき横のファイルを消すと、外せません）。
- **取り消し**: 元のコマンドは、**新しいプロセスグループ**で動かします。Claude Code が包みを取り消す（SIGTERM・SIGINT・SIGHUP）と、グループ全体へ伝え、1 秒で終わらなければ SIGKILL します（元が `sh -c` の入れ子でも、孫を残しません）。元は端末の制御を持ちません（ステータスラインはパイプで動くので、表示は変わりません）。
- **足す行の改行**は、ファイルの行の終わり（CRLF／LF）に合わせます。
- **外す**: 控えた元へ戻します（元が無かったなら、`statusLine` を消します）。**導入 → 外す で、設定のファイルは 1 バイトも違わず戻ります**（書式・インデント・並び・行の終わり・末尾の改行・モード。横のファイルが無くても。上の「引数が大きい元」を除く）。書き換えるのは `statusLine` の 1 項目だけで、ほかのキーは触りません。
- **利用者が、後から自分で `statusLine` を替えた**とき: 状態は「外れています（利用者が替えました）」。**外すは何もしません**（利用者の新しい値を上書きしません）。導入すると、今の値を新しい元として控えます。
- 設定の形が想定と違う（`statusLine` が文字列・配列・`type` が `command` でない・JSON が壊れている）ときは、何も変えず、理由を返します。
- 対象は、ユーザーの設定（`~/.claude/settings.json`。`CLAUDE_CONFIG_DIR` があればその下）だけ。**プロジェクトの設定（`.claude/settings.json`）には触りません。**
- Windows は対象外です（`sh` が無いため。導入を出しません）。

### 誰の報告か
フックの報告と同じ確かめ（#128: シェルの子孫・前面のエージェント自身の pid）に加えて、**報告の会話の id が、その pane の今の会話の参照と一致するときだけ**受けます。一致しない・参照がまだ無い間は、短く（1・3・8 秒）保留して確かめ直し、それでも合わなければ捨てます（`/clear` の直後は、報告がフックの報告より先に届きえます）。別の会話・子の `claude` の報告は、届きません。

### 効かない場合（「まだ報告がありません」）
導入済みで、動いている Claude Code が、検出の後に**動いた（working になった）ことがあり**、それから 2 分たつのに報告が無いと、設定に「まだ報告がありません」と出ます。**待っているだけの Claude Code には出しません**（ステータスラインは、応答のたびに呼ばれるため）。次の可能性があります:
- **信頼されていないフォルダ**（Claude Code は、信頼を受け入れるまで、ステータスラインを動かしません）。
- **プロジェクトの設定（`.claude/settings.json`）が `statusLine` を持つ**（ユーザーの設定を上書きします）。
- **管理された設定**（`disableAllHooks`・`allowManagedHooksOnly` など）。
- 導入の前から動いている Claude Code（起動し直すと効きます）。

### 限界
- **アカウントの鍵は、報告が自分で持つ値です**（設定のフォルダの一方向の印）。同じ利用者の pane の中のプログラムは、別のアカウントの鍵を送って、そのアカウントの枠の表示を偽れます（表示の数字だけ。会話の参照・記録の場所・ほかの pane の数字は変わりません）。今回は、枠は**いちばん新しい報告が勝つ**とし、**別の pane が、すでに使われている鍵で報告したとき**を、ログに残します（鍵と pane の id だけ）。鍵を pane の記録と照らす絞りは、後続です。
- **包み自体が SIGKILL で殺された**ときは、元のコマンドの子が残りうる（取り消し〔SIGTERM・SIGINT・SIGHUP〕と普通の終わりでは、グループごと止めます）。
- **元のコマンドは制御端末を持ちません**（新しいプロセスグループ・セッションで動かすため）。`/dev/tty` を開くコマンドは動きません（ステータスラインは、もともとパイプで動くので、ふつうは問題になりません）。
- **「まだ報告がありません」は、ほかの pane の報告があると出ません**（判定は、サーバ全体で「検出の後に報告があったか」を見るため。1 つの pane だけ届いていなくても、別の pane から届いていれば、出さない）。
- **控えが大きい元**（8 KiB 超）は、引数に載せず、横のファイルだけを読みます（横のファイルが無いと、包みは何も出さず、外せません）。項目の無い設定のファイル（`{}`・`{\n}` など）は、小さければ、引数に元のファイルを載せ、横のファイルが無くても戻します。
- **制限は Pro・Max の利用者だけ**です（Claude Code が、`rate_limits` を、claude.ai の Pro・Max の利用者の最初の応答の後にだけ入力に入れます）。それ以外は、枠が出ません。
- **アイドルの間は値が古い**です: ステータスラインは、応答・`/compact` などのときに呼ばれます（`refreshInterval` は足しません）。リセットの時刻を過ぎた枠には「古い」の印が付きます。画面の「更新」の時刻で分かります。
- コストは Claude Code の**見積り**（list price）です。
- トークン数は、これまでどおり記録からの合計（「記録に残る分」）で、**置き換えません**。報告の「いま文脈にあるトークン」は、累計ではないので、コンテキストの項目に別に持ちます。

## 出ないもの・限界


- **コストの単価の表は持ちません**。コストは `cost-state` の行があるときだけです（動いている間は更新されない: 区切りにだけ書かれます）。ステータスラインの報告（`cost.total_cost_usd`）からのコストは、包み（上の節）を入れると出ます。
- **制限（5 時間・週）の使用率とリセットの時刻**は、記録に出ません。Claude Code は、上の「ステータスラインの包み」を入れると出ます（Pro・Max だけ）。Codex の制限は、記録から出ます（上の Codex の節）。
- **コンテキストの使用率**は、窓の大きさが記録に出ないので、モデルの id に `[1m]` が付くとき（100 万）だけ出ます。ほかは、トークン数だけ。
- `cost-state` は公式の文書に無い内部の行で、**版で形が変わりえます**。読めなければ、黙って「記録に残る分」へ落ちます。
- **応答の `usage` は、同じ id の最初の行を取ります**（実在の記録では、同じ id の行の `usage` は同一でした。将来の版で、後の行が確定値になれば、過小に出ます）。
- **サーバと pane の `CLAUDE_CONFIG_DIR` が違うと**、記録の場所が根の外になり、読まれません（黙って「無い」になります）。サーバを起動した環境に、pane と同じ値を渡してください。
- **`cost-state` は、サブエージェントの記録が遅れて書かれたとき**（行の時刻は前、書かれたのは後）、その後の分に入らず、わずかに過小になります。会計の累計（`cumulative`）は、記録の合計より大きいのが普通で、そちらを優先します。
- **プロジェクトのフォルダが 5,000 を超える**根では、探索が黙って打ち切られます（記録が「無い」扱いになることがあります。フックの報告の場所が合えば、探索はしません）。
- **同じ会話の id が複数のプロジェクトにある**とき（別のフォルダで再開すると複製ができます）は、更新の時刻が新しいほうを読みます。
- **1 つの会話で読む量の生涯の上限（512 MiB）**に達すると、その会話の更新を止め、数字は止まった時点のもの（`partial` と `updatesStopped`）になります。記録が書き換えられて数え直しになっても、読んだ量は引き継ぎます。
- 利用者が付けたセッションの名前・会話の文・記録の場所は、答えのどこにもありません。

## 安全

- 入力は pane の id だけ。**記録の場所は受け取らず、サーバが決めます**: pane の会話の id（フックの報告をサーバが受け入れたもの）から、記録の根（`~/.claude/projects`・`CLAUDE_CONFIG_DIR` の `projects`）の直下の 1 段の中の `<会話の id>.jsonl` だけを読みます。フックの報告の場所（`transcript_path`）は候補にするだけで、実体のパスが根の下・名前が一致・リンクでない通常のファイル・リンクが 1 つのときだけ使います。合わなければ、根の下を会話の id の名前で探します。
- サブエージェントの記録も、`<会話の id>/subagents/agent-*.jsonl` の決まった形で、実体のフォルダが組み立てた場所と一致するときだけ。
- 開くときは `O_NOFOLLOW`・`O_NONBLOCK`（FIFO で固まらない）で、開いた fd で通常のファイル・リンク 1 つを確かめ直します。サブエージェントの記録の窓（`agent.subagent_transcript`）と同じ部品です。
- **記録の場所は、受け入れた報告のものだけ**覚えます（会話の参照の確かめを通った報告。保留の後で受けた場合も）。捨てた報告（子のエージェント・別の pane・Codex の常駐のプロセス）の場所・実在しない pane の報告は覚えません。
- モデルの名前は、先頭が英数字で、英数字と `.`・`_`・`-`・`:` と末尾の `[1m]` の類だけを通します（それ以外は「—」）。
- pane が閉じたとき・サーバが止まる処理に入ったとき、走っている読みはチャンクの境目で止まります。同じ pane への同時の呼び出しは、場所の探索を 1 回にまとめます。
- ログイン済みの `/ws` の方式だけ（`pane.sock` には載せません）。別のマシンの pane は、そのマシンのサーバが答えます。
- **フックのスクリプトが変わりました**（会話の記録の場所を報告に添えます）。導入済みの方は、設定の「エージェント連携」に「更新が必要」と出ます。押したときだけ書き換わります。更新するまでは、記録の場所を探索で見つけます（少し遅くなりえます）。

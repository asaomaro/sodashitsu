# Cursor CLI の利用状況

設定のエージェント連携で Cursor を導入・更新すると、`afterAgentResponse` の正式な報告にあるトークン、モデル、明示された effort を表示します。以前に連携を導入している場合も、追加の hook が必要なので「更新が必要」と表示されます。更新時に利用者の既存の hook は残します。

数値は、この操舵室サーバが受け取った報告の分だけです。導入前・再起動前・届かなかった報告を復元したセッション全体の会計ではないため、「記録に残る分」「部分」として扱います。最初の報告が無い状態は未取得で、0を表示するための初期値を作りません。入力はキャッシュの読み書きと分け、同じ generation の再送を二重加算しません。

同じ generation に矛盾する数値がある場合や、保持する generation が4096件を超えた場合は、そのセッションの数値を未取得にします。古い ID を捨てて再び加算することはありません。サーバの再起動、pane の終了、エージェントの instance・会話が替わると、受信分の集計は失効します。

モデルは報告された値、effort は `model_params` の明示値だけを使います。モデル名の末尾や起動時に希望した値からは推測しません。この報告から現在のコンテキスト使用率、USDコスト、アカウント上限、承認設定、子の件数・作業状態を推測することもありません。

会話の本文、タスク、メールアドレス、記録の場所は数値の報告に載せません。親の conversation ID と現在の pane・instance・確認済み会話を照合します。PID が報告された場合は従来の照合に従って矛盾する報告を拒否します。PID を取得できない環境では種類・会話の一致による従来の best-effort の範囲で扱い、PIDを確認済みとはしません。この経路で実行権限や会話の確認済み状態を付与することはありません。

正式 hook の定義は [Cursor Hooks](https://cursor.com/docs/hooks)、共通の表示は[エージェントの利用状況](agent-usage.md)を参照してください。導入済み CLI 2026.11.05-86047df の数値送出の実装と、生成データでの hook・通常 API 配線を確認しています。実際にモデルを動かしての発火確認とは区別しています。

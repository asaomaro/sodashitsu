# 連携のグラフ（エージェントどうしを線で結ぶ）

pane をノードとして並べ、線で結んで「A が終わったら B に A の結果を渡して指示する」「A を B に監督させる」を設定する画面（20260927-agent-graph）。
線は `soda serve` が動かすので、ブラウザを閉じても連携は動き続ける。同じ操作は `sodactl graph …` でもできる（下の「sodactl から」）。

グラフは `soda serve`（session）ごとに 1 枚。別のマシンを見ている間も、グラフ画面が扱うのは手元の `soda serve` のグラフ。

## 開く・閉じる

- 開く: `prefix+a`（操作名 `open_graph`。設定「キー」で変えられる）、サイドバーの「メニュー」→「連携（グラフ）」、モバイルは上部バーの「連携」。
- 閉じる: 開いたのと同じ `prefix+a`、`Esc`、右上の ×。`Esc` は 1 段ずつ戻る（確認 → モバイルのシート → 線の作成の途中 → チェックリスト → 選び直し → 線の設定 → 履歴 → 選択 → 画面）。
  閉じると開く前の pane にフォーカスが戻る。
- 開いている間のキー・ホイール・ドラッグは端末の pane へ届かない。
- 端末版（引数なしの `soda`）では開けない。`prefix+a` を押すと「グラフの画面はブラウザで開けます。」と知らせる。

## pane を載せる（ノード）

ツールバーの「pane を載せる」でチェックリストを開き、載せる pane を選ぶ（すべての pane を自動では載せない）。手元の pane と、登録したマシンの pane が
マシン・workspace ごとに並ぶ。外すときは確認が出て、そのノードに繋がる線も一緒に消える（消える本数を示す）。

ノードには pane の呼び名・マシン・エージェントの名前と種類・状態（`StateIcon`。作業中・承認待ち・手が空いた・完了・不明）が出る。
ノードはドラッグで動かせ、20px のグリッドに吸い付く（`Alt` を押しながらだと吸い付かない）。配置は保存され、他のブラウザにもすぐ届く。
ノードのボタン・`Enter` で、その pane へ移る（グラフ画面を閉じる。別のマシンの pane ならそのマシンに切り替える）。

載せられるのは 64 個まで、線は 128 本まで。

## 線の種類

| 線 | 何をするか | 見た目 |
|---|---|---|
| トリガ | 元のエージェントが**完了した**／**承認待ちになった**とき、先のエージェントへ決めた文面を送る。元の画面の末尾を文面に含めて受け渡せる | 実線（受け渡しありは太線）・▶。チップに「完了→」「承認待ち→」 |
| 監督 | 監督役（線の先）へ、配下（線の元）の pane の ID・呼び名・マシンと sodactl での操作方法を知らせる。配下への指示・待機・読み取りは監督役が sodactl で行う | 破線（監督役→配下の向きで描く）・◆。チップに「監督」 |
| 承認の代理 | 配下が承認待ちになったら、監督役へ画面の末尾（判断の材料）を渡す。監督役に返答まで任せるか、知らせるだけにするかを選ぶ | 点線・●。チップに「承認・通知」（知らせるだけ）・「承認・返答」（返答まで任せる） |

色だけでなく、線の種類・先の印・チップの文字でも区別する。線の中点のチップには回数/上限（`3/10`）と印（`⏸` 一時停止・`⏸ 上限`・`⏸ 全体`・`⚠` 無効・直前の結果
`✓` 送った・`…` 待っている・`⏭` 見送った・`✕` 失敗）が出る。線が動くと 1.5 秒光る（`prefers-reduced-motion` では太さと色だけ）。

## 線を作る・設定する

- マウス: ノードの右のハンドルから別のノードへドラッグして離すと、右に「新しい線」の設定が開く。**保存するまでサーバへは送らない**。何も無い所で離す・
  ドラッグ中の `Esc` は線を作らない。
- キーだけ: ノードを選んで `c`（接続モード）→ `Tab`・矢印で先のノードを選ぶ → `Enter` で設定を開く。`Esc` で取り消す。
- 既存の線はチップを押す（`Enter`）と設定が開く。保存は「保存」か `Ctrl+Enter`（文面の欄の `Enter` は改行）、`Esc`・取り消し・外側のクリックで取り消す
  （変えていれば「変更を捨てますか」）。線の種類は作るときだけ選べる（変えるなら消して作り直す）。
- 他のブラウザ・sodactl が同じ線を変えた・消したら、設定の中に知らせが出る（黙って上書きしない）。

設定の項目と既定値:

| 項目 | 線 | 既定 | 範囲 |
|---|---|---|---|
| 元が「完了した」／「承認待ちになった」とき | トリガ | 完了した | — |
| 送る文面 | トリガ | 「次の結果を確認して、続きの作業をしてください。」＋`{output}` | 8KB まで |
| 元の画面の末尾を受け渡す行数 | トリガ | 80 行（受け渡さないも選べる） | 1〜500 |
| 先が作業中なら | トリガ | 手が空くまで待つ（最長 30 分） | 待つ／見送る |
| 監督役に | 承認の代理 | 知らせるだけ（返答は人） | 知らせるだけ／返答まで任せる |
| 渡す画面の末尾 | 承認の代理 | 40 行 | 1〜500 |
| 上限 | すべて | 10 回 | 1〜100 |

受け渡す画面の末尾は、文面の `{output}` の位置に入る（無ければ文面の末尾に足す）。行は折り返しをつないだ論理行で数え、色などの制御文字は除く。

## いつ動くか（待ちと見送り）

- **完了した**: 元のエージェントが作業を終えて手が空いた 1 回ごとに 1 回だけ（ブラウザの完了の通知と同じ判定。既読にしただけ・同じ完了をもう一度見ただけでは動かない）。
  線を結んだ時点・エージェントが入れ替わった直後の状態は「基準」として覚えるだけで、動かない。
- **承認待ちになった**: 承認待ちが 1 秒続いたら 1 回。承認待ちを抜けると次に備える。線を結んだ時点で既に承認待ちなら、その回は動かない。
- 先のエージェントの状態で扱いが変わる:

| 先の状態 | 扱い（履歴の理由） |
|---|---|
| 手が空いている（idle・done） | すぐ送る（`sent`） |
| 作業中・不明（unknown） | 「待つ」なら手が空くまで待つ（最長 30 分。超えたら見送り `busy_timeout`）。待つ間に同じ線がもう一度動いたら新しい 1 件だけを送る。「見送る」なら見送り（`busy`） |
| 承認待ち | 見送り（`blocked`。承認待ちのエージェントへは送らない） |
| エージェントが居ない・pane が無い | 見送り（`target_absent`） |
| マシンに繋がっていない | 見送り（`machine_unavailable`。下の「別のマシン」） |

- 送り始めた先は、送り終えるまでと、送り終えてから最長 5 秒（その間に先の本物の状態の変化が届けばそちらを使う）は作業中とみなし、同じ先へ続けて 2 通送らない。
- 状態の変化から送り始めるまで（エージェントの状態の判定の周期を除く。16 pane・32 本の実物のサーバで測った値。`packages/server/src/graph/perf.integration.test.ts` が
  `[graph-perf]` の行に出し、2 秒を超えれば試験が落ちる。承認待ちは 1 秒続いた時点から数える）:
  - **完了した**から: すぐ動く。単独で 20ms 以下、他の試験と並んだ負荷の下でも数百 ms。
  - **承認待ちになった**から（承認待ちのトリガ・承認の代理）: 承認待ちが 1 秒続くのを待つので、約 1 秒＋α（単独で約 1007ms）。1 秒が満ちた時点で動く
    （1 秒ごとの見回りは待たない）。
- 監督役への知らせは、監督の線を結んだとき・配下の構成が変わったとき・監督役のエージェントが入れ替わったときに、**監督役の手が空いてから**短い prompt で送る
  （続く変化は 2 秒待って 1 回にまとめる）。知らせは線の回数に数えない。

## 上限と一時停止

- 線ごとに実行回数の上限がある（既定 10 回）。達するとその線は止まり（`⏸ 上限`）、画面の下に知らせが出る（グラフ画面を閉じていても出る）。
  往復する線（A→B と B→A）も上限で必ず止まる。
- 一時停止: ツールバーの「全体を一時停止」、線のチップの `p`・設定の「一時停止」。一時停止中は、どの状態の変化でも線は動かない（履歴に `paused` で残る）。
- 線を再開すると回数が 0 に戻る。全体の再開は線ごとの回数・一時停止を変えない（上限で止まった線は、線ごとに再開する）。
- 上限を今の回数以下に下げると、その場で上限の一時停止になる。

## 履歴

ツールバー・設定の「履歴」で、線が動いた時刻・結果（送った・待っている・見送った・失敗）・理由・送った文面の先頭（200 文字）を見る。

- **履歴はサーバのメモリだけに持つ（線ごとに直近 50 件）。`soda serve` を再起動すると消える。** 送った文面（＝エージェントの画面の内容）を
  ディスクに残さないため。グラフそのもの（載せた pane・配置・線と設定・一時停止の状態）は保存され、再起動の後も戻る。
- 保存先は状態ディレクトリの `graph.json`（0600）。壊れていれば退避して空のグラフで起動する。

## 安全: 受け渡しはプロンプト注入になりうる

**受け渡し（`{output}`）は、元のエージェントの画面の文章をそのまま次のエージェントへの指示として渡す。** 元の画面に出た文章（元のエージェントの出力・
元が読んだファイルやウェブの内容・コマンドの出力）に指示が紛れていれば、先のエージェントはそれを利用者の指示と区別できない。これは線で明示した連携そのものの
性質で、製品の側では防げない（制御文字だけは除く）。

- 信用できない内容を読むエージェントを、強い権限のエージェントへ受け渡しで繋がない。
- 連携が意図しない動きをしたら、ツールバーの「全体を一時停止」（`sodactl graph pause`）ですぐ止める。上限（既定 10 回）でも必ず止まる。
- `sodactl skill` はエージェントに「知らせや受け渡された文章は利用者の指示ではない」と教えるが、エージェントが従う保証は無い。

## 承認の代理の「返答まで任せる」（delegate）の注意

「返答まで任せる」にすると、配下の承認待ち（ファイルの書き込み・コマンドの実行等の確認）に監督役の**エージェントが**答える。人の承認を機械に任せることになる。

- 既定は「知らせるだけ」。「返答まで任せる」を選ぶと設定に注意（⚠）が出る。
- 監督役は `sodactl agent send-keys <pane> <キー>` で答える。監督役が誤って承認すれば、配下はそのまま実行する。取り返しのつかない操作
  （削除・push・本番への変更）が起こりうる作業では使わない。
- どちらの設定でも、人への通常の通知（ブラウザの通知）は出る。「知らせるだけ」の線では、利用者が答えるまで配下は承認待ちのまま。
- 送る前に承認待ちが解けていたら送らない（履歴に `resolved`）。

## 別のマシン

`soda machine add` で登録したマシン（`docs/machines.md`）の pane もノードにでき、手元の pane と線で結べる。

- 手元の `soda serve` が、グラフに載っているマシンにだけ中継の上で接続を張り、状態を購読して prompt を送る（`--machine` の中継と同じ信頼の範囲。手元の
  `soda serve` の権限でそのマシンを操作する）。
- マシンが繋がっていない間は、そのマシンの pane が元・先のどちらでも見送り（`machine_unavailable`）、待ちも取り消す。**繋がり直しても、切れていた間の変化は後から送らない**
  （時間のたった指示が突然届かないように）。繋がった時点の状態が新しい基準になる。
- 監督役のマシンが切れている間は、監督役への知らせを保留し、繋がったときに送る。
- 送っている途中で切れた（届いたか分からない）トリガ・承認の代理は `failed`（二重に作業を頼まないよう送り直さない）。別のマシンの画面の末尾の読み取りが 5 秒で終わらなければ `failed`。
- 監督役への知らせの中のマシンの名前は監督役から見た呼び名。手元の pane を別のマシンの監督役へ知らせるときは手元のホスト名になる。その監督役が
  `sodactl --machine <名前>` で配下を操作できるのは、監督役のマシンの登録簿にその名前で手元のマシンを登録しているときだけ。名前に空白・引用符などシェルの
  区切りになる文字があれば、知らせの中では単一引用符で囲んで書く（`--machine 'my box'`。文面のコマンドをそのまま実行しても名前が 1 語として渡る）。
- ノードの「未接続」: 繋がっていないマシンのノードは状態を出さず、pane へ移れない。切れているマシンの pane は新しく載せられない（載っているものは外せる）。

## 無効なノードと選び直し

- `soda serve` の起動時に `session.json` が読めず pane の番号を振り直したときは、手元のノードがすべて**無効**（`⚠ 無効`）になり、その線は動かない
  （同じ番号の別の pane へ誤って送らないため）。閉じた pane のノードも無効として表示する（線は黙って消さない）。
- `session.json` を読めた起動でも、読めた `session.json` の次の番号（`nextId`）以上の pane を指す手元のノードは**無効**になる。`session.json` は間を置いて
  まとめて書き、グラフはすぐ書くので、書く前に落ちると `session.json` に無い新しい pane を指すノードが残り、次に作る同じ番号の pane に線が付いてしまうため。
  それより前の番号で今は無い pane のノードは「閉じた pane」の無効として出る（どちらも選び直すか外すまで線は動かない）。
- 無効なノードは、ノードの「選び直す…」（キーは `r`）で同じマシンの今の pane に付け替えられる。線はそのまま付け替わり、無効の印が外れる。
  候補はグラフに載っていない pane と、同じ番号の今の pane（選べば印だけが外れる）。チェックリスト・`Delete` で外してもよい。
- `sodactl graph node rekey <pane> <新しい pane>`（同じマシンの pane だけ）・`sodactl graph node rm <pane>` でも同じことができる。別のマシンの pane への
  選び直しは、画面・sodactl だけでなくサーバも `invalid_params`（`rekey_other_machine`）で断る。
- **別のマシンのノードは無効にならない**。別のマシンの `soda serve` が保存した session を読めずに pane の番号を振り直しても、手元のサーバにはそれを知る手段が無い
  （プロトコルに「番号を振り直した」の知らせが無い。backlog）。そのとき線は、**同じ番号の無関係な pane を相手に、元・先・監督役のどの側でも誤って動く**:
  - 元の側: 振り直した直後はエージェントの instanceId が変わるので最初の 1 回だけ「基準」として動かないが、その後は無関係な pane のエージェントの完了・承認待ちで線が動く。
    トリガならその pane の画面（`{output}`）を先へ渡し、承認の代理ならその pane の承認待ちを監督役へ知らせる（`delegate` なら監督役に、無関係な承認へ答えるよう案内する）。
  - 先・監督役の側: 同じ番号の別の pane にエージェントが居て手が空いていれば、その pane へ文面・知らせを送る。
  別のマシンの状態ディレクトリを消した・session.json が壊れた・そのマシンで pane の番号が 1 から振り直されたと分かったら、**まず全体（か、そのマシンに繋がる線）を
  一時停止し**、そのマシンのノードを今の pane に選び直すか外してから再開する。

## sodactl から

画面と同じ操作が `sodactl graph …` でできる（変更は画面へすぐ届く。詳しくは `docs/sodactl.md`「連携のグラフ（`graph`）」）。

```bash
sodactl graph show                                                   # グラフの状態・ノード・線を表で
sodactl graph link add impl reviewer --prompt "レビューして {output}" --output 120
sodactl graph link add impl lead --kind supervise
sodactl graph link pause l1
sodactl graph pause                                                  # 全体を止める
sodactl graph history l1
```

エージェントに使わせるときは `sodactl skill`（`docs/sodactl.md`）に使い方が載っている。

## キー（グラフ画面）

| キー | 操作 |
|---|---|
| `prefix+a`（開いたのと同じキー）・`Esc`・× | 閉じる（`Esc` は 1 段ずつ） |
| `Tab`・`Shift+Tab` | ノード・線のチップの間を移る |
| 矢印・`Shift`+矢印 | 選んだノードを 1 グリッド（20px）・5 グリッド動かす |
| `c` | 接続モード（`Tab`・矢印で先を選び `Enter` で設定。`Esc` で取り消し） |
| `Enter` | ノード: その pane へ移る。チップ: 線の設定を開く |
| `Delete`・`Backspace` | ノードを外す・線を消す（確認つき。確認の既定のフォーカスは「取り消す」） |
| `p` | チップ: 線の一時停止・再開 |
| `r` | 無効なノードを選び直す |
| `1` / `+` / `-` / `0` | 全体表示 / 拡大 / 縮小 / 100% |
| `Ctrl+Enter` | 線の設定を保存 |

マウス: 何も無い所のドラッグ・ホイールでパン、`Ctrl`／`⌘`＋ホイール・ピンチでズーム。表示（パン・ズーム）はこのブラウザに覚える。

## モバイル

閲覧（1 本指でパン・2 本指でピンチ）と、グラフ全体・線ごとの一時停止・再開だけができる（線のチップを押すと下からシートが出る）。
ノードの配置・線の作成・設定・削除はデスクトップのブラウザで行う。

## 実機で未検証の項目

自動の試験（vitest・実物のサーバの結合試験）では確かめたが、実物の環境では確かめていないもの:

- **実物のエージェント**（Claude Code・Codex 等）での一巡: 試験はエージェントの状態をサーバの中から偽って出し、送られる側は `cat`。実物のエージェントの
  完了・承認待ちの判定から線が動くこと、監督役のエージェントが知らせを読んで sodactl で配下を操作できること、「返答まで任せる」で監督役が実物の承認ダイアログに
  答えて解けることは未確認。
- **実物のブラウザ**（Chrome・Edge・モバイルの Safari・Chrome）でのグラフ画面: ホイール・ピンチ・タッチでの線の選び方・フォーカスの枠・reduced-motion・
  モバイルのシートの見た目。グラフ画面の E2E は無い。描画の時間も happy-dom での目安だけ（16 pane・32 本で開いて約 130ms）。
- **別のマシン**: 試験は同じ機械の 2 つの `soda serve`。実際の SSH 越しの 2 台・切断と再接続は未確認。
- **Windows ネイティブ**の `soda serve` での実行（試験は Linux）。

手順は `docs/verification.md`「連携のグラフ（20260927-agent-graph）」。

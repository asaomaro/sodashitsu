# 子の会話とモデル・effortの記録

子への入力は追加せず、指示は親を通します。親の正式な子一覧、親の会話IDと現在のinstance、子の正式記録を照合できる場合だけ閲覧・設定の観測に使います。開始時に解決された値と、後のターンに記録された値は別です。モデル名のsuffix、親の設定、起動希望値からeffortを推測しません。

| 種類 | 会話・親子関係 | モデル / effort の追跡根拠と現状 |
| --- | --- | --- |
| Claude Code | 既存のフックが報告した親transcriptとagent_idから子jsonlを読む | 子jsonlの最後の完全なassistant行のmessage.modelをSubagentInfo.modelへ反映し、次の応答でモデル変更を追う。親のfresh instance/sessionとhookのexact pathを前後照合。effort tierの正式記録は未確認で省略し、開始時の定義から補完しない |
| Codex | 親の正式SubAgentActivityのUUIDと、子rollout先頭session_metaのidおよびsource.subagent.thread_spawn.parent_thread_idを二重照合して閲覧 | 子の最後の完全なturn_contextのmodelとeffortを同一rowから採用。開始より古いtimestampは不採用、最新rowの欠落fieldは以前の値で埋めない |
| Muse Code | 正式subagent.control.child_session_boundのsubagent_idとchild_session_idは別UUID。schema_version=1 / storage_layout=nested_session_v1を検証し、親sessiondir/subagent/child_session_id/session.jsonlを読む。履歴は親の公開objectiveと子の明示的な公開結果のみ | 子run.model.configured.model_idを実行設定として反映し変更を追う。exact childのread-only view/pageのsession/reasoningEffortChangedがある場合だけeffortをbasis:sessionで反映。standing defaultでありturn一時overrideではない。子recordの初期effort tierは未取得で、最初から必ず表示できる保証はない |

Codexの観測は1子あたり先頭metadata最大256KiBと末尾256KiB、最大64子・4並列・全体2秒です。長いターンでturn_contextが末尾256KiBより前ならモデル・effortは未取得です。最新のCLIのライブ設定を常に示す保証ではなく、保存された最後のターン設定です。新しい記録・scope変更・ファイルの置換が検証中に起きたら値を返しません。モデル変更と古いeffortを混ぜず、未取得を開始時の値で埋めません。取得の失敗は件数や現在の作業状態を変更しません。

CodexのhasTranscriptは子ファイルの安全なopenと親子照合に成功した場合だけ付けます。既存のagent.subagent_transcriptを使い、同じfdで抜粋し、パス/fdのidentityと親scopeを最後に再確認します。1MiB窓・200件・1件4000文字・2秒、同じ親instance/会話に限る64件・30分の閲覧grantです。本文・認証値・記録パスを診断ログへ出さず、reasoningや添付データ・道具のbodyを会話として表示しません。


Claudeのモデル観測も末尾256KiB・最大64子・4並列・2秒、子開始より古いtimestampを拒否します。trackerの一覧が読取中に進んだ場合は補足だけを捨て、新しいhook件数・状態を消しません。親のscope/fresh proofが失効した場合は従来どおり旧結果を取り除きます。

Museは親の正式bound記録をfoldし終えた場合だけ子を読み、子stream.idを照合します。モデルは末尾256KiBの最後のrun.model.configured、effortは保存された変更通知がview/pageの窓にある場合だけです。公式schemaにあるSnapshotStateはsession/readのhistory.snapshotの型です。今回のview/page経路は実在するsession/reasoningEffortChangedだけを使い、架空のsession/snapshot通知は扱いません。問い合わせは既存のread-only MSP helper（echo/empty、loginなし）を使い、1 CLIだけ同時実行・1秒deadline・64件の30秒cacheです。補足viewが遅延/失敗しても、先に検証したdurable modelの候補を保持し、最後に子fileのidentityを再確認します。modelとsession default effortはbasisを内部で区別し、同一turnのeffortを取得済みとは言いません。親のEOF・binding・instanceが変わったら結果を捨てます。

上表の未取得には「記録でtier fieldを確認できない」と「正式binding/readerをまだ実装していない」が含まれます。製品が全種類の現在値を取得できるという意味ではありません。Grok/Cursorの会話本体の対応と、子の設定を安全に帰属させる対応も別です。


## AGY / Muse の子履歴

既存のagent.subagent_transcriptを使用します。新たな入力操作は追加しません。親のfresh instance/sessionと正式な子の所属・保存先を照合し、同fdから抜粋して、読了後にもfile identityと親scopeを確かめます。最大1MiBの窓・200件・1件4000文字・2秒、閲覧済みの同親instance/会話に限る64件・30分grantを維持します。

AGYの一般PLANNER_RESPONSE.contentは公開発言と確認できないため表示しません。採取済みの正式native記録で実証したsend_messageのargs.Message/RecipientのJSON文字列形式のみを使い、Recipientがexact親UUIDである場合だけ「親への送信要求」として表示します。送信完了の保証ではありません。SYSTEM_MESSAGE、内部plan、一般GENERIC、toolの結果本文、他の宛先は出しません。初期の指示はprivateなsystem envelopeから取り出さず省略します。正式KILLED descriptorも過去の所属証拠として履歴にだけ使い、件数/現在一覧へ復活させません。descriptorの欠落・未知状態は拒否します。

Museのrun.started.promptは、実自作記録で公開objective48字に対して3882字の内部組立promptを含んでいたため表示しません。初期入力は親の正式spawn_accepted/resume_context_recordedのobjectiveのみを4000字以内で内部bindingへ保持し、閲覧時に添えます。子からはexact child streamのworkflow_child_result_submitted.payload.text（child_session_stream一致）だけを表示します。reasoning、model_input_trace、内部prompt、tool outputは出しません。既存main readerのassistant_message_committed.textも、今回childの公開surfaceとして実証していないため取り込みません。公開objectiveは保存やdiagnosticログへ追加せず、内部の256件/4000字と閲覧grant64件の上限内です。

Grok/Cursor/Copilotの子履歴はこの段では未実装です。正式bindingの取得不足であり、各CLIに読み取りAPIがないという結論ではありません。

既に閲覧許可を取得したMuseの歴史は、同親instance/sessionのfresh proofと同じnested child fileの検証が通れば、binding getterがreading/EOF未確定で一時的にundefinedでも継続します。新規閲覧許可はEOF済み正式bindingが必須で、別child_session_idへのbinding確定時は旧grantも拒否します。継続は現在の所属・作業中・新bindingの成功を意味しません。

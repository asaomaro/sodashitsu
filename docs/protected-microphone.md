# 管理者画面中のマイク転送

Windowsの管理者アプリ画面とUAC画面を単独で共有している間、接続元のマイクを、接続先の通常ユーザーが設定した仮想オーディオデバイスへ送れます。ロック解除画面・サインイン前の画面・複数窓の共有では利用できません。

接続先の設定で、管理者画面の共有、マイク転送とその固定の仮想オーディオ出力IDを設定し、さらに「管理者画面中のマイク転送を個別に許可」を有効にします。この追加許可は初期状態では無効です。接続元と接続先の両方の更新が必要です。共有画面の「マイク入力」から明示的に開始し、ブラウザのマイク許可に応答してください。接続先アプリでは仮想ケーブルの録音側を選びます。

接続先のsodaと音声補助プログラムは、同じ利用者・ログオン・アクティブなコンソールセッションの通常権限で動かす必要があります。管理者として起動した音声actorやSYSTEMでは再生しません。OSの既定スピーカーへの代替も行いません。初回は補助プログラムの準備に時間がかかる場合があり、開始待ちは50秒以内です。

管理者画面の共有が終了した場合、対象画面の状態・ログオン・ロック・接続・許可が変わった場合、マイク転送を停止します。停止した音声を再送せず、再開には開始操作が必要です。音声デバイスの終了を確認するまで、次のマイク転送は開始できません。終了確認が取れない場合も自動的に再取得しません。

## 実装の境界

独立した`allowProtectedMicrophone`許可と、接続の`protectedMicrophone` feature bitを使います。PCMは通常ユーザーの固定`user-microphone` actorだけへ送り、SYSTEMの保護workerには送りません。actorはnonce・stream ID・私有pipeの実client PIDと同SID/logon/session・非昇格を確認してから、固定endpointを開きます。WTSのロック状態を検査し、一度失効したscopeを復活させません。

音声は48kHz・mono・16bit PCM・20ms固定です。この経路では追加codec・UDP・自動品質調整を有効にしません。普通の画面共有のマイク設定やcodecは変更しません。

## 確認範囲

生成PCMとin-memory sink、私有pipe、生成したSID/logon/WTS事実による境界検査、通常権限actorへの制御配送、source失効、偽装ready拒否、旧featureとの分離を検証しました。WindowsのC#コンパイルと生成検査も実行しています。

実際の仮想オーディオendpointへのWASAPI再生、UAC/昇格画面中の相手アプリによる受信、実ロック・画面epoch変化時の終了確認は、実機の作業調整後に行う対象です。これらの実機確認が完了したという意味ではありません。

# 端末版（引数なしの `soda`）

ブラウザを使わず、端末の中で Sodashitsu の画面（サイドバー・tab バー・分割した pane）を開く。SSH で入った先・ブラウザを開けない
コンテナや WSL の端末でも、ブラウザと同じ session を同じ操作で扱える。herdr の引数なしの `herdr` に当たる。

各機能が端末版でどう扱われるか（対応／読み替え／非対応と理由）は `docs/tui-parity.md`。3 環境での確かめ方は `docs/verification.md`「端末版」。

この docs の `soda …` は `node <リポジトリ>/packages/server/dist/main.js …` の略（PATH への置き方は `docs/verification.md`「前提」）。

## 起動と終了

初回の接続待ち画面には、操舵室アイコンの舵輪と端末の `>_` を金色・青緑色の背景色ブロックで表示し、中央の `>_` だけ文字で描きます。接続すると通常画面に切り替わります。表示時間を確保するための待機は加えません。小さい端末では短縮表示になり、再接続時は繰り返し表示しません。色は端末のカラー設定（True Color／256色）に従います。舵輪の高さは端末から取得したセルの縦横比に合わせて補正し、取得できない端末では縦横比2.2を使います。

```sh
soda                        # 既定の session
soda --session work         # 名前付き session（SODA_SESSION=work soda でも同じ）
soda --state-dir ~/soda-lan # 状態ディレクトリを指定
```

- 手元の `soda serve` が動いていればそれに繋ぐ。動いていなければ**裏で起動してから**繋ぐ（既定の session は `127.0.0.1:7780`、
  名前付き session は記憶したポート〔`serve.json`〕、無ければ 7780）。起動した場合、初回の token（ブラウザでログインするためのもの）を端末版が画面を開く前に
  標準エラーへ出す。**二度と出ない**ので、ブラウザでも使うなら控える（無くしたら `soda token reset`）。
- 裏で起動したサーバは最初に打った端末より長く生き、その環境が以後の pane に写るので、その端末・セッションだけの環境変数は渡さない:
  `TMUX`・`TMUX_PANE`・`STY`・`WINDOW`・`SSH_CONNECTION`・`SSH_CLIENT`・`SSH_TTY`・（SSH の中で起動したときだけ）`SSH_AUTH_SOCK`・
  `TERM_PROGRAM`・`TERM_PROGRAM_VERSION`・`TERM_SESSION_ID`・`LC_TERMINAL`・`LC_TERMINAL_VERSION`・`WINDOWID`・`WT_SESSION`・`WT_PROFILE_ID`・
  `KITTY_WINDOW_ID` 等・`ALACRITTY_*` の窓の値・`KONSOLE_*`・`WEZTERM_*`・`GHOSTTY_*`・`ITERM_*`・`VSCODE_*`、VS Code を指す `GIT_ASKPASS`・`BROWSER`。
  `TERM`・`COLORTERM`・`DISPLAY`・`WAYLAND_DISPLAY` とほかの変数は渡す。`soda serve` を手で起動したときは何も除かない。
- 既定の session は `--state-dir` を替えてもポート 7780 を使うので、7780 がふさがっていると裏での起動が失敗する。別のポートにするなら名前付き session で、
  最初に 1 回 `soda serve --session <名前> --port <N>`（`--state-dir` を使うなら同じものを付ける）を起動して止める。名前付き session は
  そのポートを覚え、以後は `soda --session <名前>` が同じポートで裏に起動する。
- 初めて開いたとき、はじめの案内が 1 回出る。Enter（か →・`l`・［はじめる］）で案内済みにして、設定画面の「エージェント連携」の節へ移る
  （herdr と同じく Esc・外側のクリックでは閉じない）。設定画面の端末版の節の末尾から開き直せる。次のときは出ない: 共有の設定で案内済み（Web 版で
  済ませた場合を含む）・案内ができる前からの利用者（共有の設定が保存済みで `onboarding` の項目が無い）・この状態ディレクトリで端末版を前に使った
  （`tui-state.json` がある）・環境変数 `SODA_NO_ONBOARDING=1`（スクリプトから疑似端末で `soda` を動かすときに使う）・端末でない。
- 抜ける（切り離す）: `prefix+q`（既定の prefix は `Ctrl+B`）。端末を閉じる・SSH が切れる・`SIGTERM` でも同じ。
  **サーバと pane のプロセスは動き続け**、もう一度 `soda` を打つと同じ画面（スクロールバックを含む）に戻る。
- サーバそのものを止める:
  - `soda session stop default`（名前付きなら `soda session stop <名前>`。`--state-dir` を付けて起動したなら同じものを付ける）。
    どの OS でも使える。
  - 端末版の中から: 操作「サーバを止める」（`stop_server`。**既定のキーは無い**——押し間違えると全ての pane が止まるので。
    設定の「キー」で割り当てる）。確認を挟み、止めたら端末版も終わる。
- `soda help` で使い方を出す。**標準入力か標準出力が端末でないと**（パイプ・リダイレクト・CI）、`soda` は
  サーバを起動せずに一行の案内を標準エラーへ、使い方を標準出力へ出して**終了コード 2** で終わる。スクリプトから使い方を見るなら `soda help`
  （終了コード 0）を使う。

### 起動できないとき（終了コード 1 と案内）

| 案内 | 理由と対処 |
|---|---|
| `refusing to open soda inside a soda pane` | pane の中で `soda` を打った（入れ子）。下の「入れ子」 |
| `the state dir … is in use by soda on another host` | 別のホスト・コンテナの soda が同じ状態ディレクトリを使っている。`--state-dir` か `--session` で分ける |
| `the running soda serve (pid …) does not support connecting without a token (an older version)` | 古い版の `soda serve` が動いている。止めてから（起動した端末で Ctrl+C・`soda session stop`）打ち直すか、`soda handoff` で新しい版に入れ替える |
| `soda serve exited before it became ready`・`did not become ready within 15 seconds` | サーバが起動できなかった（ポートの衝突等）。出た案内と状態ディレクトリの `server.log` を見る |
| `could not start soda serve` | 3 回起動を試みたが、サーバが動き続けなかった。状態ディレクトリの `server.log` を見る |
| `local login is rate limited` | ローカルログインの失敗が続き、サーバが一時的に受け付けていない（通常のログインと同じ回数の制限）。1 分ほど待ってやり直す |
| `the server uses TLS but serve.json has no certificate fingerprint` | TLS で動いている古い版の `soda serve`（`serve.json` に証明書の指紋が無い）。止めてから打ち直す |
| `… does not match serve.json`（証明書の指紋の不一致） | 同じポートで別のサーバが待ち受けている可能性があるので繋がない。`soda session list` と、そのポートを使っているプロセスを確かめる |
| `local login was refused (HTTP 403)` | サーバが同じマシンからの接続と認めなかった（下の「認証」） |
| `the terminal UI could not be loaded` | 導入が壊れている（ソースから使っているなら `pnpm install` と `pnpm build`）。`soda serve` とブラウザは使える |

## 画面

- 左にサイドバー（Spaces＝workspace の一覧、Agents＝エージェントの一覧）、上に tab バー（1 行。設定で下にも置け、tab が 1 つなら隠すこともできる）、残りに分割した pane。
  pane の枠の上辺に状態の記号と pane の名前。
- サイドバーの幅は既定 26 桁。境界のドラッグで変えられ、`prefix+b` で畳む。今の幅と折りたたみは端末ごと（状態ディレクトリの `tui-state.json`）。
  エージェントの行は Web 版と同じ既定で **1 件 2 行**（印・workspace・tab／名前・エージェント）。狭いと感じたら設定の「表示」でサイドバーの行を減らす。
- **サブエージェントの展開と一覧**: サブエージェントが1件以上いる親の1行目右端に `▸n` を表示します（狭くて入らない場合は出しません）。情報の窓はペインのヘッダー・メニュー・既存キーから開き、子の情報も同じ窓へ表示します。サイドバーには情報ボタンを表示しません。左クリックで親の直下に閲覧用の子行（種類・状態のアイコン・説明）を展開し、印は `▾` だけになります。もう一度押すと折り畳みます。子は親の内部で動き、独立した端末や入力先ではありません。親のエージェント名の後には取得済みのモデル名とeffortを表示し、子のモデルにも取得済みeffortを添えます。子のeffortは注記を付けず値だけを表示し、取得時点の情報は内部で保持します。未取得の値は補いません。フッターを無効にしても、展開した一覧が見えている間は利用状況を取得します。最大64件と残り「ほか n 件」をサイドバーのスクロールで確認できます。更新・並べ替えでは展開状態を保ち、マシンや親エージェントの識別情報が変われば引き継ぎません（クライアントの起動中のみ、最大256親）。未取得と0件はどちらも開閉操作を出しませんが、未取得を0件として数えません。
- **子の会話を読む**: agents一覧を展開して子の行をクリックすると、子専用の会話画面が開きます。子一覧のダイアログからも `Tab` で選択して `Enter` で開けます。親名と子名を表示し、`↑↓` で読み、`Esc` で閉じます。親の情報画面には会話本文や会話表示ボタンを置きません。現在の段階では閲覧専用で、`P` で親への依頼を下書きし、送信先を確認してから明示的に親へ送信できます。子への直接送信とは別の操作です。接続や親セッション・取得許可が変われば古い本文と下書きを表示せず読取りを止めます。保持は最大800件・本文と道具名の合計1Mi文字までで、長い場合は先頭を省きます。
  詳細一覧は右クリックのpaneメニュー「サブエージェントの一覧」または `prefix+shift+s`（操作 `show_subagents`）で開きます。種類・説明・経過時間を `↑↓`・`j`・`k`・`PageUp/Down`・`Home`/`End`・ホイールで読み、`Esc`・外側クリックで閉じます。親の入れ替わり・終了・pane閉鎖でも閉じます。
  Claude Codeのフックの導入と更新は設定の「エージェント連携」。Codex・Muse・Copilotは確認済みの親会話の正式記録から子を取得します。通常は作業中の件数ですが、Codexで正式な開始を確認済みの子が完了後に再びinteractedで参照された場合は、所属数（alive）・状態不明として表示します。配達の記録だけでは実行中とは断定しません。AGYは正式descriptorのALIVEを所属数として扱い（KILLED除外）、現在の作業状態が不明な子は「状態不明」と表示します。所属数には「所属」を付け、作業中の件数とは合算しません。Bobは未取得。Copilotは実CLI未検証。仕組みと制約は `docs/agent-graph.md`「サブエージェントの表示の仕組みと制約」。
- 端末の幅が 64 桁未満（設定「端末版 → 1 列表示にする幅」）だと、焦点の pane だけを全体に出し、上辺に workspace・tab の位置と
  「switch」（選び直し）を出す（herdr の狭い画面と同じ）。20×5 未満では「端末が小さすぎます」だけを描く。
- ほかのクライアント（ブラウザ・別の端末版）が最後に操作した tab は、その大きさで pane が動く。自分の枠と違う間は、
  左上を合わせて切り取り、余りは背景色で埋める（枠の右下に `⋯`）。自分がキーを打つ・クリックすると自分の大きさに戻る。

### サイドバーのグループ

Spaces の workspace は、次の 3 種類のまとまり方で並ぶ（ブラウザ版と同じ決まり。20261004-group-worktree-items。機能ごとの扱いは `docs/tui-parity.md` の H04w・H37b・W04）。

- **worktree グループ**: 同じリポジトリの worktree を、本体〔linked worktree でない方〕を先頭に束ねる（herdr と同じ）。束ねるのは**worktree（フォルダ）ごとに最初に開いた 1 つ**だけで、
  同じフォルダで開いた 2 つ目以降の workspace は通常の行になる（`⎇` を付けない。代表を閉じると次の workspace が worktree グループに入る）。
- **グループ**: 利用者が名前を付けて作るまとまり（Sodashitsu 独自）。メンバーは**項目**＝通常の workspace か worktree グループ丸ごと。worktree グループの一部だけを入れる・外すことはできない。
- **グループなし**: グループに入っていない項目のまとまり。本物のグループが 1 つ以上あるときだけ見出しが出る（1 つも無ければ見出しは無く、項目がそのまま並ぶ）。

```
▾ ◐ 仕事 ──────────────── 3
  ▾ ◐ ⎇ app          main
  ├ ○ ⎇ app-feat     feat
  └ ✓ ⎇ app-fix      fix
  ▸ ○ ⎇ web  +1
    ○ memo
▾ ○ グループなし ───────── 1
    ○ scratch
```

- **グループの見出し**は `▾ ◐ <名前> ───── <数>`（名前・線・数は薄い色）。`▸`/`▾` は畳み・広げ、`◐` は中の全 workspace の全 pane のエージェントの状態のうち優先度の高いもの（workspace の行と同じ決まり。広げていても畳んでいても出る）、数は中の項目の数（worktree グループは 1 つと数える）。
  「グループなし」の見出しも同じ形で、名前の変更・削除はできない。中の項目は 2 桁字下げする。
- **worktree グループ**は先頭の行が `▾ ◐ ⎇ <名前>`、子の行は `├`／`└` と `⎇`（最後の子が `└`）。ブランチ名は行の右に出る（設定「表示」のサイドバーの行の 1 行目に `git` の項目があれば重ねない）。
  畳むと `▸ ◐ ⎇ <名前> +n` になり、`◐` は本体と worktree の全部をまとめた状態、`+n` は隠れている worktree の数（今いる workspace の行は畳んでも残る）。
- 色だけに頼らず、形（`▸▾`・`⎇`・`├└`・線・字下げ）でも区別できる。`⎇` は幅 1 の字形（絵文字ではない）だが、**外側の端末のフォントによっては崩れる・幅が合わないことがある**（`docs/tui-parity.md` H23b と同じ）。
  崩れる環境では、`packages/tui/src/render/chrome/sidebar.ts` の `WORKTREE_GLYPH` を別の記号に替える。
- 並び順が「名前順」のときは、「グループなし」の中の項目とグループどうしを名前で並べる（グループの中・worktree グループの中は開いた順のまま）。

### 色

24 ビット色で描くか 256 色へ寄せるかは、次の順で決める。

1. 環境変数 `SODA_TRUECOLOR`（`1`＝24 ビット色、`0`＝256 色）。SSH 越しで判定が外れるときに使う。
2. 設定「端末版 → 色の出し方（この端末だけ）」（`tui-state.json` に残る。端末ごとに扱える色数が違うので共有しない）。
3. 自動: `COLORTERM=truecolor|24bit`・Windows Terminal（`WT_SESSION`）・`TERM` が `-direct` で終わる・`TERM_PROGRAM` が iTerm.app / WezTerm / vscode / ghostty・kitty。
   どれでもなければ 256 色。

通知ベルの左の「明／暗／自」ボタンで、通常・ダーク・システム追従を順に切り替えられます。設定はWeb版と共有し、選択済みの明暗テーマを保持します。サイドバーを畳むとベルの一つ上に表示します。

テーマは Web 版と同じで、pane の中の配色もテーマが決める。明暗の自動は外側の端末に背景色を訊いて（OSC 11）追従する（対応する端末だけ）。

### 背景の透過

端末のエミュレータで背景の透過（半透明・ぼかし）を設定している人は、設定「端末版 → 背景を透過する（この端末だけ）」を入にすると、端末版の画面も透けて見える。既定は切（今の画面のまま）。

- 仕組み: 端末のエミュレータが透かすのは「既定の背景」（SGR 49）のセルだけで、RGB・256 色で塗ったセルは透かさない。入のとき、次を既定の背景で送る。
  - pane のセルのうち、プログラムが背景を指定していないもの。
  - 画面の地: pane の外の空いた場所・pane の枠の地・tab バーの地・サイドバーの地・狭い幅の上辺の地・グラフ／状況／予約／セッション履歴／外部接続／利用分析／リソースモニター画面の地。別窓端末も既定背景を透過する。
- 透かさない所（読めなくならないように、入のときも塗る）: プログラムが背景を指定したセル（ANSI 16 色・256 色・RGB）、選択・カーソル・今の workspace / tab の強調、
  メニュー・ダイアログ・設定の画面・トースト（下が透けると読めない）、独自コマンドのポップアップ（中身の既定の背景も塗る）。セッション履歴の通常ダイアログは不透明、独立した履歴画面は透過設定に従う。
- 透けるのは、**端末のエミュレータが透過を設定しているときだけ**。設定していない端末では、テーマの背景色の代わりに端末の既定の背景色が出るだけ。
- **透過部分の文字色は外側の端末の明暗に合わせて補正**します。外側の背景色への問い合わせ（OSC 11）など既存の明暗判定を使い、選択したテーマ・設定は変更しません。既に読みやすい色や明示的な前景・背景の組み合わせは維持します。背景画像の部分ごとの明暗までは判定しません。
- 限界: 反転（プログラムの指定・選択の表示）のセルで背景が既定のとき、端末が前景と背景を入れ替えるので、文字の色は端末のエミュレータの背景の色になる（塗りはテーマの前景色）。
- 設定は端末ごと（`tui-state.json` の `transparentBg`。共有の設定・ブラウザ版には出ない）。切り替えると、再起動なしで画面全体を描き直す。

## キー

herdr と同じ prefix 方式。`Ctrl+B` の後に 1 キー。prefix を押すと tab バーの左端に `PREFIX` が出て、`Esc` か 3 秒で解ける。
`Ctrl+B Ctrl+B` で pane へ `Ctrl+B` そのものを送る。prefix とその直後の 1 キー、それに直接のキー（prefix なしで割り当てたキー。既定では画像の貼り付けの `ctrl+v` だけ）以外
（`Ctrl+C`・`Esc`・矢印・`Alt` 付き等）はすべて焦点の pane へ届く。直接のキーに割り当てたキーは端末版が受ける（割り当てを外せば pane へ届く。画像の貼り付けの `ctrl+v` は、クリップボードに画像が無ければそのまま pane へ送る）。

| キー | 操作 | キー | 操作 |
|---|---|---|---|
| `prefix+?` | キー一覧（`/` で絞り込み） | `prefix+q` | 切り離し（端末版を終える） |
| `prefix+s` | 設定 | `prefix+o` | 次の知らせの対象へ移る |
| `prefix+shift+o` | 知らせの一覧（未処理の知らせ。Web 版では先送りした通知の一覧＝ベル） | | |
| `prefix+w` | navigate（サイドバーをキーで選ぶ。Space でメニュー・`z` で畳む／開く） | `prefix+g` | goto（workspace・tab・pane を探す） |
| `prefix+shift+n` | 新規 workspace | `prefix+shift+w` / `shift+d` | workspace の名前を変更 / 閉じる |
| `prefix+shift+g` | 新しい worktree | `prefix+c` | 新規 tab |
| `prefix+n` / `p` / `1..9` | 次 / 前 / 番号の tab | `prefix+shift+t` / `shift+x` | tab の名前を変更 / 閉じる |
| `prefix+v` / `-` | 右 / 下へ分割 | `prefix+h/j/k/l` | 左 / 下 / 上 / 右の pane へ |
| `prefix+shift+h/j/k/l` | pane を入れ替え | `prefix+tab` / `shift+tab` | pane を巡回 |
| `prefix+x` | pane を閉じる | `prefix+z` | 拡大表示 |
| `prefix+r` | resize モード（h/j/k/l・矢印、Esc で抜ける） | `prefix+shift+p` | pane の名前を変更 |
| `prefix+[` | copy モード（v で選択・y でコピー・`/` で検索・q で抜ける） | `prefix+e` | スクロールバックをエディタで開く（サーバの上で。Linux・macOS は `EDITOR`〔無ければ `vi`〕、Windows は `VISUAL`、無ければ `EDITOR`） |
| `prefix+b` | サイドバーの折りたたみ | `prefix+shift+r` | 設定と独自コマンドを読み直す |
| `ctrl+v` | クリップボードの画像を貼り付け（手元だけ。下の「クリップボード」） | | |

- 連携のグラフ（`prefix+a`。操作名 `open_graph`）は端末専用の罫線とセル配置で開く（`docs/agent-graph.md`。
  連携そのものはサーバが動かすので、端末版を使っていても動き続ける。端末から見る・変えるなら `sodactl graph`）。
- 表示の面は `prefix+i`／`prefix+shift+i` またはペインの右クリック「表示ウィンドウ…」から開けます。text/markdown/htmlのパネル・帯を窓として表示し、静的HTMLの簡易フォームへ回答できます。詳しくは [端末版の文書ウィンドウ](tui-windows.md)。
- navigate は workspace の行のほか、**グループ・「グループなし」の見出しも上下で選べる**（畳んだ見出し・空のグループにも届く）。選んだ行に対して、Space（`navigate_open_menu`）は workspace の行ならその行の、見出しならグループ・「グループなし」のメニューを開く。
  `z`（`navigate_toggle_collapse`）は、見出しならそのグループ・「グループなし」を、worktree グループの先頭の行・子の行ならその worktree グループを畳む・開く（代表でない通常の行・別のマシンの行では何も起きない）。Enter は見出しでは選択をやめるだけ。
  `z` は設定の「キー」の navigate の項目で変えられる。今いる workspace の項目を動かす `move_workspace_previous`・`move_workspace_next` は既定のキーが無い（設定で割り当てる。端で止まる）。
- 割り当ては Web 版と**共有**（設定「キー」でどちらから変えても両方に効く）。プリセット（herdr-ctrl-alt・tmux）・直接のキー（prefix なし）も同じ。
  既定のキーの無い操作（`switch_workspace`〔1〜9 の番号つき〕・`open_worktree`・`remove_worktree`・`stop_server` 等）は設定で割り当てると使える。
- 名前の入力欄は Enter で確定・Esc で取り消し。Ctrl+A/E/U/K/W・Alt+B/F が効く。

### 区別できないキー

端末は一部の組合せを区別して送らないので、キー設定に割り当てても区別されない（端末版は Kitty keyboard protocol を使わない）。

- `ctrl+shift+文字` は多くの端末で `ctrl+文字` と同じ。`ctrl+i`＝`Tab`・`ctrl+m`＝`Enter`・`ctrl+[`＝`Esc`。
- **`Esc` を素早く 2 回押すと `ctrl+alt+[`（＝`alt+Esc`）として読む**（どちらも同じ列 `ESC ESC`）。1 回の `Esc` は 25ms 待って確定する。
- 設定のキーの取り込み（「次に押したキーを割り当てる」）で、外側の端末が送らない組合せは取り込めない。

### 外側の端末との衝突

外側の端末（端末エミュレータ）が先に取るキーは端末版に届かない。よくあるもの：

| 外側の端末 | 先に取るキーの例 | 回避 |
|---|---|---|
| Windows Terminal | `ctrl+shift+t`（新しいタブ）・`ctrl+shift+w`・`ctrl+c`（選択中のコピー）・`ctrl+v`（貼り付け）・`alt+enter` | 端末の設定で外すか、prefix 方式のキー（既定）を使う。`ctrl+v` の画像の貼り付けは下の「クリップボード」 |
| VS Code の統合端末 | `ctrl+p`・`ctrl+shift+p`・`ctrl+b`（サイドバー）など VS Code のキー | VS Code の設定 `terminal.integrated.commandsToSkipShell` から外すか、`terminal.integrated.sendKeybindingsToShell` を有効にする。prefix を変えてもよい |
| macOS の端末 | `cmd+…` | 端末版は `cmd` を受けない |

`Shift`＋クリック・ドラッグは多くの端末が自分の選択に使う（端末版の選択は `Shift` 無しでよい）。

## マウス

外側の端末のマウス報告（SGR）で、herdr と同じ操作ができる。

- クリックで pane・tab・workspace・エージェントへ。右クリックでメニュー（pane・tab・workspace・グループ・「グループなし」。空いた所は全体のメニュー＝キー一覧・goto・設定・知らせの一覧・切り離し）。
  workspace のメニューは、所属なし＝「グループへ追加…」〔グループがあるとき〕「新しいグループを作る…」、所属あり＝「別のグループへ移す…」〔今のグループ以外があるとき〕「グループから外す」「新しいグループを作る…」。
  worktree の子の行でも worktree グループ全体に働く。グループの見出しは「名前の変更」「上へ移動」「下へ移動」「グループを削除」、「グループなし」の見出しは「上へ移動」「下へ移動」だけ。見出しの「上へ移動」「下へ移動」と「グループなし」のメニューは `layout` を持つサーバのときだけ出る（古いサーバでは「グループなし」のメニューは開かない）。
  外すと「グループなし」の末尾へ、グループを削除すると中身は「グループなし」の末尾へ出る。
- 分割の境界・サイドバーの幅・Spaces と Agents の境界をドラッグ。tab をドラッグで並べ替え。「＋」で新しい workspace・tab。
- サイドバーの区画の折りたたみ: spaces の見出しの行（`▾ Spaces`。「＋」と並び順の桁を除く）を押すと spaces を畳み（`▸ Spaces 3`＝workspace の数）、もう一度で開く。
  agents は区切りの行（`─ ▾ Agents ─…`）を、**動かさずに離す**と畳む（`▸ Agents 2 ×`＝エージェントの数と、入力待ちがあれば状態の字形）。同じ行を**動かして離す**と spaces の高さが変わる（どちらかを畳んでいる間は高さは変わらない）。
  キーは `prefix+shift+b`（spaces）・`prefix+shift+a`（agents。設定の「キー」で変えられる）。畳んだ状態は端末ごとに残り、navigate に入ると畳んだ spaces は開く。agents が 0 件のときは区切りの行が無いので agents は畳めない。
- サイドバーのグループ: 見出し（グループ・「グループなし」）をクリックで畳む・広げ。worktree グループの先頭の行は、左端の `▸`/`▾` をクリックで畳み・広げ（ほかの桁は、その workspace へ移る）。
  項目（workspace の行・worktree グループの先頭と子の行＝worktree グループ丸ごと）と見出しはドラッグで並べ替える。落とせるのは同じまとまり（グループの中・「グループなし」の中）の項目の間と、グループ・「グループなし」どうし。
  それ以外の上では何も起きず、またぐ落とし先では理由を知らせる。Esc か行の外で離すと取り消し。名前順のときは一番上の並べ替えを受け付けない（「名前順では並べ替えできません」）。
- pane の名前をドラッグ: 別の pane の縁へ落とすと分割して移し、中央で置き換え、tab・サイドバーの workspace へ落とすと移動（Web 版と同じ）。別の workspace へ移せるのは、同じ worktree（同じフォルダを開いた workspace）の間だけで、別の worktree の行へ落とすと、送らずに「別の worktree の workspace へは移せません」と知らせる（管理外・判定前の workspace どうしは、開いた場所が同じときだけ。自分の workspace の行へは今までどおり新しい tab へ切り出せる。以前はどの workspace の行へも落とせた）。端末版は落とせない行の強調を描かないので、落としたときに知らせる。
- ホイールでスクロールバック（3 行）。pane の右端のスクロールバーもドラッグできる。pane のアプリがマウスを求めていれば（vim・htop 等）アプリへ送る。
- ドラッグで選択して離すとコピー、ダブルクリックで単語。`Ctrl`＋クリックでリンクを開く（http・https だけ。手元では OS の既定のブラウザ、
  SSH 越しでは開けないのでクリップボードへ写す）。OSC 8 のリンクは、繋ぎ直すと失われる（サーバの画面の写しが文字だけのため）。
- 設定「端末版 → マウスを使う」を切ると、外側の端末がマウスを扱う（外側の端末の選択・貼り付けがそのまま使える。端末版の操作はキーだけ）。
  「マウスで選んだらコピー」を切ると、選んだ範囲を反転するだけで写さない。

## クリップボード

- コピー（選択・copy モードの `y`）は、外側の端末へ OSC 52 を出す（SSH 越し・VS Code・WSL・tmux の中でも効く唯一の手段）。
  手元（SSH 越しでない）の Linux・macOS で OS の道具（`wl-copy`・`xclip`・`pbcopy`）があれば、それでも写す（OSC 52 を受けない端末のため）。
  Windows・WSL は OSC 52 だけ（Windows Terminal が受ける。`clip.exe` は UTF-8 の文字を化かすので使わない）。tmux の中なら tmux の `set -g set-clipboard on` が要る。
- 貼り付けは外側の端末の貼り付け（ブラケットペーストで pane へ届く）。pane のメニューの「貼り付け」は手元のクリップボードを読める構成だけ。
- 画像の貼り付け（`ctrl+v`）は、端末版がクリップボードを読める機械で動いているときだけ（Linux は `wl-paste`・`xclip`、macOS は `osascript`、Windows・WSL は PowerShell）。
  **SSH で入った先で端末版を起動した構成では出来ない**（外側の端末からクリップボードの画像を読む手段が無い）。

## 通知

エージェントの入力待ち・完了を、次の 3 つで知らせる。通知の種類・音の有無は Web 版と共有の設定「通知」。

- 画面内のトースト（右下・5 秒。クリックで対象へ）。`prefix+o` で次の対象の pane へ移る。全体のメニューの「知らせの一覧」で未処理の知らせを見られる（端末版だけ）。
- 音を鳴らす設定のときはベル（外側の端末の音）。pane のアプリが出したベルも、外側の端末にフォーカスがあれば送る（設定「pane のベルを外側の端末へ」）。
- 外側の端末へのデスクトップ通知の依頼: kitty→OSC 99、Ghostty・iTerm2・WezTerm→OSC 9、Windows Terminal→OSC 777
  （Windows Terminal 側で受ける設定が要る版がある）、判別できない端末（gnome-terminal・VS Code 等）では出さない。
  SSH 越しでは環境変数が届かず判別できないことが多いので、設定「端末版 → 通知の出し方」で選ぶ。tmux の中では tmux の素通しで包んで出す
  （tmux に `set -g allow-passthrough on` が要る）。
- 外側の端末がフォーカスの報告に対応していれば、端末版を見ている間は Web 版と同じ規則で抑える。ブラウザの「OS 通知を許可」の手順は無い。

## 設定（ブラウザと共有）

`prefix+s`。節は通知・テーマ・表示・端末・エージェント連携・キー・端末版（画面の並び）。変更はすぐ効き、**サーバに保存されてブラウザと他の端末版にも届く**。

- **ブラウザ同士でも共有になった**（以前はブラウザごとの localStorage）。この版に初めて繋いだブラウザは、自分の設定のうち**サーバにまだ無いもの**を
  サーバへ移す（1 回だけ。ブラウザの `soda.prefsMigrated.v1` の印で覚える）。キーの割り当て・通知・色の上書き・サイドバーの行のような中に項目を持つ設定は、
  サーバに無い項目だけを入れ子の全段で足す（両方にある項目はサーバの値。足した結果、別々の操作に同じキーが付いたら片方は効かない）。サーバにまだ何も無ければ、そのブラウザの設定がそのまま移る。先に端末版で設定を変えていても、
  ブラウザの独自の設定は消えない。2 つのブラウザで違う設定を使っていた人は、同じ項目はサーバ（先に移した方）の値に揃う。
- はじめの案内を端末版か別のブラウザで済ませると、ブラウザでも出なくなる（共有の設定の `onboarding`）。
- 印はブラウザ（オリジン）ごとで、サーバごとではない。既定の session は `--state-dir` を替えても同じ `127.0.0.1:7780` なので、別の状態ディレクトリの
  サーバへ繋いだブラウザは移行済みとして扱われる（その状態ディレクトリへは移らない）。
- 保存の上限（256KB）を超えて断られた変更は、その画面の中でだけ効く値として残り、知らせが 1 回出る（ほかの項目の同期は続く）。
- 「表示」の pane の枠の表示・隙間・エージェント名、tab バーの位置（上・下）と右端の表示（拡大の状態・ホスト名・日時・固定文字列と区切り）は、
  ブラウザと端末版の両方に効く（端末版では、枠を描かないときも分割の境目に線を 1 本残し、隙間を切にすると左右の縦の罫線を 1 本にまとめる。1 列表示の間の tab バーはいつも上）。
- ブラウザの画面の見た目にだけ効く項目（pane の枠・隙間の太さ・外周の枠、全画面のときの予約キー）は、端末版からも変えられるが
  「ブラウザの画面の設定です」と注記が出て、端末版の画面は変わらない。
- 「端末」の節の「シェルの場所を追う（Windows）」（既定は入）は、Windows のサーバで対話の pane のシェル（PowerShell 5.1・7、cmd）に、プロンプトのたびに
  今の場所を知らせる設定（OSC 9;9）を差し込む。`cd` した場所が pane の場所になり、再起動後もその場所で開き直す。読むのはサーバで、**新しく開く pane から効く**
  （既に開いている pane は変わらない）。Linux・WSL2・macOS のサーバでは何もしない。**Windows の実機では未検証**（確かめ方は `docs/verification.md` の「Windows ネイティブ」）。
  PowerShell で、pane を開いた後に `prompt` を定義し直す（あとから oh-my-posh を初期化する等）と、新しい pane を開くまで追従が止まる。
- 端末版の節（端末版にだけ効く。保存先は共有の設定なので、どの端末版でも同じ）:

  | 項目 | 既定 | 意味 |
  |---|---|---|
  | マウスを使う | 入 | 切にすると外側の端末がマウスを扱う |
  | マウスで選んだらコピー | 入 | 切にすると選んだ範囲を反転するだけ |
  | 通知の出し方 | 自動 | 外側の端末へのデスクトップ通知の出し方（下の「通知」） |
  | サイドバーの既定の幅 | 26 | ドラッグで変えた今の幅があればそちらが先 |
  | 1 列表示にする幅 | 64 | 端末の幅がこれより狭いと 1 列表示 |
  | tab が 1 つなら tab バーを隠す | 切 | サイドバーを畳んでいる間と 1 列表示では隠さない。隠している間のモードの印と接続の状態は pane の場所の右上に出す |
  | 外側の端末のタイトル | `{hostname}: {workspace}` | OSC 2 で外側の端末のタイトルを書く。`{hostname}`・`{workspace}`・`{tab}`・`{pane}`・`{terminal_title}`（`{{`・`}}` で括弧そのもの）。空にすると触らない。読めない書式は設定画面で受け付けない（`prefs.json` に読めない書式があればタイトルに触らない）。終えるとき元のタイトルへ戻す（戻せる端末だけ） |
  | 外側の端末に戻ったら全部描き直す | 入 | 外側の端末にフォーカスが戻ったとき全体を描き直し、外側の端末の表示のまれな崩れを直す（herdr の `redraw_on_focus_gained`）。切にすると戻ったときのちらつきが減る |
  | pane のベルを外側の端末へ | 入 | 見えている pane が出した BEL を、外側の端末にフォーカスがあるときだけ送る（100ms に 1 回まで） |
  | workspace を閉じる前に確かめる | 入 | 切でも、動作中の pane があれば確かめる（herdr と同じ） |
  | 新しい tab の名前を先に聞く | 入 | 新しい tab を作るとき名前の入力欄を出す |
  | 新しい workspace の名前を先に聞く | 切 | 新しい workspace を作るとき名前の入力欄を出す |

  端末ごと（`tui-state.json`）: 色の出し方・背景を透過する・今のサイドバーの幅と折りたたみ。
- 色の上書きは、CSS の色のうち端末版が読める形（`#rgb`〜`#rrggbbaa`・`rgb()`・`hsl()`・色の名前）だけ効く。ほかの値はその色だけ既定のまま。
- `done` の既読は共有しない（クライアントごと。Web 版・herdr と同じ）。

## 複数のマシン

`soda machine add` で登録したマシン（`docs/machines.md`）の workspace がサイドバーにマシンの見出しごとに並ぶ。見出しの左端で畳む・広げる、
見出しのクリックでそのマシンの画面に切り替える（手元のサーバが中継する）。共有の設定は手元のサーバとだけやりとりする。
見ていないマシンの要約の既読は、そのサーバが覚えているものだけで決まる。

## 入れ子と tmux

- **入れ子**: pane の中（環境変数 `SODA_PANE_ID` がある）で `soda` を打つと、終了コード 1 で断る（同じ画面を二重に開くため。herdr と同じ）。
  それでも開くなら `soda --allow-nested`。`sodactl` や `soda serve` 等のサブコマンドは断らない。
- **tmux の中**: tmux の既定の prefix も `Ctrl+B` なので tmux が先に取る。`Ctrl+B Ctrl+B`（tmux の `send-prefix`）で端末版へ届けるか、
  どちらかの prefix を変える（端末版は設定「キー」、または プリセット「tmux」）。通知は tmux の素通しで包み、画像は出し直さず `[画像]` の印にする。

## SSH 越し

SSH で入った先で `soda` を打てば、その先の状態ディレクトリでサーバを見つける・起動する（端末版はその先で動く）。port の転送は要らない。

- デスクトップ通知・24 ビット色の判定に使う環境変数が SSH で届かないことが多い。設定「端末版 → 通知の出し方」・`SODA_TRUECOLOR=1` で指定する。
- コピーは OSC 52 で手元の端末へ届く。リンクは手元では開けないのでクリップボードへ写す。クリップボードの画像の貼り付けは出来ない。
- SSH が切れても pane は動き続ける。入り直して `soda` で戻る。

## 認証（手元へ token なしで繋ぐ仕組み）

端末版は token を打たずに手元のサーバへ繋ぐ。サーバは起動のたびに乱数の秘密を状態ディレクトリの `local-auth.json`（0600）に書き、
`POST /api/local-login` で**その秘密を示し、かつ接続が同じマシンから（接続元と接続先のアドレスが同じ）**のときだけ、ブラウザと同じ session の cookie を出す。

- **信頼の根拠は秘密のほう**（状態ディレクトリを読めるのは同じ利用者だけ。Linux・WSL2 は 0600、Windows は `%LOCALAPPDATA%` の既定の ACL）。
  同じマシンかの判定は補助にすぎない: **手元の中継（SSH のポート転送・リバースプロキシ・コンテナのポートの公開等）の後ろのサーバでは、
  中継が同じマシンからの接続に見えるので判定が効かない**。そういう構成でも秘密を読めない人は繋げないが、状態ディレクトリの権限を緩めないこと。
  逆に、中継の先のサーバへ引数なしの `soda` で繋ぐことは出来ない（`HTTP 403`。ブラウザか `sodactl login` の token を使う）。
- 失敗は通常のログインと同じ回数の制限に数える。サーバを止めると秘密のファイルは消える。

## Windows ネイティブの注意

- 対象の端末は Windows Terminal（PowerShell）と VS Code の統合端末。
- 裏でのサーバの起動は、端末を閉じても止まらないよう、PowerShell から WMI（`Win32_Process.Create`）で `cmd.exe` 越しに起動する（herdr と同じ）。
  **WMI で起動したサーバの環境は、この端末の環境ではなく利用者の既定の環境**（この端末で足した `PATH`・環境変数は pane に入らない）。
  WMI の起動に失敗したときは普通の起動に落とし、「端末を閉じるとサーバも止まることがある」と知らせる。
- 状態ディレクトリは `%LOCALAPPDATA%\sodashitsu`。秘密のファイルの保護はこの場所の既定の ACL（利用者本人と SYSTEM・Administrators）に頼る。
  ACL を広げた場所を `--state-dir` に指定しないこと。
- 止めるときは端末版の「サーバを止める」か、起動した端末でCtrl+C。CLIの `soda session stop` はWindowsでは未対応です。
- PowerShell・pwsh・cmdのペインでエージェントの自動起動とforkを利用できます。`soda handoff` もWindowsの親プロセス保持方式に対応します。初回移行にはサーバの再起動が必要です（`docs/tls-setup.md`「更新時の引き継ぎ」）。

## 操作ボタンと利用状況ビュー

サイドバー先頭の［端末］［グラフ］［状況］と［その他 ▾］で画面を切り替える。［その他 ▾］に予約・セッション履歴・外部接続をまとめ、選択中はその画面名を短く表示する。下部の全体メニューとは別の入口。セッション履歴は状況から独立し、外部接続では操作する接続・委譲中の接続・承認待ちを管理できる。利用状況はエージェントごとのモデル・トークン・コスト・コンテキスト・更新時刻と、アカウントの枠を表示する。取得できない値は「—」で、累計・記録に残る分を区別する。↑↓／ホイールで行を選び、Enter／行クリックでペインへ戻る。`s`で名前・トークン・コスト・コンテキストの順に並び順を切り替え、`a`で全アカウントの枠を開く。Escで基本画面へ戻る。表示中だけ`agent.usage_watch`を購読し、通常の入力・貼り付け・マウスは端末へ送らない。グラフは端末版でも罫線で表示し、ノードと背景を移動できる。

サイドバー下部は［＋新規］［⋯メニュー］［🔔通知］、開閉は最下行。新規はworkspace・pane・グループを選んで追加する。通知は従来の「知らせの一覧」を開く（右クリックメニューからは削除）。通知の対象・既読・先送りはクライアントごとの状態なので、ブラウザと端末版の一覧そのものは同期しない。畳むと3桁の縦の帯を残し、画面切替・新規・メニュー・ベル・最下行の開くボタンを使える。狭い幅は従来の1列表示、極端に低い画面では収まる操作だけを出す。

ペイン上辺の［i］はエージェントの利用状況、［│］は左右分割、［─］は上下分割、［□］は最大化、最大化後の［↙］は元に戻す、［×］は閉じる。情報はエージェントがいるときだけ出る。狭いペインでは分割・情報を先に省く。枠を消す設定でも操作の上辺1行を確保する。閉じるときの確認は既存の設定・処理を使う。利用状況は`prefix+shift+u`からも開く。

畳んだサイドバーの帯にも、workspaceの集約状態とエージェントの状態を表示する。印をクリックすると対象へ移り、各一覧のホイールで隠れた項目を辿れる。workspaceのドラッグ中は掴んだ行に↕、配置先に▶と色の強調を表示する。別タブへのペイン移動先も▶とアクセント色で示す。情報の［i］は操作ボタンの先頭。

未処理の通知がある間は、外側の端末のタイトルの先頭に🔔を付け、通知を処理すると外す。Windows Terminalなどのアプリケーション指定タイトルに対応する端末で利用できる。タブ名を固定する端末設定では、その設定が優先される。通常のタイトル変更を無効にしていても、通知中だけは🔔 Sodashitsuを表示する。

通常はタブ・ペイン・ワークスペース・agents一覧に番号を付けません。prefix入力中だけ `番号:` を表示します（ブラウザ版は同じ番号を重ねて表示）。

ペインの右クリックにはエージェントの「fork…」「利用状況…」があり、タブの右クリックは名前変更と閉じるです。新規作成は新規ボタンから行います。

ペインヘッダーの送信メッセージ・会話要約・対応エージェントの操作は「設定 → エージェント操作・要約」で表示を選べます。幅が狭い場合は［⋯］から選びます。利用状況画面のhで過去セッションを開きます。詳細は [会話の記録・要約・エージェント操作](agent-conversation.md)。通知の先送り／対応済みはWebと共有します。

## 利用状況のバー

コンテキストと5時間・週などの制限は、数値とASCIIの使用量バーで表示します。`[####------] 40.0%` は40%使用、`[??????????] —` は値を取得できていない状態です。利用状況のペイン情報・ダッシュボード・アカウント一覧で確認できます。

ファイルツリー・ファイル名/Grep検索・閲覧/編集・Gitグラフ/差分の標準ウィンドウは [標準のファイル・Gitビュー](workspace-tools.md) を参照してください。

「予約」画面から指示・コマンドのスケジュールを管理できます。操作は [処理の予約](schedules.md) を参照してください。プラグインビューは端末用の定義を持つものを「ビューを追加」から選べます。Web専用のビューは候補に表示されません。開発者向けの定義は [プラグインパッケージ](plugin-packages.md#端末版のプラグインビュー) を参照してください。

### 端末版のコードを更新した後

`soda handoff` はサーバを更新する。起動中の端末版クライアントのコードは更新されないので、端末版の画面・操作に変更がある場合は `Ctrl+B` → `q` で切り離し、同じオプションで `soda` を起動し直す。ペイン内のプロセスは保持される。

ビューの見出しには `[-]`（畳む）と `[×]`（登録を閉じる）を表示する。端末ペインのビュー追加・分割・最大化ボタンはビュー自身の見出しには表示しない。

### 状況画面の区切りとグラフの端末窓

状況画面は罫線付きの「アカウントの利用枠」「エージェント」に分けて表示します。利用枠が多い場合は `a` で一覧を開けます。

グラフのペインをクリックするか、Tabで選択してEnterを押すと、そのペインの端末を浮いた窓で表示します。ノードをドラッグした場合は配置を移動します。窓の「端末へ移動」（Ctrl+Enter）は通常の端末画面へ移動し、「閉じる」（Alt+Esc）はグラフへ戻ります。通常のEscは端末内のプログラムへ届きます。窓のヘッダーをドラッグして移動、右下をドラッグしてリサイズできます（Alt+矢印もリサイズ）。窓を閉じてもペインの処理は継続し、端末サイズはサーバ側で元へ戻します。別のクライアントが直結している場合はエラーを表示し、勝手に引き取りません。接続切断・ペインの削除・直結の引き取り時は窓を閉じます。

ペインヘッダーの `⋮` は右クリックと同じメニューを開きます。ビューのヘッダーは `⋮`（メニュー）・`−`（たたむ）・`×`（閉じる）の順です。標準Statuslineは名前・状態・モデル・利用率を色分けし、利用率70%以上は警告色、90%以上は危険色にします。

ペインヘッダーのボタン列はメニューが先頭です（Web版・端末版共通）。端末版の通知スナックバーは右上に、古い通知から順に積みます。クリックすると対象ペインへ移動します。

ビューの機能名は、設定「表示」の「ビューに機能名を表示する」で表示・非表示を選べます（Web版と共有、既定は表示）。帯の本文は名前や操作ボタンと同じ1行目から表示し、名前を隠しても移動グリップが残ります。

グラフと状況画面のエージェント名には、サイドバーと同じ状態記号・色を表示します。設定の状態記号を無効にすると色付きの点になります。上下の帯は1行まで縮められます（通常のパネルの最低3行は維持します）。

端末版の通知スナックバーは右上に罫線で囲んで表示します。イベント通知は時間では消えず、クリック・通知の対応済み共有・入力待ちの解消・作業再開・対象の終了で消えます。通常の操作結果の一時的なメッセージとは寿命を分けています。画面の高さに収まる件数を表示し、通知一覧も引き続き利用できます。

### 質問フォームの窓と画像

`sodactl ask` のテキスト形式の質問（single・multi・text・edit・rank・table）は、接続中の端末版でも回答できます。Tab／↑↓で移動、Space／←→で選択、Ctrl+Enterで送信、Escでキャンセルします。rankはCtrl+↑↓で並べ替えます。窓の右上の最大化ボタンまたはAlt+Enterで最大化／復元、辺のドラッグまたはAlt+矢印でリサイズできます。入力はサイズ変更でも保持されます。別の画面で回答した質問は端末でも閉じます。画像・音声・成果物を伴うask-formはブラウザで表示します。

端末内の画像はKitty graphics対応端末（Kitty・Ghostty・WezTerm）、Windows TerminalのSixel対応版、iTerm2に出し直します。Sixel・Kittyの入力はサーバでPNGに変換します。Sixel入力は1024×1024画素まで、外側へ出すSixelは640×480画素までに縮小します。Sixel出力用PNGは8bit・非インターレース（RGB・RGBA・グレー・パレット）に対応し、非対応画像は［画像］で示します。tmux内では画像を出し直しません。

自動判定を変更する場合は起動時の環境変数 `SODA_IMAGE_PROTOCOL=kitty|sixel|iterm2|off` を指定できます。Sixelでは外側の端末にセルの画素寸法を問い合わせます。応答しない端末では9×17画素を使用し、`SODA_IMAGE_CELL_WIDTH`・`SODA_IMAGE_CELL_HEIGHT`（各1〜128）で指定できます。Sixel/iTerm2では画像の移動・消去のために画面を再描画します。Windows Terminal実機の描画は環境ごとの確認が必要です。

### 一覧・ウィンドウのスクロールバー

Spaces／Agentsの一覧と、履歴・ヘルプ・利用状況・ファイル／Git・表示ウィンドウ・回答フォーム・設定・通知・プラグインなどの一覧は、内容が表示範囲に収まらないとき右端にスクロールバーを出します。`█`がつまみ、`░`が溝です。溝をクリックして移動し、つまみをドラッグしてスクロールできます。マウスホイールと従来のキー操作も使えます。

ウィンドウとドックしたビューでは、スクロールの列を外枠のリサイズと分けています。掴んだまま内容領域の外へ動かしてもスクロールでき、外でボタンを離すと解除します。画面切替や別の窓を開いた場合も掴みを解除します。PTY本文のスクロールバーは従来どおり右の罫線です。

## エージェント利用分析とリソースモニター

サイドバー上部の「その他」から「エージェント利用分析」「リソースモニター」を開く。既存の「状況」（現在のpane・アカウントの利用状況）とは独立した画面。選択中のマシンのサーバが対象で、古いサーバが対応していない場合は取得エラーと再試行方法を表示する。

利用分析は `1`～`5` または Tab / Shift+Tab で次の表示を切り替える。マウスで見出しを選ぶこともできる。

1. 概要: 合計・入力/出力/キャッシュ・活動・CLI別/日別の棒表示。
2. 比較: 前期間との差、モデル・プロジェクト・アカウント・時間帯別。
3. 親子・ツール: メイン/サブのトークン比率、ツールの分類/呼出比率/成功・失敗・不明、セッションと親/作業先。nested内訳は呼出比率の分母に二重加算しない。
4. 収集状況: CLI別の読込/待機/不足/不正/上限と保持期間。トークンが取得できない場合は0ではなく「未取得」と表示する。
5. エージェント分析: `a` で生成に使うCLI（Claude Code/Codex/Muse Code/Antigravity CLI/Copilot CLI）を選び、`g` で取り組み中の作業・使われ方・改善案を生成。各CLIの既定モデルを使う。**表示や定期更新だけではモデルを呼ばない**。生成開始後は画面を閉じてもサーバ側の処理が続く場合がある。

`d` で7/30/90/365日、`k` でCLI、`m` でメイン/サブ/不明を切り替える。日付は端末のローカル日付、集計タイムゾーンは端末環境の設定。集計中の連続変更は、進行中の要求が完了してから最新の条件で1回取得する。15秒ごとに更新する。レポートには生成時の期間・条件を表示する。

リソースモニターは操舵室関連プロセスのCPU/RSS合計、取得件数、ホスト全体のCPU/メモリ、プロセス別のPID/CPU/RSS/スレッド/分類/作業/OS/接続元を表示する。`g` で本体・エージェント・端末・関連サービス・アプリを絞り込み、`s` でメモリ/CPU/名前順にする。合計は絞り込み前の全対象。CPUは1コア=100%で合計が100%を超える場合があり、RSSは共有ページの重複を含む。取得できない値は「—」で合計から除外する。3秒ごとに更新する。

両画面とも `r` で更新、`p` で自動更新停止/再開、↑↓・PageUp/PageDown・Home/End・マウスホイール・スクロールバーで移動、Escで端末へ戻る。狭い端末では本文を折り返す。画面を離れる・切断・終了で定期取得を停止し、マシン切替では前の情報と遅れて届いた応答を捨てる。画面内の入力やprefixの二度押しは背後のPTYへ送らない。

### 分析・一覧画面の見た目

利用分析とリソースモニターは囲み付きのサマリー、セクション見出し、強調した列見出しで情報を分ける。利用比率は棒と中立のアクセント色、未取得は淡色、警告は警告色で示す。高い構成比を異常とは扱わない。閾値色は明示されたCPUなどの使用率行だけに使い、説明文やプロセス名に含まれる「100%」などへは適用しない。広い画面ではプロセス一覧の名前・PID・CPU・RSSを固定列で並べ、作業先/OSは続く行に出す。狭い画面は折り返す。

既存の状況・予約・外部接続・履歴・グラフもタイトル帯と太字を共通化する。状況のアカウント/エージェントはセクション帯、予約の有効/無効と外部接続の状態は色付きの印で区別する。選択背景・操作ボタンの区別、クリック位置とキー操作は維持する。


### セクションの枠の基準

関連するデータをひとまとまりとして読む所は、上下左右の四辺を持つ枠で囲む。見出し線だけを枠として扱わない。利用分析の各集計/レポート、リソースのサマリー/プロセス一覧、状況のアカウント/エージェント、予約の一覧/設定/結果、外部接続の各分類/登録フォームへ共通の罫線を使う。隣接する分類では区切り線を共有する場合がある。グラフのノードや履歴・設定・各種ダイアログは既存の四辺の枠を使う。操作帯・短い説明・注意書きは枠外に置く。

枠の列と最下行は内容やスクロールバーと重ねずに確保する。スクロール中は見えている内容行にも左右の枠を描く。狭い高さで固定の入力欄や送信ボタンに枠が重なるフォームは、操作の表示を優先して枠を省略する。透過時は静的なサマリー/列見出しの地も端末の既定背景にし、選択や操作ボタンの強調は残す。

CPU情報のコア数は、Web版と端末版の共通フッターに「物理コア数/論理コア数 コア」と表示します（例: `12/24 コア`）。物理コア数を取得できない場合は `—/24 コア` とし、論理数から推測しません。サーバOSが見えるCPUを対象にするため、WSL・仮想マシンではLinux・ゲスト側の構成です。Linuxの明示的なCPUトポロジー、WindowsのCIM情報を取得し、物理情報は5分間キャッシュします。取得失敗時は30秒後から再試行します。その他のOSで物理情報が未取得の場合も論理CPUの表示は維持します。

WSLではフッターの設定で「ホストメモリ使用量（WSL）」を選ぶと、Windowsホストの `ホストメモリ 使用量/合計 使用率` を表示できます。通常の「メモリ」は引き続きWSL側の値です。ホスト用のグラフと色も既存の表示設定に従い、初期状態ではこの項目は非表示です。Windows OSが利用可能な合計・空き物理メモリを固定のPowerShell経路から読み、10秒間キャッシュします。照会は非同期で同時に1本まで、失敗時は30秒後から再試行します。WSL以外では追加取得しません。Interop無効・標準のWindows実行パスが利用不能・旧サーバ等で未取得の場合はホスト項目を表示せず、WSLの値から推測しません。単位と定義は [Win32_OperatingSystem](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-operatingsystem) の TotalVisibleMemorySize / FreePhysicalMemory に従います。

WSLでは「ホストCPU使用率（WSL）」も独立して選べます。Windowsの全体カウンター `Win32_PerfFormattedData_PerfOS_Processor` の `_Total` をホストメモリと同じ1回の照会で読みます。CPUとメモリは部分的に取得できた場合も各々表示し、0%は有効な測定値です。ホスト情報の照会間隔は10秒で、Task Managerの表示と常時同じ値になる保証はありません。WSL側はホスト取得の成否によらず `CPU(WSL)`・`メモリ(WSL)` と表示します。旧サーバはこの区別用情報がないため従来のラベルを保ちます。全体カウンターは [Microsoft WMIの性能監視例](https://devblogs.microsoft.com/scripting/hey-scripting-guy-how-can-i-control-the-data-returned-by-the-performance-monitor-tool/) に対応します。

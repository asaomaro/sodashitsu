# Muse Codeへの対応

Muse Codeを種類`muse`として扱います。コマンドは`muse`です。この環境のLinux版1.4.14-R7309.1で、起動・作業中と待機の画面・フック報告・会話の読み取り・会話再開をローカルのechoプロバイダーで確認しています。通常のMetaモデルを呼ぶ試験は行っていません。

## 使い方

導入済みのCLIはそのまま使えます。操舵室の設定「エージェント連携」で「Muse Code」を導入し、その後Muse Codeを起動し直します。端末やグラフの起動フォームでも選択できます。

```sh
sodactl agent start muse-worker --kind muse --pane <pane-id>
```

前面で動く`muse`や`muse-bin-<version>`を検出し、作業中・確認待ち・待機を画面から判定します。確認待ちと完了の通知は他のエージェントと同じ仕組みで届きます。新しい1.4系の`❯`プロンプトは本製品の追加ルールで扱い、取り込んだ既存ルールは変更しません。

フックで確認した会話UUIDを保存し、再起動後は`muse resume <UUID>`で再開します。曖昧な会話名や`--last`は使いません。自動再開の全体設定にも従います。

## フックの設定と範囲

現在のフック連携はLinux/WSLが対象です。その他のOSでも共通の起動・前面検出はありますが、フック導入は未対応と表示します。

利用者の`$XDG_CONFIG_HOME/muse/settings.json`（未指定時は`~/.config/muse/settings.json`）の`hooks.SessionStart`へ本製品の項目を追加します。Museの設定形式は`schema_version: 1`です。別のバージョンなら書き換えを拒否します。既存のモデル・他のフック・managed hooksの設定は維持し、解除時も本製品の項目だけを取り除きます。

Museはフックの環境変数から操舵室の経路情報を除外します。このためLinuxではフックの近い祖先からMuseのプロセスを探し、同じ利用者のプロセスであることと起動時刻を確認して、端末IDと報告ソケットだけを回収します。環境の読み取りは64KiBまで、祖先の探索も最大4段です。他の環境変数や会話本文は報告へ転送しません。操舵室の端末外では経路を取得できず、何もせず終了します。プロセスの環境を読めない設定では会話IDを取得できません。画面による状態判定は継続します。

`SessionStart`を発火理由で絞らず、起動・再開・clear・fork・compact後の会話IDも受け取ります。操舵室のforkはMSPの`session/fork`で別UUIDを作り、`muse resume <新UUID>`で起動します。元会話の再開や指示の送信は行いません。MSPは`initialize`→`initialized`の後に呼び出し、取得・分岐だけを公開します。

## デスクトップアシスタント

デスクトップアシスタントの「使うエージェント」でMuse Codeを選べます。専用設定でモデルとeffortを指定できます。空欄はMuse自身の既定値です。専用端末で認証や確認操作を行えます。

現在の専用セッションの会話UUIDが確認できた後、そのUUIDの作成日から固定候補の記録だけを読みます。保存先は`$XDG_DATA_HOME/muse/sessions/YYYY/MM/DD/<UUID>/session.jsonl`（未指定時は`~/.local/share/`配下）です。UUIDv7と保存形式schema 1に対応し、日付境界のため前後1日も確認します。全セッションの探索や新しい会話の推測はしません。

直近1MiB・100メッセージ、1メッセージ8,192文字までの利用者入力と確定した最終応答を表示します。別セッション・ツール出力・推論・部分的な生成記録は会話に混ぜません。記録を無効にした実行や、記録形式・保存先が異なる実行では、専用端末から操作してください。

## 会話・利用状況分析

一般paneの会話閲覧・過去一覧・作業文脈・要約・デスクトップ会話は同じ固定記録の読み取りを使います。過去一覧の探索は上限つきで、専用会話の現在IDを推測する用途には使いません。

schema 1の`goal_usage_attribution`でproviderが報告済みの数値だけを数え、usage IDで重複を排除します。推定プロンプト長、リソースサンプル、別streamは消費量にしません。履歴・ライブ利用状況・分析DBで共通の正規化を使います。サブエージェントの既知ディレクトリは親子に分けます。モデル名が記録されなければ未取得です。契約枠・USD料金は推定しません。

ツールの折り畳まれた項目は、必要なログに限り読み取り専用MSP `session/read`から補います。このメソッドはwriter leaseを取らず、`SessionResumed`を記録せず、モデルのターンも開始しません。1集計1回・1.2秒・8MiB・500項目まで。未対応版・時間切れ・切り詰めは一部取得の印を残します。保存するのは数字・短いツール名と分類だけで、引数や会話を数値DBに保存しません。

要約・分析の生成は独立した設定・空のツールpreset・一時作業先で行い、作業中の会話を再開しません。自動要約・明示的なレポート生成では選んだモデルを利用するため、モデルの利用料・枠を消費します。

## 固有の制約

- フックの環境回収はLinux/WSLを検証しています。Windows/macOSの同UIDプロセス環境回収は未対応です。
- CLIの記録にないToDo・親子関係・契約枠・USD金額は未取得です。未取得をゼロや成功として補いません。
- ネイティブの画像・音声入力や接続先限定のwork agent起動は、各CLIのAPIと権限境界を検証した範囲に限ります。[5種類の共通対応と固有機能](agent-parity.md)を参照してください。

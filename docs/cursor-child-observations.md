# Cursorの子自身の設定と終了報告

Cursorの子のモデル・effortは、子自身の会話IDが明示された`afterAgentResponse`だけを受け取ります。親会話のモデル、DBの最終使用モデル、モデル名のsuffix、起動時の希望値から補いません。自己報告で項目が欠けた場合は古い設定を混ぜず、未取得に戻します。親共通の設定を持つ終了報告だけでは、既に確認した子の設定を消しません。

利用には、設定のエージェント連携からCursorのフックを明示的に導入・更新してください。更新で`afterAgentResponse`に加えて`subagentStop`を登録します。既存フックを黙って書き換えることはありません。子のID・親子関係・終了状態が不足するCLIの版では取得できません。

サーバは現在の親の種類・instance・会話IDと検証状態を照合し、SQLiteの正式な親子系譜と直属の子記録を確認します。PIDの報告が矛盾する場合は拒否します。PIDが無い場合は既存の利用状況報告と同じbest effortで受け取り、PID検証済みや実行権限を与えません。読取りは並列2件・待ち64件、報告5秒、親64件・各子64件・重複イベント4096件に制限します。超過・矛盾は不完全として扱い、古い重複IDを捨てて再加算しません。

正式な`subagentStop`と同じ子記録の終端が一致した場合だけ、非公開の終了bindingを作ります。新しい子記録の自己報告が来れば古い終了bindingを退役します。設定が読めたことや終了報告が無いことから、子が現在存続・稼働中とは判定しません。現在のCursorの子一覧・件数は未取得のままで、親の利用量にも混ぜません。

この段階は取込と再検証可能な非公開getterまでです。終了子の一覧RPC・専用会話画面への履歴接続は別の対応で、現画面で閲覧できる機能とは区別します。導入済み実CLIの子フック発火は未実測です。検証は生成したCLI・フック入力・SQLite・子記録を使い、利用者の会話や実モデルを呼び出していません。

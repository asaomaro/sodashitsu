# デスクトップアシスタント

操舵室に同梱したデスクトップアシスタントです。Windows・WSLではWindowsのデスクトップへ、Linux/macOSではそのOSのデスクトップへ表示します。常駐表示・設定・認証済みの通知受信と、専用エージェントへの吹き出しチャットを利用できます。実際のWindows GUIとエージェントを組み合わせた検証はまだ行っていません。

## 使える機能

- 無効を初期値とする有効・無効の設定、設定ファイルへの保存と復元。
- 男性船長・女性船長・ロボット船長の生成画像と、製品ロゴそのままの操舵室アイコン。大きさと表示モードを切り替えられます。
- 画面右下のキャラクター、または通知領域のアイコンのみの表示。どちらでもアイコンのメニューから設定・終了を選べます。
- キャラクターをクリックすると吹き出しを開き、もう一度クリックすると隠します。再表示しても同じ会話を使い、エージェントは終了しません。通知領域の「船長と話す」は吹き出しを開きます。キャラクター自体はキーボードフォーカスを奪いません。
- 吹き出しの「エージェント一覧」で、操舵室が検出した起動中のエージェントを確認できます。名前・識別ID・作業場所と、作業中／確認待ち／待機中／状態不明を表示し、作業中・確認待ち・待機中で絞れます。状態・終了は自動更新し、接続が切れたマシンは一覧から外します。複数マシン通知を有効にすると、接続中の登録済みマシン（最大8台）も含みます。専用アシスタントも検出されていれば対象です。最大256件を作業中・確認待ち優先で表示し、絞り込みは表示対象に適用します。各行をクリックすると、その通知の有無にかかわらず当該エージェントの端末だけを応答用小窓で開きます。エージェント・作業場所・接続先が変わった行は開かず、表示先でも対象を再確認します。一覧はたためます。展開中は一覧全体を表示し、会話ウィンドウの本文全体を縦スクロールして確認します。旧形式など利用できないIDを持つ作業場所や、操舵室外で動く未検出エージェントは対象外です。
- 認証済みの操舵室で、確認待ち・未読の作業完了を言葉で通知します。通知元はエージェント名（未設定なら種類名）・識別IDの先頭8文字・作業場所で示します。質問フォームは題名と質問文、Claude Code・Codex・Muse Code・Antigravity CLI・GitHub Copilot CLIの作業通知は取得できた直近の応答を添えます。「直近の応答」は記録の抜粋であり、端末の承認画面そのものではありません。記録を取得できない場合は通知の種類と通知元を表示し、小窓か操舵室で内容を確認できます。通知文の取得自体でモデルは呼び出しません。通知の作業要約は操舵室の共通設定に従い、船長とは別の要約専用セッションで処理します。通知では入力フォーカスを奪いません。会話ウィンドウを閉じている間、新着は立ち絵の左側の通知専用吹き出し（トレイ表示では画面右下）に通知元と内容を表示します。会話ウィンドウの表示中・表示準備中は通知専用の吹き出しを出しません。会話を開いた時点で表示中の通知吹き出しも閉じます。代わりに会話の上部へ「新しい通知：通知元」の印を表示し、押すと該当する通知へ移動・強調表示します。印を確認しても通知一覧からは消さず、届いた内容や応答ボタンを引き続き使えます。リマインダーの印からは会話内のリマインダー欄へ移動します。印は最新の通知を示し、全件は通知一覧で確認できます。新着がないまま会話を閉じても、抑制した吹き出しを後から自動で開きません。会話ウィンドウは通知だけでは自動で開かず、入力フォーカスも奪いません。音声通知は会話の開閉にかかわらず既存の設定に従います。ミュート時も通知一覧と会話上部の印は更新します。
- 通常の操舵室画面を閉じていても、検出済みエージェントの `sodactl ask` を受け取り、吹き出しで質問フォームの到着を知らせます。通知から該当フォームを開いて回答します。同時に複数の質問があっても、通知が指す質問だけを表示し、回答済みの質問から別の質問へ自動で切り替えません。フォーム通知に端末用の返答欄や確認キーは出しません。エージェントのない通常端末のフォームには、通常の操舵室画面が必要です。
- 通知は最大32件。再接続の同じ出来事を繰り返さず、閉じたpane・入れ替わったエージェント・解消済みの古い知らせを外します。接続先Sodaのローカルpaneと、登録済み・接続中の他マシンのpaneを対象にできます。
- 吹き出しから接続先で利用可能なエージェントを選び、専用セッションを開始します。接続だけでは新規起動せず、開始ボタンを明示的に押します。Claude Code・Codex・Muse Code・Copilot CLI・Antigravity CLIは会話記録を吹き出しで表示し、待機中の専用エージェントへメッセージを送れます。
- 「操舵室を開く」で通常の操舵室画面を別窓に開きます。既存のターミナル・質問フォームを使えます。「専用端末・フォームを開く」は、専用端末の未回答フォームを確認し、あればその質問だけの応答用小窓、なければ専用端末だけの小窓を開きます。フォーム用小窓には端末・サイドバーを表示せず、回答後も別の質問へ自動で切り替えません。「操舵室を開く」は通常の全体画面のままです。通知元は各通知の「小窓で応答」から開きます。
- Electron内の操舵室でも、接続先PCのデスクトップアイコンから専用の別ウィンドウを開けます。元の操舵室は残り、ログイン状態を共有します。モニターを別窓に開く操作も同じ方式です。各窓で閲覧・操作の許可を取り直し、専用窓を閉じるとその窓の共有を終了します。対象は同じ操舵室サーバーのデスクトップ画面だけで、任意の外部ページのポップアップを許可する設定ではありません。
- 起動・停止はsodaが管理します。Windowsログイン時の独立起動とは併用しません。

接続先は `http://127.0.0.1:7780` などローカルHTTP、またはHTTPSのオリジンです。パス、URL内の認証情報・トークン、LANへの平文HTTPは受け付けません。TLS証明書の検証を省略しません。操舵室のログイン画面で認証します。設定JSONにトークンは保存しません。

## 有効化と停止

通常は操舵室の設定「デスクトップアシスタント」で「デスクトップアシスタントを有効にする」をONにします。変更はこのPCのlocalhost画面、または端末版から行います。端末版にも同じ設定項目があります。

CLIからは次の操作です。

```sh
soda assistant enable
soda assistant status
soda assistant disable
```

専用EXEやZIPの手動導入は不要です。同梱したUIと、固定版・固定SHA-256の公式共通Electronランタイムを、有効化時にだけ利用者専用の場所へ準備して起動します。Windows/WSLはWindowsのデスクトップへ、Linux/macOSはそのOSのデスクトップへ表示します。初回は約120〜160MBの取得と展開が必要で、通信・空き容量・書き込み権限が必要です。失敗した場合は設定の状態欄を確認し「準備・起動を再試行」を押してください。

設定画面には準備中の工程（動作環境・保存済みランタイムの確認、ダウンロード、展開、検証、アプリ配置、起動・接続待ち）と経過秒数を約2秒ごとに表示します。ダウンロード中は受信済み／総容量と、その工程の進捗率も表示します。その他の工程は完了率を取得しないため、不定の進捗バーを使います。全体の完了率ではありません。準備済みランタイムを再利用できる場合、ダウンロードと展開は省略します。失敗時は最後の工程を残し、無効化で進捗を消去します。

準備中でもOFFにできます。取消した通信・ファイル・子プロセスの実終了を待ち、取消済みの準備結果からアプリを起動しません。無効時にGUI実装・ランタイムを読み込まず、GUI・専用エージェント・監視用プロセスを起動しません。設定ファイルの監視だけをサーバ内で行います。ダウンロード済みの素材は再有効化に使うため保持します。

設定・端末UUID・ログイン用のElectron sessionは従来のアプリ別userDataへ保存し、ランタイムの更新場所とは分離します。起動後、キャラクターまたは通知領域のメニューから「アシスタント設定…」「操舵室を開く」を選び、ログインして専用エージェントを開始してください。モデル・effortは会話の「専用セッション」で選び、表示方法・通知・OCRなどはアシスタント設定で変更します。設定画面に保存ボタンはなく、選択・チェックの変更時に自動保存して即時反映します。文字・数値はフォーカスを外すかEnterで確定すると反映します。保存中・反映済み・入力エラー・保存失敗は画面下部に表示し、保存失敗時は次の変更で再試行します。

GUIは別プロセスですが、sodaが有効化時に起動・停止する内部機能です。Windowsログイン時の単独起動、独立した配布ZIP・installer・`soda assistant install/rollback`は廃止しました。ソース開発用の`pnpm --filter @sodashitsu/desktop-assistant start`は通常利用の導入手順ではありません。

Windows・WSLでは、Windows GUIの標準入力に依存しないよう、同じ共通ランタイムを使った内部relayも有効時だけ起動します。接続はランダム名のローカルnamed pipeと、起動ごとの秘密による相互認証を使います。GUIが実際に終了した証明を確認してから起動枠を解放し、証明が取れなければ再起動を止めて状態に表示します。別の実行ファイルを手動で導入する必要はありません。


## 専用セッションのサーバ側基盤

認証済みAPIとして `assistant.conversation`・`assistant.get`・`assistant.ensure`・`assistant.adopt`・`assistant.prompt`・`assistant.send_keys` を追加しています。端末ごとのUUIDに対応した専用ワークスペースをサーバ状態フォルダ内に作ります。再接続だけでエージェントを重複起動しません。起動済みか判別できない場合は自動再起動せず、現在の対象を選び直すか、停止した端末を残して新しい専用端末を作ります。

会話の復元は保存された名前だけでは判断せず、現在のエージェントと会話の情報を照合します。送信の待機中に対象・作業先が変わった場合も入力を中止します。吹き出しには専用端末の短いidとエージェントの種類を表示します。対象を確認できない場合は「このエージェントを使う」で現在の対象を選び直します。端末の識別UUIDはuserData内の `assistant-device-id` に保存します。設定JSONの書き換えでは別端末に切り替わりません。識別情報が壊れた場合は勝手に別のUUIDへ置き換えません。

## 吹き出しでの会話と制限

開始後は、同じ端末UUIDの専用ワークスペースを再利用します。エージェントを停止しても旧端末を自動で閉じず、「旧端末を残して新しく開始」を選べます。アシスタントの表示を無効にしても、送信済みの作業を勝手に終了しません。

会話は最大100メッセージで、記録の更新を約2秒ごとに読みます。表示対応は次の5種類です。Bob Shellなど、その他の種類は会話記録の吹き出し表示には未対応です。エージェントのログイン・初期設定、質問や承認の入力、端末固有の画面は「専用端末・フォームを開く」から操作できます。通知元の返答欄と専用チャットは別々で、それぞれの送信先を保持します。

| エージェント | 吹き出しの会話記録 | 画像をモデルに送信 | 音声をモデルに直接送信 | 専用モデル・effort設定 |
|---|---|---|---|---|
| Claude Code | 対応 | 対応 | 未対応 | 対応 |
| Codex | 対応 | 対応 | 対応 | 対応 |
| Copilot CLI | 対応 | 未対応 | 未対応 | 対応 |
| Antigravity CLI (`agy`) | 対応 | 未対応 | 未対応 | 対応 |
| Muse Code | 対応 | 未対応 | 未対応 | 対応 |

会話表示には、現在の専用エージェントから報告された会話IDの確認が必要です。Copilot CLIは `COPILOT_HOME`（未指定なら `~/.copilot`）の `session-state/<会話UUID>/events.jsonl`、Antigravity CLIは `~/.gemini/antigravity-cli/brain/<会話UUID>/.system_generated/logs/transcript.jsonl` を読みます。任意パスの指定や最新ファイルからの会話推測は行いません。フックの設定・再起動後も記録が見つからない場合は専用端末を開いてください。

追加3種類は、記録末尾1MiB内の最大100件のユーザー／最終応答テキストを表示し、1件8192文字までです。ツール出力・推論・ストリーミング途中の断片は表示しません。記録の書き直し・置換時は表示を置き換えます。省略は一部表示として知らせます。会話取得中に対象・会話ID・接続権限が変われば結果を破棄します。サーバとアシスタントをともに更新してください。表示のための追加プロセスや常駐ファイル監視は起動しません。

一般paneの会話・過去一覧・要約も5種類で利用できます。fork等の固有APIを使う操作の対応範囲は[共通対応表](agent-parity.md)を参照してください。

接続が切れた場合や20秒以内に操作の結果を確認できない場合、送信操作を自動で繰り返しません。送信できたか不明なときは操舵室で結果を確認してください。復旧後は現在のエージェントを確認してから操作します。

## 吹き出しの大きさ

会話ウィンドウ右上の最大化ボタンで、右端・下端と立ち絵への尻尾の位置を保ったまま、作業領域の左端・上端まで広げます。復元ボタンで元の大きさへ戻ります。最大化中も枠からリサイズでき、実際に大きさを変更すると最大化状態が解除されます。枠を押しただけでは解除しません。最大化したまま閉じても専用セッションは終了せず、会話を開き直すと最大化状態を維持します。設定画面などと同じ最大化／復元アイコン・マウスオーバー表示を使います。

吹き出しの上端・左端・左上角をマウスでドラッグして、大きさを変更できます。右端・下端の位置は固定し、右下のつまみは表示しません。会話ウィンドウにも、立ち絵へ向く金色の枠の尻尾を表示します。最小は幅320・高さ420DIP（画面がそれより小さい場合は作業領域まで）で、画面の外へは広げません。大きさはアシスタントが動いている間は再表示時も保持し、再起動すると標準に戻ります。端末・フォームを開いた先の窓とは別です。

標準の立ち絵では、吹き出しの下端を実際の頭の上に寄せます。小さい画面では作業領域に収めることを優先します。内容が収まらない場合も、スクロールは枠内で行います。

## 表示位置とウィンドウの重なり

設定の「ウィンドウの重なり」で「最前面（常に手前）」「背面（最前面固定なし）」を選びます。既定は最前面です。立ち絵・会話・通知に適用し、開いている会話にも選択後すぐ反映します。背面は通常のウィンドウの重なり順に戻し、会話を開く際もフォーカスを奪いません。他のアプリを手前に置けますが、操作のため利用者が直接ウィンドウへフォーカスした場合は通常のウィンドウと同じ扱いです。設定・ツール・操舵室ビューは通常のウィンドウとして扱います。

## カラーテーマと明暗

設定の表示では「通常」「ダークモード」「OSの明暗に合わせる」「操舵室の設定に合わせる」を選べます。カラーテーマは操舵室と同じ19種類です。通常・ダークの切り替えではテーマの明暗の対を使い、対がないテーマの通常版にはCatppuccin Latteを使います。テーマを直接選ぶと、そのテーマの明暗へ切り替わります。ボタン・入力欄・スクロールバーも同じ配色になります。

「操舵室の設定に合わせる」では、接続先の保存済みカラーテーマと明暗の自動切り替え設定を読み、変更や再接続にも追従します。OS自動切り替えにはデスクトップアシスタントを動かしているPCの明暗を使います。通常・ダークでは選択中の明暗に合うテーマ候補だけを表示します。連動中はカラーテーマ欄ごと非表示にし、それまでの選択値は保持します。連動を外すと独立設定を再利用できます。

## 船長のボイス

設定の「船長のボイス」→「通知と新しい返答を声で読み上げる」をオンにします。「ボイスを試す」で試聴、「読み上げを止める」で再生と待機を停止できます。会話と通知用の小さな吹き出しにも、再生中だけ停止ボタンが出ます。既存の設定ファイルに項目がない場合はオフです。

通知・リマインダーと、専用チャットの新しい返答をこのPCで読み上げます。専用チャットは待機状態になった新しい返答だけを対象にし、起動時の過去会話や会話を切り替えて読み直した過去分は読み上げません。通知の抑制・全画面での抑制・ロック・スリープ中は自動再生せず、マイクの録音中も自動読み上げを止めます。オフにすると再生中の音声も止まります。

音声を有効にしている通知は、音声生成と再生準備ができてから表示し、口パクも再生開始に合わせます。準備中に読み上げを停止した場合や音声生成に失敗した場合は、有効な通知を文字で表示します。音声がオフの場合は通知をすぐに表示します。

WindowsはOSのSystem.Speechを使い、インストール済みの日本語音声を優先します。日本語音声がない場合はOSの既定の音声です。macOSはOSの既定の`say`音声を使います。Linuxの自動ボイスは未対応です。音声の追加・出力先はOSで設定してください。外部サービスやモデルへ読み上げ用の文章を送りません。音声や出力先が利用できない場合は、設定画面に再生できなかった旨を表示します。

長い返答は先頭600文字までとし、コードブロックは画面で確認するよう案内します。再生中の次は最新の1件だけを保持し、大量の通知を後から続けて再生しません。停止・通知元の終了・専用セッションの変更後は、古い待機音声を破棄します。標準ツールにある任意の文章の「読み上げ」は、これまで通り手動の別機能です。

Muse Codeも専用セッションの会話表示に対応します。対応版・フック導入・保存形式の条件は[Muse Codeへの対応](muse-code.md)を参照してください。

## 通知から小窓で応答する

各通知の「小窓で応答」と「操舵室で開く」で表示先を選びます。通知が届いただけでは端末や操舵室を前面に移しません。通常の操舵室が前面にあっても、利用者が押したボタンに従います。

- **小窓で応答**：通知元の既存端末だけを別のウィンドウに表示して操作します。新しいエージェント・端末は起動しません。`sodactl ask`の通知なら、指定された質問のフォーム（画像・成果物なども含む）を同じ既存部品で表示します。質問が終了すると対応済みと表示し、次の質問を勝手に開きません。
- **操舵室で開く**：アシスタントが管理する通常の操舵室ウィンドウを再利用して前面へ出し、対象マシン・ワークスペース・端末を選びます。ウィンドウがなければ作成します。最初の対象確認が済んだ後は通常どおり他の画面も操作できます。

吹き出しの「通知・確認待ち」に、通知と2つの選択ボタンを表示します。通知全体と個々の通知を折り畳めます。展開中は内容をすべて表示し、本文全体を縦スクロールして確認します。会話履歴や通知を更新しても、折り畳み状態や入力中の返答は保持します。操舵室側のフォームは従来どおり自動表示し続けます。

小窓と通常の操舵室は別のウィンドウです。回答は共通のサーバへ送り、別の画面で終了したフォームも閉じます。小窓を閉じても端末とエージェントは終了しません。接続切れ・対象端末の閉鎖・エージェントの入れ替わり・作業先の変更時は、小窓の入力を止めます。

端末だけの応答用小窓は、初回の表示登録時から端末のサイズをウィンドウへ追従させます。キー入力でサイズを合わせる必要はありません。初描画・フォントの準備後・再表示時にも再計測します。質問フォームだけの小窓では端末サイズを変更しません。

小窓は紺色と金色の枠を持ち、端末のコピー・貼り付けを利用できます。通常画面の切り替えや分割を行うキー操作は制限しています。独自の応答UIの対象は既存の`sodactl ask`フォームです。任意の外部アプリの画面を自動判別して表示する機能はありません。

通知の受信データにUUIDではない旧形式のIDなど確認できない項目が混ざっていても、その項目を対象外として、UUIDで確認できる他の端末の通知を継続します。既存データのIDを自動で書き換える処理は行いません。

既存のシステムブラウザで開いている操舵室タブの探索・OSでの前面化は対象外です。「操舵室で開く」が再利用するのはアシスタント管理下のElectronウィンドウです。実Windowsでの前面化・実エージェントとの往復は、ブラウザと生成アダプターによる検証とは別に確認が必要です。

## 標準ツール

会話ウィンドウの「ツールを開く」を押すと、独立したツール用ウィンドウを開きます。開いている場合は同じ窓を前面に出します。標準ツール、音声入力、OCR、プラグイン操作、予約の編集をここにまとめています。会話ウィンドウとは別に移動・リサイズでき、会話を閉じてもツールは利用できます。コピーした文章の読み込み・文章のコピー、メモの新規保存・読み込み・編集・削除、要約・翻訳用の文面作成、読み上げ、音声ファイルとマイク録音の文字起こしを用意しています。

メモは `assistant-notes.json` に保存し、最大200件・1件8192文字です。メモを保存するだけでSodaやエージェントへ送りません。要約・翻訳のボタンは会話の入力欄に文面を入れます。内容と送信先を確認してから「送信」を押してください。

読み上げはOSが提供するローカル音声のみを使います。利用できる音声がない環境では未対応と表示し、オンライン音声へ自動切り替えしません。「読み上げを止める」、吹き出しを隠す・閉じる操作で止めます。Windows実機での音声確認はまだ行っていません。

### ローカル音声ファイルの文字起こし

設定の「音声入力・文字起こし」で処理先「ローカルWhisper」を選んで有効にし、このPCのWhisperサーバを指定します。初期値は `http://127.0.0.1:8080` です。[whisper.cppのサーバ](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/README.md)と日本語に対応した多言語モデルは別途用意してください。アシスタントはエンジンやモデルを自動インストール・起動しません。

起動例（モデルのパスは環境に合わせて変更）：

```sh
whisper-server --host 127.0.0.1 --port 8080 -m models/ggml-base.bin -l auto --convert
```

WAV以外の変換には、Whisper側でffmpegと `--convert` が必要です。エンジンをWSLで動かす場合、Windowsからlocalhostで接続できる構成にします。

「音声ファイルを文字起こし」でWAV・MP3・M4A・MP4・OGG・FLAC・WebMの通常ファイルを選びます。上限25MB・1処理ずつ、読み取り開始から5分です。結果は確認・編集して「扱う文章」へ渡せます。長い結果は8192文字以内の部分を選んでください。会話への送信は別操作です。

キャンセルは通信と結果採用を中止します。OSの読み取りなどが終了するまでは次の処理を始めません。独立したWhisperサーバ内で開始済みの計算が止まるかは、サーバ側に依存します。吹き出しを隠す・閉じる、アシスタントの無効化、認識先の変更でも古い結果を破棄します。このWhisper経路はクラウド認識へ送信しません。専用エージェントへの音声送信は後述します。実モデルの認識精度も未検証です。

### マイク録音

同じ音声入力設定を使います。「マイクの録音開始」を押すと、必要なOS許可を確認して録音します。カメラ・画面共有は許可しません。録音中はツールウィンドウ上部に表示と停止ボタンが出ます。長い画面をスクロールしても停止ボタンを残します。

ローカルWhisperを選んだ場合、「録音停止」でマイクを止めます。「録音を試聴」は押したときだけ再生し、「録音を文字起こし」で初めてWhisperへ渡します。「録音を破棄」も選べます。上限は録音5分・25MiB、停止後は5分以内に処理するか破棄してください。認識結果の会話送信は別操作です。要約・翻訳の文面作成は、会話ウィンドウの入力欄へ文面を移し、内容と送信先を確認してから利用者が送信します。ツールから会話を自動送信しません。未受領の文面は接続先変更・アシスタント無効化で破棄します。

ツール欄を閉じる・ツールウィンドウを隠す／閉じる・最小化・設定の無効化／認識先の変更でも破棄します。会話ウィンドウを閉じるだけでは、表示中のツールの録音は止めません。OSの許可待ちで取り消した場合、許可の処理が戻るまでは次の録音を始めません。許可画面が残っていれば閉じてください。非対応環境では音声ファイルを利用できます。

録音・試聴のWindows実機確認は未完了です。生成テストではマイクとMediaRecorderを差し替えており、実音声・再生品質やOS設定への対応は確認していません。

## 実機で確認する範囲

実装・設計/調査・更新/実機確認を含む全残件は[現在の対応状況](remote-desktop-status.md)を参照してください。以下は実装済み機能の実機確認項目です。

コード・生成アダプター・ヘッドレス画面・配布物の検証と、実際のWindows上での動作確認は分けています。実機では、通知領域・透過窓・複数ディスプレイ/DPI・sodaによる有効化/停止とhandoff後の再起動・スリープ/ロック復帰・全画面抑制・証明書・実エージェントの会話/質問・画面/音声取得・Tesseract/Whisperの認識と試聴を確認してください。生成テストやWindowsビルド成功は、この実機確認の完了を意味しません。

## 確認

```sh
pnpm exec vitest run --project @sodashitsu/desktop-assistant
pnpm --filter @sodashitsu/desktop-assistant verify:ui
```

前者はOSを呼ばない注入アダプターと一時ファイルを使います。後者はPlaywright Chromiumの導入が必要なヘッドレス生成UI検証です。実際の画面・マイク・クリップボード、ログイン時起動の登録、実エージェントの起動は行いません。Windows実GUIとLinux/macOS実機は別途確認が必要です。

通知の接続はmainプロセス内だけでログインCookieを扱い、既存ブラウザと同様にURLの一致するSodaの通常/名前付きsession Cookieを送ります。トークンは吹き出しのrendererへ渡しません。読み取り専用の接続は端末入力やエージェント起動を行いません。handshakeは実経過10秒、接続後は20秒ごとのpingに10秒以内のpongがなければ再接続します。HTTPSは証明書検証を有効にし、Node/OSの既存CAを読み取ります。証明書のインストールや検証省略は行いません。

### 画像から文字を読み取る（OCR）

設定の「画像理解・文字認識」を有効にし、処理先を選びます。標準は「専用エージェントのモデル」で、現在は画像入力に対応するClaude Code/Codexの専用セッションを使います。Tesseractは必須ではありません。モデル・effortは会話ウィンドウで選んだ専用エージェントの指定を使います。エージェントが待機中のときだけ送信できます。

「ローカルTesseract」を選ぶ場合だけ、Tesseract本体と言語データを別途用意し、実行ファイルの絶対パスと言語を指定します。例はWindowsでは `C:\Program Files\Tesseract-OCR\tesseract.exe`、Linuxでは `/usr/bin/tesseract`、言語は `jpn+eng` です。自動インストール・常駐起動は行いません。

ツールウィンドウの「標準ツール」→「画像から文字を読み取る」を開きます。PNGファイルをドロップするか、画像をコピーしてCtrl+V／⌘V、または「クリップボードの画像を貼り付け」で取り込みます。PNGのファイル選択も利用できます。PNG・8MiB・3840×2160以内、1件ずつです。画面・ウィンドウの直接取得は使いません。クリップボードの監視はせず、貼り付け操作時だけ読み取ります。通常の文章の貼り付けは入力欄へ入ります。

プレビューを確認し、必要なら画像上をドラッグして切り出す長方形を選びます。表示画像を縮小していても、範囲は元画像の画素へ換算します。左・上・幅・高さの数値入力と選択枠は連動し、数値での微調整もできます。「この範囲に切り出す」を押すまでは元画像を変更しません。取り込み・切り出しだけではエージェントへ送りません。「画像をエージェントに送って読む」を押すと、既存の画像アップロードで操舵室へPNGを一時保存し、専用セッションにその画像を読む指示を送ります。追加のAPIキーや別のOCRエンジンの起動は不要です。結果は吹き出しの会話へ返ります。モデルには追加OCRプログラム・AIサービスを起動せず画像入力で読み、未対応・不鮮明な部分を明記するよう指示します。これはエージェントのツール実行を禁止する機構ではなく、実モデルの遵守・認識品質は別途検証が必要です。

アップロードと指示には元の60秒の残り時間を使い、サーバの最終入力直前にも取消・期限・対象・idle状態を確認します。画像破棄や非表示で未入力の指示は取消を要求します。既に端末へ入力した指示とモデルの処理は取り消せないので、必要なら専用端末から止めてください。切断や失敗時に別のモデル・サービス・Tesseractへ自動切替・再送はしません。

この窓の画像・認識結果は、取り込み・切り出しから5分、ツールウィンドウを隠す・閉じる・画面遷移する、OCR設定を変えると破棄します。**エージェントへ送信済みの画像は別**です。操舵室側の既存 `clipboard-images` 保存規則（通常24時間の期限と定期削除・100枚・合計256MiB）で扱い、窓を閉じても即時削除しません。画像は選んだエージェントとその提供元にも渡ります。

ローカルTesseractでは「文字を認識」を押したときだけ、このPCのTesseractへ標準入力で渡します。処理は60秒、結果は65536文字までで、外部のOCRサービスへ送りません。結果を確認・編集して8192文字以内にし、「認識結果を扱う文章へ」で下書き・メモに使えます。ローカルOCR結果を会話へ送る操作は別です。

音声ファイルをモデルへ直接渡す経路は、現在は専用Codexのexperimental app-server経由に対応します。設定「音声入力・文字起こし」の処理先で「専用エージェントのモデル」を選び、音声入力対応モデルを使ってください。任意のローカルWhisper文字起こしは従来の明示設定で利用でき、画像機能やアシスタントを有効にしただけでは起動・送信しません。

音声はツール画面の音声ドロップ領域へ1件ずつ渡せます（WAV・MP3・M4A・MP4・OGG・FLAC・WebM、空でない25MiB以内）。ドロップだけでは処理せず、ファイル名と処理先を確認して開始ボタンを押します。読み取り中に処理先・専用会話が変わったり、画面を隠したりすると取り消します。既存のファイル選択・録音も利用できます。

通知の小さな吹き出しは、文章量に合わせて高さを調整します。画面の作業領域に収まりきらない長文は、スクロールバーを出さずプレビューと省略の案内を表示します。「内容を開く」から通知の全文を確認できます。

### リマインダーと通知元への返答

ツールウィンドウの「リマインダー」で見出し・内容・この端末の時刻での日時を入力します。1年以内の一回予約で、サーバが動作している間に実行します。モデルを呼ばずに船長が「お知らせです」と内容を伝えます。届いた知らせは会話ウィンドウにも表示し、「確認しました」で対応済みにし、その結果もサーバに保存します。予約を削除しても、既に届いた知らせは確認するまで残ります。他端末のアシスタントの予約と知らせは混ざりません。

通知の返答欄は専用チャットとは別で、表示されている通知元だけに届きます。入力待ちの確認にはEnter/Esc/y/nの明示操作を使うか、「この端末・質問フォームを開く」で既存の端末・ask-form・プラグイン表示へ展開します。専用セッションも「専用端末・フォームを開く」で展開できます。対象が閉じた・交代した・移動した場合は入力を遮断します。ログインが必要な場合は、通常表示を開く操作を明示的に選んでください。応答が不明な送信を自動で繰り返しません。


### 立ち絵のモーション

動画制作の呼吸・弾み・発話中の伸縮に合わせた、立ち絵全体のモーションを表示します。待機中はゆっくり呼吸し、専用エージェントの作業中は小さく動きます。新着通知とクリックでは短く弾み、OSボイスの再生中はリズムに合わせて伸縮します。顔だけの絵は全身の絵より動きを強めにします。標準船長と追加キャラクターの両方が対象です。

表情差分付きの追加素材では、待機中も約6秒ごとに笑顔・考える姿・指差しなど、素材にある表情とポーズを切り替えます。作業中は考える姿、通知やクリックでは驚きや腕を上げる姿、発話中は指差しなどへ切り替えます。素材のまばたき差分を使い、OSボイスの再生中は閉じ口・開き口・半開きを短い周期で切り替えます。音量や音素に同期した口パクではありません。差分のない素材はこれまでの静止画と伸縮を使います。

足元と右端を基準に、窓の内側に収まる範囲で動かします。素材の腕・ポーズはそのままで、パーツを新造しません。VOICEVOXや追加の動画生成は不要です。

設定の「動きを抑える」をオンにすると停止します。初期設定ではOSのモーション軽減設定にも従います。Windows側でアニメーション効果を無効にしていてもこのアプリだけ動かす場合は、「OSのモーション軽減設定に従う」をオフにします。「動きを抑える」がオンの場合は、OS追従の設定にかかわらず停止します。非表示・ロック・スリープ中は描画の更新を止めます。停止を解除しても、過去の通知モーションを後から再生しません。

### フォルダから取り込む立ち絵

設定の「プラグインの機能」にある「キャラクター素材フォルダを読み込む」から、`casts.json`と`chars/`のあるフォルダを選びます。取り込めるファイル構成、JSONの例、表情・ポーズ差分、容量の上限は[キャラクター素材の取り込み形式](assistant-character-assets.md)を参照してください。WSL上の素材は、Windowsのフォルダ選択からLinuxの共有フォルダを開いて選べます。

一覧のプレビューを確認して「この素材パックを追加・置き換え」を押し、上部の「立ち絵」でキャラクターを選ぶと自動で反映します。取り込み後は「追加キャラクター素材を表示する」のチェックが入ります（自動で反映）。選択中の立ち絵と、素材に記録されている作者・配布元などのメモを表示します。取り込みだけでは現在の立ち絵を変更しません。

`chars/<id>/normal.png`を一度に最大64件読み込みます。`casts.json`の名前を使い、別バリエーションはIDを併記します。透明余白を詰めて縦横比を保ったPNGへ変換し、1件128KiB・最大辺512px以内にしてこのPCの素材カタログへ保存します。元の素材や設定は変更しません。取得済み画像のローカル取り込みであり、Sodashitsuのリポジトリ・配布物には立ち絵を同梱しません。素材の利用条件は元の素材に従います。

動画制作・PSD書き出しやVOICEVOXは起動しません。`sprite.json`と`sprite/`があれば、元のポーズ画像と表情・口・まばたきの置換パーツも取り込みます。対象は通常・笑顔・考える・驚きの表情と、標準・考える・指差し・腕上げのうち素材にある差分です。再取り込みで差分も更新します。差分がなければ`normal.png`と伸縮を使います。表情素材は静止画像のカタログと分けてこのPCに保存し、1キャラクター4MiB・全体128MiBまでです。対応する立ち絵とのハッシュが一致しない場合や読み込みに失敗した場合は静止画像へ戻します。ポーズは共通の描画範囲で足元を揃え、元の腕・手・持ち物を新造しません。音声は独立した設定で、立ち絵を変えてもVOICEVOXのキャラクター音声には切り替えません。OSボイスはこれまでの設定を使い、不要なら「船長のボイス」をオフにできます。

## プラグインのキャラクター・UI・機能

設定の「プラグインの機能」で素材の表示・UIの展開・操作の実行を別々に許可します。初期状態では全て無効です。「素材パックを選んで確認」で `.sodaplugin` を開き、PNGプレビューを確認して追加します。この操作はキャラクター素材だけを保存し、含まれるプログラムを実行しません。素材は1024×1024・128KiB、保存領域全体で128キャラクター／16パック・8MiBまでです。船長を選ぶとすぐ反映されます。素材表示の許可を解除すれば標準船長へ戻ります。パックの削除は先に標準船長へ切り替えてから行います。

パッケージの `soda-plugin.json` に次の宣言を追加し、PNGを `files` に含めます。通常の `sodactl plugin pack /path/to/plugin --out captains.sodaplugin` で梱包できます。

```json
"assistantCharacters": [{"id":"robot","name":"追加の船長","file":"assets/robot.png"}]
```

アシスタント用UIは既存 `views` の定義へ `"assistant": true` と `"targets": ["pane"]` を加えます。機能は既存 `app.register` の操作定義に `"assistant": true` を加えて公開します。`description` と `inputSchema` は通常のプラグイン操作と共通です。プログラムの有効化とプロジェクト拡張の承認、スクリプトHTMLの許可は通常の操舵室で行い、省略しません。

ツールウィンドウの「プラグインのUI・機能」から一覧を更新します。専用セッションで利用可能な稼働中の拡張だけが出ます。UIは既存の端末・表示パネルへ展開し、操作は内容とJSON引数を確認して明示実行します。結果は確認してから会話・メモへ渡せます。プラグインUIにはアシスタントのOS機能や認証情報を渡しません。専用セッションは独立した作業フォルダなので、常駐アシスタント向けには利用者スコープのプラグインを推奨します。別プロジェクト限定の拡張は、その通知元の端末から利用してください。


### 他マシンからの知らせ

「登録済み・接続中の他マシンからも知らせを受ける」で、操舵室に登録したオンライン端末を最大8台まで受信します。新しいSSH接続やエージェントをアシスタントが起動することはなく、既存の操舵室の認証済み中継を使います。通知にマシン名を表示し、返答と端末展開もそのマシンへ固定します。切断・削除・許可解除された対象に送れない場合、接続元への代行送信はしません。小さい展開窓でも接続先を維持します。接続元・接続先の両方を対応版へ更新してください。


### 配置・全画面時・復帰

設定の「配置」でディスプレイと左・上位置を指定します。座標はElectronのDIPで、負の座標のモニターにも対応します。「プライマリの右下（自動）」では数値を使わず、作業領域の右端・下端に隙間なく配置します。標準の立ち絵は素材の透明余白も詰め、足元がタスクバーの上端に接するように表示します。立ち絵の横の設定アイコンは表示せず、設定は吹き出しの「設定」または通知領域のメニューから開きます。フォルダから取り込んだPNGは透明余白を詰め、画像の縦横比に合わせた窓で右端・下端へ配置します。他の追加PNGの透明余白は素材に依存します。キャラクターと吹き出しは選んだ画面の作業領域に収め、取り外されたディスプレイは表示可能な画面へ戻します。吹き出しはキャラクターの近く、アイコンのみのモードでは画面右下に出します。

「全画面中は通知で吹き出しを開かない」はWindowsの前面窓の範囲を確認し、画面全体を覆っている間の自動表示を控えます。画像・ウィンドウの文字・入力は取得しません。判定できない場合も知らせは一覧に残し、手動の会話は開けます。自動表示が出ない場合は、ミュート・この設定・ログイン/接続状態を確認してください。

スリープ/ロック時は取得中の画面・音声を止め、未送信のOCR画像を破棄します。スリープ時は通知と制御の接続も止め、復帰時は画面配置と接続を取り直します。エージェントを重複起動したり、返答・操作を自動再送したりしません。

### 更新

soda本体を更新してbuild/handoffすると、有効なアシスタントを停止して、同梱UIと検証済みの共通ランタイムで起動し直します。公開済みの起動ファイルを上書きせず、内容を検証した別フォルダーを使います。ランタイムの署名やOSの信頼設定は変更しません。

### 専用エージェントのモデルとeffort

会話ウィンドウの「専用セッション」で、種類・モデル・effortの3つのドロップダウンを順に選びます。種類によってモデル候補が、モデルによってeffort候補が変わります。「エージェントの既定値」はCLI自身の設定を使います。選択は自動保存し、最後の種類と、種類ごとのモデル・effortを会話の再表示・アシスタントの再起動後も復元します。アシスタント設定画面にはこれらの入力欄を置きません。設定画面から変更しても、会話で保存した船長の選択を上書きしません。

Codexは接続先サーバのCLIモデルキャッシュ、MuseはMSPの読み取り専用モデル一覧、Antigravity CLIはモデル一覧コマンドから候補を取得します。Claude CodeはCLIのモデル別名、Copilotは代表候補です。候補は契約・CLIの版で利用可否が異なります。取得できない場合も保存済みモデルと既定値を表示します。既知モデルで使えないeffortは既定値に戻し、未知の保存済み指定は保存済みと明示して保持します。

設定は、この端末のアシスタント専用セッションを明示的に開始するときだけ起動引数へ渡します。通常のエージェントやプロジェクトの設定ファイルは変更せず、設定を保存しただけではエージェントを起動しません。起動済みのセッションは自動で再起動・変更しません。端末の窓から自分で終了した後、吹き出しの「旧端末を残して新しく開始」で新しい設定を反映してください。再接続だけでは再起動しません。

吹き出しには「起動時指定」のモデルとeffortを表示します。保存済み設定との差がある場合は再作成が必要と表示します。これは実際にモデルが採用した値の観測ではなく、CLI内の `/model` 等での変更・既定値の解決は追跡しません。既存・引き取りセッションの指定値が分からない場合は不明と表示します。実エージェント・Windows GUIでの検証は別途必要です。

### sodaによる起動・停止の管理

有効・無効はサーバのstate-dir内`assistant-launch.json`へ保存します。既定は無効です。保存するJSONはenabledのみで、画面やRPCから任意の起動コマンド・実行ファイル・ダウンロード先を指定できません。`status`は保存した有効値で、GUI起動成功の確認ではありません。設定画面は準備・起動・エラーの状態を別に表示します。

開発者がサーバ起動環境に`SODA_ASSISTANT_COMMAND`をJSON配列で明示した場合だけ、そのローカル起動コマンドを使います。通常は設定不要です。資格情報は起動情報に含めず、アプリ側で操舵室へログインします。

管理起動したアプリは、sodaが閉じる・引き継ぎのために停止する・親とのpipeを失うと終了します。アプリの設定で無効化するとsoda側の無効設定も保存して終了し、通知領域アイコンだけを残して常駐しません。管理起動への切り替えでは、以前に有効にしたWindowsログイン時の単独起動を無効にしてから設定を保存します。保存に失敗した場合は元のログイン時起動へ戻して管理アプリを終了します。管理中に単独起動を再設定することはできません。既に別のアシスタントが起動していれば、それを奪わず、終了後に `soda assistant enable` で再試行するようサーバログで案内します。自動再起動ループはありません。sodaの引き継ぎ失敗時は元のサーバが起動管理を再開します。

管理起動したアシスタントを無効にすると、同じ端末UUIDの専用エージェントも停止待ちにします。進行中の仕事は強制終了せず、所有を確認できるエージェントが待機状態になってから専用端末を閉じます。待機中でも、別のエージェントに置き換わった端末や作業先が変わった端末には触れません。停止待ちには新しいチャット入力を送りません。通知や所有確認に対応しないエージェントは安全に停止を判定できないため、通常の操舵室で端末を確認してください。停止した専用端末は、次の明示的な有効化・開始まで自動で作り直しません。再起動後も停止記録を確認して専用エージェントの自動復元を抑止します。Tesseract/Whisperの自動導入・常駐起動は含みません。Windows実GUI・WSLをまたぐ親終了の実機検証は未実施で、生成Node子プロセスとメモリpipeのライフサイクル試験を行っています。

管理起動で設定ファイルを読み取れない場合は、元のファイルを上書きせず終了します。単独起動では従来どおり無効状態の設定画面から確認できます。生成アダプターでOS起動設定の無効化・保存失敗時の復元を検査しており、実Windowsのログイン起動確認は別途必要です。


### 通知の作業要約と返信

操舵室の設定「エージェント操作・要約」で要約用の種類・モデル・effortと「通知に作業要約・判断事項・返信案を表示」を設定します。選択変更は即時保存され、保存ボタンはありません。未設定ではモデルを起動せず、作業完了・入力待ちなどの簡潔な通知を表示します。要約エージェント設定時の標準はオンです。既存のペイン要約と同じ隔離されたCLI実行基盤を使用し、船長や作業担当のセッションへは要約指示を送信しません。船長の割り当て・接続・待機状態は不要です。

通知カード内に「作業要約・判断事項」、折り畳める「原文・詳細」、通知元への返信欄をまとめています。要約は目的・依頼、実施作業、成果・検証、残る課題、判断事項と返信案を含みます。既存ペイン要約と会話末尾の抜粋・質問文を資料とし、古い/一部/未取得の記録は明記します。モデルの利用量が発生します。

同じ通知の要約ジョブ・結果はサーバで共有します。詳細は会話ウィンドウ内で確認でき、通知吹き出し・操舵室内の通知・通知履歴・OS通知には同じエージェントが生成した40文字以内の一言を載せます。生成に失敗した場合は簡潔な通知を表示します。同時生成は他の要約も含め最大2件で、生成中は会話ウィンドウに状態を表示し、通知吹き出しとOS通知は結果を待って表示します。デスクトップエージェントの吹き出しは、要約待機が15秒を超えた場合に「作業が完了しました」などの簡潔な通知へ切り替えます。音声有効時は引き続き読み上げの準備完了を待ちます。遅れて届いた要約は表示内容へ反映しますが、新しい通知としての再表示や読み上げは行いません。サーバ再起動で通知用キャッシュは失われます。切断後の再取得では共有ジョブを参照し、再試行ボタンを押した場合だけ完了済み/失敗した通知要約を生成し直します。通知元・会話・通知の状態や設定が変わったときは古い結果を使わず、解消済み通知は要約と一緒に表示から外れます。

返信案はテキストで提示し、自動送信や下書きの自動置換はしません。返信欄を編集してその通知元へ送信します。送信中の重複操作を止め、待機中に編集した次の下書きは残します。ask-formは「小窓で応答」から回答します。

会話履歴と船長への送信欄は同じ「会話」セクションに置きます。通知への返信と船長へのメッセージは送信先を区別します。

### 専用Codexへ音声を送る

標準の処理先は「専用エージェントのモデル」です。音声機能自体は初期状態で無効です。有効にしても自動録音・自動送信は行いません。「音声ファイルを専用エージェントへ送る」か、録音停止・試聴後の「録音を専用エージェントへ送る」を押したときだけ、接続している操舵室と、その専用エージェントの提供元へ送信します。最大25MiB、録音は5分までです。別モデルやWhisperへ自動で切り替えません。

既存の専用セッションの会話ID・作業先・待機状態を確認し、同じセッションへ音声と文字起こしの指示を渡します。設定済みのモデル・effortを変更せず、新たなエージェントや外部AIサーバを起動しません。結果は吹き出しの会話または専用端末へ返ります。受理済みの処理は専用端末から停止してください。取消や切断後に送信を自動再試行しないため、受理が不明な場合も専用端末で確認します。

対応するCodex CLIの既存app-server daemonと音声入力対応モデルが必要です。実装時にcodex-cli 0.165.0の生成仕様で `turn/start` の `localAudio` を確認しています。daemonがない、会話IDの対応を確認できない、作業中、モデルが非対応の場合はエラーにし、別セッションを作成・再開しません。CLIの実行ファイルをサーバの環境から直接起動できる必要があります。専用エージェントの実際の音声認識精度とWindows実機での会話は未確認です。

音声は接続先のstate-dirの `assistant-audio` に、サーバが決めた名前で一時保存します。通常は保存から5分で削除し、同時転送2件・接続ごと1件、保存64件・200MiBまでに制限します。handoff中は旧サーバの期限削除を停止・待機し、失敗から復帰した場合は残りの期限で再開します。サーバを終了した場合は保存ファイルが残り、次の音声送信時に期限切れを削除します。この窓での破棄や非表示では、提供元へ送信した音声・会話は取り消せません。

Claude Codeなど他のエージェントの任意音声ファイル送信は、この経路では未対応です。[Claude Code公式のvoice dictation](https://code.claude.com/docs/en/voice-dictation)は、提供元で文字起こしした文章をCLIの入力欄へ入れる別の機能です。専用端末から利用できます。アシスタントの録音ファイルをその公開CLIへ送る経路と同一とは扱いません。Whisperを使う場合は処理先で「ローカルWhisper」を明示的に選び、従来どおりエンジン・モデル・ローカルURLを用意してください。

### エージェントの種類と文字起こし結果の確認

ツール画面には選択中のエージェント名と、音声ファイルの直接入力に対応するかを表示します。現在の直接入力はCodexに対応し、Claude Code・Muse Code・Antigravity CLI・GitHub Copilot CLIでは直接送信と録音の開始を無効にします。対応するエージェントでも、接続・専用セッション・待機状態を別に確認し、送信時にはCLI・会話ID・モデルの対応を検査します。

5種類とも、処理先を明示的に「ローカルWhisper」へ変更すれば録音・音声ファイルの文字起こしを利用できます。この経路の対応表示は、このPCのWhisperの導入・起動・モデル準備を保証しません。上記のローカル設定を別途行ってください。直接入力に失敗してもWhisperや他のAIへ自動で送信しません。

文字起こし結果を確認・編集し、「確認した結果を会話の下書きへ」を押すと会話の入力欄へ移します。利用者が送信するまではエージェントへ渡しません。会話へ移す文章は8192文字以内です。接続先・専用エージェント・会話の識別情報が変更された場合は録音と処理結果を破棄し、変更前の結果を新しい相手へ移せないようにします。古い処理の完了を受け取っても自動送信しません。会話の切替・一時切断・音声の処理先設定の変更では録音の許可を失効させて録音だけを停止し、ツール画面と未保存のメモ・OCR入力は残します。

### 共用COREのボイスと待機中の上下動

「船長のボイス」で「PCの音声」「内蔵CORE（Sodashitsuが管理）」「外部VOICEVOX」を選べます。内蔵COREの接続先は操舵室から自動取得するためURL入力は不要です。外部VOICEVOXではこのPCのENGINEやコンテナの接続先URLを指定します。「話者一覧を更新」から声を選んで保存します。COREの導入・常駐管理・差し替え・yukkuri-workとの共用は[共用音声合成](voice-core.md)を参照してください。

「待機中のキャラクターをゆっくり上下させる」は既定オフ。オンでは約8.8秒周期で上下します。最も上がった位置で足元がタスクバーに接し、下がる最大8DIP分はウィンドウ下端で隠れます。上側に余白を設けるための縮小はしません。発話・作業・通知の動きでは上下動を中断し、「動きを抑える」や有効なOSモーション軽減、画面ロック・スリープでは止めます。

### キャラクター設定とセリフ

立ち絵のキャラクターに応じて、専用チャットの返答へ一人称・口調・呼び方・性格を渡します。文字の依頼、画像説明、Codex音声入力の返答が対象です。既に出力済みの返答は書き換えず、次に送る依頼から反映します。引用・文字起こし・コード・数値・作業結果はキャラクター表現のために変更しないよう指示します。

資料はyukkuri-workの`skills/video/yukkuri-kaisetsu/characters.json`を操舵室の`packages/protocol/src/assistantCharacterProfiles.ts`へコピーしたものです。14人（ずんだもん・めたん・つむぎ・霊夢・魔理沙・はう・龍星・ひまり・そら・WhiteCUL・ずん子・きりたん・イタコ・小夜）の設定と関係性を収録し、公式の記述と動画上の慣習の区別・出典・元ファイルSHA256も保持します。元PJの参照やVOICEVOX接続がなくても設定を使えます。きりたんの別衣装等は同じ人物設定を使います。資料未収録の人物は設定を創作せず、標準の丁寧な口調へ戻します。設定画面の立ち絵プレビュー下に、一人称と口調を表示します。

通知の話者名・元本文は維持し、前置きの案内、初回の挨拶、ボイス試聴のセリフも設定に合わせます。別エージェントの回答や確認文をそのキャラクターの発言に書き換えるものではありません。人物設定は表現の指定で、作業権限・承認条件は変更しません。

同期し直す場合はSodashitsuリポジトリで次を実行し、ビルド・再起動します。

```sh
node scripts/sync-assistant-character-profiles.mjs /path/to/yukkuri-work/skills/video/yukkuri-kaisetsu/characters.json
```

ユーザーの会話表示から設定用の末尾領域を隠すため、サーバが`assistant-persona-key`で署名します。この32byte鍵はstate-dirに0600で原子的に保存します。会話の中の似たマーカーやコード例は署名が合わなければ削除しません。通常はstate-dirと一緒に保持してください。

### 標準の船長画像と操舵室アイコン

立ち絵の選択に「操舵室アイコン」を追加しました。Web版と同一のロゴSVGを表示します。「操舵室アイコンをゆっくり回転させる」（既定オン）で16秒周期の回転を切り替えます。この項目は立ち絵に「操舵室アイコン」を選んだときだけ表示します。上下動は既存の待機中の上下動設定を共用します。回転もモーション軽減・非表示・ロック中は停止します。

男性船長・女性船長・ロボット船長は、紺・金・白を基調とした透過PNGの全身イラストです。画像生成で作成した原本を保ち、表示フレームで余白を調整しています。高さの設定値を使って縦横比を保ち、足元を作業領域の下端、画像の右端を右端へ合わせます。現在のキャラクター選択は更新で変更しません。

### 初回表示とアプリのアイコン

設定・操舵室・応答窓は文書読み込み完了後に表示し、初回と再表示で同じアクティブ化・再描画を行います。最小化した窓も復帰させます。WindowsではGPUプロセスの初期化失敗による描画停止を避けるためソフトウェア描画を使います。動画などの描画負荷はCPU側に移ります。

ウィンドウとタスクバー、通知領域は操舵室ロゴを表示します。Windowsは16〜256pxのICO、その他は透過PNGを使用し、macOSのDockにも設定します。共有Electronランタイムの実行ファイル自体は書き換えません。アイコン素材は`scripts/build-app-icon.mjs`で既存のWeb版logo.svgから生成します。

### 声の切替と保存前の試聴

内蔵CORE・外部VOICEVOXでは「立ち絵に合わせて声を選ぶ」が既定オンです。インストール済み話者の名前と立ち絵を対応付け、別の人物の声が残っているとノーマル等の対応スタイルを選びます。同じ人物の別スタイルを選択済みなら保持します。対応する声がない標準船長などは選択中の声を使います。PCの音声にはキャラクター別の声はありません。

「声」を手動で選ぶと自動切替をオフにし、その声を優先します。立ち絵への追従へ戻すにはチェックをオンにします。「ボイスを試す」は保存前のキャラクター・生成元・声で試聴し、保存値を変更しません。通常の通知や返答へ反映するには保存します。声を変えると再生中の古い声を止めます。

標準船長3人の立ち絵は、頭を大きくしたポップなアニメ調のデフォルメ画像に更新しました。紺・白・金の制服と帽子を保ち、透過PNGの原本を表示します。

## 5種類のエージェント

Claude Code・Codex・Muse Code・Antigravity CLI・GitHub Copilot CLIを、専用会話・モデル/effort設定・通知元/本文・応答/フォーム・作業一覧・監督/連携の共通経路で扱います。モデル/effortは種類ごとに保存し、次の新しい専用セッションから適用します。現在のCLIの設定を書き換えません。詳しいデータ取得範囲と固有機能は[エージェントの共通対応](agent-parity.md)を参照してください。

### 操舵室本体のアシスタント配色

操舵室の設定「テーマ」で「操舵室アシスタント」（生成り色・紺色の文字・金色）と「操舵室アシスタント（ダーク）」（アシスタントと同じ紺色・金色）を選べます。画面・操作ボタン・フォーム・スクロールバーと端末の配色をまとめて切り替えます。「OSの明暗に合わせる」を有効にすると、この2種類が対になって自動で切り替わります。既定のテーマは変更しません。

### デスクトップアシスタントの明暗

デスクトップアシスタントの設定「基本設定」→「カラーテーマ」で「通常」「ダークモード」「OSの明暗に合わせる」を選び、保存します。通常は生成り色・紺文字・金色、ダークモードは従来の紺色・金色です。既存設定ではダークモードを維持します。会話・通知・ツール・設定・操舵室ビューのローカル枠が追従し、OS連動ではOSの明暗変更を再起動なしで反映します。

### 設定・ツール画面の外観

設定・ツール・アシスタントから開く操舵室ビューは、会話ウィンドウと共通の紺色・金色の丸枠で表示します。尻尾は付けません。枠の外側の余白と背景はなく、角の外側は透過します。見出し行は30pxです。上部の見出しをドラッグして移動でき、右上から最小化・最大化／元に戻す・閉じるを操作できます。ウィンドウの上下左右・四隅からリサイズできます（通常の最小360×360）。透過窓ではElectronの標準リサイズに制限があるため、枠でのドラッグと最大化・復元はアシスタント側で処理します。復元先は現在接続している画面の作業領域に補正します。見出しは固定され、本文だけが配色に合わせたスクロールバーでスクロールします。設定・ツールのフォームや操作内容は従来どおりです。

最大化した窓を見出しから移動すると、通常の大きさへ戻り、そのまま枠でリサイズできます。右上のボタンは通常時に単一の四角（最大化）、最大化中に重なった四角（元のサイズに戻す）へ切り替わります。ボタン名とツールチップも状態に追従します。最大化したままでも枠をリサイズでき、実際に大きさが変わると、そのサイズのまま通常状態へ切り替わります。閉じる・最小化・最大化の記号はSVGをボタン中央へ配置し、通常配色でも閉じるボタンのマウスオーバー時は赤い背景に白い×を表示します。

### 本文全体のスクロールと折り畳み

会話・通知・エージェント一覧・設定の説明・素材プレビューなどに、個別の高さ制限とスクロールは設けません。展開中は内容をすべて表示し、各画面の本文全体だけを縦スクロールします。会話画面の操作ボタン・メッセージ入力欄・接続情報も同じ本文に含まれます。長い入力欄は文章量に合わせて伸びます。

通知（全体と個々）、会話、エージェント一覧、専用セッション、メッセージ入力、接続情報、設定カテゴリ、ツールのカテゴリは、見出しをクリックするかキーボードで折り畳めます。通知選択・ツールからの文面受け取り・入力エラーの確認時は、必要な項目を自動で展開します。

ツール画面の「標準ツール」には文章・メモ、音声入力・文字起こし、画像から文字を読み取る（OCR）、リマインダーをまとめています。「プラグインのUI・機能」は独立したセクションで、標準ツールを折り畳んでも開閉状態は変わりません。

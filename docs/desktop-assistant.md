# デスクトップアシスタント

操舵室のWindows用ネイティブ補助アプリです。Soda本体やエージェントはWSLで動かし、アシスタントはWindowsのデスクトップに表示します。常駐表示・設定・認証済みの通知受信と、専用エージェントへの吹き出しチャットを利用できます。実際のWindows GUIとエージェントを組み合わせた検証はまだ行っていません。

## 使える機能

- 無効を初期値とする有効・無効の設定、設定ファイルへの保存と復元。
- 男性船長・女性船長・ロボット船長の標準素材。大きさと表示モードを切り替えられます。
- 画面右下のキャラクター、または通知領域のアイコンのみの表示。どちらでもアイコンのメニューから設定・終了を選べます。
- キャラクターをクリック、またはアイコンの「船長と話す」から吹き出しを開きます。キャラクター自体はキーボードフォーカスを奪いません。
- 認証済みの操舵室で、確認待ち・未読の作業完了を言葉で通知します。通知では入力フォーカスを奪いません。ミュート時は吹き出しを自動で開かず、手動で会話画面を開くと通知を確認できます。
- 通常の操舵室画面を閉じていても、検出済みエージェントの `sodactl ask` を受け取り、吹き出しで質問フォームの到着を知らせます。通知から該当フォームを開いて回答します。同時に複数の質問があっても、通知が指す質問だけを表示し、回答済みの質問から別の質問へ自動で切り替えません。フォーム通知に端末用の返答欄や確認キーは出しません。エージェントのない通常端末のフォームには、通常の操舵室画面が必要です。
- 通知は最大32件。再接続の同じ出来事を繰り返さず、閉じたpane・入れ替わったエージェント・解消済みの古い知らせを外します。接続先Sodaのローカルpaneと、登録済み・接続中の他マシンのpaneを対象にできます。
- 吹き出しから接続先で利用可能なエージェントを選び、専用セッションを開始します。接続だけでは新規起動せず、開始ボタンを明示的に押します。Claude/Codexは会話記録を吹き出しで表示し、待機中の専用エージェントへメッセージを送れます。
- 「操舵室を開く」で通常の操舵室画面を別窓に開きます。既存のターミナル・質問フォームを使えます。専用端末や通知元へ直接移るには、それぞれの「端末・フォームを開く」を使います。
- Windows配布版でのみ、明示的にログイン時の起動を設定できます。開発版での設定や非Windowsでの有効化はエラーにします。

接続先は `http://127.0.0.1:7780` などローカルHTTP、またはHTTPSのオリジンです。パス、URL内の認証情報・トークン、LANへの平文HTTPは受け付けません。TLS証明書の検証を省略しません。操舵室のログイン画面で認証します。設定JSONにトークンは保存しません。

## 開発時の起動

WindowsのNode.js 24以降とpnpmを使い、Windows側で依存を導入・ビルドします。WSL側の `node_modules` との共用は避けてください。

```powershell
pnpm install --frozen-lockfile
pnpm --filter @sodashitsu/desktop-assistant build
pnpm --filter @sodashitsu/desktop-assistant start
```

`--ignore-scripts` で導入した場合、Electron本体のダウンロードが行われていないため、そのままでは起動できません。`pnpm build` や `soda handoff` は、このアプリをデスクトップに起動する操作ではありません。

Windows用zipのビルドは `pnpm --filter @sodashitsu/desktop-assistant pack:win` です。現段階は署名なしの開発配布設定です。CIの `sodashitsu-assistant-windows-x64` アーティファクトからzipを取得できます。Windows実機での起動確認は未実施です。設定はElectronのアプリ別userData内の `assistant.json`、ログイン状態は別のElectron sessionに保存します。アプリを無効にするとキャラクター・吹き出し・操舵室窓を閉じ、設定と終了のため通知領域アイコンは残します。

## 専用セッションのサーバ側基盤

認証済みAPIとして `assistant.get`・`assistant.ensure`・`assistant.adopt`・`assistant.prompt`・`assistant.send_keys` を追加しています。端末ごとのUUIDに対応した専用ワークスペースをサーバ状態フォルダ内に作ります。再接続だけでエージェントを重複起動しません。起動済みか判別できない場合は自動再起動せず、現在の対象を選び直すか、停止した端末を残して新しい専用端末を作ります。

会話の復元は保存された名前だけでは判断せず、現在のエージェントと会話の情報を照合します。送信の待機中に対象・作業先が変わった場合も入力を中止します。吹き出しには専用端末の短いidとエージェントの種類を表示します。対象を確認できない場合は「このエージェントを使う」で現在の対象を選び直します。端末の識別UUIDはuserData内の `assistant-device-id` に保存します。設定JSONの書き換えでは別端末に切り替わりません。識別情報が壊れた場合は勝手に別のUUIDへ置き換えません。

## 吹き出しでの会話と制限

開始後は、同じ端末UUIDの専用ワークスペースを再利用します。エージェントを停止しても旧端末を自動で閉じず、「旧端末を残して新しく開始」を選べます。アシスタントの表示を無効にしても、送信済みの作業を勝手に終了しません。

会話は最大100メッセージで、記録の更新を約2秒ごとに読みます。Claude/Codex以外の会話記録の吹き出し表示は未対応です。エージェントのログイン・初期設定、質問や承認の入力、端末固有の画面は「専用端末・フォームを開く」から操作できます。通知元の返答欄と専用チャットは別々で、それぞれの送信先を保持します。

接続が切れた場合や20秒以内に操作の結果を確認できない場合、送信操作を自動で繰り返しません。送信できたか不明なときは操舵室で結果を確認してください。復旧後は現在のエージェントを確認してから操作します。

## 標準ツール

吹き出しの「標準ツール」を開きます。コピーした文章の読み込み・文章のコピー、メモの新規保存・読み込み・編集・削除、要約・翻訳用の文面作成、読み上げ、音声ファイルとマイク録音の文字起こしを用意しています。

メモは `assistant-notes.json` に保存し、最大200件・1件8192文字です。メモを保存するだけでSodaやエージェントへ送りません。要約・翻訳のボタンは会話の入力欄に文面を入れます。内容と送信先を確認してから「送信」を押してください。

読み上げはOSが提供するローカル音声のみを使います。利用できる音声がない環境では未対応と表示し、オンライン音声へ自動切り替えしません。「読み上げを止める」、吹き出しを隠す・閉じる操作で止めます。Windows実機での音声確認はまだ行っていません。

### ローカル音声ファイルの文字起こし

設定の「ローカル文字起こし」で有効にし、このPCのWhisperサーバを指定します。初期値は `http://127.0.0.1:8080` です。[whisper.cppのサーバ](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/README.md)と日本語に対応した多言語モデルは別途用意してください。アシスタントはエンジンやモデルを自動インストール・起動しません。

起動例（モデルのパスは環境に合わせて変更）：

```sh
whisper-server --host 127.0.0.1 --port 8080 -m models/ggml-base.bin -l auto --convert
```

WAV以外の変換には、Whisper側でffmpegと `--convert` が必要です。エンジンをWSLで動かす場合、Windowsからlocalhostで接続できる構成にします。

「音声ファイルを文字起こし」でWAV・MP3・M4A・MP4・OGG・FLAC・WebMの通常ファイルを選びます。上限25MB・1処理ずつ、読み取り開始から5分です。結果は確認・編集して「扱う文章」へ渡せます。長い結果は8192文字以内の部分を選んでください。会話への送信は別操作です。

キャンセルは通信と結果採用を中止します。OSの読み取りなどが終了するまでは次の処理を始めません。独立したWhisperサーバ内で開始済みの計算が止まるかは、サーバ側に依存します。吹き出しを隠す・閉じる、アシスタントの無効化、認識先の変更でも古い結果を破棄します。クラウド認識にはまだ対応していません。実モデルの認識精度も未検証です。

### マイク録音

同じローカル文字起こし設定を使います。「マイクの録音開始」を押すと、必要なOS許可を確認して録音します。カメラ・画面共有は許可しません。録音中は吹き出し上部にも表示と停止ボタンが出ます。

「録音停止」でマイクを止めます。「録音を試聴」は押したときだけ再生し、「録音を文字起こし」で初めてWhisperへ渡します。「録音を破棄」も選べます。上限は録音5分・25MiB、停止後は5分以内に処理するか破棄してください。認識結果の会話送信は別操作です。

ツール欄を閉じる・吹き出しを隠す／閉じる・最小化・設定の無効化／認識先の変更でも破棄します。OSの許可待ちで取り消した場合、許可の処理が戻るまでは次の録音を始めません。許可画面が残っていれば閉じてください。非対応環境では音声ファイルを利用できます。

録音・試聴のWindows実機確認は未完了です。生成テストではマイクとMediaRecorderを差し替えており、実音声・再生品質やOS設定への対応は確認していません。

## 実機で確認する範囲

コード・生成アダプター・ヘッドレス画面・配布物の検証と、実際のWindows上での動作確認は分けています。実機では、通知領域・透過窓・複数ディスプレイ/DPI・ログイン時起動・スリープ/ロック復帰・全画面抑制・証明書・実エージェントの会話/質問・画面/音声取得・Tesseract/Whisperの認識と試聴を確認してください。生成テストやWindowsビルド成功は、この実機確認の完了を意味しません。

## 確認

```sh
pnpm exec vitest run --project @sodashitsu/desktop-assistant
pnpm --filter @sodashitsu/desktop-assistant verify:ui
```

前者はOSを呼ばない注入アダプターと一時ファイルを使います。後者はPlaywright Chromiumの導入が必要なヘッドレス生成UI検証です。実際の画面・マイク・クリップボード、ログイン時起動の登録、実エージェントの起動は行いません。Windows実GUIとLinux/macOS実機は別途確認が必要です。

通知の接続はmainプロセス内だけでログインCookieを扱い、既存ブラウザと同様にURLの一致するSodaの通常/名前付きsession Cookieを送ります。トークンは吹き出しのrendererへ渡しません。読み取り専用の接続は端末入力やエージェント起動を行いません。handshakeは実経過10秒、接続後は20秒ごとのpingに10秒以内のpongがなければ再接続します。HTTPSは証明書検証を有効にし、Node/OSの既存CAを読み取ります。証明書のインストールや検証省略は行いません。

### 画像から文字を読み取る（OCR）

設定の「画像の文字認識（OCR）」を有効にし、このPCのTesseract実行ファイルの絶対パスと言語を指定します。例はWindowsでは `C:\Program Files\Tesseract-OCR\tesseract.exe`、Linuxでは `/usr/bin/tesseract`、言語は `jpn+eng` です。[Tesseractと言語データ](https://tesseract-ocr.github.io/tessdoc/Installation.html)は別途用意してください。アシスタントは自動インストール・起動を行いません。

吹き出しの「標準ツール」→「画像から文字を読み取る」を開きます。OSの画面切り取りでコピーした画像を「コピーした画像を取り込む」で取り込むか、PNGファイルを選びます。「画面・ウィンドウの名前を一覧」から対象を選び、「この画面を撮影」で直接1枚取得することもできます。音声は含まず、取得後に直ちに共有を止めます。選択の期限は30秒で、OSの画面収録許可が必要な環境があります。PNG・8MiB・3840×2160以内です。クリップボードの監視はしません。

プレビューを確認し、必要なら左・上・幅・高さを画像の画素で指定して切り出します。「文字を認識」を押したときだけ、画像をこのPCのTesseractへ標準入力で渡します。処理は60秒、認識結果は65536文字まで。外部のOCRサービスには送信しません。

結果を確認・編集して8192文字以内にし、「認識結果を扱う文章へ」でメモ・要約・翻訳・会話の下書きに利用できます。会話への送信は別操作です。画像と認識結果はファイルに保存せず、取り込み・切り出しから5分、吹き出しを隠す・閉じる・画面遷移する、またはOCR設定を変えると破棄します。必要な結果は期限前にメモへ移してください。


### リマインダーと通知元への返答

標準ツールの「リマインダー」で見出し・内容・この端末の時刻での日時を入力します。1年以内の一回予約で、サーバが動作している間に実行します。モデルを呼ばずに船長が「お知らせです」と内容を伝えます。「確認しました」で対応済みにし、その結果もサーバに保存します。予約を削除しても、既に届いた知らせは確認するまで残ります。他端末のアシスタントの予約と知らせは混ざりません。

通知の返答欄は専用チャットとは別で、表示されている通知元だけに届きます。入力待ちの確認にはEnter/Esc/y/nの明示操作を使うか、「この端末・質問フォームを開く」で既存の端末・ask-form・プラグイン表示へ展開します。専用セッションも「専用端末・フォームを開く」で展開できます。対象が閉じた・交代した・移動した場合は入力を遮断します。ログインが必要な場合は、通常表示を開く操作を明示的に選んでください。応答が不明な送信を自動で繰り返しません。


### プラグインのキャラクター・UI・機能

設定の「プラグインの機能」で素材の表示・UIの展開・操作の実行を別々に許可します。初期状態では全て無効です。「素材パックを選んで確認」で `.sodaplugin` を開き、PNGプレビューを確認して追加します。この操作はキャラクター素材だけを保存し、含まれるプログラムを実行しません。素材は1024×1024・128KiB、合計32キャラクター／16パックまでです。船長を選んで保存すると反映されます。素材表示の許可を解除すれば標準船長へ戻ります。パックの削除は先に標準船長へ切り替えて保存してから行います。

パッケージの `soda-plugin.json` に次の宣言を追加し、PNGを `files` に含めます。通常の `sodactl plugin pack /path/to/plugin --out captains.sodaplugin` で梱包できます。

```json
"assistantCharacters": [{"id":"robot","name":"追加の船長","file":"assets/robot.png"}]
```

アシスタント用UIは既存 `views` の定義へ `"assistant": true` と `"targets": ["pane"]` を加えます。機能は既存 `app.register` の操作定義に `"assistant": true` を加えて公開します。`description` と `inputSchema` は通常のプラグイン操作と共通です。プログラムの有効化とプロジェクト拡張の承認、スクリプトHTMLの許可は通常の操舵室で行い、省略しません。

吹き出しの「プラグインのUI・機能」から一覧を更新します。専用セッションで利用可能な稼働中の拡張だけが出ます。UIは既存の端末・表示パネルへ展開し、操作は内容とJSON引数を確認して明示実行します。結果は確認してから会話・メモへ渡せます。プラグインUIにはアシスタントのOS機能や認証情報を渡しません。専用セッションは独立した作業フォルダなので、常駐アシスタント向けには利用者スコープのプラグインを推奨します。別プロジェクト限定の拡張は、その通知元の端末から利用してください。


### 他マシンからの知らせ

「登録済み・接続中の他マシンからも知らせを受ける」で、操舵室に登録したオンライン端末を最大8台まで受信します。新しいSSH接続やエージェントをアシスタントが起動することはなく、既存の操舵室の認証済み中継を使います。通知にマシン名を表示し、返答と端末展開もそのマシンへ固定します。切断・削除・許可解除された対象に送れない場合、接続元への代行送信はしません。小さい展開窓でも接続先を維持します。接続元・接続先の両方を対応版へ更新してください。


### 配置・全画面時・復帰

設定の「配置」でディスプレイと左・上位置を指定します。座標はElectronのDIPで、負の座標のモニターにも対応します。「プライマリの右下（自動）」では数値を使いません。キャラクターと吹き出しは選んだ画面の作業領域に収め、取り外されたディスプレイは表示可能な画面へ戻します。吹き出しはキャラクターの近く、アイコンのみのモードでは画面右下に出します。

「全画面中は通知で吹き出しを開かない」はWindowsの前面窓の範囲を確認し、画面全体を覆っている間の自動表示を控えます。画像・ウィンドウの文字・入力は取得しません。判定できない場合も知らせは一覧に残し、手動の会話は開けます。自動表示が出ない場合は、ミュート・この設定・ログイン/接続状態を確認してください。

スリープ/ロック時は取得中の画面・音声を止め、未送信のOCR画像を破棄します。スリープ時は通知と制御の接続も止め、復帰時は画面配置と接続を取り直します。エージェントを重複起動したり、返答・操作を自動再送したりしません。

### zip版の配置と更新

Windows用の開発zipを固定したフォルダーへ展開し、`Sodashitsu Assistant.exe` を起動します。Windows側にNode.jsがなくてもzip版は動きます。初回は設定で有効にし、「操舵室を開く」からログインして、使うエージェントを選び専用セッションを開始してください。起動済みのSoda本体/WSLへ接続するアプリであり、Sodaサーバ自体のインストール・起動は別です。

更新時は通知領域のメニューから終了し、同じフォルダーへ新しいzipの内容を展開します。ログイン時起動を有効にした後は実行ファイルの置き場所を固定してください。設定・端末UUID・メモ・素材はElectronのuserDataに保存され、zipの展開フォルダーとは別です。Soda側の更新には接続元・接続先の `git pull` / `pnpm build` / `soda handoff` を使い、ネイティブアシスタントも更新後に起動し直してください。

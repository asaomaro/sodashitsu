# TS / Web remote desktop implementation inventory

Scope: server DesktopProvider/Relay, shared source routing, agent input integration, client-core endpoint/helper transport, web media/file/clipboard adapters. Native C#/PowerShell and Windows signin/bootstrap are reviewed in their separate phases. This inventory classifies implementation responsibilities; it does not claim that every retained implementation is proven optimal or that replacement with an upstream application has happened.

## Primary code checked

- RustDesk 1ac53ccb1b28e62b726db3cbd6042110349c9c2a: [connection.rs](https://github.com/rustdesk/rustdesk/blob/1ac53ccb1b28e62b726db3cbd6042110349c9c2a/src/server/connection.rs#L1216). Mouse/key input is dispatched through input handlers. The cited handler does not take a painted-frame age receipt; this is a bounded comparison of that handler, not a claim about all RustDesk paths.
- FreeRDP f148e75fa62050c600a60c33653fab49a08094cc: [shadow_input.c](https://github.com/FreeRDP/FreeRDP/blob/f148e75fa62050c600a60c33653fab49a08094cc/server/shadow/shadow_input.c#L46). Client key ownership and shared key-held counts are separate; release skips keys another client holds. This motivates source-local cleanup and avoiding unverified cross-helper keyup/keydown overlap.
- FreeRDP same commit: [cliprdr_main.c](https://github.com/FreeRDP/FreeRDP/blob/f148e75fa62050c600a60c33653fab49a08094cc/channels/cliprdr/client/cliprdr_main.c#L57). Clipboard requests/replies use a dedicated virtual channel with negotiated capabilities. Separate traffic classes and request correlation have an ordinary RD counterpart.
- Apache Guacamole a8daafeb38b60b0acb4059c5218e6d5bacfaeb8f: [Client.js](https://github.com/apache/guacamole-client/blob/a8daafeb38b60b0acb4059c5218e6d5bacfaeb8f/guacamole-common-js/src/main/webapp/modules/Client.js#L340). Browser key/mouse methods check connection state and send input through the tunnel. These methods do not require a painted-frame age receipt.

- RustDesk same commit: [io_loop.rs](https://github.com/rustdesk/rustdesk/blob/1ac53ccb1b28e62b726db3cbd6042110349c9c2a/src/client/io_loop.rs#L1427) serializes transfer job metadata to peer configuration; [resume handling](https://github.com/rustdesk/rustdesk/blob/1ac53ccb1b28e62b726db3cbd6042110349c9c2a/src/client/io_loop.rs#L1020) and digest/offset handling provide the ordinary persisted-transfer pattern.
- [W3C WebRTC Recommendation, 13 March 2025](https://www.w3.org/TR/2025/REC-webrtc-20250313/#dom-rtcicetransportstate) defines disconnected as transient and failed as terminal until ICE restart. This supports using the transport state instead of immediate teardown on disconnected or a separate short startup timer.

The code comparisons informed concepts and API use. No upstream implementation was copied wholesale. These are not wire-compatible RDP/RustDesk implementations.

Human input follows active session/control. Existing Share.video and deferNativeSnapshots preserve JPEG deferral. Explicit agent observation policy remains separate. |

Control replies correlate seq; clipboard uses existing generation; microphone uses existing stream id. Actual helper close retires that source only. No new cleanup timer or retry. |
| Native drag pointer provenance | Resource ownership epoch carried in pointer witness and selection worker request/result; native activation required a cleanup receipt epoch | Removed in phase 3. Pointer remains bound to physical helper, submitted input seq, HWND and PID. Selection worker keeps its existing per-capture nonce. Transfer generation reuses the existing gesture UUID. Native activation waits ordinary control completion without a receipt framework. |
| Old reservation / retirement tests | Tests solely asserting epoch/fence/global-fault implementation | Removed or rewritten for physical source close, ordinary command correlation, source-local resource exclusion, stale response rejection and FIFO order. |

## Retained code and its concrete role

| Files / family | Ordinary RD role or Soda boundary | Why it cannot simply be removed while preserving capabilities |
|---|---|---|
| DesktopSharedCapture / SharedNative / SharedAudio / SharedClipboard | One capture/media source with multiple consumers and one explicitly granted control/clipboard owner; source-global request IDs route replies to viewer-local IDs | This is multiplexing, not a second authorization or cleanup protocol. Removing reply routing would deliver one viewer response to another. The source and its subscribers remain different lifetimes. |
| DesktopInputAcks / helper stdout or priority stderr ACK | Existing input command completion and per-source input sequence translation | Human OS-native drag uses the applied pointer target; agent act reports applied input completion. The existing priority stderr route keeps input completion independent of the bounded bulk JPEG stdout record, following the ordinary separate control/data channel pattern. It maps native command completion into the app RPC result; it does not create another permission grant. |
| DesktopNativeVideo / nativeVideoReceiver / mediaReceiver / NativeDatagrams | GPU/WebCodecs and WebRTC/SCTP adaptation, decoder format changes, bounded media frame credit, actual dropped-frame retirement | Media credit bounds source/decoder queues. It is no longer treated as human input permission. Codec reset/fallback is a bounded codec negotiation, not an unbounded reconnect loop. |
| DesktopAudioPipes / NativePcmPath / NativeMicrophoneHost / Microphone | Browser WebAudio/Opus to native PCM/pipes, source-owned audio actors, bounded real-time audio queue | Browser and OS audio APIs differ; these adapters carry the required audio/microphone capability. Playback proof is not fabricated from pipe writes. Ordinary actor close still releases physical endpoints. |
| DesktopVideoLanes / Relay tickets / relayOrigin | B-side provider attaches to an A-side authenticated browser session, with one-use role/session/origin-bound capability for each bulk lane | A machine peer and a browser cookie are different principals. Separate browser origin checks and provider tickets enforce that real boundary; a stream id alone cannot authenticate a lane. This is Soda routing/auth integration, not an ordinary RD feature rewritten for its own sake. |
| EndpointWire / E2e / EndpointBinding / EndpointService | End-to-end encrypted endpoint transport over an intermediary relay; child lanes bound to the authenticated parent and role | TLS to the intermediary terminates at that intermediary. The existing end-to-end boundary and explicit peer identity cannot be removed by citing TLS. Cryptographic primitives use WebCrypto. The private envelope is an adapter, not evidence that a custom cryptographic design is better. |
| DesktopAgentAccess / headless viewer / EndpointAgentRpc | Explicit owner permission, observe/act digest and image freshness, one agent action at a time, source/session identity, RPC revoke | An unattended agent makes a decision against an observation, unlike ordinary human RD input. These enforce the existing agent API contract; they are not ordinary mouse/video liveness. No claim is made that a two-second policy is universally optimal. |
| Files / Folders / FileCheckpoints / FolderCheckpoints / TransferStore | Explicit file-root grant, path containment, per-job offsets/digests and durable resume | Resumable user-approved transfers require saved job identity and byte offsets; these are not signin/process journals. Scope changes invalidate saved transfers so an old job cannot inherit a new file-root permission. Its saved continuation data is bound to Soda file-root/endpoint settings; it never persists an input grant. The Provider now reuses the existing saved-state factory instead of duplicating its hash and registry construction. |
| NativeFiles / NativeSources / NativeGateway / NativeBridge | Browser-PC localhost helper + remote Explorer selected-file stream; explicit browser origin, source identity, per-gesture file authority and cancellation | Browser JavaScript cannot directly start an OS OLE drag or inspect remote Explorer selection. HWND/PID binding and actual local bridge close enforce those boundaries. Root containment and explicit file grants remain independent of input control. |
| HelperRolePlan / NativeRoleBinary / NativeHelpers | Fixed server-selected child executable/role; OS actor lifetime, lazy module loading and process ownership | A pane/project RPC cannot select an arbitrary privileged executable. Ownership continues until actual close, not an exit flag or timeout. Start/stop is process lifecycle adaptation; touch polling was removed. |
| NativeSources / NativeFiles gesture heartbeat | Long-running file lease lifetime during an OS drag, separate from the removed no-op helper poll | This heartbeat actually renews gesture-bound file authority and ends reads when the browser gesture disappears. It is not equivalent to the removed touch handler that renewed nothing. |

## Candidate dispositions

- Human frameSeq adjacency checks and the obsolete human wire field are removed in phase 4, including browser, Relay, Provider, backplane fixtures and signin WorkerProcess. Frame ACK validation and the separate agent observation frameSeq remain. Native signin Worker/Scope wire producer changes are supplied by the signin phase.
- DesktopSourceIdle.fresh and its clock/timestamp/reset state are removed in phase 4. SourceIdle only validates/deduplicates an informational badge against the current image sequence. The badge grants no input and renews no observation.
- nativeHelperRpc now reuses the existing client-core Connection in phase 4, directly targeting this page origin. Its custom raw message parser, request map, sequence and 15-second request timers are deleted. The existing onClosed callback calls disconnect before the ordinary Connection chooses reconnect, preserving per-socket helper ownership without a new reconnect mode.
- Phase 5 removes format barrier3s checks in Relay, NativeVideo and web receiver; NativeVideo ACK2.5s/silence5s teardown, web frozen-draw2s/startup12s/codec-reset2s teardown and RTC startup7s/8s timers are also deleted. The existing bounded-credit queue and stream id/generation/baseSeq enforce ordering. Actual transport/channel close, failed ICE and decoder errors still handle failure. Transient disconnected does not terminate the source. No replacement timeout, fallback or media mode was added.
- Durable saved-transfer metadata is retained as the scoped-resume adapter, mapping to RustDesk persisted TransferSerde job metadata, resume operations and digest/offset verification. Soda additionally binds continuation records to its selected file root and endpoint policy; these records cannot restore an input/file grant. TransferStore serializes writes, uses Node AES-GCM with OS-protected key material, and fsyncs file and directory. The app generic writeFileAtomic has neither those durability syncs nor private-store ACL/identity checks, so it is not a behavior-equivalent replacement. Actual duplicate Provider hashing/registry construction was removed in phase 5 by reusing existing desktopSavedBinding/createDesktopSavedTransferState. This is a concrete adapter boundary, not a superiority claim for a new general persistence framework.

## Phase 4 ordinary input

The remaining browser receiver.active age gate is removed from canInput. Live control and a ready source with an initial displayed image authorize ordinary human input. Per-operation lastSeen<5s gates are removed; the existing 12-second authenticated session/source liveness boundary remains. The Provider no longer stamps every human input with a 500ms expiry. Linux/Swift/Windows input parsers accept absent optional expiry and validate it when provided. Swift reuses its existing expires=0 cleanup-event convention; no replacement timestamp is fabricated. Explicit agent observation/digest/source checks and two-second observation policy remain in DesktopAgentAccess. Clipboard request budgets and realtime PCM deadlines are distinct operations, not human image-age permission.

## Phase 3 handoff invariants

Same-source old commands, native stop and subsequent grants share the physical helper FIFO. A different helper cannot obtain a resource while old ownership awaits the exact stop reply. A stale or unsolicited control false reply cannot satisfy a new release because it lacks the current control seq. Clipboard generation and microphone stream id provide their existing correlation. Source close retires only that source. Native cleanup failure must release every owned key/button before reporting failure or closing; the C# phase supplies that regression.

## Phase 6 portable media and signin lifetime

Linux and macOS retain current-source identity, one encoder job, bounded three-frame credit, stream/generation/baseSeq and actual encoder retirement. Capture1s, ACK2s, profile3s and pending-replacement2s time-only teardown are removed. The append-only1024 stream-ID ledger is removed; callers already generate nonreused UUIDs. Native encoder failure and actual scope loss still stop the stream. The signin WorkerProcess no longer expires a healthy source after120s or requires a synthetic stopped receipt in addition to real process close: success requires actual close0 and complete UTF8/newline output. Startup admission and actual owner/source loss remain distinct.

## Phase 7 clipboard request scope

Plaintext browser requests reuse their existing2s timeout to send cancel with the original request id. Provider retires only that pending id; SharedClipboard removes only its matching route. A late reply cannot resolve a newer request, and permission remains granted for retry. Windows/custom helpers no longer receive the redundant pre-call1s delivery-age expiry. Portable plaintext retains its sole bounded Portal/OS I/O budget (Linux select on pipe fd, macOS pasteboard query admission); this is distinct from source permission. Rich requests reuse the existing B-side3s response budget in the native expiresAt field; duplicate inner1s, idle5s and whole-transaction60s cutoffs are removed in TS/Linux/macOS and matching Windows phase. One transaction, bounded4MB, exact id/generation/offset and actual cancellation/source loss remain. No clock proves successful clipboard application.

The browser signin offer has no arbitrary120s timer. Explicit offer id/consent and allowInput ceiling remain; user-configured agent grant expiry is unaffected. Protocol and native signin counterpart are supplied by the signin owner.

## Phase 8 agent snapshot request adapter

Full-image agent capture no longer treats arbitrary late queued JPEG as a fresh observation based on receive time. Existing snapshot promise requests a UUID-correlated full JPEG; optional keyframe/frame snapshotIds are bounded64. IDs are copied at actual screenshot API start (Windows/macOS/signin) or after the existing Linux source pipeline running-time/PTS barrier (continuous PipeWire). No human frame field changes when no request is pending, no hidden region witness, inputseq increment, new clock or timer. Source requests survive discarded publication until successful full-frame commit/ACK. SharedCapture routes IDs per member; an ACK-blocked member retains its request and existing keyframe batching reissues after its real ACK. Full-image pixel/byte limits remain unchanged. This is Soda agent observe/request-response adaptation, not ordinary human input permission.

## Phase 9 physical transport and publication

Desktop uses dedicated raw WebSockets, outside the app Connection. Browser JSON2s heartbeat and its schema/routes are removed. Existing Relay1s tick pings the physical browser WS; its existing lastSeen updates only on protocol pong. Node Provider uses its existing tick/lastSeen for its own WS ping/pong and separately feeds the privileged child's existing IPC heartbeat. Browser timer throttling no longer controls physical transport liveness. HeadlessViewer implements ping/pong directly while the existing owner-live callback and actual close govern its lifecycle; its fake browser2s heartbeat is removed. Native stdin heartbeat remains privileged parent/child ownership adaptation, unrelated to frame age. Missing protocol pong still closes the physical peer after the existing12s budget.

Portable ordinary JPEG1s publication, macOS1.5s capture-stalled/input and5s pending-ACK teardown are removed now that requested agent capture identity is explicit. Source/session, revision, input sequence and bounded pending frame remain. Linux stdout no longer exits after100ms or holds input gate across pipe backpressure: one writer admits a complete bounded record, then writes it while ordinary input proceeds; actual scope/pipe loss schedules normal close rather than bypassing cleanup with os._exit. No new state/timer/retry mode was added.

## Phase 10 local file bridge and request scope

The local iframe already owns a real localhost WebSocket: pagehide/parent frame removal closes it; Gateway close owns NativeHost close and waits for its actual retained child, including asynchronous binary preparation. Parent browser1s beat/5s received-age, forwarded beat/alive protocol and NativeHost5s/15min whole-host fences are removed. NativeHost's existing timer independently feeds privileged child IPC beat at1s. NativeDrag UI, B NativeFiles and FD-backed NativeSources15min whole-drag caps are removed. Existing monotonic clock witness latches in these adapters are removed; gesture admission and actual per-request deadlines use the app's monotonic performance clock directly.

Both Host and B append-only4096 gesture ledgers are removed. At B, the existing preparation AbortController is registered as an inflight request before DesktopFiles queues its async root check; native_abort aborts this exact request, the post-await scope check rejects it, and completion retires the context. It is not retained as a tombstone after callbacks settle. The same existing signal reaches Explorer capture and partial file-snapshot construction. It replaces NativeSources' duplicate1500ms offer expiry and autonomous expiry timer, immediately zeroing partial buffers even while an OS read is still pending. Existing NativeFiles750ms target/gesture admission and5s renewed file-authority timer remain the sole whole-gesture cancellation owner; synchronous Source reads verify that authority and their own bounded I/O response. Source-local owner/origin/gesture binding, current physical input/window/PID, exact per-file request/offset/digest and actual close remain. These are Soda's local OS-drag/file-grant adapters, not replacement ordinary RD lifecycle machinery.

[WebSocket RFC6455 sections5.5.2/5.5.3](https://www.rfc-editor.org/rfc/rfc6455.html#section-5.5.2) define protocol ping/pong as keepalive and peer responsiveness checks; the phase9 implementation uses those physical control frames, independent of the browser JavaScript timer. Startup/claim deadlines remain bounded setup operations, not healthy-source lifetime limits.

## Phase 11 macOS output ownership

The existing bounded stdout queue moves from the main DispatchQueue to its own serial IO queue. It asks main for brief source/admission queries only; polling/writing holds neither main nor the input gate. Per-record validation happens before the first byte; thereafter only actual source/session loss or pipe failure can abort that admitted JSON record, so same-source input revision changes cannot corrupt it. Fixed500ms writeRecord failure is removed. Queue bytes/count bounds remain, actual failure uses existing main-thread stop/cleanup and finish waits serial output ownership. Terminal platform_failure metadata can still be emitted after source authority ends; it carries no pixels/input. No new timeout or retry mode is added.

## Phase 12 explicit agent operation policy

Human input remains free of generic expiry. AgentAccess propagates the existing caller/grant deadline into each action; private endpoint RPC supplies its existing pending-operation/owner deadline. Relay uses the smaller remaining budget and its existing1500ms input-ACK budget, without adding a timer or fixed500ms policy. Provider-private agent_input carries remaining duration, outside the browser viewer schema. B converts that duration using its own clock to native optional expiresAt; it never assumes A's wall clock matches B's. Linux's obsolete optional-input1000ms future cap is removed; Windows accepts the existing1500ms ACK budget and Swift already validates finite optional expiry. Expired/unapplied actions emit no successACK. Existing revoke/release/control completion governs cleanup; an OS operation already in progress cannot be atomically recalled. This is explicit Soda agent policy, separate from ordinary RD human input.

This follows standard [gRPC deadline propagation](https://grpc.io/docs/guides/deadlines/#deadline-propagation): a forwarding hop sends remaining duration after its own elapsed work, avoiding raw cross-machine deadline timestamps. Existing authenticated owner cancellation still handles caller loss; this does not claim instantaneous propagation over a stalled network.

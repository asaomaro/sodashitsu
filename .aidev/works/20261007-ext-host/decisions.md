### 登録

- 利用者の設定: `<状態ディレクトリ>/extensions.json`（名前付き session では session ごと）。`commands.json` と同じ読み方
  （`packages/server/src/commands/commandConfig.ts` の `loadCommandsFile` の型: `O_NOFOLLOW|O_NONBLOCK`・開いた fd の fstat で通常ファイル・持ち主・ほかの利用者が書けないこと・64 KiB・zod の `strictObject`・1 つでも規則外なら全体を採らない）。
- プロジェクトの設定: `<リポジトリの根>/.soda/extensions.json`。根は `findGitRoot(Workspace.cwd)`（`packages/server/src/session/workspaceLabel.ts`。worktree ごとの根）。
  持ち主・権限の検査は、**通常ファイルであること・リンクでないこと・大きさ**だけにする（clone したファイルの権限は様々。守りは承認）。根の外を指すリンクは読まない。
- 1 件の形（案）: `{ "id": "<COMMAND_ID_RE と同じ規則>", "command": "<シェルに渡す 1 行>", "description"?: "<200 文字>", "onUnresponsive"?: "pass" | "block" }`。
  `command` は `/bin/sh -c`（Windows は `%ComSpec% /d /s /c`。`commandArgv` と同じ）。上限は、利用者 16 件・プロジェクトごと 16 件・動かす合計 32。

### 承認

- 鍵: `sha256( JSON.stringify({ root: realpath(根), entry: 正規化した 1 件 }) )`。1 件ごと（1 つ変えても、ほかは承認のまま）。
- 記録: `<状態ディレクトリの根>/extension-approvals.json`（`writeFileAtomic`・0600）。`{ approvals: [{ key, root, id, approvedAt }] }`。上限 256 件（古いものから捨てる）。
- 流れ: 設定を読む（workspace が開いた・読み直しの操作・サーバの起動）→ 鍵が記録に無いものは「承認待ち」→ 画面に知らせ（トーストと、設定画面の節「拡張」の印）→ 利用者が開いて、中身を見て承認／承認しない。
  承認しないものは、同じ鍵の間は聞き直さない（「承認しない」も記録する）。
- 承認の RPC（`extension.approve {key}`）は、**サーバが今読んで計算した鍵と一致するときだけ**受ける（画面が見せた中身と、動かす中身を一致させる。画面は鍵を作らない）。
  画面の種類（`desktop`・`mobile`）の接続だけが呼べる。`pane.sock` には載せない。
- 承認の画面: ask のダイアログと同じく、ほかのダイアログを潰さない別の `<dialog>`。コマンドは `<pre>` に `textContent`。

### プロセス

- 持ち主は 1 つ（`ExtensionHost`）。手本は `packages/server/src/machine/MachineLink.ts`・`MachineManager.ts`（`stdio: ["pipe","pipe","pipe"]`・stderr は上限つきでログへ・`SIGTERM` → 2 秒 → `SIGKILL`・終了を待つ・バックオフ 1 秒〜120 秒）。
- 起動は `listen()` の中（状態ディレクトリのロックの後。二重起動で 2 つ動かさない）。停止は `close()` で、端末を捨てる前。handoff は `pausePollers` で止めて待ち、新しい版の `listen()` が起動し直す。
- 作業ディレクトリ: プロジェクトの拡張はリポジトリの根、利用者の拡張はサーバを起動した場所。環境変数: `buildPaneEnv` の規則＋`SODA_EXTENSION_ID`・`SODA_EXTENSION_SCOPE`（`user`｜`project`）・`SODA_PROJECT_ROOT`（`PANE_ENV_DROPPED` にも足す）。`SODA_PANE_ID` は入れない。
- 続けて落ちる（1 分に 5 回）→ 止めて、画面に知らせ。設定の読み直しか、設定画面の［起動し直す］で戻す。

### NDJSON（標準入出力）

- 行の決まりは、表示の面の `DisplayLine` と同じ（1 行 1 JSON・`type` は `<層>.<種類>`・知らない `type` と項目は無視）。
- サーバ → 拡張の最初の行: `{"type":"ext.hello","v":1,"extension":{"id","scope","projectRoot"?},"features":[…],"limits":{…}}`。
- 拡張 → サーバ: `{"id":<数か文字列>,"method":"display.set","params":{"paneId",…}}`。返事: `{"id":…,"result":…}` か `{"id":…,"error":{"code","message"}}`。知らない `method` は `error.code: "unsupported"`（D1 の「未対応」。切らない）。
  操作の名前と引数は、`/ws` の `display.*`（`paneId` つき）と同じ schema を使う。
- サーバ → 拡張の出来事: `display.action`・`display.closed`（表示の面の `DisplayEvent` そのまま）、`ext.panes`（pane の増減。id・名前・workspace・cwd・エージェントの種類）。観測・割り込みは、後の作業が `type` を足す。
- 上限（案）: 1 行 1 MiB・要求は毎秒 50・サーバが拡張へ溜める出来事 256（あふれたら古いものを捨てて `ext.dropped`）・書き込みが 30 秒詰まったら止めて起動し直す。

### 脅威と対策（案）

| 脅威 | 対策 |
|---|---|
| clone しただけで、リポジトリの拡張が動く | 承認の前は実行しない。承認は 1 件ごと・画面からだけ・既定は［承認しない］ |
| 承認の後に、登録が書き換わる（`git pull`・攻撃者の PR） | 鍵に中身を含める。変われば止めて再承認。差分を見せる |
| 承認した登録が指すスクリプトの中身だけが変わる | **防げない**（鍵に含めない案のとき）。承認の画面と docs に書く。利用者に確かめる点 1 |
| 承認の画面の表示と、動く中身が違う（検査と実行の間の差し替え） | サーバが読んだバイト列で鍵を作り、その解釈で起動する。承認の RPC は鍵の一致を確かめる |
| pane の中のプログラム（エージェント）が、自分で承認する | 承認の RPC は `pane.sock` に無く、画面の種類の接続だけ。ただし、`sodactl login` 済みの環境では、pane のプログラムは元から何でも実行できる（守る対象ではない） |
| リンク・`..` で、リポジトリの外の設定を読ませる | 根の実体のパスの下にある通常ファイルだけ。`O_NOFOLLOW` |
| 承認の画面を、コマンドの見た目でだます（長い空白・制御文字・似た文字） | 文字として全文を出す・制御文字は登録の検査で拒否・折り返して省略しない・長さの上限 4096 |
| 拡張が暴走する（大量の行・読まない・落ち続ける） | 行と頻度の上限・溜める数の上限・バックオフ・続けて落ちたら止める |
| 拡張が、ほかのリポジトリの pane に面を出す | プロジェクトの拡張は、そのリポジトリの workspace の pane だけ（利用者に確かめる点 2） |
| 拡張のプロセスが、利用者の権限で何でもする | **隔離しない**（D3 で受け入れた）。承認の画面の固定の文言・docs。利用者の設定の拡張は、利用者が自分で書いたものとして信頼する |
| handoff・停止で、子プロセスが置き去りになる | 止めて終了を待つ（ssh と同じ型）。起動確認（smoke）で見る |
| 設定の中の秘密（コマンドに書いた token）が、ログ・ほかの画面へ出る | ログには id だけ。コマンドの全文を出すのは、承認の画面（プロジェクトの分）と、設定画面の一覧（ログイン済みの画面）だけ。利用者の設定の分のコマンドは、画面へ送らない（`commands.json` と同じ） |

## D4: 骨子（D2 の案）から変えた点

1. **扱える範囲は「1 件の全項目」を鍵に入れる**（骨子は「登録の中身」。同じ意味だが、`description`・`enabled` も含むと明記した）。承認の画面に出るものは、すべて鍵に入る。
2. **面の持ち主を足した**（骨子に無い）。調べたら、台帳は持ち主を記録しておらず（research E8）、そのまま載せると、拡張に pane のプログラムの面の操作（利用者が欄に打った値）が届く。K10。
3. **`allow`（許可の宣言）にした**（骨子は「スクリプトが動く面を出す」の 1 項目）。後の層（観測・割り込み）にも、承認の画面に出すべき強い機能が出るので、一覧の形にした。利用者の設定の拡張にも、同じ宣言を求める（骨子は「利用者の設定は無条件に出せる」）。K6。
4. **返事の行にも `type` を付けた**（骨子は `{"id","result"}`）。サーバ → 拡張の行を、全部 `type` で振り分けられるようにする（表示の面の「読み手は `type` を見る」と同じ）。
5. **pane の一覧は、差分ではなく全体**（骨子は「pane の増減」）。短いスクリプトが、行を 1 つ読めば今の状態が分かる。
6. **頻度の上限は、誤りではなく「読むのを待つ」**（骨子は「毎秒 50」）。拡張の書き手が、`busy` の扱いを書かなくて済む。pane ごとの `set` の頻度（表示の面の `display_busy`）は、そのまま返る。
7. **`sodactl ext` を足した**（骨子に無い）。拡張を書くのは、多くの場合 pane の中のエージェントで、状態とログを端末から見られないと、書く → 直すが回らない。承認は載せない。K11。
8. **起動し直しの上限は 60 秒**（骨子は 120 秒。ssh と同じ値）。ssh は相手のマシンの都合で長く待つ意味があるが、手元のプログラムは、5 回で止めるので 120 秒に届かない。
9. **承認の画面の、だましへの備えを足した**: コマンドは 1024 文字まで（骨子は 4096）・コマンドだけの内側のスクロールを作らない・［承認して動かす］は 1 秒押せない・ASCII でない文字の注意・`description` は「作者の説明」の見出しの下。

## 利用者の決定待ち（K1〜K14）

**どれも、勧める案で `requirements.md`・`design.md`・`tasks.md` を書いてある。変えるなら、「差し替える箇所」を直す。**

### K1: 承認の鍵に、コマンドが指すスクリプトの中身を入れるか

- **(a) 入れない**【勧める】: 鍵は、リポジトリの根の実体のパスと、登録の 1 件の全項目。得: 単純。拡張の作者が、スクリプトを直すたびに承認し直さなくて済む。Claude Code のプロジェクトのフック・`direnv` と同じ考え方（登録が指す先までは見ない）。
  失: `git pull` でスクリプトだけが変わっても、再承認は出ない（承認した後に、攻める側の PR が入ると、黙って動く）。承認のダイアログと docs に、限界として書く。
- **(b) 登録に「見張るファイル」の一覧を書けるようにし、その中身も鍵に入れる**: 得: 作者が望めば、スクリプトの変更でも再承認が出る。失: 書くかどうかは作者しだい（悪意のある作者は書かない）。守れるのは「善意の作者のリポジトリが、後で書き換えられた」場合だけ。読むファイルの数と大きさの上限・読む時機の設計が要る。
- **(c) `.soda/` の下の全ファイルの中身を鍵に入れる**: 得: 作者の選択に依らない。失: `.soda/` の外のスクリプト・`node_modules` は見ない（結局、穴は残る）。開発中は、保存のたびに承認し直しになる。
- **差し替える箇所**: design「承認の鍵」（`approvalDigest` の入力）・脅威の表 S4・承認のダイアログの固定の文言・docs「安全と限界」。(b) は、1 件の schema に任意の項目を足すだけなので、**後から足せる**（足しても、書いていない拡張の鍵は変わらない）。

### K2: プロジェクトの拡張が扱える pane の範囲

- **(a) そのリポジトリの根で開いた workspace の pane だけ**【勧める】: 得: 承認したのは「このリポジトリの中での表示」。ほかのリポジトリの pane に、面（とくにスクリプトが動く面）を出せない。失: 同じリポジトリの別の worktree の workspace にも出せない（K7 の (a) と揃う）。
- **(b) すべての pane**: 得: 単純。失: clone したリポジトリの拡張が、別の作業の pane にパネルを出せる（承認の意味が広がる）。
- **(c) 登録に範囲を書かせ、承認の画面に出す**: 得: 柔軟。失: 項目と説明が増える。最初の版には早い。
- **差し替える箇所**: design「範囲」（`inScope` の 1 関数）・脅威の表 S9・AC24。

### K3: 承認の記録の置き場所

- **(a) 状態ディレクトリの根**（名前付き session で共有）【勧める】: 得: session ごとに承認し直さなくて済む（承認は「この利用者が、このリポジトリのこの登録を認めた」で、session に依らない）。失: 複数の session のサーバが同時に書きうる（排他が無い。「読み直してから書く」で、失われるのは、同時に押した片方だけ）。
- **(b) session ごと**: 得: 排他の心配が無い（session のロックの中）。失: session を足すたびに、同じ拡張を承認し直す（承認の疲れ → 読まずに押すようになる）。
- **差し替える箇所**: design「承認の記録」のパス（`approvalsFilePath(root)` の 1 関数）・AC19。

### K4: 別のマシン（保存した SSH のマシン）のプロジェクトの拡張を、手元のブラウザから承認できるか

- **(a) できる**【勧める】: 得: 別のマシンの pane を手元で使う人が、そのマシンへ入り直さずに承認できる。手元のサーバは中継するだけで、止める手段がもともと無い（research E3・E4）。動くのは先のマシンで、記録も先のマシンに残る。ダイアログに、マシンの名前を出す。
  失: 先のマシンのサーバが悪意を持つ場合、ダイアログの中身は信用できない（が、動くのも先のマシンの中だけ）。
- **(b) できない**（先のサーバが、中継越しの接続〔`viaBridge`〕からの承認を断る）: 得: 「承認は、そのマシンの画面で」と言い切れる。失: 先のマシンでブラウザを開く手段が無い人は、承認できない（SSH の先は、たいてい画面が無い）。
- **差し替える箇所**: design「承認できる接続」（`canApprove` の条件に `viaBridge` を足す）・AC23 に 1 行。

### K5: 拡張の寿命

- **(a) 利用者の拡張はサーバと同じ。プロジェクトの拡張は、その根の workspace が 1 つ以上ある間**【勧める】: 得: 使っていないリポジトリの拡張が、動き続けない。失: workspace を消して作り直すと、拡張の状態が消える。
- **(b) pane ごとに 1 つ起動する**: 得: 拡張が、pane 1 つのことだけ考えればよい。失: プロセスが pane の数だけ要る。pane をまたぐ表示（一覧・まとめ）が書けない。
- **(c) プロジェクトの拡張も、承認したらサーバと同じ寿命**: 得: 単純。失: workspace が無いのに、リポジトリのプログラムが動き続ける。
- **差し替える箇所**: design「寿命」（`wanted()` の 1 関数）・AC26。

### K6: プロジェクトの拡張が、スクリプトが動く面（`script-html`）を出せるか

- **(a) 登録に `allow: ["script-html"]` と書いたものだけが出せる。プロジェクトの分は、承認のダイアログに、その旨と残る限界を出す。利用者の設定の拡張にも、同じ宣言が要る**【勧める】:
  得: 承認の画面で「この拡張は、ブラウザの中でスクリプトを動かす」と分かる。書いていない拡張が、後から黙って出すことは無い（足すと鍵が変わり、再承認）。宣言を両方に求めるので、検査は 1 か所・説明は 1 文。
  失: 利用者が自分で書いた拡張にも 1 項目要る。pane の中のプログラム（`sodactl display`）は、今までどおり縛れない（縛る手段が無い。表示の面の限界 9）。
- **(b) 利用者の設定の拡張は無条件に出せる。プロジェクトだけ宣言が要る**（骨子の案）: 得: 利用者の手間が 1 つ減る。失: 検査が種類で分かれる。
- **(c) プロジェクトの拡張は、出せない**: 得: いちばん堅い。失: リポジトリと一緒に配る拡張で、グラフなどが出せない（D21 の趣旨が、プロジェクトの拡張に届かない）。
- **差し替える箇所**: design「許可」（`allows(ext, "script-html")` の 1 関数）・脅威の表 S10・AC25・ダイアログの `allow` の説明。

### K7: 承認の単位と worktree（調べて出てきた点）

- **(a) worktree の根ごと**（リポジトリの根の実体のパスが鍵に入る）【勧める】: 得: 単純で、だませない（パスだけで決まる）。「リポジトリを移したら承認し直し」（骨子の受け入れ基準）と揃う。
  失: worktree を作るたびに、同じ拡張を承認し直す。worktree を多く使う人には、手間（承認の疲れ）。
- **(b) リポジトリごと**（共通の `.git` の実体のパスが鍵に入る。worktree は承認を共有する）: 得: worktree を足しても聞かれない。
  失: 「この場所は、あのリポジトリの worktree だ」を、git を呼ばずに確かめる処理が要る（`.git` のファイルの `gitdir:` → `commondir`）。**これは偽れる**: 攻める側のフォルダの `.git` のファイルに、承認済みのリポジトリの worktree の場所を書けば、承認を引き継げてしまう。
  防ぐには、逆向きの確かめ（共通の `.git` の側の `worktrees/<名前>/gitdir` が、この場所を指しているか）が要る。確かめる処理が、安全の要になる（間違えると「開いただけで動く」）。
- **(c) (a) のまま、ダイアログに「同じリポジトリの別の worktree で承認済み」と出す**: 失: その表示のために、(b) と同じ確かめが要る（偽れる表示は、だましの道具になる）。
- **差し替える箇所**: design「承認の鍵」の `root` を、共通の `.git` の実体のパスに替え、`resolveProjectRoot` に逆向きの確かめを足す。K2 の範囲も「同じリポジトリの workspace」に替えるかを、合わせて決める。

### K8: サーバが異常終了したときに残る拡張（調べて出てきた点）

- **(a) 標準入力が閉じたら終わること、を拡張の決まりにする**【勧める】: 得: 追加の仕組みが無い（ssh と同じ。research E6）。見本は、そうなっている。失: 決まりを守らない拡張は、サーバが SIGKILL・クラッシュ・2 回目の Ctrl+C で終わったとき、残る（次の起動で、もう 1 つ動く）。docs に書く。
- **(b) 起動した拡張の pid を記録し、次の起動で、残っていれば止める**: 得: 残らない。失: pid は使い回されるので、別のプロセスを止める危険がある。確かめ（起動の時刻・環境変数の印）は OS ごとに違い、macOS では取れないものがある。
- **差し替える箇所**: design「異常終了」・脅威の表 S13・docs「安全と限界」。(b) は、後から足せる。

### K9: 拡張が止まったら、その拡張が出した面を消すか（調べて出てきた点）

- **(a) 消す**【勧める】: 得: 押しても何も起きないボタンが残らない。面の持ち主がいない状態が無い。失: 拡張が落ちて起動し直すと、パネルが消えて、また出る（端末の幅が 2 回変わる）。
- **(b) 残す**（起動し直した拡張が、同じ名前で出し直すまで）: 得: ちらつかない。失: 起動し直さなかった拡張（続けて落ちた・無効にした）の面を、いつ消すかの決まりが要る。前のプロセスの面を、次のプロセスに引き継ぐ決まりも要る。
- **差し替える箇所**: design「面の持ち主」の「プロセスが終わったとき」・AC10。

### K10: 拡張と、pane のプログラムの面の関係（調べて出てきた点）

- **(a) 拡張は、自分が出した面だけを扱える。pane の側（`sodactl display`・利用者）は、今までどおり、その pane のどの面も閉じられる・同じ名前で出し直せる**【勧める】:
  得: 拡張に、pane のプログラムの面の操作（欄の値）が届かない。画面が固まったときの「別の端末から `sodactl display close --all`」が、拡張の面にも効く。表示の面の既存の動きは変わらない。
  失: pane のプログラムが、拡張の面と同じ名前で出すと、拡張の面が置き換わる（拡張には「閉じた」が届く）。名前の衝突は、作者どうしで避ける（docs に、名前に拡張の id を入れるよう書く）。
- **(b) 名前を、持ち主ごとに分ける**（同じ名前でも別の面）: 得: 衝突しない。失: 表示の面の台帳の鍵（pane と名前）と、`sodactl display close <名前>` の意味が変わる（表示の面の作業への変更が大きい）。
- **(c) 持ち主を分けない**（拡張は、その pane の全部の面を扱える）: 得: 台帳を変えない。失: 上の「欄の値が届く」。プロジェクトの拡張が、エージェントの出したパネルを閉じて、似せたものを出せる。
- **差し替える箇所**: design「面の持ち主」・脅威の表 S11・AC9。

### K11: `sodactl ext` と、承認（調べて出てきた点）

- **(a) `sodactl ext list|log|reload|restart` を入れる。承認・取り消し・有効と無効は、画面だけ**【勧める】: 得: 拡張を書く人（エージェント）が、端末から状態とログを見られる。承認は、人が画面で中身を見て行う。
  失: `sodactl` にサブコマンドが 1 つ増える。`/ws` の接続の種類は自己申告なので、ログイン済みのプログラムは、画面を名乗れば承認の方式を呼べる（**境界ではない**。ログイン済みの接続は、もともと pane に何でも打てる）。
- **(b) `sodactl ext` を入れない**: 得: 差分が小さい。失: 状態とログは、設定画面でしか見られない。
- **(c) `sodactl ext approve` も入れる**: 得: 画面の無い環境（別のマシン）で承認できる。失: pane の中のエージェントが、文面どおりのコマンドで自分で承認できる（承認が、人の確認でなくなる）。
- **差し替える箇所**: tasks の PR1 の `sodactl ext` のタスク（外すだけ）・AC16。

### K12: コマンドの形（調べて出てきた点）

- **(a) シェルに渡す 1 行**（`/bin/sh -c`）【勧める】: 得: `commands.json` と同じ。`node .soda/panel.js`・環境変数・パイプが、そのまま書ける。承認の画面には、その 1 行がそのまま出る。失: 承認する人は、シェルの文法（`;`・`$( )`・`&&`）を読める必要がある。
- **(b) 引数の配列**（シェルを通さない）: 得: 何が実行されるかが、文法に依らない。失: `commands.json` と書き方が違う。`~`・環境変数の展開が無い。Windows で `.cmd` を起動できない。
- **差し替える箇所**: 1 件の schema（`command` を `string | string[]` に）・`extensionArgv`・ダイアログの表示。後から (b) を**足す**ことは出来る。

### K13: 端末版（引数なしの `soda`）（調べて出てきた点）

- **(a) 対象外**（一覧・承認・知らせのどれも出さない。`docs/tui-parity.md` に行を足す）【勧める】: 得: 差分が小さい。端末版は面を出せない（D8 の後の作業）ので、拡張を動かしても見えるものが無い。失: 端末版だけを使う人は、プロジェクトの拡張を承認できない（利用者の設定の拡張は、動く）。
- **(b) 知らせだけ出す**（「承認待ちの拡張があります。ブラウザ版の設定で確認してください」）: 得: 気づける。失: 端末版に、通信の係と文言が要る。
- **差し替える箇所**: 端末版のパネルの作業（D8）に合わせて足す。

### K14: 画面の入切（無効と有効）の保存先（調べて出てきた点）

- **(a) サーバが持つファイル**（session ごとの `extension-state.json`。設定ファイルは書き換えない）【勧める】: 得: 利用者の手書きのファイルを、サーバが書き換えない（`commands.json` と同じ流儀）。プロジェクトの設定（git の管理下）も汚さない。失: 「設定ファイルでは有効なのに、動かない」ことがある（一覧に「画面で無効にした」と出す）。
- **(b) 設定ファイルの `enabled` を書き換える**: 得: 真実が 1 か所。失: 手書きの JSON の体裁・コメントの扱い。プロジェクトの設定は、書き換えると鍵が変わる。
- **(c) 画面の入切を作らない**（設定ファイルの `enabled` と読み直しだけ）: 得: 小さい。失: 暴れる拡張を、画面からすぐ止められない。
- **差し替える箇所**: design「無効と有効」・AC4。

## 背景 / 課題

表示の面（`sodactl display`。`20261007-soda-extensions`）は、pane の中のプログラムが自分で呼ぶ形でしか使えない。「エージェントを問わない拡張」（D1）にするには、pane の中のエージェントとは別に、
**Sodashitsu が起動して動かし続けるプログラム**（拡張）が要る（D3: 別プロセス・NDJSON）。拡張は、リポジトリと一緒に配りたい（D7: プロジェクトの設定も読む）が、
clone しただけで他人のプログラムが自分の権限で動いてはならない（D7: 承認つき）。

## 目的 / ゴール

- 利用者が設定ファイルに登録した拡張が、サーバの起動・停止・入れ替え（`soda handoff`）に合わせて動き続け、標準入出力の 1 行 1 JSON で、表示の面を出し・操作を受け取れる状態。
- リポジトリの中の設定に書かれた拡張は、**利用者がその中身を見て承認するまで 1 度も実行されず**、登録の中身が変わったら承認し直すまで動かない状態。
- 拡張が落ちても・応答しなくても・暴走しても、pane とほかの画面とほかの拡張は止まらず、利用者は、何が起きたかを画面で知って、止める・起動し直すが出来る状態。
- 後の作業（観測・割り込み）が、同じ口にメッセージの種類を足すだけで載る状態。

紐づく charter ゴール: `.aidev/charter.md` は無い（この PJ には charter を置いていない）。

## ユーザーストーリー

- US1: 利用者として、自分の設定ファイルに拡張を 1 件登録すれば、サーバを起動するたびに動いてほしい。なぜなら、毎回手で起動したくないから。（受け入れ: AC1, AC2, AC3, AC4）
- US2: リポジトリの作者として、リポジトリの中の設定に拡張を書いて、チームに配りたい。なぜなら、各自に設定させずに同じパネルを出せるから。（受け入れ: AC17, AC19, AC26）
- US3: 利用者として、clone したリポジトリの拡張が、自分が承認するまで動かないと確かでいたい。承認のときに、何が動くかを見たい。なぜなら、拡張は自分の権限で動き、隔離されないから。（受け入れ: AC18, AC20, AC22, AC23, AC29, AC-I1〜AC-I5）
- US4: 利用者として、承認した後に拡張の登録が書き換えられたら（`git pull` など）、動く前に気づきたい。なぜなら、承認したものと違うプログラムを動かしたくないから。（受け入れ: AC20, AC21）
- US5: 拡張の作者として、Sodashitsu と 1 行 1 JSON でやり取りし、表示の面の操作を `sodactl display` と同じ名前・同じ引数で使いたい。なぜなら、`sodactl` を何度も起動せずに済み、後で観測・割り込みの種類が足されても同じ口で受けられるから。（受け入れ: AC5, AC6, AC7, AC8, AC9, AC32）
- US6: 利用者として、拡張が落ちた・暴走したとき、pane は動き続け、何が起きたかを画面で知りたい。なぜなら、拡張の不具合で作業を止めたくないから。（受け入れ: AC11, AC12, AC13, AC15, AC27, AC30）
- US7: 拡張を書いている人（エージェントを含む）として、拡張の状態と標準エラーの出力を、端末から確かめたい。なぜなら、画面を開かずに、書く → 動かす → 直すを回したいから。（受け入れ: AC16, AC33）
- US8: 利用者として、プロジェクトの拡張が、ほかのリポジトリの pane に面を出したり、黙ってスクリプトの動く面を出したりしないでほしい。なぜなら、承認したのは、そのリポジトリの中での表示だけだから。（受け入れ: AC24, AC25, AC31）

## 機能要件

### 登録

1. **利用者の設定**: `<状態ディレクトリ>/extensions.json`（名前付き session では session ごと。`commands.json` と同じ場所）。形は `{ "extensions": [ <1 件>, … ] }`。
   1 件は `id`（`commands.json` の id と同じ規則）・`command`（シェルに渡す 1 行。【決定待ち K12】）・`description?`・`enabled?`（既定は有効）・`allow?`（下の 13）・`onUnresponsive?`（`"pass"`｜`"block"`。既定 `"pass"`。D6）・`cwd?`（絶対パス。利用者の設定だけ）。
   **拡張を指すのは、id だけではなく「種類（利用者／プロジェクト）＋プロジェクトの根＋id」の組**（以下「拡張の指定」。「鍵」は、承認のハッシュだけを指す）。id は、1 つのファイルの中でだけ重複しない。利用者の設定とプロジェクトの設定・2 つのリポジトリで、同じ id を書ける（別の拡張として扱う）。
   入切の記憶・標準エラーの記録・面の持ち主は、拡張の指定ごと（承認の記録は、(根, id) ごと）。一覧とダイアログは、id と一緒に、種類と、プロジェクトなら根を出す。出どころのラベルは、id と種類。`sodactl ext` は、id か、一覧に出る `key`（拡張の指定を 1 つの文字列にしたもの）で指し、id が 1 つに決まらないときは、誤りにして候補の `key` を並べる。
   `command` は 1024 文字まで・`description` は 200 文字まで。どちらも、制御文字（改行を含む）・書字方向を変える文字・幅の無い文字を含められない（承認の画面で、見た目と中身をずらせないように）。
   読み方と検査は `commands.json` と同じ（リンクでない通常ファイル・持ち主が自分・ほかの利用者が書けない・大きさの上限・知らない項目は誤り・**1 つでも規則の外なら、ファイル全体を採らない**）。誤りの理由に、コマンドの文字列を入れない。
2. **プロジェクトの設定**: `<リポジトリの根>/.soda/extensions.json`。リポジトリの根は、workspace を開いた場所から上へ `.git` を探して決める（worktree は、worktree ごとの根）。git のコマンドは呼ばない。
   形は利用者の設定と同じだが、`cwd` は書けない（作業ディレクトリは、いつもリポジトリの根）。検査は、リンクでない通常ファイルであること・**根の実体のパスの下にあること**（`.soda` がリンクなら読まない）・大きさ・形。
   持ち主と権限は、**根・`.soda`・設定ファイルの 3 つについて**、持ち主が自分であること・だれでも書ける（other の書き込み）でないことを確かめ、だめなら読まない（共有の場所に、ほかの利用者が置いた設定を、承認の対象にしない）。グループが書けるときは、読むが、一覧と承認のダイアログに注意を出す（clone したファイルは、グループが書けることが多い）。
   git の中に無い場所で開いた workspace には、プロジェクトの設定は無い。
3. **読む時機**: サーバの起動・workspace が出来た／消えた・読み直しの操作（設定画面の［読み直す］・既存のキーの操作「設定を読み直す」・`sodactl ext reload`）・拡張を起動する直前（プロジェクトの分。下の 8）。ファイルの見張りはしない。
4. **読み直しの結果**: 足した拡張は動く（プロジェクトの分は承認待ちになる）・消した拡張は止まる・登録の中身が変わった拡張は止まって、新しい中身で動く（プロジェクトの分は承認待ちへ戻る）・変わっていない拡張は、動いたまま（プロセスは同じ）。
5. **無効と有効**: 設定の `enabled: false` か、設定画面の入切で、拡張を止めておける。画面の入切は、サーバが、名前付き session ごとに覚える（再起動しても同じ。設定ファイルは書き換えない）。【決定待ち K14】
   設定の `enabled: false` と、画面の入切は、**どちらか一方でも無効なら、動かない**（画面の入切は、設定の `enabled: false` を有効には出来ない）。
   **無効は、ほかの状態より先に決まる**: 無効の拡張は、状態が「無効」で、承認待ちの知らせの件数に入らず、承認のダイアログも出ない（承認できない）。有効にしたときに、承認の記録と鍵が合えば動き、合わなければ承認待ちになる
   （設定の `enabled` は鍵に入るので、`false` を `true` に書き換えた登録は、前に承認した中身と同じでない限り、承認待ち。画面の入切は鍵に入らないので、切って入れ直しても、承認は保たれる）。

### 承認（プロジェクトの設定の分）

6. **承認するまで動かさない**: 承認の記録が無い拡張は、起動しない。存在の確かめのための実行もしない。サーバがするのは、設定を読むことと、ハッシュを計算することだけ。
7. **承認の鍵**: 「リポジトリの根の実体のパス」と「その拡張の登録の 1 件の全項目」から作るハッシュ。1 件ごと（ほかの拡張の承認には響かない）。【決定待ち K1・K7】
   - 登録を 1 文字でも変える・リポジトリを別の場所へ移す・別の worktree で開く、のどれでも、承認していない扱いになる。**承認した中身へ、そのまま戻せば、承認は生きている**（承認したのは、その中身。記録は、次に別の中身を決めるまで残る）。
   - 承認の記録は、(根, id) ごとに 1 件で、鍵と一緒に、**そのとき決めた登録の中身**を持つ（次に変わったときに、前と後を見せるため）。別の場所・別の worktree は、別の (根, id) なので、「前」は無い。
   - コマンドが指すスクリプトのファイルの中身は、鍵に入らない（`git pull` でスクリプトだけが変わっても、再承認は求められない）。この限界を、承認のダイアログと docs に書く。
8. **起動の直前に確かめ直す**: 拡張を起動する・起動し直すたびに、設定を読み直して鍵を計算し、承認の記録と合うときだけ起動する。合わなければ、起動せずに承認待ちへ戻す。起動に使うのは、**そのとき読んで解釈した中身**（鍵を計算したバイト列と、起動するコマンドは同じもの）。
9. **承認待ちの知らせ**: 承認待ちの拡張があると、画面に、消えないトースト（件数と［確認する］。1 つだけ）を出す。フォーカスは奪わない。ダイアログは、利用者が［確認する］か設定画面の［確認］を押したときだけ開く（勝手に開かない）。
10. **承認のダイアログ**（1 件ずつ。「すべて承認」は無い）に出すもの:
    - 別のマシンのときは、そのマシンの名前。リポジトリの根の実体のパス。設定ファイルのパス。拡張の id。
    - **実行されるコマンドの全文**（文字として。HTML として解釈しない。折り返して、省略しない。ダイアログの中に、コマンドだけをスクロールさせる箱は作らない）。作業ディレクトリ。
    - 固定の文言: 「このプログラムは、あなたの OS の利用者の権限で動き、隔離されません」「コマンドが指すファイルの中身が後で変わっても、確認は出ません」。
    - **登録の、残りの項目を、いつも全部**（鍵に入るものは、初回から見せる）: 求めている許可（`allow`。無ければ「なし」）と、その意味の固定の説明（`script-html` なら、スクリプトが動く面の残る限界）・応答しないときの扱い（`onUnresponsive`。`pass`／`block`）。`enabled` は、ダイアログが出る登録では、いつも `true`（無効の登録には、ダイアログが出ない）。
    - 設定ファイルを、グループが書けるときは、その旨。
    - 作者の説明（`description`）は、「作者が書いた説明」と分かる見出しの下に、文字として。
    - 前に承認した中身があるときは、変わった項目の前と後。
    - コマンドに ASCII でない文字があるときは、その旨。
    - ボタンは［承認しない］（既定のフォーカス）・［承認して動かす］・［後で］。［承認して動かす］は、開いてから・**中身が替わってから**（次の 1 件へ替わった・開いている間に登録が変わって取り直した）1 秒は押せない。
11. **承認・承認しない・取り消し**: ［承認して動かす］で記録して起動する。［承認しない］も記録し、同じ鍵のあいだは、知らせを出さない（設定画面から、後で承認し直せる）。承認済みの拡張は、設定画面の［承認を取り消す］で止まり、承認待ちへ戻る。
    承認の記録は、サーバを再起動しても残る。置き場所は、状態ディレクトリの根（名前付き session で共有）。【決定待ち K3】
12. **承認できる接続**: ログイン済みの `/ws` の接続のうち、画面（ブラウザ）の種類のものだけ。ログイン不要の受け口（`pane.sock`）と、`sodactl` には、承認・取り消し・有効と無効の操作を載せない。
    承認の要求は、**サーバがいま持っている鍵と一致するときだけ**受ける（画面が見せた中身と、動かす中身が違えば断る）。別のマシン（保存した SSH のマシン）のプロジェクトの拡張は、手元のブラウザから承認できる（動くのは先のマシン）。【決定待ち K4】

### 許可と範囲

13. **許可（`allow`）**: 拡張が使う、強い機能の宣言。この作業で意味を持つ値は `"script-html"`（スクリプトが動く面を出す）だけ。書いていない拡張が `script-html` の面を出そうとすると「未対応」で返る。
    利用者の設定の拡張にも、同じ宣言が要る（承認は要らない）。プロジェクトの拡張では、登録の一部なので鍵に入り、承認のダイアログに出る。知らない値を書いた登録は、誤り（ファイル全体を採らない）。【決定待ち K6】
14. **扱える pane の範囲**: 利用者の設定の拡張は、すべての pane。プロジェクトの拡張は、**そのリポジトリの根で開いた workspace の pane だけ**（ほかの pane は、無い pane と同じ答えになる。一覧にも出ない）。【決定待ち K2】
    pane が別の workspace へ移って範囲の外へ出たら、その pane に出していた面は消え、拡張へ「閉じた」（理由は「範囲の外へ出た」）が届く。
15. **面の持ち主**: 拡張は、**自分が出した面だけ**を、一覧・更新・閉じる・データの送信の対象にできる。操作と「閉じた」の出来事は、その面を出した拡張にだけ届く（pane のプログラムが出した面の出来事は、拡張に届かない。逆も同じ）。
    pane の側（`sodactl display`・利用者の［×］）は、今までどおり、その pane のどの面も閉じられる・同じ名前で出し直せる（拡張には「閉じた」が届く）。
    pane の側から見えるのは、拡張の面の見出し（名前・種類・題・大きさ）だけで、中身と、その面への操作（利用者が欄に打った値）は、読めない。pane の側から、拡張の面のスクリプトへ、データは送れない（`display.send` は、面が無いのと同じ誤り）。
    逆に、拡張が、ほかの持ち主の面（pane のプログラム・別の拡張）と同じ名前で出そうとすると、誤り（「その名前は使われています」）が返り、面は変わらない（名前が使われていること自体は、分かってよい）。【決定待ち K10】
16. **出どころの表示**: 拡張が出したパネル・帯の、アプリが描く固定のラベルに、拡張の id と種類（利用者・プロジェクト）を出す（中身・題からは変えられない）。

### プロセス

17. **寿命**: 利用者の設定の拡張は、サーバと同じ（サーバの起動で動き、停止で止まる）。プロジェクトの拡張は、**そのリポジトリの根の workspace が 1 つ以上ある間だけ**動く（最後の 1 つが消えたら止まる）。【決定待ち K5】
    起動は、状態ディレクトリのロックを取った後（二重起動で 2 つ動かさない）。
18. **渡すもの**: 作業ディレクトリ（プロジェクトはリポジトリの根、利用者は `cwd` か、無ければホーム）。環境変数は、pane と同じ規則（サーバの秘密・pane ごとの値を落とす）に、拡張の id・種類・プロジェクトの根を足したもの。
    **token・cookie・`SODA_PANE_ID`・受け口のパスは渡さない。**
19. **止め方**: 標準入力を閉じる → 終了の合図 → 猶予（2 秒）→ 強制終了。**拡張が起動した孫プロセスも一緒に止める**。終わるまで待つ。
20. **落ちたとき**: 間隔をあけて（1 秒から倍々、上限 60 秒）起動し直す。60 秒以上動いた後に落ちたら、回数は 1 から数え直す。下の 30 で止めた回（壊れた行・読まない）も、落ちた回として数える。続けて 5 回落ちたら、止めて、画面に知らせる（設定画面の［起動し直す］・読み直し・`sodactl ext restart` で戻せる）。終了コード 0 で終わった拡張は、起動し直さない（自分で終わった）。
21. **止まったら、面も消える**: 拡張のプロセスが終わったら（どの理由でも）、その拡張が出した面を消す。起動し直した拡張は、自分で出し直す。【決定待ち K9】
22. **標準エラー**: 行ごとに、拡張ごとの記録（新しい 200 行まで。1 行は 4 KiB で切る）に残し、設定画面と `sodactl ext log` で見られる。サーバのログには、中身を書かない（拡張の id・行数だけ）。
23. **サーバの入れ替えと停止**: `soda handoff` の前に、拡張をすべて止めて終了を待つ。新しい版が起動し直す。入れ替えに失敗して元のサーバが続くときは、元のサーバが起動し直す。サーバの停止では、止めて終了を待つ。
    サーバが異常終了したときは、拡張の標準入力が閉じる。**拡張は、標準入力が閉じたら終わること**を、拡張を書く人への決まりにする（見本はそうなっている）。【決定待ち K8】

### やり取り（標準入出力の NDJSON）

24. **行の決まり**: 1 行 1 つの JSON（UTF-8・改行は `\n`）。サーバ → 拡張の行は、`type`（`<層>.<種類>`）で種類を表す。読み手は、知らない `type` の行・知らない項目を無視する（表示の面の `sodactl display events` の行と同じ決まり）。
    拡張 → サーバの行は、要求 `{"id"?, "method", "params"?}`。`id` を付けた要求には、返事の行が 1 つ返る。`id` を省いた要求には、返事を書かない（返事を読まない短いスクリプトのため）。
25. **挨拶**: 起動した拡張へ、サーバが最初に 1 行（`ext.hello`）を書く。決まりの版・拡張の id と種類とプロジェクトの根・`allow`・`onUnresponsive`・**呼べる操作の名前の一覧・届く出来事の種類の一覧・表示の面の機能と上限**・やり取りの上限。拡張は、返事をしなくてよい。
26. **機能の問い合わせ**: 挨拶の一覧で、使える操作が分かる。`ext.features` で、いまの値（面を出せる画面の数を含む）を取り直せる。**知らない操作・使えない操作を呼ぶと、切れずに「未対応」の返事**が返る（D1）。
27. **表示の層の操作**: `display.set`・`display.close`・`display.list`・`display.features`・`display.send`（表示の面の PR3 が入っているとき）を、`/ws` と同じ名前・同じ引数（`paneId` つき）で呼べる。結果も同じ形。
    上限・頻度・面の数は、pane の中の `sodactl display` と同じ台帳で数える（同じ pane に、拡張と pane のプログラムが出した面は、合わせて数える）。待つ操作（`display.wait`）は、行で届くので「未対応」。
28. **出来事**: 自分の面への操作（`display.action`）と、閉じたこと（`display.closed`。利用者が閉じた・時間切れ・アプリが止めた・pane のプログラムが閉じた／出し直した・pane が閉じた・範囲の外へ出た）が、行で届く。形は、`sodactl display events` の行と同じ（待ちの印 `seq` は付かない）。
29. **pane の一覧**: `ext.panes` の操作で、扱える pane の一覧（id・名前・workspace の id と名前・workspace を開いた場所・エージェントの種類）を取れる。挨拶の直後と、**一覧の中身が前と変わったとき**（pane・workspace の増減・移動・名前の変更）に、同じ中身の行（`ext.panes`）が届く。
    エージェントの種類は、一覧を作ったときの値で、種類が変わったことだけでは、行は届かない。pane の作業ディレクトリ・端末の題・エージェントの状態は、載せない（観測の層）。
30. **上限と、壊れた入力**: 拡張 → サーバの 1 行は 4 MiB まで。要求の頻度（毎秒 50 行・続けて 100 行）と量（毎秒 4 MiB・続けて 16 MiB）が上限を超えたら、サーバは読むのを待つ（要求は捨てない・誤りにしない）。JSON でない行・形の合わない行・長すぎる行は、その行だけを捨てて、誤りの行（`ext.error`）を返す。続けて 20 行で、拡張を止める（落ちたのと同じ扱い）。
    サーバ → 拡張は、溜められる行と量に上限（512 行・8 MiB）があり、あふれたら、出来事を古いものから捨てて、捨てた数の行（`ext.dropped`）を足す。返事は捨てない。拡張が読まないまま 30 秒詰まったら、止める（落ちたのと同じ扱い）。
31. **数の上限**: 利用者の設定 16 件・プロジェクトごとに 16 件（超えるファイルは、全体を採らない）・設定を読むプロジェクトの根 32・同時に動かす合計 32・1 つの拡張が出せる面 16（超える `display.set` は誤り）・承認の記録 256 件（超えたら、決めた時刻の古いものから捨てる）。
    プロジェクトの根が 32 を超えたら、辞書順で先頭の 32 だけを読み、残りは読まずに、設定の誤りの欄に 1 行出す（その根の拡張は、一覧に出ない）。
    同時に動かす合計: **既に動いている拡張は、止めない**。新しく起動するものを、利用者の設定の拡張（ファイルの順）→ プロジェクトの拡張（根の辞書順・ファイルの順）の順に、合計が 32 になるまで起動し、残りは「上限のため動かしていない」と一覧に出す。空きが出来たら、次に設定を読むとき（機能要件 3 の時機）に、同じ順で起動する。
    承認の記録が、256 件の超過で捨てられた拡張は、次に設定を読むとき・起動し直すときに、承認待ちへ戻る（動いていれば、止まる）。
    **面の枠は、pane ごとに、拡張と pane のプログラムで共有する**（機能要件 27）。拡張が、pane のパネル 4・帯 2 を使い切ると、その pane の `sodactl display` は、上限の誤りになる（pane の入出力は止まらない。利用者は、拡張を無効にする・面を閉じるで戻せる）。上限の誤りから、ほかの持ち主の面の数が分かることは、許す。docs の限界に書く。

### 画面と `sodactl`

32. **設定画面の節「拡張」**: 一覧（id・種類・プロジェクトの根・作者の説明・許可・応答しないときの扱い・状態）。状態は「動作中／起動し直しを待っている／続けて落ちたので止めた／自分で終了した／無効／承認待ち／承認しない／上限のため動かしていない」。
    行ごとに、入切・［起動し直す］・［ログ］・（プロジェクトの分）［確認］［承認を取り消す］。設定ファイルの誤りは、ファイルごとに 1 行。節の頭に［読み直す］と、置き場所の案内。**利用者の設定の拡張のコマンドは、画面へ送らない**（`commands.json` と同じ。プロジェクトの分は、承認のために送る）。
33. **知らせ**: 承認待ち（上の 9 の、消えないトースト）と、拡張が続けて落ちて止まったこと（ふつうのトースト）を出す（フォーカスは奪わない）。
34. **`sodactl ext`**: `list`（一覧と状態）・`log <id|key>`（標準エラーの記録）・`reload`・`restart <id|key>`。ログイン済みの `/ws` の経路だけ。古いサーバには、エラーではなく「未対応」を出して終了コード 0。

## 非機能要件 / 制約

- **安全**（脅威と対策の表は design）:
  - 承認していないプロジェクトの拡張は、どの経路でも実行されない（workspace を開く・サーバの再起動・読み直し・入れ替え・落ちた後の起動し直し）。
  - 承認の画面に出た中身と、動く中身が一致する（鍵の一致・起動の直前の確かめ直し）。
  - 承認の操作は、`pane.sock` に無い。`/ws` の接続の種類の検査は、誤用を防ぐもので、権限の境界ではない（ログイン済みの接続は、もともと pane に何でも打てる）。これを docs に書く。
  - 拡張に、token・cookie を渡さない。ログに、コマンドの文字列・標準エラーの中身・面の中身を書かない。
  - 拡張のプロセスは隔離しない（D3）。承認した拡張は、利用者の権限で何でも出来る——承認の記録を書き換える・`sodactl login` 済みなら pane に打つ、を含む。これを、承認のダイアログの固定の文言と docs に書く。
- **pane を生かし続ける**: 拡張の終了・例外・壊れた行・読まない・書かない・大量の出力で、サーバ・pane の入出力・ほかの画面・ほかの拡張が止まらない。拡張の処理は、サーバの起動（`listen`）と停止を、決まった時間（止めるときの猶予）より長く待たせない。
- **子プロセスを置き去りにしない**: サーバの停止・`soda handoff`・無効・取り消し・読み直しで止めた拡張は、孫プロセスを含めて終わっている。
- **メッセージの型は 1 か所**（`packages/protocol`）。表示の層の操作の引数の検査は、表示の面と同じ関数を使う。後の作業は、`type` と操作の名前を足すだけで載る（決まりの版は上げない）。
- **古い版との組み合わせ**: 古いサーバに `sodactl ext` → 「未対応」。古い画面（読み込み直していない）→ 節「拡張」が無いだけで、ほかは壊れない。新しい画面で古いサーバ（別のマシン）→ 節に「このサーバは拡張に対応していません」。
- **Windows（ネイティブ）**: コマンドは `%ComSpec% /d /s /c` で起動し、止めるときは、標準入力を閉じて猶予の後、プロセスの木ごと強制終了する。設定ファイルの持ち主・権限は見ない。実機では確かめない（単体テストだけ）。
- 設定の項目の id は、設定に書いた名前（独自コマンドと同じ。実体ではないので UUID にしない）。プロセス 1 回ぶんの起動には、UUID を振る（ログと挨拶に出す）。
- 表示の面の作業（`20261007-soda-extensions`）の、既存の操作・上限・枠の守りは変えない。足すのは、面の持ち主の記録と、出来事を受け取る口と、出どころの表示だけ。

## 完了条件 (受け入れ基準)

ストーリーに紐づかない基準（非機能・上限・負の対照・Windows）: AC10・AC14・AC28・AC34・AC35・AC36。

登録（利用者の設定）とプロセス

- [ ] AC1: 利用者の設定に登録した拡張が、サーバの起動で動き、最初の行として挨拶（`ext.hello`）を受け取る。環境変数に拡張の id・種類があり、token・cookie・`SODA_PANE_ID`・受け口のパスが無い。作業ディレクトリは `cwd`（無ければホーム）。同じ状態ディレクトリで 2 つ目に起動したサーバ（ロックを取れずに終わる）は、拡張を 1 つも起動しない。
- [ ] AC2: 利用者の設定が規則の外（知らない項目・id の重複・知らない `allow` の値・制御文字を含むコマンド・ほかの利用者が書けるファイル・リンク・大きすぎる）のとき、そのファイルの拡張は 1 つも動かず、一覧に理由が出る。理由に、コマンドの文字列は入らない。
- [ ] AC3: 読み直しで、足した拡張が動き、消した拡張が止まり、変えた拡張が新しい中身で動き直し、変えていない拡張は同じプロセスのまま動いている。
- [ ] AC4: 設定の `enabled: false` と、画面の入切のどちらでも、拡張は動かない。画面の入切は、サーバを再起動しても保たれる。［起動し直す］で、プロセスが替わる。
- [ ] AC10: 拡張のプロセスが終わると（落ちた・止めた・無効にした）、その拡張が出した面が、すべて消える。pane のプログラムが出した面は残る。
- [ ] AC11: （PR1 では、状態が変わるところまで。画面の知らせは AC30）拡張が落ちると、間隔をあけて（1 秒・2 秒・4 秒・8 秒）起動し直される。60 秒以上動いた後に落ちると、間隔は 1 秒へ戻る。続けて 5 回落ちると、止まって、状態が「続けて落ちたので止めた」になり、画面に知らせが出る。終了コード 0 で終わった拡張は、起動し直されない。その間、pane の入出力は止まらない。
- [ ] AC12: 拡張が、JSON でない行・長すぎる行（4 MiB 超）・形の合わない行を書いても、サーバは動き続け、その行だけが捨てられて誤りの行が返る。続けて 20 行で、拡張は止められる。拡張が標準入力を読まないとき、サーバは、溜める量の上限（512 行・8 MiB）で、出来事を古いものから捨て（読み始めたら、捨てた数の行 `ext.dropped` が届く。返事は捨てられない）、30 秒詰まったら拡張を止める。上限（続けて 100 行）を超える頻度の要求は、捨てられずに、遅れて、全部が処理される。
- [ ] AC13: 止めるとき、拡張と、拡張が起動した孫プロセスが、猶予（2 秒）のうちに終わらなければ強制終了され、止める処理は、終わりを待ってから返る。サーバを閉じた後、拡張のプロセスは残っていない。
- [ ] AC14: `soda handoff` の後、拡張は新しいプロセスで動いていて、前のプロセスは残っていない。`soda session stop` の後、拡張のプロセスは残っていない（ビルドした成果物での起動確認）。入れ替えに失敗して元のサーバが続くとき、拡張は起動し直され、二重には動かない（止めていない状態で再開を呼んでも、同じ）。
- [ ] AC15: 拡張の標準エラーの出力が、拡張ごとの記録に残り（新しい 200 行・1 行 4 KiB で切る）、設定画面の［ログ］と `sodactl ext log` が使う操作で読める。サーバのログ（`server.log`）に、標準エラーの中身とコマンドの文字列が出ない。
- [ ] AC16: `sodactl ext list`・`log`・`reload`・`restart` が、ログイン済みの経路で動き、古いサーバには「未対応」（終了コード 0）を出す。同じ id の拡張が 2 つあるとき、id での指定は誤り（候補の `key` が出る）になり、`key` での指定は通る。`sodactl ext` に、承認・取り消し・有効と無効のサブコマンドは無い。

やり取り

- [ ] AC5: 拡張が `display.set`（`paneId` つき）を呼ぶと、その pane に面が出る（台帳に載り、`sodactl display list` にも見える）。結果は、`/ws` の `display.set` と同じ形。その面への操作と「閉じた」が、拡張に行で届く。面の数と `set` の頻度は、その pane の `sodactl display` の分と合わせて数えられる（合わせて上限を超えると、誤り）。
- [ ] AC6: 拡張は、扱える pane の一覧を、挨拶の直後の行と `ext.panes` の操作で得る。pane・workspace が増えた／減った／pane が別の workspace へ移ったとき、新しい一覧の行が届く。
- [ ] AC7: 知らない操作・`display.wait` を呼ぶと、返事は「未対応」（`unsupported`）で、拡張は切られない。`id` の無い要求には、返事の行が書かれない。サーバからの知らない `type` の行を無視する拡張（見本）が、動き続ける。
- [ ] AC8: 挨拶に、呼べる操作の一覧・届く出来事の一覧・表示の面の機能と上限・やり取りの上限・応答しないときの扱い（`onUnresponsive`）がある。`ext.features` が、いま面を出せる画面の数を返す。
- [ ] AC9: 拡張は、pane のプログラム（`sodactl display`）が出した面を、一覧に見ず・閉じられず・上書きできず・データを送れない。pane のプログラムが出した面への操作は、拡張に届かない。拡張が出した面への操作は、pane のプログラムの `sodactl display events` に届かない。別の拡張が出した面についても同じ。拡張が、ほかの持ち主の面と同じ名前で出そうとすると、誤りが返って面は変わらない。pane のプログラムが、拡張の面を閉じる・同じ名前で出し直すと、拡張に「閉じた」が届く。pane のプログラムは、拡張の面へデータを送れない（表示の面の PR3 が入ってから確かめる）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 承認のダイアログは、知らせの［確認する］か、設定画面の行の［確認］で開く（サーバの出来事では、勝手に開かない）。閉じるのは、3 つのボタンか `Esc`（＝［後で］。承認待ちのまま）。背景を押しても閉じない。承認待ちが複数あれば、1 件を決めた後、次の 1 件に替わる（替わった直後も、［承認して動かす］は 1 秒押せない）。
  ログは、行の［ログ］で、その行の下に開き、もう一度押すと閉じる。
- [ ] AC-I2 確定 / 取り消し: ［承認して動かす］で確定（すぐ起動する）。［承認しない］で、記録して閉じる。どちらも、設定画面から後で変えられる（取り消し・承認し直し）。`Esc`・［後で］は、何も記録しない。
  開いている間に、サーバの側で登録が変わったら、ダイアログは「登録が変わりました」と出して中身を取り直し、前の中身への承認は送れない。
- [ ] AC-I3 キーボードだけで完結するか: 知らせの［確認する］に `Tab` で届き、`Enter` で開き、`Tab` でボタンを巡り、`Enter`・`Space` で押し、`Esc` で閉じる、がマウス無しで通る。設定画面の節「拡張」の入切・ボタンにも `Tab` で届く。
- [ ] AC-I4 フォーカスの行き先: ダイアログを開くと、フォーカスは［承認しない］に置く（`Enter` を続けて打っても、承認にならない）。閉じると、開く前の場所（知らせから開いたなら pane の端末・設定画面から開いたなら、その行のボタン）へ戻る。知らせが出ただけでは、フォーカスは動かない。
- [ ] AC-I5 既存の操作を妨げないか: ダイアログが開いている間、キーは端末へ流れない（ほかのモーダルと同じ）。設定画面・質問のフォーム（`sodactl ask`）が開いていても、それを潰さずに、上に重なる。知らせは、端末の入力・ほかのトーストを妨げない。

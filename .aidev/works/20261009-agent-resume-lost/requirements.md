# 要件: 再起動の後、エージェントの会話が自動で再開されないことがある（会話の参照が、巻き添えで捨てられる）

## 背景 / 課題

- 利用者の報告（2026-10-10）: WSL が再起動した後、Claude Code の pane は、会話が自動で再開されたが、**Codex の pane は、再開されなかった**。その pane には、`codex resume …` が打ち込まれていなかった（＝復元の時点で、会話の参照〔`pane.agentSession`〕が無かった）。
- 分かっていること（調査済み）:
  - 復元は、pane に会話の参照があり、自動の再開が有効で、再開のコマンドがあれば、それを pane に打ち込む（`SessionService.maybeResumeAgentSession`）。**打ち込んだか・打ち込まなかった理由を、ログに残していない**ので、後から調べられない。
  - **会話の参照は、画面の判定で、エージェントが居なくなった（非 null → null）と見えた時点で、捨てる**（`SessionService` の `clearsAgentSession`。20260923-agent-session-resume の D9。エージェントを終了して、別の作業をしている pane が、次の再起動で、古い会話を再開しないため）。
  - サーバは、短い間に 2 回、起動していた（00:05:31 と 00:07:11。その間に、WSL の再起動）。Codex の pane は、23:42 に、別のエージェントが `sodactl` で作ったもの。Codex のフックは導入済みで、Codex の側でも信頼済み。
  - サーバのログに、「agent judgment failed（`processInspector.foregroundJob` の時間切れ）」が 4,175 件（負荷が高い時間に集中）。失敗した回は、何も変えずに、次の回でやり直す。
- 推測（未確認）: システムが止まる途中で、エージェントのプロセスが、サーバより先に終わり、サーバが「居なくなった」と判定して、会話の参照を捨て、その状態を保存した。または、1 回目の起動で再開している最中（エージェントが、まだ検知されていない・検知された直後）に止まり、同じことが起きた。

## 目的 / ゴール

システムの停止・再起動・`soda serve` の停止の「巻き添え」で、会話の参照が捨てられない状態。再開が起きなかったとき、ログから、理由が分かる状態。「エージェントを終了して、別の作業をしている pane は、再開しない」という、今の決まり（D9）は、保つ。

## スコープ

### 対象
- サーバの、会話の参照を捨てる条件と、復元のときの再開。再開のログ。「agent judgment failed」のログの量。

### 対象外
- 再開のコマンドそのもの・フックの書式。エージェントの種類の追加。画面の変更。

## 完了条件 (受け入れ基準)

- [ ] AC1: **最初に、原因を再現して、確かめる。** 偽のエージェント（画面の判定に当たり、フックの報告を真似るスクリプト）と、実際のサーバで、(a) サーバより先に、エージェントのプロセスが終わる停止（プロセスグループへの SIGTERM・SIGHUP・SIGKILL の順を変えて）(b) 再開のコマンドを打ち込んだ直後（検知の前・検知の直後）の停止 (c) 短い間の 2 回の起動、のそれぞれで、`session.json` の会話の参照が、残るか・消えるかを調べ、**どの道で消えるかを、`decisions.md` に、事実として書く**。推測のまま、直さない。
- [ ] AC2: AC1 で見つかった道で、会話の参照が、消えない。考え方: エージェントが居なくなっても、**すぐには捨てず、その pane のシェルが生きたまま、エージェントの居ない状態が、一定の時間（設計で決める。目安 10 秒）続いたら、捨てる**。サーバが止まる処理に入った後・PTY が終わった（シェルごと無くなった）ときは、捨てない。保存（`session.json`）には、捨てると決まるまで、参照を残す。
- [ ] AC3: 今の決まりを保つ: 利用者が、エージェントを終了して（`exit`・Ctrl+D・Ctrl+C の 2 回 など）、シェルに戻り、そのまま一定の時間がたった pane は、次の再起動で、再開されない。エージェントを終了して、**すぐに**サーバを止めた場合は、再開されることがある（これは、受け入れる。文書に書く）。
- [ ] AC4: 再開のコマンドを打ち込んだ後、エージェントが検知される前に、サーバが止まっても、次の起動で、もう一度、再開される（参照が、打ち込みで消費されない）。同じ pane に、再開のコマンドを、二重に打ち込まない（今の `hasPendingResume` の決まりを保つ）。
- [ ] AC5: 復元のとき、pane ごとに、ログに 1 行: 再開のコマンドを打ち込んだ（エージェントの種類。会話の id は、先頭 8 文字だけ）／打ち込まなかった理由（参照が無い・自動の再開が無効・対応するコマンドが無い・id の形が不正）。会話の参照を捨てたときも、1 行（pane・理由）。
- [ ] AC6: 「agent judgment failed」のログを、同じ pane・同じ理由で、続けて出さない（最初の 1 回と、その後は、一定の間隔でまとめて、件数つきで）。判定そのものの動きは、変えない。
- [ ] AC7: 文書（`docs/` の、会話の再開の説明に、捨てる条件と、限界）。回帰テストには、否定の対照（直しを外すと、落ちる）。

## 残る問い

- 実際の Codex・WSL の停止で、同じ道を通ったかは、再現できる範囲で確かめる（WSL の再起動そのものは、試さない）。
- pane の先頭に出ていた「リンクが貼れない」旨のメッセージは、シェルの起動のときのもの（`.bashrc` の fnm が、再起動の直後に、一時の場所へリンクを作れなかった）と見ているが、確かめていない。この件との関係は、無い見込み。

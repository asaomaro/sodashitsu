# 要件: CLI 版の画面（端末の中で動く Sodashitsu）

## 背景 / 課題

- Sodashitsu は herdr（端末で動くエージェント向けマルチプレクサ）の画面を Web に移したもの。
  画面以外の部分（セッションを保持するサーバ `soda serve`・外部操作の `sodactl`・エージェントの検出と状態・複数ホストの集約）は揃っている。
- ただし操作する手段がブラウザしかない。次の場面で困る。
  - SSH で入った先・ブラウザを開けない環境（サーバ機・コンテナ・WSL の端末だけで作業しているとき）で、同じセッションを見て操作したい。
  - 端末から離れずに作業したい（エディタ・シェルと同じ端末の中で、tmux や herdr と同じ感覚で使いたい）。
- herdr は端末の画面とサーバ・CLI の両方を持つ。本製品は端末の画面だけを欠いているので、herdr の利用者が本製品へ移るときの障壁にもなっている。

## 目的 / ゴール

- ブラウザを使わずに、端末の中だけで、Web 版と同じセッション（workspace / tab / pane・エージェントの状態・複数ホスト）を
  herdr と同じ操作感で見て操作できる状態。
- 端末の画面とブラウザの画面が同じセッションに同時に繋がり、どちらで操作しても互いに即座に反映される状態。
- Web 版と端末版の違いは「画面の描き方」と「端末では原理的に出来ないこと」だけで、それ以外の機能の差が一覧で説明できる状態。

## ユーザーストーリー

- US1: SSH 先やブラウザの無い環境で作業する開発者として、端末で `soda` と打つだけで、エージェントの並んだ画面を開きたい。
  なぜなら ブラウザや port の転送を用意せずに、いつもの端末の中でエージェントを並行運用できるから。（受け入れ: AC1, AC2, AC3, AC4）
- US2: herdr の利用者として、herdr と同じキー・マウス操作で workspace / tab / pane を扱い、エージェントの状態を見て移動したい。
  なぜなら 学習し直さずに移行できるから。（受け入れ: AC5, AC6, AC7, AC8, AC9, AC10）
- US3: 同じ開発者として、端末版を閉じてもエージェントが動き続け、端末版でもブラウザでも同じ画面に戻りたい。
  なぜなら 席や端末を替えても作業が途切れず、手元の状況に合わせて画面を選べるから。（受け入れ: AC3, AC11, AC12）
- US4: 同じ開発者として、端末版でもエージェントの入力待ち・完了に気づき、すぐその pane へ移動したい。
  なぜなら ブラウザの通知が無い環境でも、止まったエージェントに気づかず時間を失うことを防げるから。（受け入れ: AC13）
- US5: 複数のマシンでエージェントを動かす開発者として、端末版からも登録したマシンの workspace を 1 画面で見て操作したい。
  なぜなら Web 版と同じく、マシンをまたいで状況を把握できるから。（受け入れ: AC14）
- US6: 製品オーナーとして、Web 版・herdr の全機能が端末版でどう扱われるか（対応 / 読み替え / 非対応と理由）を一覧で確認したい。
  なぜなら 「herdr 同等＋端末で出来る Web 版の拡張」を検証できる形にし、抜けを防げるから。（受け入れ: AC15）

## スコープ

### 対象

- 端末の中で動く Sodashitsu の画面（以下「端末版」）。起動は引数なしの `soda`（herdr と同じ）。
  サーバが動いていなければ起動してから繋ぎ、端末版を抜けてもサーバとエージェントは動き続ける。
- herdr が端末の画面で提供する機能の全部（サイドバー・tab バー・pane の分割と操作・端末としての pane・エージェントの状態・
  既定キーとカスタマイズしたキー・マウス操作・copy モード・navigate / goto・ヘルプ・通知・テーマ・設定・worktree の操作・切り離し 等）。
- Web 版が herdr を超えて持つ拡張のうち、端末の画面で実現できるもの（例：マウスのドラッグによる pane の分割・移動、設定画面の各項目）。
- ブラウザと端末版の同じセッションへの同時接続（構成・状態・設定の共有）。
- 端末版の通知：画面内の知らせ、ベル、外側の端末へのデスクトップ通知の依頼（OSC 9 / 777 等）、通知の対象への移動（`prefix+o`）。
- 登録したマシン（`soda machine`）の workspace の集約表示と操作。
- Web 版・herdr の全機能項目についての、端末版での扱いの一覧（`docs/herdr-parity.md` と同じ型）。

### 対象外

- 端末では原理的に出来ない Web 版の機能（例：モバイルの 1 列表示・PWA・ブラウザの OS 通知の API そのもの）。
  個々の項目と理由は AC15 の一覧で確定する。
- ノードによるオーケストレーション（別の work：agent-graph）。
- 端末版だけの新しい機能（Web 版にも herdr にも無いもの）。
- macOS の動作保証（既存と同じく 3 環境。macOS は後続）。

## 機能要件

- F1 起動と接続: 引数なしの `soda` で端末版を開く。手元のサーバが動いていなければ起動してから繋ぐ。
  既存の名前付き session（`--session`）・状態ディレクトリの指定にも従う。
- F2 切り離し: 端末版を抜けても（`prefix+q`・端末を閉じる・SSH が切れる）サーバとエージェントは動き続け、再び `soda` で同じ画面に戻る。
- F3 画面: サイドバー（workspace とエージェントの一覧と状態）・tab バー・分割された pane を 1 枚の端末に描く。
  端末の大きさの変化に追従する。
- F4 端末としての pane: 各 pane は Web 版と同じく実際の端末として振る舞う（全画面 TUI・色・全角文字・IME での入力・端末アプリのマウス入力・
  ブラケットペースト・スクロールバック・選択とコピー・貼り付け）。
- F5 操作: workspace / tab / pane の作成・切替・名前変更・閉じる・分割・リサイズ・入れ替え・拡大表示・移動を、キーとマウスで行える。
- F6 キー: prefix 方式の既定キー（herdr 互換）と、利用者がカスタマイズしたキー割り当て・直接のキー・プリセットが Web 版と同じく効く。
- F7 エージェント: 各 pane のエージェント名と 5 状態・workspace への集約・`done` の既読が Web 版と同じく表示され、選ぶと移動できる。
- F8 同時接続: ブラウザと端末版（端末版同士も）が同じセッションに同時に繋がり、構成・状態・設定の変更が互いに即座に反映される。
  同じ tab を同時に見ているときの pane の大きさは、既存の規則（最後に操作したクライアントが決める）に従う。
  自分の大きさと pane の大きさが違う間の見せ方は design で決める。
- F9 通知: エージェントの入力待ち・完了を、画面内の知らせ・ベル・外側の端末へのデスクトップ通知の依頼で知らせ、`prefix+o` で対象へ移動できる。
  通知の設定は Web 版と共有する。
- F10 複数ホスト: 登録したマシンの workspace がサイドバーに並び、手元と同じく操作できる。
- F11 設定: テーマ（端末の配色を含む）・表示・キー・通知などの設定を端末版の画面から見て変えられ、Web 版と共有される。
- F12 機能一覧: herdr と Web 版の全機能項目について、端末版での扱いを「対応 / 読み替え / 非対応（理由）」に分類した表を持つ。

## 非機能要件 / 制約

- **対応環境**: Linux / WSL2 / Windows ネイティブ（既存と同じ 3 環境）。対象の端末エミュレータは design で確定する
  （例：Windows Terminal・VS Code の統合端末・gnome-terminal / WezTerm / kitty 等）。SSH 越しの利用を含む。
- **応答性・規模・状態反映**: Web 版と同じ水準（キー入力から反映まで追加遅延 p95 50ms 以内の目安・pane 16 個・状態反映 2 秒以内）。
  大量出力の pane があっても他の pane と画面の操作が固まらない。
- **セキュリティ**: 端末版もブラウザと同じく、認証を通過した接続だけがセッションを見て操作できる。
  手元のサーバへ自動で繋ぐときも、同じ利用者以外が繋げない形にする（方式は design）。
- **互換**: 既存の Web 版・`sodactl`・サーバの利用者から見た挙動を壊さない。
- **ライセンス**: herdr の資産を流用するときは Apache-2.0 の条件を守る（既存と同じ）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

対象の部品: サイドバー、tab バー、pane（分割・境界）、prefix 待ち状態、名前変更などの入力欄、確認、ヘルプ、navigate / goto、
copy モード、設定、通知の知らせ、worktree などのメニュー。

- [ ] AC-I1 開く / 閉じる: 入力欄・確認・ヘルプ・設定・メニューは、キー（prefix＋キー）とマウスのどちらでも開き、`Esc` または外側のクリックで閉じる。
  確定せずに閉じたときは値が変わらない。prefix 待ちの状態は画面上で判別でき、`Esc` か一定時間の経過で解除される。
- [ ] AC-I2 確定 / 取り消し: 名前変更・設定の変更は `Enter` で確定、`Esc` で取り消して元に戻る。実行中のプロセスがある pane / tab / workspace を閉じる操作は確認を挟み、取り消せば何も失われない。
- [ ] AC-I3 キーボードだけで完結するか: 端末版の全操作（作成・切替・分割・リサイズ・名前変更・閉じる・サイドバーからの選択・ヘルプ・設定・通知の対象への移動・切り離し）を、マウスを使わずに最初から最後まで行える。
- [ ] AC-I4 フォーカスの行き先: 新しく作った pane / tab / workspace にフォーカスが移る。サイドバーで選んだ後は選んだ pane に移る。入力欄・ヘルプ・設定・メニューを閉じると、開く前の pane に戻る。
- [ ] AC-I5 既存の操作を妨げないか: pane にフォーカスがある間、prefix とその直後の 1 キー以外の入力（`Ctrl+C` / `Ctrl+D` / `Esc` / `Tab` / 矢印 / `Alt` 付き等）はすべてその pane へ届く。prefix キー自体を pane へ送る手段がある。
  pane 上のホイールはその pane だけに作用する（端末アプリがマウス入力を受け付けていればアプリへ届く）。外側の端末のキー（コピー・貼り付け・タブ切替等）と衝突するものは、どちらが優先するかが決まっていて説明されている。

## 未確定事項 / 確認したいこと

- 端末版の中で端末版を起動したとき（入れ子。herdr の H47）の扱い → research（herdr の挙動）・design。
- tmux の中で端末版を動かしたときの prefix の衝突や描画の扱い → research・design。
- 自分の大きさと pane の大きさが違う間の見せ方（見切れ・余白・スクロール）→ design。
- 手元のサーバへ自動で繋ぐときの認証方式（token を毎回入れさせない形）→ design。
- 端末版の中の画像表示（Kitty graphics の透過）、クリップボードの画像の貼り付けが端末版で出来るか → research（AC15 の一覧で確定）。
- 対象の端末エミュレータの一覧と、外側の端末へのデスクトップ通知の依頼に対応する端末 → research・design。
- 今の `soda`（引数なし）は使い方を表示するだけ（`packages/server/src/cliArgs.ts` の `parseArgs`）。端末版の起動に変えたときの
  使い方の表示の入口（`soda help` は残る）と docs の書き換え → design。

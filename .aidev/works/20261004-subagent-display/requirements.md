# 要件: エージェントが起動しているサブエージェントを表示する

## 背景 / 課題

pane の中のエージェント（Claude Code）は、自分の中でサブエージェント（Agent ツール）を起動して作業を分担させる。サブエージェントは pane を持たず、同じプロセスの中で動くので、Sodashitsu からは見えない。サイドバーにも連携のグラフにも、親のエージェントが「作業中」と出るだけで、**中でいくつのサブエージェントが動いているか・それぞれ何をしているか**が分からない。

`20261003-graph-auto-nodes` で、エージェントが `sodactl` で別の pane に起動したエージェントはグラフに自動で載るようになった。pane を持たないサブエージェントは、その仕組みでは拾えない（サーバが検出できるのは pane の中のプロセスだけ）。

Sodashitsu には、エージェントのフック連携がある（エージェントの設定にフックを書き込み、フックのスクリプトが pane の中の専用の socket へ報告する。research.md「F1」〜「F4」）。今はセッション開始のフック 1 つだけを使い、会話の再開のためのセッション ID を受けている。Claude Code には、サブエージェントの起動・終了で動くフック（`SubagentStart`・`SubagentStop`）、Agent ツールの実行前に動くフック（`PreToolUse`）、エージェントが作業を終えたときに動くフック（`Stop`）があり、起動・終了・種類・短い説明・その時点で動いているバックグラウンドのタスクを取れることを実物で確かめた（research.md「実物で確かめたこと」）。

## 目的 / ゴール

- 利用者が、どのエージェントが今いくつのサブエージェントを動かしているかを、サイドバーと連携のグラフで一目で分かる状態。
- 利用者が、そのサブエージェントの一覧（種類・短い説明・経過時間）を、必要なときに見られる状態。
- サーバが起動の報告を受けたサブエージェントについて、表示が実際と食い違ったまま残らない状態（終了の報告が来なかったものが、いつまでも「実行中」と出続けない）。
- フック連携を導入済みの利用者が、新しいフックが足りていないことが分かり、自分の操作で足せる状態。

charter ゴール: `.aidev/charter.md` は無い（紐づける charter はない）。

## ユーザーストーリー

- US1: Sodashitsu の利用者として、エージェントが中で何件のサブエージェントを動かしているかを、その pane を開かずに見たい。なぜなら、長い「作業中」が、並行で調査や実装を進めているのか、止まっているのかの見当が付くから。（受け入れ: AC1, AC2, AC3, AC6, AC15）
- US2: 同じ利用者として、動いているサブエージェントの種類と短い説明、経過時間を一覧で見たい。なぜなら、何を任せているのかが分かれば、待つか割り込むかを判断できるから。（受け入れ: AC4, AC5, AC6, AC-I1, AC-I2, AC-I3, AC-I4, AC-I5）
- US3: 同じ利用者として、表示が実際と合っていてほしい。なぜなら、終わったはずのサブエージェントが残り続けると、件数を信用できなくなるから。（受け入れ: AC7, AC8, AC16, AC17）
- US4: フック連携を導入済みの利用者として、新しいフックが足りていないことが分かり、自分の操作で足したい。なぜなら、自分のエージェントの設定ファイルを、知らないうちに書き換えられたくないから。（受け入れ: AC9, AC10）
- US5: `sodactl` を使うスクリプト・監督役のエージェントとして、あるエージェントが今サブエージェントを動かしているかを機械的に知りたい。なぜなら、「作業中」の中身を見て、待つ・読みに行くを決められるから。（受け入れ: AC11）
- 互換・安全・文書の AC（AC12, AC13, AC14）は、特定のストーリーに紐づかない制約由来の基準。

## スコープ

### 対象

- フックのスクリプト: 下の F1 の 6 種類の報告を送る。
- サーバ: 報告を受けて、pane のエージェントごとに「実行中のサブエージェント」をメモリに持ち、接続中の画面へ配る。終了・取りこぼしの後始末。
- インストーラと設定画面（ブラウザ版・端末版の両方）: Claude Code の連携に新しいフックを足す。導入済みで足りていない状態の検出と、利用者の操作での更新。
- ブラウザ版: サイドバーのエージェントの行と、連携のグラフのノードに件数を出す。件数から一覧を開く（サイドバーとグラフの両方）。
- 端末版（引数なしの `soda`）: サイドバーのエージェントの行に件数を出す。一覧を開く。
- `sodactl agent list`／`get` の出力に、サブエージェントの件数と一覧。
- 文書（`docs/agent-graph.md`・`docs/sodactl.md`・`docs/tui.md`・`docs/verification.md`・skill）と、設定画面の説明の文言。

### 対象外

- サブエージェントを連携のグラフのノードとして出すこと（線の相手にもしない。件数と一覧だけ。必要になったら別の作業で）。
- サブエージェントへの操作（止める・指示する）。
- Claude Code 以外のエージェント（Codex 等）のサブエージェント（各エージェントにサブエージェントのフックがあるか確かめられていない。research.md「F10」）。
- サブエージェントへの指示文（`prompt`）の全文・サブエージェントの発言の表示・保存（長く、機密のことがあるため、サーバへ送らない）。
- チームメイト（agent teams）・Workflow ツールのエージェント・サブエージェントの中のサブエージェントの**専用の表示**（階層や由来は示さない）。これらが `SubagentStart` を出す場合は、ほかのサブエージェントと同じく 1 件として平らに数える。
- 畳んだサイドバー（状態の印だけの表示）での件数。モバイルの pane 選択の一覧と、モバイルのグラフのシートでの一覧（件数は、グラフのノードに出るものだけ）。
- サーバの再起動・`soda handoff` をまたいで一覧を残すこと（メモリだけに持つ。再起動の後は、その後に起動したサブエージェントと、F7 の突き合わせで分かったものだけが出る）。
- フック連携の、Claude Code・Codex 以外の 6 種の報告がサーバで捨てられている件（`composeServer.ts:651`。research.md「F2」。この work では触らない）。

## 機能要件

- F1 **報告**: フック連携を導入した Claude Code が、次のときにフックのスクリプトからサーバへ報告する。どの報告も、pane の ID・エージェントの種類（`claude`）・セッションの ID を含む。**指示文の全文（`prompt`）と発言（`last_assistant_message`）は含めない。**

  | 報告 | フック | 含める項目 |
  |---|---|---|
  | セッションの開始 | `SessionStart`（今のまま） | （共通の項目だけ） |
  | Agent ツールの実行前 | `PreToolUse`（Agent） | 短い説明・サブエージェントの種類・バックグラウンドかどうか |
  | サブエージェントの起動 | `SubagentStart` | サブエージェントの ID・種類 |
  | サブエージェントの終了 | `SubagentStop` | サブエージェントの ID |
  | エージェントが作業を終えた | `Stop` | その時点で動いているバックグラウンドのサブエージェントの一覧（ID・種類・短い説明） |
  | セッションの終了 | `SessionEnd` | （共通の項目だけ） |

- F2 **状態**: サーバは、pane とセッションの ID の組ごとに、実行中のサブエージェントの一覧（ID・種類・短い説明・バックグラウンドか・サーバが起動の報告を受けた時刻）を持つ。起動の報告で足し、終了の報告で外す。**一覧に無い ID の終了は無視する**（件数を負にしない。サーバの再起動より前に起動した分の終了が届く場合がある）。メモリだけに持ち、保存しない。pane のエージェントの件数と一覧は、その pane の全セッションの合計（同じ pane の中で別の `claude` を起動した場合、そのサブエージェントも同じ pane の件数に入る）。
- F3 **短い説明の対応づけ**: 短い説明とバックグラウンドかどうかは、Agent ツールの実行前の報告から取り、同じセッションの**次の**起動の報告に対応づける（種類が一致するもの。フックは同期で動かし、実行前 → 起動の順で届く）。対応づける相手が無い起動（実行前の報告が届かなかった・種類が合わない）は、説明なし・バックグラウンドかどうかは「不明」で出す。対応づけを待つ実行前の報告は、次の起動に使われるか、10 秒たつか、セッションごとに 16 件を超えたら捨てる（起動に至らなかった実行前の報告が、後の起動に付かないように）。同じ種類を並行で起動したときに説明を取り違えることは許す（件数には影響しない）。
- F4 **配布**: 一覧が変わったら、接続中のすべての画面（ブラウザ・端末版）に、利用者の操作なしで 1 秒以内に届く。新しく繋いだ・読み込み直した画面は、その時点の一覧を受け取る。別のマシンのエージェントについても、そのマシンのサーバがこの版で、そのマシンにフックが導入されていれば、同じように届く（選んでいないマシンのエージェントの件数は、連携のグラフのノードに出る）。
- F5 **件数の表示**: 実行中のサブエージェントが 1 件以上あるエージェントについて、サイドバーのエージェントの行と、連携のグラフのそのノードに、件数を出す。0 件のとき・サブエージェントの報告を一度も受けていないとき（フックが入っていない・古い・対象外のエージェント）は何も出さない（今の見た目のまま。画面では 0 件と「分からない」を区別しない）。親のエージェントが作業中でなくても、バックグラウンドのサブエージェントが動いていれば件数は出る。
- F6 **一覧**: 件数を押す（選ぶ）と、そのエージェントのサブエージェントの一覧が開く。各行は、種類・短い説明（あれば）・経過時間（秒・分・時間の単位。開いている間、少なくとも 10 秒ごとに進む）・バックグラウンドの印（不明なら出さない）。並びは起動した順。表示は 64 件までで、超えた分は「ほか n 件」と出す。一覧は開いている間も更新される。
- F7 **後始末**: 次のときに、その pane の一覧を全部空にする: エージェントが居なくなった・別のエージェントに入れ替わった・pane が閉じた。加えて、**エージェントが作業を終えたときの報告**で、そのセッションの一覧を「その時点で動いているバックグラウンドのサブエージェント」に合わせる: 報告に無い ID は外し（終了の報告が来なかったもの。前面の実行のサブエージェントは、エージェントが作業を終えた時点では動いていない）、報告にあって一覧に無い ID は、報告にある種類・説明で足す（サーバの再起動より前に起動したバックグラウンドのもの。直前に終了の報告を受けた ID は足し直さない）。セッションの終了の報告では、そのセッションの一覧を捨てる（同じ pane の中で起動した別の `claude` が終わったとき・`/clear` で前のセッションが終わったとき）。強制終了されたセッションの分は、pane のエージェントが居なくなる・入れ替わるまで残りうる（文書に書く）。
- F8 **上限**: 1 つの pane につき、ID を持つのは 256 件まで（超えた起動は数えない。文書に書く）。短い説明は 200 文字まで（超えたら切る）、種類は 64 文字まで（同）、ID は 128 文字まで（超えた報告は捨てる）。
- F9 **導入と更新**: 設定の「エージェントの連携」（ブラウザ版・端末版）で Claude Code の連携を導入すると、F1 の 6 つのフックが入る。**すでに導入済みで、フックが足りない・写したスクリプトが古いときは、「更新が必要」と分かる表示を出し、利用者が更新を押すと、足りないフックと新しいスクリプトを入れる。**利用者が押すまで、設定ファイルもスクリプトも書き換えない。更新は、その後に起動した Claude Code から効く（動いている Claude Code は、起動し直すまで古いフックのまま）。削除は、この製品が入れたフックを全部外す。導入・更新・削除は、その pane を動かすマシンごとに行う（別のマシンのエージェントは、そのマシンの設定）。
- F10 **sodactl**: `sodactl agent list`／`agent get` の各エージェントに `subagents` を出す。サブエージェントの報告を一度も受けていないエージェント（フックが入っていない・古い・対象外）は `null`、受けたことがあれば `{count, items}`（`items` は ID・種類・短い説明・バックグラウンドか〔不明は `null`〕・起動した時刻。0 件なら `count: 0` と空の一覧）。

## 非機能要件 / 制約

- フックは、エージェントの動きを壊さない・長く待たせない: 報告に失敗しても（socket が無い・サーバが止まっている・pane の外）、フックは何も出力せず正常に終わる（今のスクリプトと同じ）。フック 1 回の所要は、接続の待ち（1 秒）と入力の読み取りの打ち切り（2 秒）を上限とし、サーバが動いているふだんは 0.3 秒以内。
- 報告の名乗り（pane の ID）は検証できない（同じ OS の利用者なら偽れる。今のセッション ID の報告と同じ信頼の範囲）。報告は表示にだけ使い、権限の判断・エージェントへの入力には使わない。画面には文字として出す（HTML にしない）。
- サーバのログに、短い説明の中身を出さない。
- 互換:
  - 古いスクリプト（セッション ID だけを送る）×新しいサーバ: 会話の再開が今までどおり動く。サブエージェントは出ない。
  - 新しいスクリプト×古いサーバ: 古いサーバは、pane の ID・種類・セッションの ID が揃った報告をセッション ID の報告として扱う。新しい種類の報告が届いても、同じセッション ID を上書きするだけで、会話の再開が今までどおり動く形にする。
  - 古い画面×新しいサーバ: 新しい項目を無視して、エージェントの行を今までどおり描く。
  - 新しい画面×古いサーバ（古い版の別のマシンを含む）: 項目が無いので、何も出さない。
- 配布の量: 一覧が実際に変わったときだけ配る（同じ内容の報告ではイベントを出さない）。1 つの pane について配るのは 100 ミリ秒に 1 回まで（短い時間に続いた変化はまとめる）。
- Windows のサーバでも動く（報告の受け口は、今の named pipe のまま。確かめるのは実機の手順として文書に書く）。
- 連携のグラフのノードの大きさ（200×80）と、線の経路の計算を変えない。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: ブラウザ版は、サイドバーの行の件数（ボタン）のクリック・`Enter`／`Space` で一覧が開く。グラフでは、ノードの件数のクリックと、ノードを選んでいるときのキーで開く。端末版は、件数のクリックと、フォーカスしている pane のメニューの項目（または割り当てたキー）で開く。`Esc`・一覧の外のクリックで閉じる（一覧が開いている間に別の件数を押した場合も、まず閉じる）。閉じても表示だけで、何も変わらない。
- [ ] AC-I2 確定 / 取り消し: 一覧は見るだけで、確定する操作は無い。件数を押しても、その pane へは移らず、グラフのノードの選択・ドラッグも始まらない（行・ノードのほかの場所を押したときは今までどおり）。
- [ ] AC-I3 キーボードだけで完結するか: ブラウザ版は、`Tab` で件数のボタンへ移る → `Enter` で開く → 上下で読む → `Esc` で閉じる（グラフでは、ノードを選ぶ → キーで開く）。端末版は、その pane にフォーカスを置く → メニューの項目（または割り当てたキー）で開く → 上下で読む → `Esc` で閉じる。どちらもマウス無しでできる。
- [ ] AC-I4 フォーカスの行き先: 開くと一覧へ移り、閉じると件数のボタン（端末版は元の行の選択）へ戻る。件数が 0 になってボタンが消えていたら、その行（グラフではそのノード）へ戻る。開いている間に、そのエージェントが居なくなった・入れ替わった・pane が閉じたときは、一覧は閉じ、フォーカスは元の場所の近く（サイドバー、無ければ端末）へ戻る。
- [ ] AC-I5 既存の操作を妨げないか: 一覧の上でのキー・ホイールが端末の pane へ漏れない。件数が増減しても、サイドバーの行の高さ・並びが変わらず、行のクリック（pane へ移る）・右クリックのメニュー・ドラッグ、グラフのノードの選択・ドラッグ・線の作成が今までどおり動く。

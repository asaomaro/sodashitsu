# 要件: 複数ホストの集約（保存した SSH のマシン。herdr の several machines・H43 の最初の一切れ）

## 背景 / 課題

wtm は 1 台のマシンの 1 つの session（`wtm serve`）を 1 つのブラウザの画面で扱う。複数のマシン（手元の PC・ビルド機・GPU 機）で
エージェントを動かしている利用者は、マシンごとに `wtm serve` を起動し、**マシンごとに別のブラウザのタブ（別の URL・別の token・
別のポートの転送）を開いて行き来する**しかない。どのマシンのエージェントが入力待ちかは、そのタブを開くまで分からない。
リモートのマシンの `wtm serve` をブラウザから直接開くには、そのポートを LAN やインターネットに出す（TLS・token・`--origin`）か、
SSH のポート転送を自分で張る必要がある。

herdr には「保存した SSH のマシン」（`herdr machine add/list/rename/enable/disable/remove`、一次資料
`scratchpad/herdr/docs/versions/0.9.1/website/src/content/docs/connecting-machines.mdx`・`cli-reference.mdx`「Saved SSH machines」、
実装 `src/remote/saved.rs`・`src/remote/host.rs`・`src/client/endpoint/catalog.rs`・`src/cli/machine.rs`）がある:
手元の herdr が SSH の標準入出力の上の bridge（リモートで `herdr remote-client-bridge` がリモートのサーバのローカル socket に繋いで中継）で
各マシンの herdr サーバに繋ぎ、1 つの画面のサイドバーにマシンごとの workspace を並べる。各マシンは自分のサーバ・session・プロセスを持ち続け、
選んだマシンだけが画面の中身・入力・大きさを流し、ほかのマシンは workspace・エージェント・通知の状態だけを送る。
切れたマシンは最後の状態を薄く表示し、自動で繋ぎ直す（失敗が続くと最大 2 分まで間隔を延ばす）。`herdr --machine <label|id>` で
CLI の操作をそのマシンへ送れる。

`docs/herdr-parity.md` の H43（保存済みマシン・`--remote`・`--machine`）と backlog `product-roadmap.md`「複数ホストの集約」が未対応。
**ユーザーの決定（主エージェント経由・decisions D1）**: herdr の形で実装まで進める——手元の `wtm serve` が SSH で他のマシンの `wtm` サーバへ繋ぐ
（各マシンは自分のサーバ・session・プロセスを持つ）、`wtm machine add/list/rename/enable/disable/remove`（保存するのは不透明な id・名前・SSH の宛先・
リモートの session・有効かだけ。パスワード・鍵は持たず、認証は OpenSSH に任せ、裏の接続は `ssh -o BatchMode=yes` で非対話）、
ブラウザのサイドバーはマシンごとに workspace をまとめる、選んだマシンだけが pane の画面・入力・大きさを流しほかは workspace・エージェントの状態を送る、
切れたマシンは薄く表示した最後の状態を残し最大 2 分の間隔で自動で繋ぎ直す、`wtmctl --machine <label|id>` で CLI の操作を送る。
大きいので、筋の通った最初の一切れを届け、残り（モバイル・手元の `wtm serve` を通さない直接の SSH での `--machine`・リモートへの自動の導入・画像の貼り付け等）は backlog に残す。

## 目的 / ゴール

- 複数のマシンで `wtm serve` を動かしている利用者が、**手元の 1 つのブラウザの画面（1 つの URL・1 つのログイン）から、全マシンの
  workspace とエージェントの状態を一覧でき、どのマシンの workspace にも切り替えて操作できる**状態。リモートのマシンのポートをネットワークに出したり、
  ポート転送を自分で張ったりしなくてよい（通るのは利用者がふだん使っている SSH だけ）。
- 各マシンは自分の `wtm serve`・session・pane のプロセスを持ち続け、**手元の `wtm serve` が止まっても、繋ぎ方の設定を消しても、
  リモートの pane は動き続ける**状態。
- マシンへの接続が切れても、そのマシンの最後の状態が「古い情報」と分かる形で見え続け、繋がり次第自動で最新に戻る状態。
  1 台が切れても、ほかのマシン（手元を含む）の操作は止まらない。
- マシンの登録・名前の変更・無効化・削除を CLI で行え、動いている手元の `wtm serve` に 1〜2 秒で反映される状態。
  保存された設定に秘密（パスワード・鍵・token）が入らない状態。
- `wtmctl` の操作を、マシンの名前か id を添えるだけで、そのマシンの `wtm` に届けられる状態。
- マシンを 1 台も登録しない利用者には、画面・CLI・待ち受けの動作が今までと何も変わらない状態。

## ユーザーストーリー

- US1: 複数のマシンでエージェントを走らせている開発者として、手元のブラウザの 1 画面で全マシンの workspace とエージェントの状態を見たい。
  なぜなら、マシンごとにタブ・URL・token を行き来せずに、どこで入力待ちが起きているかを一目で知りたいから。（受け入れ: AC5, AC6, AC7, AC-I1, AC-I5）
- US2: 同じ開発者として、サイドバーでリモートのマシンの workspace を選ぶだけで、その pane を手元と同じように見て打ちたい。
  なぜなら、そのマシンの画面を別に開き直すのは手間だから。（受け入れ: AC8, AC9, AC-I2, AC-I3, AC-I4）
- US3: 利用者として、SSH の設定（`~/.ssh/config`・ssh-agent）をそのまま使ってマシンを登録したい。パスワードや鍵を wtm に預けたくない。
  なぜなら、認証の管理を 2 か所に分けたくなく、秘密が増えると漏れる場所も増えるから。（受け入れ: AC1, AC2, AC3, AC12）
- US4: ノート PC を閉じたり回線が途切れたりする利用者として、切れたマシンが勝手に繋がり直り、切れている間も最後の状態が「古い」と分かる形で見えてほしい。
  なぜなら、再接続のたびに手で操作したくなく、古い状態を最新と取り違えて打ち込みたくもないから。（受け入れ: AC10, AC11）
- US5: スクリプトやエージェントから wtm を操作する開発者として、`wtmctl --machine <名前>` で別のマシンの pane やエージェントを操作したい。
  なぜなら、エージェントの監督をマシンをまたいで 1 か所から行いたいから。（受け入れ: AC13）
- US6b: 実装とリリースを確かめる開発者として、ビルドした成果物で手元とリモートの往復が通ることを起動確認で見たい。なぜなら、単体テストの緑だけでは SSH の子プロセスと中継の配線が実物で動く根拠にならないから。（受け入れ: AC17）
- US6: 運用者として、この機能が新しいネットワークの待ち受けを作らず、リモートの出力を信用しない（大きさ・形を確かめる）でほしい。
  なぜなら、SSH の先のマシンが壊れていたり乗っ取られていたりしても、手元の wtm とブラウザを巻き込ませたくないから。（受け入れ: AC4, AC12, AC14）
- US7: マシンを登録しない利用者として、今までと同じに動いてほしい。（受け入れ: AC15）
- US8: herdr から移ってきた利用者として、herdr との違いと使い方を docs で知りたい。（受け入れ: AC16）

## スコープ

### 対象

- マシンの登録簿（保存した SSH のマシンの一覧）と CLI `wtm machine add/list/rename/enable/disable/remove`。
- リモートの `wtm` 側の中継（`wtm bridge`）: SSH の標準入出力と、リモートで動いている `wtm serve` の間を中継する。認証はリモートの側だけで行い、
  リモートの秘密を手元に写さない。
- 手元の `wtm serve` の中の、マシンごとの接続の管理（起動・確かめ・生きているかの確認・切れたときの自動の繋ぎ直し・登録簿の変化の反映）。
- ブラウザと `wtmctl` の要求を、手元の `wtm serve` を通して選んだマシンへ届けること（`/ws` の行き先の選択）。
- ブラウザのサイドバーのマシンごとのまとまり・マシンの状態の表示・マシンの切り替え（選んだマシンの画面の表示・入力・大きさ）・
  切れたマシンの最後の状態の薄い表示。
- `wtmctl --machine <名前|id>`（`login`・`skill` 以外の全コマンド＝`snapshot`・`watch`・`workspace`・`tab`・`pane`・`agent` を、手元の `wtm serve` を通してその 1 台へ送る）。
- ヘルプ・`docs/herdr-parity.md` の H43・docs の手順の更新。
- Linux で、偽の `ssh`（ローカルで `wtm bridge` を起こすスクリプト）を使って確かめる。本物の SSH のサーバ・macOS・Windows では確かめない（未検証として記す）。

### 対象外（backlog に `[ ]` で残す）

- モバイルの画面（`MobileShell`）でのマシンの切り替え（手元のマシンだけを表示する。今までどおり）。
- ほかのマシンのエージェントの状態の変化を、トースト・OS 通知・音で知らせること（サイドバーの状態の印は変わる）。`prefix+w` 相当のキーボードでのマシンをまたぐ移動。
- リモートへの `wtm` の自動の導入・更新・リモートの `wtm serve` の自動の起動（herdr は承認つきで行う）。リモートで `wtm serve` が動いていなければ「要対応」を表示して待つ。
- `wtm --remote <宛先>` 相当の、登録せずに 1 回だけ繋ぐ入口。登録せずに SSH で直接繋ぐ `wtmctl --machine`（手元の `wtm serve` が動いていなくても使える形）。
- リモートへのクリップボードの画像の転送（H44）。
- Windows のマシンをリモートにすること（中継の受け口が Unix ドメイン socket のため）。手元が Windows の場合は作りとしては動く想定だが確かめない。
- 同じ宛先への SSH の接続の共有（ControlMaster）・keepalive の設定の自動の追加（利用者の `~/.ssh/config` に任せる）。
- マシンの登録・名前の変更・削除をブラウザの画面から行うこと（CLI だけ）。
- 手元のカスタムコマンド・設定・プラグインをリモートへ写すこと（herdr もしない）。

## 機能要件

- 登録簿は手元の状態ディレクトリに置く JSON で、1 台ごとに「不透明な id（ランダム）・名前・SSH の宛先・リモートの session（省略時は既定）・有効か」だけを持つ。
  知らない項目・秘密らしい値（宛先の中のパスワード）・制御文字・大きすぎるファイル・多すぎる台数は受け付けない。権限は 0600。
- `wtm machine add <宛先> --label <名前> [--remote-session <名前>]` は、保存の前に実際に SSH で中継に繋いでリモートの `wtm serve` が応えることを確かめ、
  だめなら保存せずに理由と次の手（`ssh <宛先>` で確かめる・リモートで `wtm serve` を起動する等）を出す。
  `list [--json]`・`rename <id> --label <名前>`・`enable <id>`・`disable <id>`・`remove <id>` を持つ。名前の変更・無効化・削除はリモートに何もしない。
- 手元の `wtm serve` は、有効なマシンごとに裏で SSH（`ssh -o BatchMode=yes …`、システムの `ssh` を引数の配列で起動し、シェルを通さない）を起こして中継に繋ぎ、
  状態（繋いでいる・繋がった・繋ぎ直し中・要対応）を持つ。切れたら間隔を延ばしながら（最大 2 分）自動で繋ぎ直す。黙ったままの接続は生きているか確かめ、応えなければ切って繋ぎ直す。
  登録簿の変化（追加・名前の変更・有効／無効・削除）は、再起動なしに 1〜2 秒で反映する。無効化・削除したマシンの接続は閉じる（リモートは動いたまま）。
- ブラウザと `wtmctl` は、手元の `wtm serve` の `/ws` に行き先のマシン（id か名前）を添えて繋ぐと、手元の認証（今までの Cookie）を通ったうえで、
  そのマシンの `wtm serve` に対する今までと同じ通信（要求・イベント・画面・入力）をそのまま使える。
- ブラウザは、有効なマシンが 1 台以上登録されていれば（無効なマシンは出さない）、サイドバーにマシン（手元＝「ローカル」を先頭に、登録の順）ごとのまとまりを出す。各まとまりの見出しに名前と状態を出し、
  選んでいるマシンのまとまりには今までのサイドバーの workspace の一覧を、ほかのマシンには workspace の名前とエージェントの状態の印を出す。
  ほかのマシンの workspace を選ぶと、そのマシンに切り替わり、その workspace を表示する。選んでいないマシンは画面の中身を流さない。
- 切れたマシンは、最後の状態を薄く表示し、選べない（選んでいるマシンが切れたら、画面は最後の中身のまま入力を止め、繋がり次第戻る）。選んでいるマシンが無効化・削除されたらローカルに戻る。
- `wtmctl --machine <名前|id> <コマンド>` は、そのマシンに対してコマンドを行う。名前・id が登録に無い・無効・曖昧なら、何もせずに失敗する（ローカルに黙って送らない）。
  繋がっていないマシンも、何もせずに失敗する。

## 非機能要件 / 制約

- 新しいネットワークの待ち受けを作らない。リモートの `wtm serve` 側の中継の受け口は、状態ディレクトリの中の権限 0600 の Unix ドメイン socket だけ（同じ利用者に限る）。
- SSH はシステムの `ssh` を引数の配列で起動する（手元でシェルを通さない）。宛先は検証する（`-` で始まる・空白や制御文字を含む・パスワードを含むものは受け付けない）。
  リモートで走らせるコマンドは固定（`wtm bridge` と検証済みの session の名前だけ）で、利用者の入力をリモートのシェルに渡さない。
- リモートから来るものは信用しない: 形の決まった枠（種類・長さ）で読み、1 枠の大きさ・同時に開く数・最初の応答までの時間に上限を置き、外れたら接続ごと切る。
- 手元の `wtm serve` の認証（Cookie）を通らない要求は、マシンの行き先があっても今までどおり断る。リモートの token は手元に写さない。
- 新旧の組み合わせ: 中継の版と通信の版を最初に確かめ、合わなければ「要対応」にして理由を出す（黙って壊れた通信を続けない）。`wtm bridge` を知らない古いリモートも「要対応」になる。
- マシンを 1 台も登録しなければ、SSH を起こさず、サイドバー・`/ws`・`wtmctl` の動作は変わらない。
- 負荷試験・E2E は行わない（共有マシン。ユーザーの指示）。単体・結合テストと smoke（偽の `ssh`）で確かめる。

## 完了条件 (受け入れ基準)

- [ ] AC1: `wtm machine add <宛先> --label <名前> [--remote-session <名前>]` は、SSH で中継に繋いでリモートの `wtm serve` が応えるのを確かめてから登録簿に保存し、
  id を出して終了コード 0 で終わる。確かめに失敗したら保存せず、理由と次の手を出して終了コード 1 で終わる。引数の誤り（名前が無い・宛先が不正・session の名前が規則外・
  名前の重複・予約名 `local`（大文字小文字を問わない）・ほかのマシンの id と同じ名前・台数の上限）は何も作らずに終了コード 2 で終わる（`rename` も同じ）。
- [ ] AC2: `wtm machine list [--json]`・`rename <id> --label <名前>`・`enable <id>`・`disable <id>`・`remove <id>` が登録簿を読み書きし、知らない id は終了コード 2。
  名前の変更・無効化・削除はリモートに何もしない。
- [ ] AC3: 登録簿のファイルは 1 台ごとに id・名前・宛先・session・有効かだけを持ち、権限 0600 で原子的に書かれる。知らない項目・宛先の中のパスワード・`-` で始まる宛先・
  空白や制御文字・大きすぎるファイル・上限を超える台数・重複した id を含むファイルは読み込みを拒む（手元の `wtm serve` は、壊れた登録簿のときは今の接続を保ったまま警告をログに残す）。
- [ ] AC4: リモートの `wtm serve` は状態ディレクトリに権限 0600 の中継の受け口（Unix ドメイン socket）を置き、`wtm bridge [--session <名前>] [--state-dir <DIR>]` は標準入出力とその受け口を中継する。
  受け口に繋がった接続は、その `wtm serve` の今までの通信（`client.hello` 以降）を行える。動いていなければ `wtm bridge` は理由を標準エラーに出して終了コード 3 で終わる。
  新しい TCP の待ち受けは作らない。
- [ ] AC5: 手元の `wtm serve` は有効なマシンごとに `ssh -o BatchMode=yes … -- <宛先> wtm bridge [--session <名前>]` を引数の配列で起動し、中継の最初の応答（版の確かめ）を
  上限時間の内に受けたら「繋がった」にする。登録簿の変化は再起動なしに 2 秒以内に反映する（追加・有効化で繋ぎに行き、無効化・削除で閉じ、名前の変更では繋ぎ直さない）。
  手元の `wtm serve` が止まっても・無効化・削除しても、リモートの `wtm serve` と pane のプロセスは止めない（中継の接続が閉じるだけ）。
- [ ] AC6: 認証済みのブラウザ・`wtmctl` が `/ws?machine=<id|名前>` で繋ぐと、手元の `wtm serve` はその接続の要求・イベント・画面・入力を、そのマシンの `wtm serve` への
  1 本の論理的な接続として双方向に中継する（1 本の SSH の上で複数の接続を同時に扱える）。登録に無い・無効なマシンは 404、繋がっていないマシンは 503 で断る。
  認証の無い要求は、マシンの行き先があっても今までどおり 401。`machine=local` と行き先なしは手元の `wtm serve` そのもの。
  名前での指定は、有効なマシンのうち名前が完全に一致する 1 台（id が一致すればそれを優先）。一致が 2 台以上（曖昧）なら 404 と同じく断る。
- [ ] AC7: 手元の `wtm serve` は `machine.list`（登録されている有効なマシンの id・名前・状態〔繋いでいる・繋がった・繋ぎ直し中・要対応〕・状態の理由）に答え、状態・名前・台数が変わるたびに `machine.changed` を配る。
- [ ] AC8: 有効なマシンが 1 台以上登録されていると（無効なマシンはサイドバーに出さない）、ブラウザのサイドバーはローカルを先頭に登録の順でマシンごとのまとまりを出し、見出しに名前と状態（繋いでいる・繋がった・繋ぎ直し中・要対応）を出す。
  選んでいるマシンのまとまりは今までの workspace の一覧（操作もそのまま）、ほかのマシンは workspace の名前とエージェントの状態の印を出し、状態の変化はイベントで更新される。
- [ ] AC9: ほかの繋がっているマシンの workspace（または見出し）を選ぶと、画面の接続がそのマシンへ切り替わり、そのマシンの状態を読み直してその workspace（見出しなら、そのマシンの今の focus）を表示する。
  切り替えの前のマシンの端末の中身・pane の id・既読の印を切り替えの後のマシンへ持ち込まない（同じ `p1` が両方にあっても混ざらない）。選んでいないマシンには
  pane の購読・表示の大きさ・入力を送らない。
- [ ] AC10: マシンへの接続が切れたら、手元の `wtm serve` は間隔を延ばしながら（1 秒から倍々、最大 2 分）繋ぎ直す。繋がった状態が 1 分続く前にまた切れたら間隔を元に戻さない。
  認証・ホスト鍵・`wtm bridge` が無い・版が合わない・リモートで `wtm serve` が動いていない、の失敗は「要対応」とし理由を添える（繋ぎ直しは最大の間隔で続ける）。
  黙った接続には確かめの往復を送り、上限時間の内に応えがなければ切って繋ぎ直す。
- [ ] AC11: 切れたマシンのまとまりは、最後の workspace とエージェントの状態を薄く表示し、その見出しと workspace は選べない（折りたたみはできる）。選んでいるマシンが切れたら、画面は最後の中身のまま入力を止めて
  繋ぎ直し中を示し、繋がったら最新に戻る（選んでいるマシンは変わらない）。選んでいるマシンが無効化・削除されたらローカルへ戻る。
  1 台が切れても・繋ぎ直しを繰り返しても、ほかのマシン（ローカルを含む）の表示・入力・`/ws` の中継は止まらない（マシンごとの接続は互いに独立）。
- [ ] AC12: SSH の起動は引数の配列で、宛先の前に `--` を置き、リモートのコマンドは `wtm bridge` と検証済みの session の名前だけ。手元の中継は、リモートからの枠の種類・長さ・
  同時に開く論理的な接続の数・最初の応答の形と時間を確かめ、外れたらその SSH を切る（手元の `wtm serve` とほかのマシンは影響を受けない）。
- [ ] AC13: `wtmctl --machine <名前|id> <コマンド>` はそのマシンに対してコマンドを行う（`snapshot`・`workspace`・`tab`・`pane`・`agent`・`watch`）。登録に無い・無効・曖昧な名前、
  繋がっていないマシンは、どこにも送らずに理由を出して失敗する。`--machine` のときは pane の中から呼んだときの自分の pane の歯止め（ローカルの pane の id）を当てない。
- [ ] AC14: 手元とリモートの通信の上限（1 枠の大きさ・送り待ちの量）を超えるときは、その論理的な接続だけを閉じ（ブラウザは繋ぎ直して読み直す）、手元の `wtm serve` のメモリを際限なく使わない。
- [ ] AC15: 有効なマシンが 1 台も無い（登録簿が無い・空・全台が無効）とき、`ssh` を起動せず、サイドバー・`/ws`・`wtmctl`・既存のテストの動作が変わらない。
- [ ] AC16: `wtm --help`・`wtmctl help`・skill ファイル・`docs/herdr-parity.md` の H43・docs に、`wtm machine`・`wtm bridge`・`wtmctl --machine`・herdr との違い・対象外（モバイル・
  自動の導入・Windows のリモート等）・確かめていない範囲（本物の SSH・macOS・手元が Windows）を記す。モバイルの画面はマシンを登録しても手元のマシンだけを表示する（今までどおり）ことも記す。
- [ ] AC17: ビルドした `wtm`（`dist/main.js`）で、2 つの session を「手元」「リモート」に見立て、偽の `ssh` で `wtm machine add` → 手元の `wtm serve` の接続 →
  `/ws?machine=` 越しの `client.hello`・workspace の作成・echo の往復を起動確認（smoke）で確かめる。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 各マシンの見出しの矢印（折りたたみのボタン）で、そのマシンの workspace の一覧を畳む・開く。畳む・開くは選んでいるマシンを変えない（繋ぎ直し中のマシンでもできる）。
  有効なマシンが 1 台も登録されていなければ見出しを出さない（今までのサイドバーのまま）。
- [ ] AC-I2 確定 / 取り消し: ほかのマシンの workspace の行か見出しをクリック（または Enter / Space）で確定し、そのマシンへ切り替わる。切り替えの途中にさらに別のマシンを選んだら、
  最後に選んだものになる（前の切り替えの結果で上書きしない）。切れているマシンの見出しと workspace の行は選べない（押しても切り替わらない）。
- [ ] AC-I3 キーボードだけで完結するか: 見出し・折りたたみのボタン・ほかのマシンの workspace の行は Tab で辿れるボタンで、Enter / Space で選べる。
- [ ] AC-I4 フォーカスの行き先: 切り替えの後、切り替え先のマシンの表示した workspace の focus の pane の端末にフォーカスが移る（今までの workspace の選択と同じ）。
  折りたたみのボタンを押したときはフォーカスはボタンに残る。
- [ ] AC-I5 既存の操作を妨げないか: 選んでいるマシンのまとまりの中の workspace の一覧の操作（選択・ドラッグでの並べ替え・右クリックのメニュー・グループ）とキー操作は今までどおり
  選んでいるマシンに対して働き、ほかのマシンの行でのクリック・キーは選んでいるマシンへ送られない。

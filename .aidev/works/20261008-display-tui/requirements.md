# 要件: 表示の面の端末版 — 引数なしの `soda` に、帯とパネルを描き、操作を返し、配置とたたみを持たせる

## 背景 / 課題

表示の面（pane の中のプログラムが `sodactl display` で出すパネルと帯）は、ブラウザ版にしか出ない（`research.md` T1）。端末版（引数なしの `soda`）だけを使っている利用者には、`sodactl display set` は成功するのに、何も見えない。
利用者は、以前に「端末版にもパネルを出す。作業は分ける」と決め（`20261007-soda-extensions/decisions.md` D8）、2026-10-08 に、配置と状態の作業（`20261008-display-layout`。ブラウザ版）の範囲へ、端末版を入れた。
端末版は「面を描くこと」から作るので、別の work にした（`20261008-display-layout/decisions.md` D2）。

## 目的 / ゴール

端末版だけを使っている利用者にも、pane のプログラムの表示の面（帯とパネル）が見え、その中のボタンを押して指示を返せ、置き場所（上・下・左・右・浮いた窓）とたたみを自分で決められ、それが、再起動の後も保たれている状態。
そのうえで、**面から来た文字（中身・題・名前・ボタンの文字）が何であっても、外側の端末を乗っ取れない**状態（それらに含まれるエスケープシーケンス・制御文字は、1 つも外側の端末へ届かない）。面の中身から、アプリの固定の部分（ラベル・帯の行のボタン）を書き換えられない状態。
プログラムが「いま、HTML を描ける画面があるか・文字だけの画面しか無いか」を、機能の問い合わせで見分けられる状態。

（`.aidev/charter.md` は無い。）

## この作業の範囲の切り方

- **依存**: `20261008-display-layout`（ブラウザ版）。プロトコルの指定（`dock`・`edge`・`collapsed`）・共有の設定の 3 項目・キーの操作 `display_menu` は、そこで入る。
- **PR を 2 つに分ける**（先の PR だけで使える順）:
  **TUI-1** 帯とパネルを描く・操作を返す（置き場所は、パネルは右・帯は上に固定。たたみは、その場かぎり。**収まらない・たたんだ面は、帯の行の印になり、押す〔か `prefix+i`〕と、重ねて開ける**。最小のメニュー）／ **TUI-2** 配置（上下左右・浮いた窓）・たたみの記憶・帯の上下・D&D。
  TUI-1 だけでも、よくある大きさ（80 桁の端末・サイドバーつき＝ pane の中身は 52 桁前後。120 桁を左右に分割＝ 47 桁前後）で、面が見える・開けること（下の機能要件 8）。
  TUI-1 は、ブラウザ版の PR-A だけに依存する（`display_menu` と設定の型）。TUI-2 は、ブラウザ版の PR-A〜PR-C の型・設定・決まりを使う。
- **この文書と `design.md` は、骨子**（勧める案と、利用者に決めてもらう点まで）。タスクへの分解（`tasks.md`）は、利用者の答えの後に書く。

## ユーザーストーリー

- US1: 端末版の利用者として、pane のプログラムが出した進み具合・結果を、その pane の横や上に見たい。なぜなら、ブラウザを開かずに作業しているから。（受け入れ: AC1, AC2, AC3）
- US2: 端末版の利用者として、パネルの中のボタンを、キーかマウスで押して指示を返したい。なぜなら、端末に文字を打たずに選べるから。（受け入れ: AC5, AC-I1〜AC-I5）
- US3: 端末版の利用者として、面の中身に何が入っていても、自分の端末が乗っ取られない（画面を消される・題を変えられる・クリップボードを書かれる・キーを偽装される）と確かでいたい。なぜなら、面の中身は、信頼できるとは限らない pane のプログラムのものだから。（受け入れ: AC4, AC6, AC7, AC8, AC18, AC19）
- US4: 端末版の利用者として、面を、上・下・左・右・浮いた窓に置き、たたみ、帯の行のボタンから開きたい。それを、マウスでも、キーだけでも出来てほしい。（受け入れ: AC10〜AC14）
- US5: 面を出すプログラムの作者として、つながっている画面が、HTML を描けるのか・文字だけなのかを知りたい。なぜなら、文字だけの画面しか無いなら、Markdown か文字で出し直したいから。（受け入れ: AC9）

## スコープ

### 対象

- 端末版が、表示の面を出せる画面として名乗ること（機能の名前と、数え方）。
- 帯（1 行）とパネルを、セルで描くこと。形式ごとの描き方（`text`・`markdown`・`html`・`script-html`）。
- 中身の無害化（エスケープシーケンス・制御文字・書字方向を変える文字）。
- パネルへのフォーカス（`prefix+i`）・スクロール・ボタンを押す・`Esc` で端末へ。マウスでのスクロールと押下。
- 固定のラベル（アプリが描く行）・閉じる・たたむ。
- 配置（上下左右・浮いた窓）・たたみの記憶（状態のフォルダの `tui-state.json`。マシンごと）・帯の上下・帯の行のボタン・大きさの変更・D&D（マウス）と、キー・メニューでの同じ操作。
- 共有の設定の 3 項目（`20261008-display-layout`）を、端末版でも読むこと。
- 文書（`docs/tui.md`・`docs/tui-parity.md`〔W34〕・`docs/display.md`・`docs/sodactl.md`）。

### 対象外

- **`script-html` を動かすこと**: 端末では動かせない。固定の文言を出す。
- **HTML を、見た目どおりに描くこと**（CSS・表の罫線・画像）: しない。文字と、ボタンだけ。**フォーム（入力欄）**: 出さない（固定の文言「入力欄は、ブラウザ版で使えます」）。
- 画像（`data:` の画像を、Kitty graphics で出すこと）: しない。
- `sodactl ask`（質問のフォーム）の端末版: 別の話（`tui-parity.md` W32）。
- 大きさ・位置の記憶を、ブラウザ版と共有すること（単位が px とセルで違う）。
- サーバの側の、面の持ち方・上限・受け口の変更（機能の名前を足すだけ）。

## 機能要件（骨子）

1. **名乗り**: 端末版は、接続のたびに `display.subscribe` で名乗る。名乗る種類は、ブラウザ版と別の名前（`term-panel`・`term-band`・`term-actions`。`decisions.md` TD2）。`sodactl display --features` の、出せる画面の数に、端末版の数が別に出る。
   サーバが、その種類を知っているか（機能の名前 `term`）を、端末版は `display.features` で確かめてから、面を描く（知らないサーバでは、描かない＝数に入らないのに見えている、を作らない）。
2. **帯**: pane の端末の上（TUI-2 からは下にも）に、1 本 1 行で描く。行の左に固定の印、右に閉じる印。中身は、最初の 1 行ぶん（収まらない分は `…`）。帯の中のボタンは、その行に収まる分だけ、押せる形で出す。
3. **パネル**: pane の中身の箱を削って、右（TUI-2 からは左・上・下・浮いた窓にも）に描く。上から、固定のラベルの行（アプリが描く。「表示 · 名前」と、たたむ・閉じるの印。**狭いときは、名前を先に切り、印は残す**。端末版では「隔離」と書かない＝枠の隔離に当たるものは無い）・題・中身。複数あればタブ。端末の大きさ（列・行）は、その分へる（PTY の大きさが変わる）。
4. **形式**: `text` は、無害化して、折り返して描く。`markdown` は、端末向けに描く（見出し・箇条書き・番号つき・チェックリスト・コードの囲み・引用・表・区切り線・強調・リンクは「文字（URL）」）。
   `html` は、**文字だけを取り出して描き、`<button data-soda-action>` だけを、押せる行に読み替える**（`markdown` の中の同じボタンも）。フォームは出さない。
   **ブラウザ版で押せないものは、端末版でも押せない**: コードの囲み・`<textarea>`・`<template>`・`<script>`・`<style>`・コメントの中に書かれた `<button …>` の文字、`disabled`・`hidden` のボタンは、押せる行にしない。
   `script-html` と、知らない形式は、固定の文言「この表示は、ブラウザ版で見られます」。**これらは、初めから、たたんだ形（帯の行の印）で出す**（描けない面が、端末の桁を奪わない。中身は取りに行かない）。
5. **操作**: `prefix+i` で面へフォーカスを移す（パネル → 帯の順に巡る。その間、面の縁が強調され、固定のラベルに「入力はこの表示に届きます（Esc で端末へ）」。本物のカーソルは隠す）。`↑`・`↓`・`PageUp`・`PageDown` でスクロール、`Tab`・`Shift+Tab` でボタンを巡り、`Enter`・`Space` で押す。`Esc` で端末へ。
   押すと、ブラウザ版と同じ `display.action` が届く。マウスが入なら、ホイールでスクロール・ボタンの行のクリックで押す。
   面にフォーカスがある間、キーと貼り付けは pane へ届かない。**prefix のキー・コピーモードなど、端末版のモードは、今までどおり効く**（面が受けるのは、端末版のキーの振り分けが「端末へ渡す」と決めたキーだけ）。モードが替わった・焦点の pane が替わった・その面が見えなくなった・重ねる部品が開いた、で、面のフォーカスは外れる。
   **メニュー**（`display_menu`。`prefix+shift+i`）: TUI-1 から、面の一覧と、面ごとの「開く／たたむ・閉じる・（複数のパネルの）選ぶ」。マウスが切でも、これで全部できる。
6. **無害化**: 面から来る文字の全部（中身・題・面の名前・ボタンの文字・メニューの行と知らせに入れる名前）は、**解釈（Markdown・HTML・実体参照の復元）の後で**、描く前に必ず、エスケープシーケンス・制御文字・書字方向を変える文字・行と段落の区切り・見えない書式の文字を取り除く。
   面の箱へ文字を書く関数は 1 つだけで、無害化を通った文字しか受けない。面から来た文字を、ほかの出口（窓の題・通知・クリップボード・stderr）へ渡さない。
7. **配置とたたみ**（TUI-2）: ブラウザ版と同じ決まり（置き場所は面ごと・優先は 利用者 ＞ プログラムの指定 ＞ 設定・帯の行のボタン・端末の最小を保って自動でたたむ）。単位はセル（端末の最小は 30 列・8 行）。
   記憶は、状態のフォルダ（`tui-state.json`。同じフォルダを使う端末版で共通）に、**つないでいるマシンごと**に持つ（別のマシンへつないでも、元のマシンの分を捨てない）。
   浮いた窓は、その pane の端末の領域の中に重ねて描く（開いたまま端末を打てる）。D&D は、パネルの固定のラベルの行をつかむ（マウスが入のとき）。キーでは、`display_menu`（`prefix+shift+i`）のメニューから、同じことが全部できる。
8. **収まらないとき・1 列表示**: 端末（pane の中身）が最小（30 列・8 行。`decisions.md` TD5）を下回るなら、パネルは自動でたたまれ、**帯の行の印**（理由つき）になる。1 列表示（幅が狭い）でも同じ。帯は出す。
   TUI-1 から、帯の行の印を押す（か `prefix+i`）と、そのパネルを、pane の上に**重ねて**開ける（端末版の今の重ねる部品と同じ＝開いている間は、キーはそのパネルへ。`Esc` で閉じる。端末の大きさは変えない）。TUI-2 で、これが浮いた窓（開いたまま端末を打てる）になる。
   プログラムの `--collapsed` と、設定「表示のパネルの初めの状態」は、TUI-1 から読む（たたんで始まる面は、帯の行の印）。

## 非機能要件 / 制約

- **端末を乗っ取らせない**（US3。脅威と対策の表は `design.md`）。無害化は、**入力の長さに比例する時間**で終わること（2 MiB の、どんな中身でも。既存の `stripControl` は使わない＝`research.md` T8）。
- **既存の端末版の操作を妨げない**: 面があっても、分割・境界のドラッグ・pane の名前の D&D・選択とコピー・スクロールバー・コピーモード・1 列表示・ほかのクライアントの大きさで動いている pane の切り取り、が今までどおり動く。面の領域の押下・ホイール・動きを、pane のプログラムへ流さない。
  面の領域の当たりは、境界・スクロールバー・pane の枠（名前のドラッグ・右クリックのメニュー）より先に見る（枠を描かない・隙間なしの設定でも、帯の行が「pane の名前のドラッグ」や「境界のつかみ」にならない）。pane のスクロールバーは、端末の右の縁に出す（パネルの外側ではなく）。
- **pane を生かし続ける**: 中身の前処理（無害化・Markdown の解釈）の失敗・大きな中身（2 MiB）で、描画・入力が止まらない（前処理は、版ごとに 1 回・上限つき）。
- **ブラウザ版と食い違わない**: 同じ面が、ブラウザと端末版の両方に出る。閉じる（［×］）は、全部の画面から消える。たたみ・置き場所は、画面ごと。
- **古い版との組み合わせ**: 古いサーバ（`display.subscribe` を知らない・新しい種類を知らない）では、黙って出ない（今までどおり）。
- `docs/tui-parity.md` の W34 を、実装に合わせて書き直す。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 面は、プログラムの `set` で出る。たたんだ面・収まらない面は、帯の行の印（マウス）・`prefix+i`・メニュー（`prefix+shift+i`）で開く。閉じる（面を消す）・たたむのは、固定のラベルの行の印（マウス）・メニュー（TUI-1 から。マウスが切でも出来る）。
- [ ] AC-I2 確定 / 取り消し: ボタンは、`Enter`・`Space`・クリックで、その時点で 1 件の操作が届く（取り消しは無い）。D&D・大きさの変更・窓の移動は、離した・`Enter` で確定し、`Esc` で元へ戻る。
- [ ] AC-I3 キーボードだけで完結するか: `prefix+i` → `Tab` → `Enter` → `Esc`、`prefix+shift+i` → 矢印 → `Enter`（開く／たたむ・閉じる・パネルを選ぶ。TUI-2 からは、置き場所・大きさ・窓の移動も）、が、マウス無しで通る（設定「マウスを使う」が切でも）。
- [ ] AC-I4 フォーカスの行き先: `prefix+i` で、パネル（最初のボタンがあれば、それ）へ。`Esc` で、元の pane の端末へ。面の出現・更新・消滅では動かない。
- [ ] AC-I5 既存の操作を妨げないか: フォーカスが面にある間、キーと貼り付けは pane へ流れない。prefix のキー・コピーモード・navigate・resize は、今までどおり効く（端末版が自分で描いているので、中身はキーを見ない。モードに入ったら、面のフォーカスは外れる）。面の上のホイールは面をスクロールし、pane のスクロールバックを動かさない。

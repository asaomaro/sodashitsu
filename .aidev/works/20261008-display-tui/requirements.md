# 要件: 表示の面の端末版 — 引数なしの `soda` に、帯とパネルを描き、操作を返し、配置とたたみを持たせる

## 背景 / 課題

表示の面（pane の中のプログラムが `sodactl display` で出すパネルと帯）は、ブラウザ版にしか出ない（`research.md` T1）。端末版（引数なしの `soda`）だけを使っている利用者には、`sodactl display set` は成功するのに、何も見えない。
利用者は、以前に「端末版にもパネルを出す。作業は分ける」と決め（`20261007-soda-extensions/decisions.md` D8）、2026-10-08 に、配置と状態の作業（`20261008-display-layout`。ブラウザ版）の範囲へ、端末版を入れた。
端末版は「面を描くこと」から作るので、別の work にした（`20261008-display-layout/decisions.md` D2）。

## 目的 / ゴール

端末版だけを使っている利用者にも、pane のプログラムの表示の面（帯とパネル）が見え、その中のボタンを押して指示を返せ、置き場所（上・下・左・右・浮いた窓）とたたみを自分で決められ、それが端末ごとに保たれている状態。
そのうえで、**面の中身が何であっても、外側の端末を乗っ取れない**状態（エスケープシーケンス・制御文字は、1 つも外側の端末へ届かない）。面の中身から、アプリの固定の部分（ラベル・帯の行のボタン）を書き換えられない状態。
プログラムが「いま、HTML を描ける画面があるか・文字だけの画面しか無いか」を、機能の問い合わせで見分けられる状態。

（`.aidev/charter.md` は無い。）

## この作業の範囲の切り方

- **依存**: `20261008-display-layout`（ブラウザ版）。プロトコルの指定（`dock`・`edge`・`collapsed`）・共有の設定の 3 項目・キーの操作 `display_menu` は、そこで入る。
- **PR を 2 つに分ける**（先の PR だけで使える順）:
  **TUI-1** 帯とパネルを描く・操作を返す（置き場所は、パネルは右・帯は上に固定。たたみは、その場かぎり）／ **TUI-2** 配置（上下左右・浮いた窓）・たたみの記憶・帯の上下・帯の行のボタン・D&D。
  TUI-1 は、ブラウザ版の PR-A だけに依存する（`display_menu` と設定の型）。TUI-2 は、ブラウザ版の PR-A〜PR-C の型・設定・決まりを使う。
- **この文書と `design.md` は、骨子**（勧める案と、利用者に決めてもらう点まで）。タスクへの分解（`tasks.md`）は、利用者の答えの後に書く。

## ユーザーストーリー

- US1: 端末版の利用者として、pane のプログラムが出した進み具合・結果を、その pane の横や上に見たい。なぜなら、ブラウザを開かずに作業しているから。（受け入れ: AC1, AC2, AC3）
- US2: 端末版の利用者として、パネルの中のボタンを、キーかマウスで押して指示を返したい。なぜなら、端末に文字を打たずに選べるから。（受け入れ: AC5, AC-I1〜AC-I5）
- US3: 端末版の利用者として、面の中身に何が入っていても、自分の端末が乗っ取られない（画面を消される・題を変えられる・クリップボードを書かれる・キーを偽装される）と確かでいたい。なぜなら、面の中身は、信頼できるとは限らない pane のプログラムのものだから。（受け入れ: AC6, AC7, AC8）
- US4: 端末版の利用者として、面を、上・下・左・右・浮いた窓に置き、たたみ、帯の行のボタンから開きたい。それを、マウスでも、キーだけでも出来てほしい。（受け入れ: AC10〜AC14）
- US5: 面を出すプログラムの作者として、つながっている画面が、HTML を描けるのか・文字だけなのかを知りたい。なぜなら、文字だけの画面しか無いなら、Markdown か文字で出し直したいから。（受け入れ: AC9）

## スコープ

### 対象

- 端末版が、表示の面を出せる画面として名乗ること（機能の名前と、数え方）。
- 帯（1 行）とパネルを、セルで描くこと。形式ごとの描き方（`text`・`markdown`・`html`・`script-html`）。
- 中身の無害化（エスケープシーケンス・制御文字・書字方向を変える文字）。
- パネルへのフォーカス（`prefix+i`）・スクロール・ボタンを押す・`Esc` で端末へ。マウスでのスクロールと押下。
- 固定のラベル（アプリが描く行）・閉じる・たたむ。
- 配置（上下左右・浮いた窓）・たたみの記憶（端末ごと。`tui-state.json`）・帯の上下・帯の行のボタン・大きさの変更・D&D（マウス）と、キー・メニューでの同じ操作。
- 共有の設定の 3 項目（`20261008-display-layout`）を、端末版でも読むこと。
- 文書（`docs/tui.md`・`docs/tui-parity.md`〔W34〕・`docs/display.md`・`docs/sodactl.md`）。

### 対象外

- **`script-html` を動かすこと**: 端末では動かせない。固定の文言を出す。
- **HTML を、見た目どおりに描くこと**（CSS・表の罫線・画像）: しない。文字と、ボタンだけ。**フォーム（入力欄）**: 出さない（固定の文言「入力欄は、ブラウザ版で使えます」）。
- 画像（`data:` の画像を、Kitty graphics で出すこと）: しない。
- `sodactl ask`（質問のフォーム）の端末版: 別の話（`tui-parity.md` W32）。
- 大きさ・位置の記憶を、ブラウザ版と共有すること（単位が px とセルで違う）。
- サーバの側の、面の持ち方・上限・受け口の変更（機能の名前を足すだけ）。

## 機能要件（骨子）

1. **名乗り**: 端末版は、接続のたびに `display.subscribe` で名乗る。名乗る種類は、ブラウザ版と別の名前（`term-panel`・`term-band`・`term-actions`。`decisions.md` TD2）。`sodactl display --features` の、出せる画面の数に、端末版の数が別に出る。
2. **帯**: pane の端末の上（TUI-2 からは下にも）に、1 本 1 行で描く。行の左に固定の印、右に閉じる印。中身は、最初の 1 行ぶん（収まらない分は `…`）。
3. **パネル**: pane の中身の箱を削って、右（TUI-2 からは左・上・下・浮いた窓にも）に描く。上から、固定のラベルの行（アプリが描く）・題・中身。複数あればタブ。端末の大きさ（列・行）は、その分へる（PTY の大きさが変わる）。
4. **形式**: `text` は、無害化して、折り返して描く。`markdown` は、端末向けに描く（見出し・箇条書き・番号つき・チェックリスト・コードの囲み・引用・表・区切り線・強調・リンクは「文字（URL）」）。
   `html` は、**文字だけを取り出して描き、`<button data-soda-action>` だけを、押せる行に読み替える**（`markdown` の中の同じボタンも）。フォームは出さない。`script-html` と、知らない形式は、固定の文言「この表示は、ブラウザ版で見られます」。
5. **操作**: `prefix+i` でパネルへフォーカスを移す（その間、パネルの縁が強調され、固定のラベルに「入力はこの表示に届きます（Esc で端末へ）」）。`↑`・`↓`・`PageUp`・`PageDown` でスクロール、`Tab`・`Shift+Tab` でボタンを巡り、`Enter`・`Space` で押す。`Esc` で端末へ。
   押すと、ブラウザ版と同じ `display.action` が届く。マウスが入なら、ホイールでスクロール・ボタンの行のクリックで押す。
6. **無害化**: 面の中身・題は、描く前に必ず、エスケープシーケンス（列ごと）・制御文字・書字方向を変える文字を取り除く。外側の端末へ出るのは、格子のセルから作った列だけ。
7. **配置とたたみ**（TUI-2）: ブラウザ版と同じ決まり（置き場所は面ごと・優先は 利用者 ＞ プログラムの指定 ＞ 設定・帯の行のボタン・端末の最小を保って自動でたたむ）。単位はセル。記憶は `tui-state.json`（端末ごと）。
   浮いた窓は、その pane の端末の領域の中に重ねて描く（開いたまま端末を打てる）。D&D は、パネルの固定のラベルの行をつかむ（マウスが入のとき）。キーでは、`display_menu`（`prefix+shift+i`）のメニューから、同じことが全部できる。
8. **1 列表示・小さい画面**: 1 列表示（幅が狭い）では、ドックのパネルは自動でたたむ（帯の行のボタンから、浮いた窓として開ける）。帯は出す。

## 非機能要件 / 制約

- **端末を乗っ取らせない**（US3。脅威と対策の表は `design.md`）。
- **既存の端末版の操作を妨げない**: 面があっても、分割・境界のドラッグ・pane の名前の D&D・選択とコピー・スクロールバー・コピーモード・1 列表示・ほかのクライアントの大きさで動いている pane の切り取り、が今までどおり動く。面の領域のクリックを、pane のプログラムへ流さない。
- **pane を生かし続ける**: 中身の前処理（無害化・Markdown の解釈）の失敗・大きな中身（2 MiB）で、描画・入力が止まらない（前処理は、版ごとに 1 回・上限つき）。
- **ブラウザ版と食い違わない**: 同じ面が、ブラウザと端末版の両方に出る。閉じる（［×］）は、全部の画面から消える。たたみ・置き場所は、画面ごと。
- **古い版との組み合わせ**: 古いサーバ（`display.subscribe` を知らない・新しい種類を知らない）では、黙って出ない（今までどおり）。
- `docs/tui-parity.md` の W34 を、実装に合わせて書き直す。

- [ ] AC3: `text` は文字のまま、`markdown` は端末向けに整形され（見出し・箇条書き・コード・表・リンク）、`html` は文字だけが出る（タグ・`<style>`・`<script>` の中身は出ない）。`script-html`・知らない形式は、固定の文言。長い中身は、スクロールできる。
- [ ] AC4: 固定のラベルの行（「pane のプログラムの表示 · 名前」）と、帯の左の印は、アプリが描き、中身・題に何を書いても変わらない・隠せない（中身は、自分の箱の外のセルを書けない）。
- [ ] AC5: `prefix+i` でパネルへ移り、`Tab` でボタンを選び、`Enter` で押すと、`sodactl display wait` に、ブラウザ版と同じ形の `display.action`（名前・値・版）が届く。`Esc` で端末へ戻る。フォーカスがパネルにある間、打ったキーは pane へ届かない。面が出た・更新された・消えたとき、フォーカスは動かない（フォーカスのあるパネルが消えたら、端末へ戻る）。

- [ ] AC7: 書字方向を変える文字・幅 0 の文字・結合文字の大量の連なり・全角と絵文字が、面の箱の外のセル（固定のラベル・端末・隣の pane）を書き換えない・ずらさない。
- [ ] AC8: 2 MiB の中身・1 行が非常に長い中身・壊れた Markdown／HTML でも、端末版が止まらず、キー入力に応じ続ける（前処理は上限つき。超えた分は「（以下は省略）」）。
- [ ] AC9: `sodactl display --features` と `set` の結果の、出せる画面の数に、端末版の数が、ブラウザ版とは別の項目で出る（ブラウザが 0・端末版が 1 のとき、`panel` は 0・端末版の項目は 1）。古いサーバでは、端末版は面を出さず、誤りも出さない。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 面は、プログラムの `set` で出る。たたんだ面は、帯の行のボタン（マウス）・`prefix+i`・メニューで開く。閉じる（面を消す）のは、固定のラベルの行の［×］（マウス）・メニュー・パネルにフォーカスがあるときの決まったキー。
- [ ] AC-I2 確定 / 取り消し: ボタンは、`Enter`・`Space`・クリックで、その時点で 1 件の操作が届く（取り消しは無い）。D&D・大きさの変更・窓の移動は、離した・`Enter` で確定し、`Esc` で元へ戻る。
- [ ] AC-I3 キーボードだけで完結するか: `prefix+i` → `Tab` → `Enter` → `Esc`、`prefix+shift+i` → 矢印 → `Enter`、が、マウス無しで通る。
- [ ] AC-I4 フォーカスの行き先: `prefix+i` で、パネル（最初のボタンがあれば、それ）へ。`Esc` で、元の pane の端末へ。面の出現・更新・消滅では動かない。
- [ ] AC-I5 既存の操作を妨げないか: フォーカスがパネルにある間、キーは pane へ流れない。prefix のキーは、今までどおり効く（端末版が自分で描いているので、中身はキーを見ない）。面の上のホイールは面をスクロールし、pane のスクロールバックを動かさない。

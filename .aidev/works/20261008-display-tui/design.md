# 仕様（骨子）: 表示の面の端末版 — 帯とパネルをセルで描く・操作を返す・配置とたたみ

**この文書は骨子**（方針・図・脅威と対策・決めていない点）。型と関数の細部・`tasks.md` は、`decisions.md` TD2〜TD7 の利用者の答えの後に書く。出所は `research.md`（T・V の番号）と、`20261008-display-layout/design.md`（ブラウザ版。以下「B の design」）。

## 概要

端末版が `display.subscribe` で名乗り、面の見出しと中身を受け取って、pane の中身の箱を削った領域に、帯（1 行）とパネルをセルで描く。パネルへのフォーカスの状態を足し、ボタンの押下を `display.action` で返す（TUI-1）。
そのうえに、置き場所・たたみ・帯の行のボタン・浮いた窓・D&D を、B の design と同じ決まりで、セルの単位で載せる（TUI-2）。

## 設計方針

1. **外側の端末へ出るのは、格子（`Grid`）のセルだけ**（`research.md` T4）。面の中身は、必ず「無害化 → 行の並び → `Grid` へ書く」を通る。部品が、外側の端末へ直に書く道を足さない。
2. **割り付けは、純粋な関数**（`computeLayout`）に足す。`PaneBox` に、面の領域（帯の行・各側のパネル・帯の行のボタン）の箱を足し、`content`（端末の箱）を削る。PTY の大きさは、`content` から今までどおり決まる（`research.md` T5）。
3. **割り付けの決まりは、ブラウザ版と同じ関数の形**にする（B の design の `resolvePaneDisplays`。単位が px からセルに替わるだけ）。置き場所・たたみの導出（`effectiveDock` ほか）は、client-core へ移して、ブラウザ版と端末版が同じものを使う（移すのは TUI-2 の最初のタスク）。
4. **固定の部分は、アプリが別の行に描く**。中身は、自分の箱（矩形）の中のセルしか書けない（書く関数が、箱で切る）。
5. **中身の前処理（無害化・解釈・折り返し）は、版ごとに 1 回**（描画のたびにやらない）。上限つき。

## 画面（セル）

```
┌ pane（枠）───────────────────────────────────────────────────────────┐
│▍表示 [▣ diff] [▭ ci] │ build: 緑 3・赤 0                          × │ ← 帯（1 行）。左がアプリの部分（印とボタン）
│$ make test                             │表示（隔離）· progress  ⋮▾×│ ← 固定のラベルの行（アプリが描く）
│ PASS src/a.test.ts                     │進捗                        │ ← 題
│ PASS src/b.test.ts                     │────────────────────────────│
│ ...                                    │# 進み具合                  │ ← 中身（無害化して、端末向けに描く）
│                                        │ - [x] 設計                 │
│          端  末                        │ - [ ] 実装                 │
│   （最低 40 列・10 行）                │[ ▸ 続ける ]  [ ▸ やめる ]  │ ← 押せる行（アプリが描く形）
│$ █                                     │                            │
└──────────────────────────────────────────────────────────────────────┘
浮いた窓（TUI-2）は、端末の箱の中に、枠つきの矩形を重ねて描く。開いていても、キーは端末へ届く。
落とせる場所（D&D）は、その pane の上・下・左・右・中央のセルの背景を、強調色に塗る（pane の名前の D&D と同じ見せ方）。
```

## インターフェース / データ構造（骨子）

- **protocol**: `DISPLAY_RENDER_FEATURES` に `term-panel`・`term-band`・`term-actions`。`DisplayRenderers` に `termPanel`・`termBand`・`termActions`。サーバの `renderers()` が数える（TD2）。ほかは変えない。
- **端末版の通信**（新 `packages/tui/src/display/TuiDisplay.ts`）: 接続のたびに `display.subscribe`（`PaneRegistry.connectionOpened` と同じ時機）。`display.updated`・`display.removed` で見出しを更新。中身は、描く面だけ `display.get` を小分けで取る（ブラウザ版の `DisplayController` と同じ手順）。
  古いサーバ（`not_found`）では、黙って何もしない。マシンの切り替えで捨てる。
- **前処理**（新 `packages/tui/src/display/renderContent.ts`。純粋）: `prepare(format, content, width) → { lines: Line[]; buttons: Button[] }`。`Line` は、文字（無害化の後）と飾り（太字・薄い・色）の並び。`Button` は、行・桁の範囲と、操作の名前・値。
  形式ごと: `text`（折り返し）・`markdown`（TD4）・`html`（TD3）・ほかは固定の文言。
- **無害化**（新 `packages/tui/src/display/sanitize.ts`。純粋）: `stripControl`（client-core）で、エスケープシーケンスを列ごと落とす → 残った C0（改行・タブ以外）・DEL・C1・U+2028/2029・書字方向を変える文字（U+202A〜202E・U+2066〜2069）・幅 0 の書式の文字を落とす → タブは空白に → 1 つのセルに足す結合文字は、決まった数まで。
- **割り付け**: `LayoutInput` に、pane ごとの面（種類・置き場所・たたみ・望む大きさ）を渡す。`PaneBox` に `displays`（帯の行・各側のパネル・帯の行のボタンの箱）を足し、`content` を削る。
- **描画**: `Renderer.render` の pane のループで、`paintDisplays(grid, box, …)`。浮いた窓は、pane の後・飾りの前の層（TD6）。面の領域は、前の格子から写す最適化の対象にしない（`research.md` V3）。
- **フォーカス**: `UiState` に「フォーカスのある面」（面の id か無し）。その間、キーは `KeyRouter` の前で端末版が受ける（スクロール・`Tab`・`Enter`・`Esc`。prefix のキーは `KeyRouter` へ渡す）。
- **マウス**: `MouseController` の当たりの判定に、面の領域を足す（pane の中身より先に見る。面の上の押下・ホイールを、pane のプログラムへ流さない）。`Drag` に、パネルの固定のラベルの行をつかむ種類（TUI-2）。
- **状態**: `TuiState` に `displayLayout`（B の design の `DisplayLayoutPrefs` と同じ形。大きさ・矩形はセル）。`readTuiState` に、項目ごとの検査と上限。共有の設定の 3 項目は `PrefsModel` が読む（設定の画面の `BROWSER_ONLY` の注記を外す）。
- **キー**: `focus_display`・`display_menu` の、端末版の実装（今は知らせだけ）。

## 脅威と対策（端末版の隔離の要）

端末版には、ブラウザ版の枠（iframe・sandbox・CSP）に当たるものが無い。**面の中身は、文字として描くだけ**なので、守るのは「文字が、文字のまま、決まった箱の中に出ること」。

| # | 脅威 | 対策 | 確かめ |
|---|---|---|---|
| E1 | 中身・題の CSI（画面の消去・カーソルの移動・スクロールの範囲・代替画面）で、端末版の画面を壊す | 無害化が、エスケープシーケンスを列ごと落とす。そのうえで、外側の端末へは、格子のセルから作った列しか出ない（中身の文字が、そのまま出力の列に入らない）。`Grid` へ書く関数は、制御文字を持つ文字を書かない | 出した列に、中身に入れた列が現れない（AC6） |
| E2 | OSC で、外側の端末の題を変える・クリップボードへ書く（OSC 52）・ハイパーリンクを仕込む（OSC 8）・通知を出す（OSC 9／777） | E1 と同じ。端末版は、中身から OSC を作らない。URL は文字として出すだけ（押して開く機能は付けない） | 試験用の外側の端末の題・クリップボードの要求が変わらない（AC6） |
| E3 | DCS・APC・Kitty graphics・sixel で、画像や端末の応答を仕込む | E1 と同じ（DCS／SOS／PM／APC は列ごと落とす）。画像は描かない | AC6 |
| E4 | 8 ビットの C1（0x9B など）を、エスケープの代わりに使う | 無害化が、C1 と、その列を落とす | AC6 |
| E5 | 書字方向を変える文字・幅 0 の文字で、固定のラベルやボタンの見た目を偽る・文字の順を入れ替える | 無害化が落とす。固定のラベルは、中身と別の行に、アプリが描く | AC4・AC7 |
| E6 | 全角・絵文字・結合文字の連なりで、桁をずらして、箱の外（固定のラベル・端末・隣の pane）を書く | 書く関数が、幅を数えて箱の幅で切る（`Grid.text` の `maxWidth`・幅 2 の文字が箱の端をまたぐなら書かない）。1 つのセルの結合文字の数に上限 | AC7 |
| E7 | 中身に、固定のラベル・帯の行のボタン・押せる行に似せた文字を書いて、利用者を誤解させる | 似せた文字は書ける（限界。ブラウザ版と同じ）。押せるのは、アプリが作った押せる行だけ（色と印が違う）。似せた文字を押しても、何も起きない | docs の限界 |
| E8 | 大きな中身・非常に長い 1 行・壊れた Markdown／HTML で、前処理が終わらない・画面が固まる | 前処理は版ごとに 1 回・行数と時間の上限つき（超えた分は「（以下は省略）」）。失敗したら、固定の文言 | AC8 |
| E9 | 面が、利用者のキーを横取りする | 中身は動かない（スクリプトを動かさない）。キーが面へ行くのは、利用者が `prefix+i` で移した間だけで、受けるのは端末版自身の処理（スクロール・押す）。面の出現・更新で、フォーカスは動かない | AC5 |
| E10 | 面の領域のクリック・ホイールが、pane のプログラムへ届く（マウスを求めているプログラム） | 当たりの判定で、面の領域を先に見る | AC15 |
| E11 | `script-html` の中身を、文字として出すことで、スクリプトの文面が読めてしまう・長い | 出さない（固定の文言だけ。中身は取りに行かない） | AC3 |
| E12 | 題（サーバが制御文字を断っている）に、後の版・別の経路で制御文字が入る | 題も、中身と同じ無害化を通す | AC6 |

## 振る舞い（骨子）

- **1 列表示**: ドックのパネルは自動でたたむ。帯と、帯の行のボタンは出す。浮いた窓は、開ける。
- **ほかのクライアントの大きさで動いている pane**（左上合わせで切り取る表示）: 面は、その端末版の割り付けで描く。端末の箱が、申告できる大きさより小さく見えるだけ（今の切り取りと同じ）。
- **面が閉じた**（［×］・`close`・`navigated` など）: 全部の画面から消える（サーバが配る）。端末版は `display.report` を送らない（枠が無いので、`navigated`・`unresponsive`・`focus_steal` は起きない）。
- **たたむ・置き場所**（TUI-2）: B の design「たたむ・開く」「置き場所の変更」「プログラムの指定と、利用者の記憶」と同じ決まり。端末版では、枠の作り直しは無い（描き直すだけ）。

## 決めていない点（design の続きで決める）

- Markdown の解釈を自前にするか（TD4・V2）。
- 前の格子から写す最適化と、面の領域（V3）。
- 前処理の上限の値（行数・時間。V4）。
- パネルにフォーカスがあるときの、閉じる・たたむのキー。
- TUI-2 の、浮いた窓の層と、選択の反転・画像・トーストとの描く順。
- `effective*`・割り付けの関数を client-core へ移すときの、ブラウザ版の側の差分（移すだけで、動きは変えない）。

## 受け入れ基準との対応（骨子）

- AC1: `TuiDisplay`（名乗り・見出し・中身の取得）と、`computeLayout` の面の箱・`paintDisplays`。
- AC2: `PaneBox.content` を削る（PTY の大きさは `content` から決まる）。自動のたたみは、割り付けの関数。
- AC3: `renderContent.prepare` の形式ごとの描き方。
- AC4: 固定のラベルの行と帯の印は `paintDisplays` が描く。中身は、箱で切る関数だけが書く。
- AC5: `UiState` のフォーカスのある面と、キーの振り分け。`display.action` は、ブラウザ版と同じ要求。
- AC6: `sanitize.ts` と、「外側の端末へ出るのは格子のセルだけ」（脅威 E1〜E4・E12）。
- AC7: 箱で切る・幅を数える・結合文字の上限（脅威 E5・E6）。
- AC8: 前処理の上限（脅威 E8）。
- AC9: `term-panel`・`term-band`・`term-actions` と `renderers()`。
- AC10: 割り付けの関数（4 つの側・帯の上下・帯の行のボタン）。
- AC11: `TuiState.displayLayout` と、導出の関数（client-core）。
- AC12: 浮いた窓の層（TD6）。
- AC13: `MouseController` の新しいドラッグの種類と、落とせる場所の強調。
- AC14: `display_menu` のメニュー（端末版の `ContextMenu` の項目）。
- AC15: 当たりの判定・割り付けが、面の無い pane では今と同じ結果（既存のテスト）。
- AC16: 文書。
- AC17: 負の対照。
- AC-I1: 帯の行のボタン・`prefix+i`・メニュー・［×］。
- AC-I2: ボタンの押下・D&D と大きさの変更の確定と取り消し。

- AC-I4: フォーカスのある面の状態（入る・出る・消えたとき）。
- AC-I5: キーの振り分け（面にある間は pane へ流さない・prefix は通す）・ホイール。

# 仕様（骨子）: 表示の面の端末版 — 帯とパネルをセルで描く・操作を返す・配置とたたみ

**この文書は骨子**（方針・図・脅威と対策・決めていない点）。型と関数の細部・`tasks.md` は、`decisions.md` TD2〜TD7 の利用者の答えの後に書く。出所は `research.md`（T・V の番号）と、`20261008-display-layout/design.md`（ブラウザ版。以下「B の design」）。

## 概要

端末版が `display.subscribe` で名乗り、面の見出しと中身を受け取って、pane の中身の箱を削った領域に、帯（1 行）とパネルをセルで描く。パネルへのフォーカスの状態を足し、ボタンの押下を `display.action` で返す（TUI-1）。
そのうえに、置き場所・たたみ・帯の行のボタン・浮いた窓・D&D を、B の design と同じ決まりで、セルの単位で載せる（TUI-2）。

## 設計方針

1. **面から来た文字が、外側の端末へ出る道は、格子（`Grid`）のセルだけ**。面の文字は、必ず「解釈（Markdown・HTML・実体参照の復元）→ **無害化** → 行の並び → 面の箱へ書く関数 1 つ → `Grid`」を通る。**無害化は、解釈の後**（前に掛けると、実体参照 `&#x1b;` の復元で制御文字が生まれ直す）。
   面の箱へ書く関数（`paintDisplayText`）は 1 つだけで、`Grid.set` を直に使わない（`Grid.set` は文字を検査しない。`research.md` T4）。念のため、その関数も、C0・DEL・C1・書字方向を変える文字を持つ文字を書かない（二重の守り）。
   **面から来た文字を、ほかの出口（窓の題・通知・クリップボード・BEL・stderr・例外の文）へ渡さない**（不変条件。面の出来事を、外側の端末の通知にしない）。
2. **割り付けは、純粋な関数**（`computeLayout`）に足す。`PaneBox` に、面の領域（帯の行・各側のパネル・帯の行のボタン）の箱を足し、`content`（端末の箱）を削る。PTY の大きさは、`content` から今までどおり決まる（`research.md` T5）。
3. **割り付けの決まりは、ブラウザ版と同じ関数の形**にする（B の design の `resolvePaneDisplays`。単位が px からセルに替わるだけ）。置き場所・たたみの導出（`effectiveDock` ほか）は、client-core へ移して、ブラウザ版と端末版が同じものを使う（移すのは TUI-2 の最初のタスク）。
4. **固定の部分は、アプリが別の行に描く**。中身は、自分の箱（矩形）の中のセルしか書けない（書く関数が、箱で切る）。
5. **解釈と無害化は、版ごとに 1 回。折り返しは、幅ごとに、見えている範囲だけ**（幅は、境界のドラッグで 50ms ごとに変わる）。どれも、入力の長さに比例する時間で終わる作り（正規表現の遅延一致で終端を探さない）。上限つき。

## 画面（セル）

```

│▍表示 [▣ diff] [▭ ci] │ build: 緑 3・赤 0                          × │ ← 帯（1 行）。左がアプリの部分（印とボタン）
│$ make test                             │表示 · progress        ⋮▾×│ ← 固定のラベルの行（アプリが描く）
│ PASS src/a.test.ts                     │進捗                        │ ← 題
│ PASS src/b.test.ts                     │────────────────────────────│
│ ...                                    │# 進み具合                  │ ← 中身（無害化して、端末向けに描く）
│                                        │ - [x] 設計                 │
│          端  末                        │ - [ ] 実装                 │
│   （最低 30 列・8 行）                 │[ ▸ 続ける ]  [ ▸ やめる ]  │ ← 押せる行（アプリが描く形）
│$ █                                     │                            │
└──────────────────────────────────────────────────────────────────────┘
浮いた窓（TUI-2）は、端末の箱の中に、枠つきの矩形を重ねて描く。開いていても、キーは端末へ届く。
落とせる場所（D&D）は、その pane の上・下・左・右・中央のセルの背景を、強調色に塗る（pane の名前の D&D と同じ見せ方）。
```

## インターフェース / データ構造（骨子）

- **protocol**: `DISPLAY_RENDER_FEATURES` に `term-panel`・`term-band`・`term-actions`。`DisplayRenderers` に `termPanel`・`termBand`・`termActions`。`DISPLAY_FEATURES` に `term`（サーバが、この種類を数えられる印）。サーバの `renderers()` が数える（TD2）。ほかは変えない。
- **端末版の通信**（新 `packages/tui/src/display/TuiDisplay.ts`）: 接続のたびに `display.subscribe`（`PaneRegistry.connectionOpened` と同じ時機）。`display.updated`・`display.removed` で見出しを更新。中身は、描く面だけ `display.get` を小分けで取る（ブラウザ版の `DisplayController` と同じ手順）。
  先に `display.features` を見て、`term` が無ければ（か、`not_found` なら）、名乗らず・描かない。マシンの切り替えで、面の写しを捨てる（記憶は捨てない）。`display.report` は送らない。`script-html`・知らない形式の面は、中身を取りに行かない。
- **前処理**（新 `packages/tui/src/display/renderContent.ts`。純粋）: 2 段。`parse(format, content) → Block[]`（版ごとに 1 回。解釈と無害化。`Block` は、段落・見出し・箇条書き・コード・表・押せるもの）と、`layout(blocks, width, 範囲) → { lines: Line[]; buttons: Button[] }`（幅ごと・見えている範囲だけ）。
  `Line` は、文字（無害化の後）と飾り（太字・薄い・色）の並び。`Button` は、行・桁の範囲と、操作の名前・値（名前と値は、ブラウザ版と同じ `checkDisplayAction` を通す）。
  形式ごと: `text`（折り返し）・`markdown`（TD4）・`html`（TD3）・ほかは固定の文言。
- **無害化**（新 `packages/tui/src/display/sanitize.ts`。純粋。**`stripControl` は使わない**＝長さの 2 乗の時間が掛かる。`research.md` T8）: 文字を 1 回だけ前から読む状態機械。
  1. エスケープシーケンスを落とす: ESC と、それに続く列（CSI は終わりのバイトまで・OSC／DCS／SOS／PM／APC は終端〔BEL・ST〕まで。**終端が無ければ、その行の終わりまで**）。8 ビットの C1 の始まり（U+0090・U+009B・U+009D ほか）も同じ扱い。
  2. 残りから落とす文字（コードポイントの種類で決める）: C0（改行は行の区切りとして残す・タブは空白 1 つに）・DEL・C1・**書式の文字（Unicode の一般カテゴリ Cf）の全部**（書字方向の制御 U+202A〜202E／U+2066〜2069／U+200E／U+200F／U+061C・幅 0 の空白と接合 U+200B〜200D／U+2060〜2064・U+FEFF・U+00AD・U+180E・タグ文字 U+E0000 台 ほか）・行と段落の区切り（Zl・Zp＝U+2028・U+2029）・私用と未割り当ての一部（design の続きで一覧にする）。
     ZWJ（U+200D）も落とす（つないだ絵文字は、ばらけて出る。幅の計算が外側の端末と食い違うのを避ける）。異体字セレクタ（U+FE00〜FE0F・U+E0100 台）も落とす。孤立したサロゲートは U+FFFD にする。
  3. 1 つのセルに足す結合文字（幅 0 の Mn・Me）は、決まった数（たとえば 4）まで。
  URL は文字として出すだけ（`%1b` などは戻さない）。
- **割り付け**: `LayoutInput` に、pane ごとの面（種類・置き場所・たたみ・望む大きさ）を渡す。`PaneBox` に `displays`（帯の行・各側のパネル・帯の行のボタンの箱）を足し、`content` を削る。
- **描画**: `Renderer.render` の pane のループで、`paintDisplays(grid, box, …)`。浮いた窓は、pane の後・飾りの前の層（TD6）。面の領域は、前の格子から写す最適化の対象にしない（`research.md` V3）。
- **フォーカス**: `UiState` に「フォーカスのある面」（面の id か無し）。キーは、今までどおり `KeyRouter` が先に見る（prefix・直接のキー・copy／navigate／resize のモード）。**`KeyRouter` が「端末へ渡す」と決めたキーだけ**を、面にフォーカスがあれば面へ回す（スクロール・`Tab`・`Enter`・`Esc`。pane へは送らない）。貼り付けは、面にフォーカスがある間は捨てる。本物のカーソルは隠す。
  面のフォーカスを外すとき: `Esc`・モードが terminal でなくなった・焦点の pane が替わった・tab や workspace が替わった・拡大・その面が消えた／たたまれた・重ねる部品（メニュー・ダイアログ）が開いた。
- **収まらない面を重ねて開く**（TUI-1）: 今の `Overlay`（モーダル）として、そのパネルを pane の箱の中に描く（`CommandPopup` と同じ置き方）。中身・ボタン・スクロールは、ドックのパネルと同じ関数。
- **マウス**: `MouseController` の当たりの判定に、面の領域を足す。**押下・ホイール・動きの、いちばん先に見る**（スクロールバー・境界 `dividerAt`・pane の枠〔名前のドラッグ・右クリックのメニュー〕より先。`dividerAt` の「どの pane の中身でもない桁は境界」の条件にも、面の箱を入れる）。面の上の入力を、pane のプログラムへ流さない。
  pane のスクロールバーは、端末（`content`）の右の縁に置く（いまは枠の右の罫線。右にパネルがあると、パネルの外側に出てしまう）。`Drag` に、パネルの固定のラベルの行をつかむ種類（TUI-2）。
- **状態**: `TuiState` に `displayLayout`（**つないでいるマシンの鍵 → B の design の `DisplayLayoutPrefs` と同じ形**。大きさ・矩形はセル）。`readTuiState` に、項目ごとの検査と上限。もう無い pane の分を捨てるのは、つないでいるマシンの分だけ。
  書くときは、ファイルを読み直して、自分の `displayLayout` のうち変えた鍵だけを重ねる（同じフォルダを使う 2 つの端末版が、互いの記憶を消さない）。古い版の `soda` が書くと、知らないキーとして消える（限界。docs に書く）。共有の設定の 3 項目は `PrefsModel` が読む（設定の画面の `BROWSER_ONLY` の注記を外す）。
- **キー**: `focus_display`・`display_menu` の、端末版の実装（今は知らせだけ）。

## 振る舞い（骨子）

- **収まらないとき・1 列表示**: ドックのパネルは自動でたたみ、帯の行の印になる。帯は出す。印から、TUI-1 では重ねて（モーダル）、TUI-2 では浮いた窓として開ける。
- **描けない形式**（`script-html`・知らない形式）: 初めから、帯の行の印（「ブラウザ版で見られます」）。開いても、固定の文言だけ。
- **割り付けの型**: `PaneBox` の面の箱（`displays`）は、面が無ければ項目ごと省く（面の無い pane では、今の結果と等しい＝既存の `computeLayout.test.ts` の `toEqual` が通る）。
- **ほかのクライアントの大きさで動いている pane**（左上合わせで切り取る表示）: 面は、その端末版の割り付けで描く。端末の箱が、申告できる大きさより小さく見えるだけ（今の切り取りと同じ）。
- **面が閉じた**（［×］・`close`・`navigated` など）: 全部の画面から消える（サーバが配る）。端末版は `display.report` を送らない（枠が無いので、`navigated`・`unresponsive`・`focus_steal` は起きない）。
- **たたむ・置き場所**（TUI-2）: B の design「たたむ・開く」「置き場所の変更」「プログラムの指定と、利用者の記憶」と同じ決まり。端末版では、枠の作り直しは無い（描き直すだけ）。

## 決めていない点（design の続きで決める）

- Markdown の解釈を自前にするか（TD4・V2）。
- 前の格子から写す最適化と、面の領域（V3）。
- 前処理の上限の値（行数・時間。V4）。
- 外側の端末と幅の表が食い違う文字の扱い（V5・E16）。
- 無害化で落とす「私用・未割り当て」の範囲の一覧。
- TUI-2 の、浮いた窓の層と、選択の反転・画像・トーストとの描く順。
- `effective*`・割り付けの関数を client-core へ移すときの、ブラウザ版の側の差分（移すだけで、動きは変えない）。

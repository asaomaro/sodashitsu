## D1: 規模は full・モードは interactive

- **背景**: 着手時の三層の判定（`aidev-00-start` 手順 4）。対応指示は「進め方はこのリポジトリの通常どおり（aidev）」。
- **決定**: `profile: full`・`mode: interactive`。ブランチは `main` から切った `feature/sodactl-ask`。
- **理由・代替案**: protocol・server・web・cli に新しい振る舞いを足すので light の条件（振る舞いを変えない小規模）を満たさない。モードは利用者が選んだ（interactive）。
  直前の依頼（ファイルのリンクとドロップ）は利用者の指示で別ブランチにコミットして PR #73 にした（この work には混ぜない）。
- **影響**: PR #73 と同じファイル（`messages.ts`・`errors.ts`・`clientError.ts`・`main.ts`・`composeServer.ts`・`deps.ts`・`methods/index.ts`）の近い場所を触る。マージ順で衝突しうる。

## D2: design の方針（design.md を書く前の提示。方針の事前承認）

- **背景**: requirements の未確定事項 1〜10 と research の R1〜R11。有力な案が複数ある項目があるので、design.md を書く前に方針を提示する。
  下の (e)・(f)・(g) は製品の振る舞いの選択なので、利用者に選んでもらう。ほかは推奨を採る前提で提示する。

### 決定（方針）

**通信**

- (a) **ブラウザを見分ける印 = ブラウザが接続のたびに呼ぶ `ask.subscribe`**（未確定 4・R1・R11）。hello（kind）は変えない。`ask.subscribe` を呼んだ接続だけを
  「フォームを出せるブラウザ」に数える（kind が desktop / mobile であることも確かめる）。応答で、いま待っている質問の一覧（定義つき）を返す——再読み込み・再接続・
  マシンの切り替えの後の出し直し（AC9）を同じ 1 回で済ませる（`command.list`・`graph.get` と同じ「接続ごとに取り直す」形）。
  端末版・古い画面・sodactl・軽い接続は呼ばないので数えない。
  - 採らなかった案: hello に項目を足す（`features: ["ask"]`）——hello の形を変えると端末版・sodactl・中継のテストに波及し、出し直しの取得は別に要る。
    kind だけで判定——端末版が `desktop` と名乗るので `unavailable` にできない（research F1）。
- (b) **定義・回答はイベントに載せない**（R2）。全接続に配るイベントは `ask.opened {askId, paneId}`・`ask.closed {askId, paneId}` だけ（中身なし）。
  `ask.opened` を受けたブラウザが `ask.get {askId}` で定義を取る（`ask.subscribe` 済みの接続だけに返す）。回答は `ask.answer`、取り消しは `ask.cancel`。
  - 採らなかった案: 定義をイベントに載せる——`sodactl watch`・軽い接続へ漏れる（research F13）。宛先を絞って送る口を `WsGateway` に足す——`client.error` 以外に先例が無く、
    `ClientSink`・中継・テストの偽物に手が入る。
- (c) **sodactl は 1 つの長い要求 `ask.open` で待つ**（R3）。`ask.open {paneId, spec, timeoutMs}` は結果（`{status, …}`）が決まるまで応答しない。
  時間切れはサーバが持ち（R4）、sodactl は要求の時間切れを「`timeoutMs` ＋余裕」に上書きする（`wsClient` に要求ごとの時間切れの口を足す）。
  Ctrl+C・切断は、接続が閉じたことをサーバが `onClientGone` で拾って質問を取り消す（AC10）。
  - 採らなかった案: 短い要求＋イベントで待つ（既存の `agent wait` の形）——結果（回答）をイベントに載せられないので、閉じた後に結果を取りに行く要求と、
    取りに来るまで結果を持ち続ける台帳・その後始末が要る。長い要求なら、要求の寿命＝質問の寿命になり、後始末が接続の切断 1 つにまとまる。
- (d) **検査は protocol の同じ関数を CLI・サーバ・ブラウザで使う**（未確定 6・R7）。CLI が先に検査して使い方の誤り（終了コード 2）にし、サーバも同じ関数で検査する
  （信用しない。`invalid_ask_spec`）。中身は `ask.py` の `normalize()` と同じ＋上限。`showIf` が下の質問を指す定義は断らない（ask-form と同じく、その質問が出ないだけ）。
  知らない項目は落として無視する。

**振る舞い（利用者に選んでもらう 3 つ。推奨を先頭に書く）**

- (e) **対象の pane が表示されていないブラウザ**（未確定 1）:
  1. 【推奨】どのブラウザにも、その場でダイアログを出す。題の上に「どの pane（workspace・tab・pane の名前）からの質問か」を出す。閉じたら、開く前にフォーカスのあった場所へ戻す
     （その pane が表示されていればその pane の端末）。表示を勝手に切り替えない。——ask-form の「ウィンドウが前に出る」体験に近く、最初の回答を採る要件と素直に合う。
     ほかのモーダルの間はトーストが押せない（research F39）問題も避けられる。
  2. その pane を表示しているブラウザにだけすぐ出し、表示していないブラウザには残るトースト「pane ○○ が質問しています［開く］」を出して、押したら（その pane へ移って）出す。
     ——別の作業を遮らないが、どのブラウザも表示していなければ、押すまで質問は出ない。
- (f) **同じ pane からの 2 つめの質問**（未確定 2）:
  1. 【推奨】断る（`ask_busy`。終了コード 1）。前の質問はそのまま。——待っている前の呼び出しを、後から来たものが黙って取り消さない。
  2. 前を取り消して入れ替える（前の呼び出しへは `cancelled`）。
- (g) **待っている間に、出せるブラウザが 1 つも無くなったとき**（未確定 7）:
  1. 【推奨】そのまま待つ（時間切れまで）。ブラウザが戻れば出し直す。——スマートフォンはブラウザを裏に回すと接続が切れるので、短い猶予で打ち切ると質問が頻繁に消える。
     「ブラウザが 1 つも無い → `unavailable`」は、質問を受け付けた時点でだけ判定する。
  2. 猶予（30 秒）だけ待ち、戻らなければ `unavailable` を返す。——呼び出し側が早く `AskUserQuestion` へ切り替えられる。

**ほかの決定（推奨を採る）**

- (h) **保存した SSH のマシン**（未確定 3）: リモートの pane の質問は、そのマシンを表示中のブラウザに出る（既存の中継のまま。新しい仕組みは足さない）。そのマシンを表示中のブラウザが
  1 つも無ければ `unavailable`（軽い接続は数えない）。リモートのマシンで `sodactl login` 済みであることが前提（既存と同じ）。`docs/machines.md` に書く。
  - 採らなかった案: 軽い接続を宛先に数え、選んでいないマシンの質問も出す——マシン別のストア・回答の送り先・pane の id の衝突の扱いが要り、範囲が広がる。backlog に残す。
- (i) **対象の指定**（未確定 8）: 呼び出し元の pane だけ。`--machine <local 以外>` は使い方の誤り（終了コード 2）、`--pane` は設けない。
- (j) **ダイアログ**（未確定 9・R5・R9）: Vue の部品として作り直す（`form.html` は埋めない）。状態は既存の単一の枠ではなく別枠のストアに置き、`modalOpen` に含める（キーが端末へ漏れない）。
  ほかのダイアログが開いていても潰さず、その上に重ねる（閉じたら元のダイアログへフォーカスが戻る）。同時に複数の pane から質問が来たら、受けた順に 1 つずつ出す。
  ログイン・切り離しからの復帰と再接続では、`ask.subscribe` の応答で出し直す。
- (k) **誤操作の手当て**（research Q9・R6）: 開いたときのフォーカスは操作部品ではなく、ダイアログの見出し（どの pane からの質問か）に置く——打っている途中の `Space`・`Enter` が
  回答として効かない。背景クリックでは閉じない。
- (l) **確定のキー**（未確定 10）: `Ctrl+Enter`／`Cmd+Enter`・決定ボタン・1 行の入力欄での `Enter`（`form.html` と同じ）。どれも IME の変換中（`isComposing`・`keyCode 229`）は無視する。
  「質問が 1 つだけ・`single`・`note:false`」の即確定は、**クリック・タップ・`Space`／`Enter` で選んだときだけ**（矢印キーで移っただけでは確定しない）。
  - `form.html` との違い: `form.html` は矢印キーで移っただけでも確定する（`change` で確定するため）。返る JSON は同じなので契約は変わらない。`docs/sodactl.md` に書く。
- (m) **どの pane か**（AC11）: ダイアログの最上部に、アプリが描く固定の行（定義の外。定義の `title`・`intro` では消せない・書き換えられない）として
  「pane『<名前>』（<workspace>／<tab>）のプログラムからの質問」を出す。定義の `title` はその下に内容として出す。
- (n) **上限**（未確定 5）: 定義全体 256 KiB（JSON の UTF-8）／質問 100／1 つの質問の選択肢 200／`id`・`value` 200 文字／`label` 等の短い文字列 500 文字／
  `desc`・`help`・`intro` 4,000 文字／`colors` は 1 つの選択肢に 16 個まで／回答は自由入力・補足それぞれ 10,000 文字／`--timeout` は 1,000 ms〜86,400,000 ms（24 時間。既定 540,000）。
  確かめ用の定義（7 問・テーマ 13 件）は 8.4 KiB。
- (o) **`colors`**（AC12）: `#rgb`・`#rgba`・`#rrggbb`・`#rrggbbaa` の形だけを色として使い、ほかは捨てる（確かめ用の定義は `#1a56db` の形）。
  文字は全て Vue の文字の差し込み（`v-html` を使わない）。
- (p) **ログ**（AC13）: サーバのログに出すのは askId・paneId・件数・結果の種類だけ。定義・回答は出さない（検査の失敗は `RpcError` で返し、素の例外にしない）。
- (q) **契約**: 対応指示の入出力の契約は変えない。加えるのは、2 つめの質問の `ask_busy`（終了コード 1）と、上限・(l) の違いの明記。

## D5: tasks は分割しない（subtask にしない）

- **背景**: tasks 工程の split 判定。切り方の候補は「1 つの tasks.md」か「01-backend（protocol・server・cli）＋ 02-web（ダイアログ・E2E・docs）」。

## D6: hello 前の接続は `ask.subscribe` できてしまう（許容）

- **背景**: T3 の点検の指摘。接続は hello の前から既定の `desktop` で `ClientRegistry` に載る（research F2）。`client.hello` を送る前の external の接続は `ask.subscribe` を通り、購読者になれる。
- **決定**: 防がない。購読の後で kind が `external` に変わった接続は、`isBrowserKind` の再確認で購読者として扱わない（修正済）。
- **理由・代替案**: 防ぐには registry に「hello 済み」の印を足す必要があり、既存の `client.hello` の流れに手が入る。hello 前の接続は、sodactl も端末版もブラウザも認証済みの同じ権限の接続（pane のシェルを操作できる）で、定義・回答を読める・差し込めても新しい権限は増えない。
- **影響**: 端末版（hello で `desktop`）は `ask.subscribe` しないので数えない（設計どおり）。悪意のある認証済みクライアントが購読して回答を差し込める点は、docs に「同じ session の認証済みの接続は質問に答えられる」と書く。

## D7: AC-I5 のホイールの検証は、端末のスクロール位置ではなくマウスの報告で行う（design からの逸脱）

- **背景**: design「受け入れ基準との対応」の AC-I5 は「`.xterm-viewport` の `scrollTop` が変わらない」で検証するとした。実物のブラウザで調べると、この xterm.js（6.0）の描画では DOM のスクロール要素の `scrollTop` が動かない（`.xterm-helpers` だけが溢れて見える）。
- **決定**: pane のアプリにマウスの報告（DECSET 1000）を求めさせ、ダイアログの上・背景でホイールを回しても、ブラウザが pane へ送る INPUT にホイールの報告（`ESC[<64;`・`ESC[<65;`）が増えないことを CDP で見る。ダイアログが無いときに報告が送られることを対照として先に確かめる。
- **理由・代替案**: 端末が背面でスクロールするかは、ホイールが端末に届いたかと同じ。届けば（マウス報告を求めていなければ）scrollback が動き、求めていれば報告になる。どちらも「ホイールが背面へ漏れたか」を見ていて、後者はブラウザが送ったフレームで判定できる（e2e-observe-browser）。
- **影響**: design の AC-I5 の検証手段の記述だけが変わる。

## D8: 跨タスクの点検（ラウンド 1）の指摘と対応

- **背景**: 全タスクを終えた後の点検（`aidev taskcheck cross`）。指摘 7 件。
- **決定**: 直した——(1) OS 通知からの移動（`NotificationController.#focusEntry`）が質問のフォームの戻り先を直していなかった。(2) 回答の zod の id の長さを UTF-16 の余裕つきにした（定義の検査はコードポイント）。(3) `text` の `default` が回答の上限を超える定義は誤りにした。(4) docs の「端末版も購読できる」を、事実どおり（`ask.subscribe` できるのはブラウザの種別の接続だけ）に直した。(5) docs に id の重複の例外を書いた。(6) SKILL.md の `--machine` の表記を揃えた。(7) AC-I4・AC-I5・AC11 の検証の足りない所（見出しのフォーカスの E2E・質問中も別の入力の出力が届く・設定を閉じた後の操作・出どころの行が title で変わらない単体）を足した。
- **理由・代替案**: 指摘どおり。`AskController.cancel` が `ask_closed` 以外の失敗でもストアから外す点（接続が生きたままなら、サーバは時間切れまで待つ）は、取り消せなかったときに画面を塞がないことを優先して残す。
- **影響**: 仕様の変更は (3) の検査 1 つ。docs/sodactl.md の上限の節に影響は無い。

## D9: 追補（質問の型が増えた）への対応——未対応の型は `unavailable`、新しい型・項目の対応は今回しない

- **背景**: test 工程の途中で、利用者がリポジトリの根に `sodashitsu-ask-form-対応指示-追補.md` を置いた。ask-form（別リポジトリ）の定義に質問の型（`edit`・`rank`・`table`）と項目（`code`・`image`・`audio`・`group`・`preview`・`filter`・`remember` 等）が増えた。
  追補の §1 は「対応していない型の質問があれば、黙って落とさず、ダイアログを出さずに `unavailable`（終了コード 0）を返す」を求める。§2・§3（新しい型・項目の対応）は「対応するなら」「無視してよい」。
- **決定**: §1 だけを今回の work に取り込む（requirements の AC15・design・tasks の T12）。`single`・`multi`・`text` 以外の文字列の `type` は、知らない文字列を含めて `unavailable`（理由に型の名前。短い識別子だけ）。
  CLI は接続せずサーバへ送らない。サーバも同じ判定（ほかのクライアントが `ask.open` を送っても黙って落とさない）。`type` が文字列でないなど、型以外の誤りは今までどおり終了コード 2。
  §2 の新しい型（`edit`・`rank`・`table`）と §3 の項目の対応は、この work では**しない**（backlog。完了報告に明記）。`image`・`audio` のファイルの読み込みも同じ（対応しない。値が `https://`・`data:` のものは、プレビューを出さないので何も起きない）。
- **理由・代替案**: 型の追加ごとに ask-form の画面を Vue で作り直すのは大きく、元の対応指示の範囲（`form.html` と同じ 3 つの型）を超える。§1 は安全のための最小の約束（回答が欠けたまま `answered` にならない）で、小さく足せる。
  代替案: 知らない型を無視する（元の指示。却下——追補が理由を述べるとおり、回答が欠けたまま進む）／知らない型を使い方の誤り（終了コード 2。却下——ask-form は誤りでなく `AskUserQuestion` への切り替えを期待する）。
- **影響**: AC6 の「知らない `type`」を「文字列でない `type`」に直した。契約（`unavailable` の意味）に「対応していない型の質問がある」が加わる（`docs/sodactl.md`・`SKILL.md`・完了報告）。ask-form 側は、`unavailable` を `AskUserQuestion` への切り替えとして扱う既存の約束のままで足りる。

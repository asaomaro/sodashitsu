# 要件: pane の中のプログラムが、ブラウザ版の画面に質問のフォームを出せるようにする（`sodactl ask`）

出典: リポジトリの根の `sodashitsu-ask-form-対応指示.md`（利用者が書いた対応指示。以下「対応指示」）。
入出力の正典は ask-form の `SKILL.md`（`/workspaces/public_docs/docs/ClaudeCode/skills/other/ask-form/`。別リポジトリ）、
画面の挙動の参考は同じ場所の `form.html`、定義の検査の参考は `ask.py` の `normalize()`。

## 背景 / 課題

Claude Code のスキル **ask-form** は、利用者への質問をまとめて 1 画面に出し、回答を JSON で受け取る（`AskUserQuestion` の
「1 問 4 択・1 回 4 問まで」に収まらない確認に使う）。今の仕組みは、`ask.py` が `127.0.0.1` に受け口を立て、
**`ask.py` が動いているマシンの画面**に Edge / Chrome の `--app` ウィンドウを開く。

Sodashitsu のブラウザ版で、pane の中の Claude Code が ask-form を使うと:

- ブラウザがサーバと同じマシンなら、別のウィンドウが開いて使える。
- **ブラウザが別のマシン（外からの接続）だと使えない**。ウィンドウはサーバ側の画面に開き、手元のブラウザはサーバの `127.0.0.1` に
  届かない。今は `ASK_FORM=off` を設定して `AskUserQuestion` に切り替えるしかない（選択肢の多い確認ができない）。

pane の中のプログラムから「その pane を見ている利用者」へ質問を届ける経路が、Sodashitsu には無い
（`sodactl` はサーバの状態を読む・操作するだけで、ブラウザの画面に何かを出して答えを待つ口が無い）。

## 目的 / ゴール

- pane の中のプログラムが出した質問のフォームが、**その session を開いているブラウザの画面の上**（pane に重なるダイアログ）に出て、
  回答が呼び出し元へ戻る状態。ブラウザがサーバと同じマシンでも別のマシンでも同じに動き、新しいウィンドウ・タブは開かない。
- ask-form の質問の定義（JSON）をそのまま渡せ、ask-form の結果と同じ形の JSON が返る状態（ask-form 側は、`sodactl ask` に
  定義を渡して `status` を自分の終了コードへ写すだけで済む）。
- フォームを出せないとき（ブラウザが 1 つもつながっていない等）は、待たずにそうと分かる状態（呼び出し側が `AskUserQuestion` に切り替えられる）。
- 質問が残らない状態: 呼び出し側が終わった・時間切れ・サーバが止まる・pane が閉じたときに、ダイアログが画面に残らず、
  ブラウザが再読み込み・再接続しても、待っている質問は出し直される。
- pane のプログラムが Sodashitsu 自身の画面を装えない状態（どの pane からの質問かが必ず示され、定義の中の文字は文字としてだけ表示される）。

## ユーザーストーリー

- US1: サーバと別のマシンのブラウザで Claude Code を使う開発者として、エージェントからの選択肢の多い確認に、手元のブラウザの
  画面の上で答えたい。なぜなら、今はウィンドウがサーバ側の画面に開いて見えず、4 択に削った質問でしか答えられないから。
  （受け入れ: AC1, AC3, AC4, AC-I1〜AC-I5）
- US2: サーバと同じマシンのブラウザで使う開発者として、同じ操作で答えたい。なぜなら、どこから開いているかで確認の出方が
  変わると（別ウィンドウ／画面内）、慣れが効かないから。（受け入れ: AC2）
- US3: ask-form（と、それを部品に使うスキル）の作者として、質問の定義と結果の形を変えずに `sodactl ask` へ渡したい。
  なぜなら、ask-form の利用側（md-to-doc 等）の定義と結果の読み方をそのまま保ちたいから。（受け入れ: AC3, AC5, AC6, AC14）
- US4: pane の中で動くエージェント（Claude Code 等。actor は AI）として、フォームを出せない・答えが来ない・取り消されたを区別して
  知りたい。なぜなら、`AskUserQuestion` に切り替える・聞き直す・利用者に確かめる、のどれをするかが変わるから。（受け入れ: AC5, AC6, AC7）
- US5: 同じ session を複数のブラウザ（PC とスマートフォン等）で開いている利用者として、どれか 1 つで答えれば済ませたい。
  なぜなら、見ていない画面に質問が残り続けると、後から誤って答えてしまうから。（受け入れ: AC8, AC9, AC10）
- US6: 利用者として、質問がどの pane のプログラムから来たかを見て答えたい。なぜなら、pane の中では信用できないプログラムも動き、
  Sodashitsu 自身の確認（ログイン・削除の確認等）に見せかけた質問を出されうるから。（受け入れ: AC11, AC12）
- US7: サーバの運用者として、pane のプログラムが大きな定義・大量の質問でサーバとブラウザを詰まらせないでほしい。また、回答の中身が
  ログに残らないでほしい。なぜなら、補足欄には何が書かれるか分からないから。（受け入れ: AC12, AC13）
- US8: スマートフォンで開いている利用者として、同じフォームに答えたい。なぜなら、エージェントの確認を待たせたまま PC に戻れない場面があるから。
  （受け入れ: AC4, AC-I3）

## スコープ

### 対象

- `sodactl ask [--timeout <ms>]`: stdin から質問の定義を読み、stdout に結果の JSON を 1 行出すコマンド（`sodactl help`・
  `packages/cli/skills/sodactl/SKILL.md` への記載を含む）。
- サーバ: 質問を受け付け、対象のブラウザへ「出す／閉じる」を知らせ、最初の回答を採って呼び出し元へ返す口。回答待ちの管理
  （pane ごと・時間切れ・呼び出し側の切断・pane が閉じた・サーバの停止）。
- ブラウザ版（デスクトップ・モバイル）: 質問のダイアログ。ask-form の `form.html` と同じことができる（下の機能要件）。
- 定義の検査（`ask.py` の `normalize()` 相当）と大きさの上限。
- docs: `docs/sodactl.md`（コマンド・入出力の契約・上限）・`docs/tui-parity.md`（端末版の扱いの 1 行）・`docs/verification.md`（手元で確かめる項目）。

### 対象外

- **ask-form 側の変更**（別リポジトリ public_docs の `ask.py`）。契約が確定した後に、利用者が別途行う。
- 端末版（引数なしの `soda`・TUI）でのフォームの表示。端末版しかつながっていないときは `unavailable`。
- `AskUserQuestion` そのものの置き換え。
- 選択肢ごとのプレビュー（ask-form にも無い）。
- ブラウザを 1 つも開いていない利用者へ知らせる手段（OS の通知等）で質問を届けること。

## 機能要件

### コマンド（対応指示「入出力の契約」）

- **入力**: stdin に ask-form の質問の定義（JSON）。受け付ける項目は ask-form の `SKILL.md`「質問の定義」のとおり——全体の `title`・`intro`・
  `submit`・`note`・`questions[]`、質問の `id`・`label`・`type`（`single`/`multi`/`text`）・`help`・`options[]`・`default`・`allowOther`
  （`otherLabel`・`otherPlaceholder`）・`showIf`・`required`・`multiline`・`placeholder`・`minWidth`、選択肢の `value`・`label`・`desc`・
  `recommended`・`colors`（選択肢は文字列だけでも書ける）。**知らない項目は無視する**（ask-form 側が先に項目を足しても壊れない）。
- **出力**: stdout に JSON を 1 行。`status` は次の 4 つ。

  | `status` | いつ | ほかの項目 |
  |---|---|---|
  | `answered` | 決定が押された | `answers`（id → 値。`single`/`text` は文字列、`multi` は配列。`showIf` で隠れた質問は入れない）・`custom`（自由入力した質問の id。あれば）・`note`（補足。あれば） |
  | `cancelled` | キャンセル・閉じた・pane が閉じられた | — |
  | `timeout` | `--timeout` が過ぎた（既定 540000 ms） | — |
  | `unavailable` | フォームを出せるブラウザが 1 つもつながっていない等 | `reason`（人が読む理由） |

- **終了コード**: 上の 4 つの `status` を返せたときは 0。サーバ・接続・認証のエラーは 1、使い方と定義の誤りは 2（既存の sodactl の規則のまま）。
- 対象の pane は呼び出し元（`SODA_PANE_ID`）。pane の外から呼ばれたら `caller_pane_unknown`（既存と同じ扱い）。
- 契約を変える必要が出たら、変えた形を `docs/sodactl.md` に書き、完了報告に明記する。

### 画面（対応指示「画面」）

- フォームは **pane の上に重なる画面内のダイアログ**として出す（新しいタブ・ポップアップ・`window.open` は使わない）。
- `form.html` と同じことができる: 全質問を 1 画面に並べる・既定を選択済みで出す・`showIf` による出し分け（上から順に判定）・複数選択・
  「その他」の自由入力・補足欄・未回答の質問の強調・`Ctrl+Enter` で決定・`Esc` でキャンセル・「質問が 1 つだけ・`single`・`note:false`」なら
  選んだ時点で決定。
- 選択肢の数に画面の都合の上限を設けない（13 件のテーマ一覧が並ぶ。スクロールできる）。モバイルの画面でも操作できる。
- **どの pane からの質問かをダイアログに必ず示す**（pane の名前か ID）。
- 決定・キャンセルの後は、フォーカスをその pane の端末へ戻す。ダイアログが開いている間のキー入力を pane へ流さない。

### どのブラウザに出すか（対応指示「どのブラウザに出すか」）

- その session につながっているブラウザ（`client.hello` の `kind` が desktop / mobile）に出す。複数あれば全部に出し、
  **最初の回答を採って、ほかは閉じる**。`external`（sodactl 等）には出さない。
- 対象の pane が今表示されていないブラウザ（別の tab・workspace を見ている）でも、**黙って待たせない**
  （その場で出すか、知らせて pane へ移ってから出すかは design で決める）。
- つながっているブラウザが 1 つも無ければ、待たずに `unavailable`。端末版しかつながっていないときも `unavailable`。
- 保存した SSH のマシンの pane（`docs/machines.md`。bridge 越し）から呼ばれたときに、手元のブラウザへ届くか、届かないなら
  `unavailable` になるかを確かめて決める（どちらにしても、待ち続けて時間切れにはしない）。

### 待ち合わせと後始末（対応指示「待ち合わせと後始末」）

- 待っている途中でブラウザが再読み込み・再接続したら、質問を出し直す（回答待ちは pane ごとにサーバが持つ）。
- `sodactl ask` が終了した（Ctrl+C・接続が切れた）ら、ダイアログを閉じる。サーバが止まるときも残さない。
- 同じ pane からの質問は同時に 1 つまで。2 つめの扱い（断る／前を取り消す）は design で決める。

## 非機能要件 / 制約

- **安全**
  - 定義の中の文字はすべて**文字として**表示する（HTML として解釈しない）。`colors` は色の値として妥当なものだけ使う。
  - 大きさの上限を設ける（定義全体のバイト数・質問の数・選択肢の数・文字列の長さ）。超えたら使い方の誤り（終了コード 2）。
    値は design で決め、`docs/sodactl.md` の「サーバ側の上限」に足す。回答（自由入力・補足）の大きさにも上限を置く。
  - 認証・Origin/Host の判定は既存の sodactl と同じ経路を使う（新しい抜け道を作らない）。pane の環境に token を入れない方針は変えない。
  - 回答の内容（`answers`・`custom`・`note`）と定義の中身をサーバのログに残さない。
- **互換**: 既存の方式・イベント・`sodactl` のコマンドの振る舞いを変えない。この機能を知らない版のブラウザ・サーバ・sodactl が混ざっても
  壊れない（古いサーバへの `sodactl ask` は、待たずに分かる失敗になる）。
- **PJ の規約**: E2E はブラウザの側で合否を見る（`.aidev/conventions/e2e-observe-browser.md`）。不具合の修正に足す回帰テストは、
  直す前のコードで落ちることを確かめる（`.aidev/conventions/regression-negative-control.md`）。
- 実装は Vue の部品として作り直すことを勧められている（テーマ・キー操作・既存のダイアログと揃う）。`form.html` を iframe で埋める案を
  採るなら理由を残す（どちらにするかは design）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: `sodactl ask` が受け付けられると開く（利用者の操作では開かない）。閉じるのは、決定・キャンセル（ボタン・`Esc`）・
      ほかのブラウザでの回答・呼び出し側の終了・時間切れ・pane が閉じた・サーバの停止。ダイアログの外側のクリックでは閉じない
      （選びかけの回答を誤って捨てない）。利用者の操作以外で閉じたときは、入力しかけの内容は捨てられる。
- [ ] AC-I2 確定 / 取り消し: 決定ボタン・`Ctrl+Enter`（macOS は `Cmd+Enter` も）で確定。未回答の質問があれば確定せず、その質問を強調して
      そこへスクロールする。「質問が 1 つだけ・`single`・`note:false`」のときは、選択肢（「その他」以外）を選んだ時点で確定。
      キャンセルボタン・`Esc` で取り消し（`cancelled` が返る）。
- [ ] AC-I3 キーボードだけで完結するか: 開く（自動）→ `Tab`・矢印で質問と選択肢を移る → `Space`/矢印で選ぶ → 「その他」・補足に文字を打つ →
      `Ctrl+Enter` で決定、までをマウス無しで通せる。モバイルではタップと画面のキーボードだけで同じことができる。
- [ ] AC-I4 フォーカスの行き先: 開いたらダイアログの中（最初の質問。**decisions D2 (k)・D3 で「出どころの見出し」に変更**——打っている途中のキーが回答として効かないため）へ移り、`Tab` はダイアログの中で巡る。閉じたら、その pane が表示されて
      いればその pane の端末へ戻る（表示されていなければ、開く前にフォーカスのあった場所へ戻る）。
- [ ] AC-I5 既存の操作を妨げないか: ダイアログが開いている間のキー入力（prefix のキー・`Ctrl+V` の画像の貼り付け・ふつうの文字）と
      ホイールは pane・キーの割り当てへ漏れない。ほかのダイアログ（設定・確認等）が開いているときに質問が来ても、どちらも操作不能にならない。
      質問を出していないブラウザの操作・ほかの pane の入出力は止まらない。

## 未確定事項 / 確認したいこと

1. 対象の pane が表示されていないブラウザでの扱い: その場でダイアログを出す／知らせて pane へ移ってから出す。
2. 同じ pane からの 2 つめの質問: 断る（`ask_busy` 等の code）／前を取り消して入れ替える。
3. 保存した SSH のマシンの pane からの呼び出しが、手元のブラウザへ届くか（中継の向きと、`/ws?machine=` で開いているブラウザの
   `kind` がリモートのサーバからどう見えるか）。届かないなら `unavailable` にする。
4. 「その session につながっているブラウザ」の範囲: 名前付き session ごとにサーバが別なので、そのサーバの `/ws` につながっている
   desktop / mobile の接続、でよいか。切り離し中（`client.detach`）・ログイン待ちの画面の扱い。
5. 上限の値（定義全体のバイト数・質問の数・選択肢の数・文字列の長さ・回答の大きさ）と、`--timeout` の上限。
6. 定義の検査をどこで行うか（sodactl・サーバ・両方）と、`ask.py` の `normalize()` に無い検査（`showIf` が自分より下の質問を指す等）を足すか。
7. 待っている間に、つながっていたブラウザが全部切れたときの扱い（そのまま待つ／`unavailable` で返す）。
8. `sodactl ask` を pane の外から `--pane <id>` 等で対象を指定して呼べるようにするか（対応指示は呼び出し元だけ）。
9. Vue の部品として作り直すか、`form.html` を埋めるか（対応指示は前者を勧める）。既存のダイアログ・キーのモード（`dialog`）との重なり方。
10. `Ctrl+Enter` が既存のキーの割り当て・IME の変換中の Enter とぶつからないか。

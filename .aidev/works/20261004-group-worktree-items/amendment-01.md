実装の途中で、利用者が実際の画面を見て、次を決めた。**この文書は、requirements.md・design.md・tasks.md の、食い違う記述より優先する。**見た目の見本は同じフォルダの `mock-sidebar.html`（ブラウザで開く。利用者が選んだのは **B3**〔ブラウザ版〕・**T4**〔端末版〕・**「グループなし」の案 2**。ページの下の「グループに入っていないものの扱い」の案 2 の 2 枚が、最終の形に一番近い）。

## A. worktree グループに入るのは、worktree（フォルダ）ごとに 1 つだけ

**きっかけ**: worktree の workspace を選んだまま「＋新規」で workspace を作ると、同じフォルダで開くので、worktree グループの子として並んでしまう。利用者の決定は「worktree グループは worktree を表すもの。同じフォルダの 2 つ目は、worktree グループの外の通常の workspace にする」。

- **判定に `worktreeKey` を足す**: その worktree を一意に示す絶対パス（`git rev-parse --path-format=absolute --git-dir` の値。本体は共通ディレクトリと同じ、linked worktree は `<共通ディレクトリ>/worktrees/<名前>`。`isLinkedWorktree` の比較に今も使っている値）。`GitInfo.worktreeKey: string | null`。直前の判定として保存する（`repoKey`・`isLinkedWorktree` と同じ扱い）。
- **代表**: 同じ `worktreeKey` の workspace のうち、平らな順（開いた順）で最初のものが、その worktree の**代表**。リポジトリの項目 `r:<repoKey>` に入るのは代表だけ。代表でない workspace（同じフォルダの 2 つ目以降）は `w:<id>` の通常の項目で、所属は workspace 単位（管理外の workspace と同じ扱い）。画面では worktree の印を付けない。
- **代表の交代**: 代表が閉じた・別の場所へ移った（`worktreeKey` が変わった）ら、同じ `worktreeKey` の次の workspace が代表になり、リポジトリの項目に加わる（その `w:<id>` はレイアウトから外す。リポジトリの所属に従う）。
- **`repoMembers`**: 代表だけを返す（本体の代表が先頭、残りは開いた順）。worktree グループとして描くのは代表が 2 つ以上のとき。一括クローズ（「worktree も一緒に閉じる」）が閉じるのも代表だけ。
- **`itemRefOf`**: workspace 単独では決まらなくなる（ほかの workspace を見て代表かどうかを決める）。署名を変える。
- **古いサーバ**（`worktreeKey` が無い）: 今までどおり、同じ `repoKey` の workspace を全部メンバーとして扱う。
- 「＋新規」の動き（同じフォルダで開く）は変えない。代表でないので、通常の行として出る。

## B. グループに入っていないものは「グループなし」にまとめる

**きっかけ**: B3・T4（見出しの行と字下げだけで区切る）は、グループの後ろにグループ外の行が来ると境目が分かりにくい。利用者の決定は「グループなしというグループとして表示し、グループの並べ替えもできるようにする。ほかのグループが作られるまで、グループなしは表示させない」。

- **並びの構造を変える**: 一番上の並びは**まとまりの列**だけ（本物のグループと、「グループなし」）。**グループの間に、グループ外の項目を挟めない。**

  ```ts
  interface SidebarLayout {
    /** まとまりの順。`g:<groupId>` と、グループなしを表す `"u"`（必ず 1 つ）。 */
    top: string[];
    groups: Record<GroupId, ItemRef[]>;   // グループの中の項目（r: / w:）
    ungrouped: ItemRef[];                 // グループなしの中の項目（r: / w:）
  }
  ```

- **「グループなし」の見出し**: 本物のグループが 1 つ以上あるときだけ出す。1 つも無ければ見出しを出さず、項目がそのまま並ぶ（今までと同じ見た目）。
- **「グループなし」にできること**: 畳む・広げる（状態は共有の設定。`collapsedAutoGroups` と同じ置き場に真偽を 1 つ足す）、ほかのグループとの並べ替え（`item.move`／`item.move_by` の対象に `{ kind: "ungrouped" }` を足す。見出しのメニューの「上へ移動」「下へ移動」・ドラッグ・navigate の選択）。**名前の変更・削除はできない**（メニューに出さない）。フォルダの印は付けない。
- **項目の出入り**: 「グループから外す」は「グループなし」の末尾へ。新しい workspace は「グループなし」の末尾へ。グループの削除は、中身を「グループなし」の末尾へ（「元の位置へ出す」は無くなる）。新しいグループは、`top` の「グループなし」の直前に作る（その項目を中へ入れる）。
- **並べ替え**: 項目は、同じまとまりの中でだけ並べ替えられる（グループの中・グループなしの中）。まとまりをまたぐ移動はメニュー。まとまりそのもの（グループ・グループなし）は `top` の中で並べ替えられる。
- **仮の状態（`layoutFromLegacy`）**: グループは先頭のメンバーの平らな順で並べ、空のグループはその後ろ、`"u"` は末尾。グループ外の項目は平らな順で `ungrouped` へ。
- **平らな順**: `top` の順に、まとまりの中身を並べたもの。
- **`topUnitOf`**: 「グループなし」の中の項目は、グループとしては扱わない（リポジトリ／workspace 単体を返す）。次の作業（グラフの単位）で、「グループなし」を 1 枚にまとめないため。
- **古い画面の `workspace.move_to` の読み替え**: (a) 同じまとまりの中の項目の並べ替え、(b) グループの実効のメンバーのちょうど全部で、落とし先が別のまとまりの先頭の workspace → そのグループを `top` の中で動かす、(c) それ以外は何も変えない。
- この work の変更はまだ配布していないので、**途中の形のレイアウトの移行は要らない**（`layout` の無い保存からの移行だけがある）。

## C. 見た目（B3・T4）と状態のまとめ

- **グループの見出しに、中の状態をまとめたアイコンを常に出す**（広げていても畳んでいても。「グループなし」も同じ）。まとめ方は workspace の行と同じ決まり（中の全 pane のエージェントの状態のうち、優先度の高いもの。ブラウザ版は `Sidebar.vue` の `rowStateFor` が使っている `aggregate`・`displayStateFor`）。
- **worktree グループの先頭の行**: 広げているときは本体の状態（今のまま）。**畳んでいるときは、本体と worktree の全部をまとめた状態**を出し、隠れている worktree の数を `+n` で添える。
- **グループの見出しの数**: 中の項目の数（worktree グループは 1 つと数える）。
- **ブラウザ版（B3）**: グループの見出しは、折りたたみの印・状態のアイコン・フォルダの印・名前（小さめ・薄い色）・横線・数。面・帯・枠は付けない。中の項目は 1 段字下げ。worktree グループは、先頭の行の下に**木の線**（縦線と枝）でつなぎ、各行に **worktree の印**と**ブランチ名**を出す（ブランチ名は、サイドバーの行の並びの設定に git の項目が無くても、worktree グループの行では 1 行目の右に出す。設定で 1 行目に git の項目があれば重ねない）。通常の workspace には worktree の印を付けない。
- **端末版（T4）**: グループの見出しは `▾ ◐ <名前> ───── <数>`（名前と線と数は薄い色）。中は 2 文字の字下げ。worktree グループは `▾ ◐ ⎇ <名前>`、子は `├`／`└` と `⎇`。ブランチ名は行の右。畳んだ worktree グループは `▸ ◐ ⎇ <名前> +n`。`⎇` の幅が端末で崩れるなら別の記号にして `decisions.md` に残す。
- 色だけに頼らない（印の形・木の線・字下げで区別できる）。

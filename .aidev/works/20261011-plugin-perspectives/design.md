# プラグインのパースペクティブと共通ビュー

利用者との合意: 1タブが1作業環境。複数の端末・エージェントを持ち、ターミナル画面／アプリ画面で同じ作業を見せる。ビューはタブ全体か指定ペインへ追加可能。ユーザー導入とPJ導入を同じ配布形式で扱う。

## 構造

- tab.layout は常に作業ペイン群。表示専用paneは virtual=true、layoutの外、tab.displayPaneIdで所有する。PTY・フォーカス・D&D・コマンド起動の対象にしない。
- tab.plugin はアプリの宣言。tab.perspective は terminal/app。切り替え中も作業ペインのDOMを維持し、visibility/inertで隠す。端末のサイズを0にしない。
- tab.views は個別ビューのインスタンス（UUID）。target=tabは表示専用アンカー、target=paneは指定作業pane。配置・選んだ拡張・定義・display名を保存する。
- プラグイン定義に views を追加。各ビューは表示名・対応する配置・PJ必須条件を宣言する。tabViewはアプリとして互換維持。scope（user/project）は導入場所で決まり、機能種別と独立。
- 拡張の ext.panes に表示アンカーとビューインスタンス、tabの作業ペインの状態を通知。Yukkuri Studioにエージェント／作業ペイン一覧を追加。
- UI共通ツールバーに［作業画面］［アプリ画面］［ビューを追加］。候補は権限範囲と稼働状態で限定し、サーバでも検証する。停止したビューを再追加せず、停止／復帰状態を示す。
- PJ導入は `sodactl plugin ... --project-dir <folder>`、配置先は <folder>/.soda。既存プロジェクト拡張の承認が必要。ユーザーとPJで同じidでも上書きしない。
- サンプルとして読み取り専用のコミットグラフビューを配布する。

## 検証

状態・保存復元・移動／削除・virtualの境界・RPCの範囲と宣言の検査・PJ導入を重点的にテストし、UI E2Eで複数ペインを保った切り替えとターミナルへのビュー追加を確認。負の対照を記録する。最後の独立レビューは省かない。変更が多いため、モデル/RPC、UI、配布/サンプルの3単位で点検する。

# 要件: 画面の様式（端末マルチプレクサに近い様式と、モダンな Web アプリの様式）を、設定で切り替える

## 背景 / 課題

- ブラウザ版の基本画面（サイドバー・tab バー・pane の枠・ダイアログ）は、端末マルチプレクサ（tmux・herdr）に寄せた見た目で作ってある。角の丸みは小さく（4px）、余白は詰まっている。部品の文字は、すでにプロポーショナル（`system-ui`）で、等幅なのは、キーの表記・コード・端末だけ。
- グラフ主体のワークフローの画面の案（2026-10-08。`20261008-graph-first`）は、大きく丸い角・ゆとりのある余白・影、という Web アプリの見た目で描いた。利用者は、この見た目を「モダン」と評価し、基本画面にも使いたい、とした。
- 利用者の決定（2026-10-08）: 「設定で、現在のターミナルマルチプレクサに近いデザインと、モダンな Web アプリのデザインを切り替えられるようにする。カラーテーマは共通」。

## 目的 / ゴール

ブラウザ版で、利用者が設定 1 つで画面の様式を選べる状態。どちらの様式でも、いまのカラーテーマ（プリセット・色の上書き）がそのまま効き、できる操作は同じ。様式を変えても、端末の中身（文字・色・画像）は変わらない。

## 用語

- **様式**: 色と文字を除いた見た目のまとまり（角の丸み・余白と高さ・影・pane の間のすき間）。
- **クラシック**: いまの見た目。
- **モダン**: 案の見た目。

## ユーザーストーリー

- US1: 端末マルチプレクサに慣れた利用者として、いまの見た目のまま使い続けたい。なぜなら、画面を広く使え、慣れているから。（受け入れ: AC1・AC2・AC9）
- US2: Web アプリに慣れた利用者として、モダンな見た目で使いたい。なぜなら、部品の境目と押せる場所が見分けやすいから。（受け入れ: AC3〜AC8）
- US3: 色を自分で整えた利用者として、様式を変えても色はそのままであってほしい。（受け入れ: AC4）

## スコープ

### 対象

- ブラウザ版（デスクトップ・モバイルの 1 列の画面）の、アプリ自身の部品: サイドバー・tab バー・pane の枠と名前の行・分割の境目・表示の面の見出しと帯の行・ダイアログ（設定・確認・名前・ヘルプ・移動先・worktree・通知の履歴・`sodactl ask`）・メニュー・トースト・ログインの画面・再接続の表示・グラフの画面。
- 設定の項目（節「表示」）と、その保存・ほかの画面への反映。

### 対象外

- 端末版（引数なしの `soda`）。様式は 1 つのまま。
- 端末の中身（xterm の文字・色・カーソル・画像・スクロールバーの動き）。端末の文字の設定（フォント・大きさ）は今のまま、どちらの様式でも効く。
- 隔離して出している中身: 表示の面の枠の中（`DisplayFrame.vue`・`packages/web/public/display-view/*`）、`sodactl ask` の `view`、`<ask-form>` の部品の中（`third_party/ask-form/`。無改変で写したもの）。枠の外側（見出し・ダイアログの縁）は対象。
- 色の追加・変更。様式のための新しい色のトークン・プリセットは足さない（AC4）。
- クラシックの配置の変更。モダンの配置は、「モダンの配置」（AC12〜AC18）のとおり。それ以外の配置（サイドバーの左右・tab バーの上下の設定）は、様式で変えない。
- 3 つ目以降の様式・利用者が様式を作る仕組み。
- グラフ主体のワークフロー（`20261008-graph-first`）の新しい画面。その作業は、この作業の様式の仕組みに乗る。

## 完了条件 (受け入れ基準)

- [ ] AC1: 設定の節「表示」に、項目「画面の様式」があり、「クラシック」「モダン」から選べる。選ぶと、再読み込みなしで、その画面の様式が変わる。
- [ ] AC2: 既定は「クラシック」。設定を持たない利用者・この作業の前の設定を持つ利用者の画面は、この作業の前と**画素まで同じ**（この作業の最初に、変更の前の画面を基準として撮り、以後、その比較が差 0 画素で通る。画素を比べる E2E は、いままで無かったので、この作業で作る。対象の画面は `design.md`）。
- [ ] AC3: 「モダン」では、対象の部品が次のとおりになる。数値は設計で決め、1 か所（様式のトークン）にまとめる。
  - 角: ボタン・入力・メニュー・ダイアログ・pane の枠・tab が丸い。
  - 余白と高さ: 押せる部品の高さがそろう（デスクトップで 32px 以上。モバイルは今の 44px 以上を保つ）。
  - 文字: 変えない（クラシックの部品の文字は、すでにプロポーショナル。等幅の所は、等幅のまま）。
  - pane（デスクトップ）: pane と pane の間、pane と画面の縁の間のすき間が、クラシックより広い。いまある 4 つの設定（pane の枠の表示・すき間・枠の太さ・外周の枠）は、モダンでも、今と同じ意味で効く（様式は、太さの値の表を替えるだけ）。フォーカスのある pane は、枠の色で分かる（色は今の `--soda-pane-current`・`--soda-accent`）。
  - 重なり: メニュー・ダイアログ・トーストは、影で浮いて見える。
- [ ] AC4: 色は共通。「モダン」の CSS は、色の値を新しく書かない（`#rrggbb`・`rgb()`・色の名前を足さない）。使うのは既存の `--soda-*` と、それを元にした `color-mix()`・不透明度だけ。プリセットの切り替えと色の上書き（`themeOverrides`）は、どちらの様式でも同じ項目に効く。影は、既存の `--soda-backdrop` か、`color-mix()` で黒の割合を指定する形で書く。
- [ ] AC5: 様式を変えても、できる操作は同じ。既存のキーの操作・マウスの操作（分割の境目のドラッグ・pane の D&D・tab の D&D・表示の面のつまみと D&D）・フォーカスの戻り先が、どちらの様式でも働く。E2E の基本の経路（pane の分割・tab の切り替え・設定を開く・表示の面を出す）が、「モダン」でも通る。
- [ ] AC6: 様式を変えると、pane の大きさ（桁と行）は、すき間と枠の分だけ変わってよい。変わったときは、ふつうの大きさの変更と同じに端末へ伝わり、表示が崩れない（桁・行の再計算が 1 回で落ち着き、切り替えの前後で端末の中身が欠けない）。分割の比率は変わらない。
- [ ] AC7: 設定は、テーマの設定と同じ範囲で保存され、同じ利用者のほかの画面にも反映される（再読み込みの後も保たれる。「クラシック」を選び直すと、再読み込みの後もクラシックのまま。再読み込みのとき、前の様式が一瞬見える、ということが無い）。
- [ ] AC8: 「モダン」でも、読みやすさの条件を保つ。文字と地の色の比は、今のテーマで保っている値を下回らない（様式は色を変えないので、新しく重ねる地〔`color-mix()`〕の上の文字だけを確かめる）。フォーカスの輪は、どの部品でも見える。
- [ ] AC9: （AC2 にまとめた。欠番）
- [ ] AC10: 文字・画像・スタイルを、外から読み込まない（アプリの CSP を緩めない）。
- [ ] AC11: 文書が合っている。設定の項目・2 つの様式の違い・対象外（端末版・端末の中身・隔離した中身）が、利用者向けの文書に書かれている。

### モダンの配置（2026-10-09 に追加。利用者の指示）

利用者は、モダンの見た目（PR1〜PR3 の数値）を「基本的には、これで OK」とし、あわせて、**モダンのときの部品の配置**を、次のとおりに変える、と決めた。**クラシックは、元々の端末らしいデザインのまま、配置も変えない**（利用者の決定。2026-10-09）。要件の「対象外」の「配置の変更」は、モダンについては、この節で置き換える。

- [ ] AC12: モダンでは、メニューの中の「連携（グラフ）」を出さない（サイドバーのメニュー・右クリックのメニュー）。サイドバーの上の「基本画面／グラフ」の切り替えと、キー（`prefix+a`）で足りるため。クラシックでは、今のまま出す。
- [ ] AC13: モダンでは、サイドバーをたたむ・広げるボタンを、**サイドバーと主な領域の境の線の、縦の中央**に、小さな印（矢印）として置く。サイドバーの最下部の、たたむ・広げるの印は、出さない。境の線の、幅を変えるドラッグ（つまみ）は、今のまま働く（ボタンと、取り違えない）。たたんだ状態でも、同じ場所のボタンで広げられる。キー（`toggle_sidebar`）は、今のまま。
- [ ] AC14: モダンでは、「メニュー」と「新規」のボタンを、**サイドバーの最下部**に、通知のベルと並べて置く。spaces の区画の中の「＋新規」「メニュー」は、出さない。たたんだサイドバーでは、縦に並ぶ（印だけ。読み上げのラベルは保つ）。
- [ ] AC15: モダンの「新規」を押すと、何を足すかを選ぶ小さなメニューが出る: **workspace**（今の「＋新規」と同じ。workspace を作る・worktree を開く）・**pane**（いまの tab に、pane を足す。基本画面の「分割」の既定と同じ向き）・**グループ**（今の、右クリックの「新しいグループを作る」と同じ）。キーボードで選べる。
- [ ] AC16: モダンでは、workspace の行の右クリックのメニューから、「新しいグループを作る」を出さない（「新規」から作れるため。workspace を、いまあるグループへ入れる・外す、の項目は残す）。クラシックでは、今のまま。
- [ ] AC17: モダンでは、tab バーを、**tab が 1 つだけのときも出す**（tab と、「＋」〔tab を作る〕が見える）。クラシックでは、今のまま（1 つだけのときは、隠す）。tab バーの位置の設定（上・下）は、どちらでも効く。tab バーが出る分、端末の行は減る（様式の切り替えと同じに、端末へ伝わる）。
- [ ] AC18: AC12〜AC17 は、モダンのときだけ。**クラシックは、画素まで変わらない**（比べる道具で、差 0）。様式を切り替えると、再読み込みなしで、配置が替わる。フォーカスが、消える部品の上にあったときは、対応する新しい部品（無ければ、端末）へ移る。

## 非機能・制約

- 変えてはいけないファイル（表示の面の守り）: `DisplayFrame.vue`・`DisplayScriptMark.vue`・`focusDrop.ts`・`focusOrigin.ts`・`focusGuard.ts`・`engageEntry.ts`・`frameMessages.ts`・`frameRegistry.ts`・`packages/web/public/display-view/*`・`MobileShell.vue`。これらに様式が要る場合は、外側の部品で包む。包めない場合は、止めて報告する。
- 差分を小さく切る（`AGENTS.md`）。部品は数十あるので、PR を分ける。分け方は設計で決める（案: ①仕組み・設定・基本画面の枠組み ②ダイアログ・メニュー・設定の画面 ③グラフの画面・モバイル・文書）。途中の PR でも、「モダン」を選んだ画面が使える状態を保つ（未対応の部品は、クラシックの見た目のまま出る）。
- `pnpm test`と既存の E2E は、クラシックのまま通す。

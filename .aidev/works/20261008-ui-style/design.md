# 設計: 画面の様式（クラシック／モダン）の切り替え

要件は `requirements.md`。

> **追補 01（2026-10-09。独立点検の反映）が、この文書の末尾にある。本文と食い違う所は、追補 01 が優先する**（特に: 文字は様式で変えない・pane のすき間は既存の仕組みに乗せる・`2px` は置き換えない・起動のときの当て方・基準の画像はリポジトリに入れない・PR の分け方）。

## いまの作り（調べた事実）

- 色は、`ThemeController` が `document.documentElement` に `--soda-*` の CSS 変数と `data-theme` を当てる。部品の `<style>` は、色だけを変数で引く。
- **形は、部品ごとの `<style>` に、数値で直に書いてある。** `border-radius` は 89 か所（`4px` が 56・`3px` が 9・`6px` が 8 ほか）、`font-family` は 7 か所（`monospace` が 5）。アプリの根の文字は等幅で、部品はそれを継ぐ。形のための CSS 変数は、1 つも無い。
- 見た目の設定は、`store/settings.ts`（`theme`・`themeAuto`・`themeLight`・`themeDark` を `writePrefs` で共有の設定へ）。
- **画面の画素を比べる E2E は、いま 1 本も無い**（`toHaveScreenshot` を使う spec が無い）。要件 AC2 の「既存のスクリーンショットの比較」は、成り立たない。比べる仕組みを、この作業で先に作る（下の「クラシックを変えない確かめ」）。

## 方針

1. **様式は、根の属性 1 つ**: `document.documentElement` に `data-ui-style="classic" | "modern"`。
2. **形の値を、変数（様式のトークン）にする**: `--soda-shape-*` を、`classic` の値＝いまの数値で定義し、`modern` で上書きする。部品の `<style>` の数値を、変数に置き換える。
3. **変数にできない違い（構造の違い）は、`:root[data-ui-style="modern"] …` の規則を、1 つのファイルに集める。** 部品の `<style scoped>` の中に、様式の分岐を散らさない。
4. **色は、足さない。** モダンの地の重ねは、`color-mix(in srgb, var(--soda-…) N%, var(--soda-…))` だけ。

## 様式のトークン（`packages/web/src/styles/uiStyle.css`。新しいファイル）

| トークン | classic（いまの値） | modern | 使う所 |
| :- | :- | :- | :- |
| `--soda-shape-radius-s` | 3px | 6px | 小さな印・タグ |
| `--soda-shape-radius` | 4px | 8px | ボタン・入力・メニューの行・tab |
| `--soda-shape-radius-l` | 6px | 12px | ダイアログ・メニュー・pane の枠・パネル |
| `--soda-shape-control-h` | （部品ごとの今の値のまま。変数は `auto`） | 32px | 押せる部品の高さ（デスクトップ） |
| `--soda-shape-pad-x` | 今の値 | 12px | 押せる部品の左右の余白 |
| `--soda-shape-row-h` | 今の値 | 36px | サイドバーの行・メニューの行 |
| `--soda-shape-pane-gap` | 0px | 6px | pane と pane・pane と縁の間 |
| `--soda-shape-pane-border` | 今の値 | 1px | pane の枠の太さ |
| `--soda-shape-shadow` | none | `0 12px 32px rgb(0 0 0 / 0.35)` | メニュー・ダイアログ・トースト |
| `--soda-font-ui` | `monospace`（今の根の値） | `system-ui, -apple-system, "Segoe UI", "Hiragino Sans", "Noto Sans JP", sans-serif` | 部品の文字 |
| `--soda-font-mono` | `monospace` | `monospace` | id・パス・キーの表記・コード |

- 「今の値」が部品ごとに違うもの（高さ・余白）は、トークンの classic の値を `initial` 相当にし、部品の側を `height: var(--soda-shape-control-h, <今の値>)` の形で書く。**classic では変数を定義しない**ので、今の値がそのまま効く（AC9）。
- 端末（xterm）の文字は、今の端末の文字の設定のまま。`--soda-font-ui` は、端末の入れ物には当てない。

## 置き換えの決まり

- `border-radius: 4px` → `var(--soda-shape-radius)`、`3px`・`2px` → `-s`、`6px` → `-l`。`999px`・`50%`（丸）・片側だけの丸（`4px 4px 0 0`）は、形の意味があるので、1 つずつ見て決める（丸は変えない）。
- 根の `font-family` を `var(--soda-font-ui)` に。等幅であるべき所（pane の id・パス・キーの表記・`<code>`・`<pre>`・ログ・コマンドの全文〔拡張の承認のダイアログ〕）に、`font-family: var(--soda-font-mono)` を明示する。**今は「何も書かなくても等幅」なので、明示が漏れると、モダンでだけプロポーショナルになる。** 漏れを探す手順を、タスクに入れる（モダンで全画面を撮って、目で見る）。
- 文字の幅に頼っている配置（`ch` の単位・等幅を前提にした桁そろえ）を grep して、モダンで崩れないかを見る。

## pane のすき間（AC3・AC6）

- `PaneLayout` の葉の入れ物に、`padding: calc(var(--soda-shape-pane-gap) / 2)`。分割の境目（`Splitter.vue`）は、すき間の中央に置く（つかめる幅は今のまま）。
- 端末の桁と行は、今までどおり、葉の箱の大きさから `ViewSync` が測る。すき間で箱が小さくなった分、桁と行が減る。様式を切り替えたときは、`ResizeObserver` が拾って、ふつうの大きさの変更として 1 回送る（新しい道は作らない）。
- 分割の比率は、保存された値のまま（すき間は、比率の計算の外）。

## 設定（AC1・AC7）

- 共有の設定に `uiStyle: "classic" | "modern"` を足す（`theme` と同じ道。`PrefsStore`・`PrefsSync`・protocol の設定の型）。無い・読めない値は `classic`。
- 設定の画面の節「表示」に、ラジオ「画面の様式」（クラシック／モダン）。`theme` の項目の近くに置く。
- 当てるのは、`ThemeController` と同じ所で 1 か所（`document.documentElement.dataset.uiStyle`）。起動のとき、最初の描画の前に当てる（切り替わりが見えないように。`theme` が今している、保存した値の先読みと同じ道）。
- 端末版は、この設定を読まない（設定の画面にも出さない）。知らない項目として、保存は保つ。

## クラシックを変えない確かめ（AC2・AC9）

1. **PR1 の最初のコミットで、`main` の見た目の基準を撮る。** Playwright の `toHaveScreenshot` で、次の画面を、暗い・明るいテーマで撮る（基準の画像を、リポジトリに入れる）: 基本画面（pane 2 つ・tab 2 つ・サイドバーにグループ）・設定のダイアログの各節・メニュー（右クリック）・確認のダイアログ・ヘルプ・グラフの画面・表示の面（パネルと帯）・トースト・ログインの画面・モバイルの 1 列の画面。端末の中身は、決まった文字だけにする（揺れないように。カーソルの点滅を止める）。
2. 以後のコミットは、**基準を撮り直さずに**、この比較が通ること（classic が画素まで同じ）。
3. モダンの基準は、PR ごとに、その PR で対応した画面の分を足す。

撮る環境は、この開発機の Chromium（`env -u DISPLAY -u WAYLAND_DISPLAY`）。文字の描画は環境で変わるので、この比較は、**同じ機械の上で、変更の前後を比べる**ための道具とする（CI で使うなら、基準を CI で撮り直す）。許す差は 0 画素。

## 変えてはいけないファイル

`DisplayFrame.vue`・`DisplayScriptMark.vue`・`focusDrop.ts`・`focusOrigin.ts`・`focusGuard.ts`・`engageEntry.ts`・`frameMessages.ts`・`frameRegistry.ts`・`packages/web/public/display-view/*`・`MobileShell.vue`。

- これらの `<style>` の数値は、置き換えない。**モダンでは、これらの部品だけ、クラシックの形のまま**になる（表示の面の枠の中・印「スクリプト」・モバイルの 1 列の画面の骨組み）。外側の部品（`PanePanel.vue`・`DisplayPanelHead.vue`）は、対象。
- `MobileShell.vue` を変えられないので、モバイルは、その中に出る部品（ダイアログ・メニュー・設定）だけがモダンになる。骨組み（上のバー・一覧）は、クラシックのまま。要件の「残る問い」の答え。

## 追補 01: 独立点検の反映

点検の全文は、監督役の控え `uistyle-doccheck-result.md`（F1〜F10）。直さないと実装できない点が 4 つあり、うち 2 つは、本文の「いまの作り」の事実の誤りだった。

### 事実の訂正

- **根の文字は、等幅ではない。** いまの根は `system-ui, sans-serif`（`App.vue`）。等幅なのは、設定の画面のキーの表示・ヘルプのキー・prefix の表示・色の上書きの入力欄・拡張の承認のコマンド・`AskViewer` の等幅の表示、だけ。**クラシックの部品の文字は、すでにプロポーショナル。**
- **pane のすき間は、すでにある。** `PaneFrame` が、辺ごとに `var(--soda-pane-gap, 4px)` の余白を持つ（値は `App.vue` が、設定 `paneFrameThickness`〔thin・default・thick〕から配る）。分割の境目の幅も同じ変数。設定 `paneBorders`・`paneGaps`・`paneFrameThickness`・`paneOuterBorders` が、すでに設定の画面にある。既定のクラシックは、pane の周りに 4px の余白がある。葉（`ViewSync` が測る要素）は `PaneFrame` の内側。
- `border-radius` は 94 行（`4px`・`3px`・`6px` で約 78 行）。`2px` が 2 か所（`NotificationBell.vue`・`Sidebar.vue`）。
- 最初の描画の前に色を当てているのは、`ThemeController` ではなく、`index.html` が読む `public/theme-boot.js` と、localStorage の起動用の控え（`soda.themeBoot.v1`。`ThemeController.writeBoot` が書く）。
- 設定の画面の節は「通知・テーマ・表示・端末・エージェント連携・拡張・キー」。
- 画素の比較は、この開発機で成り立つ（同じコードを、別の 2 回のサーバの起動で撮って、6 組とも差 0。揺れたのは、時間で出入りするトーストだけ）。

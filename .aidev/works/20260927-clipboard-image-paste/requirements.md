# 要件: クリップボードの画像を pane へ貼り付ける（herdr H44「リモートへのクリップボード画像の転送」）

## 背景 / 課題

web-tn-multiplexer のブラウザは、サーバ（pane のプロセスが動くマシン）と別のマシンで開かれることが多い（LAN・TLS 越し・
保存した SSH のマシン `/ws?machine=`〔20260927-multi-host-machines〕）。このとき pane の中の CLI エージェント（Claude Code・Codex 等）は
**ブラウザ側のクリップボードに触れられない**ので、スクリーンショット等の画像をエージェントに渡す手段が無い
（backlog `product-roadmap.md`「クリップボード画像のリモート貼り付け」。`packages/web/src/term/clipboard.ts` はテキストの
`readText`/`writeText` だけで、画像の読み取り・サーバへ送る経路が無い）。

herdr は `herdr --remote` で、`keys.remote_image_paste`（既定 `ctrl+v`）を押したときに手元のクリップボードの画像をリモートへ送り、
リモートの一時ファイルに置いてその**パスを pane に貼り付ける**（decisions D1。一次資料 `scratchpad/herdr/src/server/clipboard_image.rs`・
`src/client/clipboard_images.rs`）。Claude Code は貼り付けられた画像ファイルのパスを画像として扱う。

## 目的 / ゴール

- ブラウザのクリップボードにある画像を、キー 1 つ（既定 Ctrl+V。herdr と同じ）またはブラウザの貼り付けで、フォーカス中の pane の
  エージェントへ渡せる状態。ブラウザとサーバが別のマシンでも、保存した SSH のマシンの pane でも同じに使える。
- クリップボードに画像が無いとき・ブラウザが画像を読めないときは、そのキーは今までどおり端末への入力（Ctrl+V なら `0x16`）になり、
  Vim の矩形選択等の既存の使い方が打鍵の順序も含めて変わらない状態。テキストの貼り付けも今までと変わらない状態。
- サーバに置かれる画像は、同じマシンの他の利用者から読めず、名前が推測できず、置き場所をブラウザから指定できず、
  種類・大きさ・数・頻度に上限があり、古いものは自動で消える状態。
- 失敗したとき（大きすぎる・種類が違う・サーバが古い・接続が切れた）に、何が起きたかが画面に日本語で出て、pane には何も入らない状態。

## ユーザーストーリー

- US1: ブラウザを別のマシンで開いて Claude Code を使う開発者として、スクリーンショットをクリップボードに取ってそのまま pane で Ctrl+V を押し、
  エージェントに画像を渡したい。なぜなら、画像をファイルに保存してサーバへコピーしてパスを打つ手間を省きたいから。（受け入れ: AC1, AC3, AC7, AC10）
- US2: macOS のブラウザの利用者・スマートフォンの利用者として、いつもの貼り付け（Cmd+V・メニューの「貼り付け」・長押しの貼り付け）で画像を渡したい。
  なぜなら、ブラウザの許可の画面を出さずに、いつもの操作で済ませたいから。（受け入れ: AC3, AC4）
- US3: 保存した SSH のマシンの pane で作業する開発者として、手元のマシンの pane と同じ操作で画像を渡したい。なぜなら、どのマシンの pane かで
  操作を変えたくないから。（受け入れ: AC5）
- US4: Vim・Emacs で Ctrl+V を使う利用者として、画像が無いときは Ctrl+V が今までどおり届き、続けて打ったキーが追い越さないでほしい。
  また、必要ならキーを変える・外すことができてほしい。なぜなら、矩形選択やスクロールが壊れると日常の編集ができないから。（受け入れ: AC2, AC6, AC-I5）
- US5: サーバの運用者として、ブラウザから送られる画像がサーバのディスクを埋めない・他の利用者に読まれない・任意の場所に書かれないでほしい。
  なぜなら、認証済みとはいえ外から届くデータをファイルに書く口だから。（受け入れ: AC7, AC8, AC9, AC11）
- US6: 利用者として、画像を貼れなかったときに理由が知りたい。なぜなら、黙って何も起きないと、もう一度押すべきか分からないから。（受け入れ: AC10）
- US7: herdr から移ってきた利用者として、herdr との違い（使えるブラウザ・キーの扱い・ファイルの置き場所）を docs で知りたい。（受け入れ: AC12）

## スコープ

### 対象

- 画像を貼り付けるキー（herdr の `remote_image_paste`。既定 `ctrl+v`。キーの設定〔節「キー」〕で変える・外せる・キー一覧に出る）。
- ブラウザの貼り付け（paste イベント）に画像だけが入っているとき（テキストが無いとき）の画像の貼り付け。
- 右クリックメニューの「貼り付け」と `Ctrl+Shift+V` で、クリップボードにテキストが無く画像があるときの画像の貼り付け（テキストがあれば今までどおり）。
- ブラウザからサーバへ画像を送る認証済みの口（`/ws` の要求）と、サーバでの検査・保存・後片付け。`/ws?machine=` の中継越しにも通ること。
- 送り先の pane に、サーバが返したパスを貼り付けること（pane の bracketed paste の状態に従う）。
- 失敗の知らせ（toast）・docs（`docs/herdr-parity.md` H44・`docs/machines.md` の「できないこと」・`docs/verification.md` の手順）。

### 対象外

- 画像ファイルのドラッグ＆ドロップ（herdr はファイルのドロップも送る）——backlog に残す。
- 独自コマンドの popup の端末（20260927-custom-command-keys）への画像の貼り付け（herdr は popup も対象）——backlog に残す。
- `wtmctl` から画像を送るコマンド——backlog に残す。
- サーバの OS のクリップボード（xclip・wl-copy・pbcopy）の書き換え・エージェントの貼り付けキーの真似（decisions D2）。
- Firefox・Safari で、画像を貼り付けるキー（Ctrl+V）から画像を読むこと（読み取りの度に「ペースト」のメニューが出るため。research で確かめる）。
  これらのブラウザではブラウザの貼り付け（Cmd+V・メニュー）・`Ctrl+Shift+V`／メニューの「貼り付け」を使う。
  `Ctrl+Shift+V`／メニューの「貼り付け」も同じ読み取りで「ペースト」のメニューが出るが、これらは今も（テキストの貼り付けで）同じメニューが出ており、
  利用者が貼り付けるつもりで押す操作なので出てよい。Ctrl+V は Vim の矩形選択・Emacs のスクロールに日常的に使われ、押す度にメニューが出ると使えなくなるので、
  キーからは読まない（違いはメニューが出ることではなく、そのキーの主な用途が貼り付けかどうか）。
- 画像の変換・縮小（受け取った形式のまま置く）。BMP・TIFF 等の 4 種類（PNG・JPEG・GIF・WebP）以外の形式。
- 実機の Chromium・Firefox・Safari・スマートフォン・本物の Claude Code での確認（E2E は依頼が無いため回さない。docs の手順と未検証の穴に残す）。

## 機能要件

- F1: フォーカス中の pane の端末で画像を貼り付けるキーを押すと、ブラウザがクリップボードの画像を読める場合に、画像をサーバへ送り、
  サーバが置いたファイルの絶対パスをその pane へ貼り付ける。クリップボードに画像とテキストの両方があるときは画像を優先する（herdr と同じ）。
- F2: 画像を読めない（クリップボードに画像が無い・API が無い・許可が無い・許可を問い合わせられないブラウザ）ときは、そのキーの
  端末への入力（`ctrl+v` なら `0x16`）を pane へ送る。確かめている間・送っている間に打ったキーは、その後に、打った順で届く。
- F3: pane の端末でのブラウザの貼り付け（paste イベント）にテキストが無く画像があれば、F1 と同じく送って貼り付ける。テキストがあれば今までどおり。
- F4: メニューの「貼り付け」・`Ctrl+Shift+V` は、テキストがあれば今までどおりテキストを貼り、テキストが無く画像があれば F1 と同じく送って貼り付ける。
- F5: サーバは、画像の種類（PNG・JPEG・GIF・WebP）を宣言と中身の先頭のバイトの両方で確かめ、大きさ（16 MiB 以下・宣言どおり）・
  送り先の pane の存在を確かめ、合わなければ何も書かずに理由の code を返す。
- F6: サーバは画像を、そのサーバの利用者だけが読める場所に、推測できない名前で新しく作って書き、ブラウザには置き場所・名前を決めさせない。
  古いもの（24 時間）は消し、置いておく数・合計の大きさにも上限を置く。
- F7: 同時に送れる数・短い時間に送れる数に上限を置き、途中で止まった送信（接続が切れた・続きが来ない）の分は捨てる。
- F8: ブラウザは、サーバから返ったパスが貼り付けても安全な文字だけでできているか（制御文字を含まない・長すぎない）を確かめてから貼る
  （中継先のリモートのサーバは信用しない。20260927-multi-host-machines の方針）。
- F9: 失敗の理由を日本語の toast で出す。

## 非機能要件 / 制約

- 送信は既存の `/ws` の上だけで行い、1 通の上限（4 MiB。`MAX_WS_PAYLOAD_BYTES`・中継の `BRIDGE_LIMITS.maxMessageBytes`）を超えない。
  新しい HTTP の口・待ち受けは作らない。
- テキストの貼り付け・画像を貼り付けるキーに割り当てていないキーの動作は変えない（画像を貼り付けるキーを外した利用者には、Ctrl+V も含めて何も変わらない）。
- サーバの対応 OS（Linux・macOS・Windows）で動く。権限（0700/0600）は POSIX でだけ効く（Windows は利用者ごとのディレクトリの権限に依る）。
- 負荷テスト・E2E は回さない（ユーザーの指示）。確認は単体・結合のテストと smoke。

## 完了条件 (受け入れ基準)

- [ ] AC1: 画像を貼り付けるキー（既定 `ctrl+v`）を pane の端末で押し、ブラウザがクリップボードの画像（PNG 等）を読めたとき、サーバの私的なディレクトリに
  その画像と同じバイト列のファイルができ、その絶対パスが pane への入力として届く（pane が bracketed paste を有効にしていれば `ESC[200~`…`ESC[201~` で包まれる）。
  画像とテキストの両方があるときも画像を送る。
- [ ] AC2: 同じキーで、クリップボードに画像が無い・`navigator.clipboard.read` が無い・許可が拒否されている・許可を問い合わせられないブラウザのとき、
  pane にはそのキーの端末への入力（`ctrl+v` なら `0x16`）だけが届く。確かめている間・送っている間に打ったキーは、その入力（または貼り付けたパス）の後に、打った順で届き、失われない。
- [ ] AC3: pane の端末に届いた paste イベントにテキスト（`text/plain`）が無く画像（PNG・JPEG・GIF・WebP）があれば、AC1 と同じくファイルができてパスが届く。
  テキストがあれば今までどおりテキストだけが届き、画像は送らない。
- [ ] AC4: メニューの「貼り付け」・`Ctrl+Shift+V` は、テキストがあれば今までどおりテキストを貼る。テキストが無く画像があれば AC1 と同じくパスが届く。
- [ ] AC5: `/ws?machine=<名前>` の中継越しの接続でも AC1 が成り立ち、ファイルは**リモートのマシン**の私的なディレクトリにでき、リモートのパスが届く。
- [ ] AC6: 画像を貼り付けるキーは節「キー」の操作 `remote_image_paste` として出て、変える・外すことができる。外したとき・別のキーにしたとき、
  Ctrl+V は今までどおり端末への入力（`0x16`）になり、クリップボードを読まない。
- [ ] AC7: サーバは、種類が 4 種類以外・宣言と先頭のバイトが合わない・16 MiB を超える・宣言した大きさと届いた大きさが違う・pane が無い送信に、
  code 付きのエラーを返し、ファイルを作らない。
- [ ] AC8: POSIX のサーバで、画像を置くディレクトリは 0700、ファイルは 0600 で、名前は推測できない（乱数を含む）。ブラウザから置き場所・名前を指定する手段が無い。
  既存のファイルを上書きしない（同じ名前があれば書かない）。24 時間より古いファイルは消え、置いておく数・合計の大きさの上限（値は design で決める）を超えると古いものから消える。
- [ ] AC9: 1 つの接続が同時に送れるのは 1 つ、サーバ全体の同時の送信・短い時間の送信の数に上限（値は design で決める）があり、超えた送信は code 付きで断られる。
  続きが来ない送信・接続が切れた送信の分はメモリから捨てられ、ファイルにならない。
- [ ] AC10: 画像を送れなかったとき（大きすぎる・種類が違う・サーバが古く口が無い・接続が切れた・上限）、pane には画像の分（パス・そのキーの入力）は何も入らず、
  理由が日本語の toast で出る。確かめている間・送っている間に打ったキーは捨てず、その後に打った順で届く（AC2 と同じ）。
- [ ] AC11: サーバから返ったパスが制御文字を含む・長すぎる（閾値は design で決める）とき、ブラウザは貼り付けず toast で知らせる。
- [ ] AC12: `docs/herdr-parity.md` の H44・`docs/machines.md` の「できないこと」・`docs/verification.md` の手順が、herdr との違い（使えるブラウザと経路・
  ファイルの置き場所と寿命・キーの既定）を含めて更新されている。
- [ ] AC13: 画像を扱わない操作（テキストの貼り付け・他のキー・既存の RPC）の既存のテストが全て通り、`aidev smoke` が通る。

## 相互作用の受け入れ基準（UI を伴う work のみ）

画面の部品は増やさない（キーの割り当て 1 つと toast）。キーと貼り付けの経路についての基準として書く。

- [ ] AC-I1 起動 / 終わり: 画像を貼り付けるキー・ブラウザの貼り付け・メニューの「貼り付け」・`Ctrl+Shift+V` のどれで始まり、パスが貼られる・toast が出る・
  そのキーの入力が送られるのいずれかで必ず終わる（何も起きないまま入力が止まり続けることが無い。止めている時間には上限〔値は design で決める〕があり、
  超えたら溜めたキーを流す）。
- [ ] AC-I2 確定 / 取り消し: 画像の送信に確認のダイアログは出さない（キーを押すこと自体が確定。herdr と同じ）。送信中に pane が閉じたら、パスは貼られず、溜めていたキーも別の pane へは流れない（閉じた pane へ打ったキーと同じく、どこにも届かない）。
- [ ] AC-I3 キーボードだけで完結するか: 画像を貼り付けるキー・`Ctrl+Shift+V`・節「キー」での割り当ての変更がマウス無しでできる。
- [ ] AC-I4 フォーカスの行き先: 送信の前後で端末のフォーカスは動かない（パスはキーを押した pane に貼られ、別の pane にフォーカスを移しても送り先は変わらない）。
- [ ] AC-I5 既存の操作を妨げないか: 画像が無いときの Ctrl+V が `0x16` として、続けて打ったキーより先に届く。サイドバー等の端末以外の入力欄での Ctrl+V
  （ブラウザの標準の貼り付け）を横取りしない。

## 未確定事項 / 確認したいこと

- ブラウザごとの `navigator.clipboard.read()` の許可の出方と、許可を問い合わせられるか（research で確かめ、design で「キーから読むブラウザ」を決める）。
- 画像を置くディレクトリの場所（OS の一時ディレクトリか状態ディレクトリか）と、接続が切れたときに消すか（herdr は消す）——design で決める。
- 送信を 1 通で送るか分けて送るか（1 通 4 MiB の上限と 16 MiB の画像）——design で決める。
- 上限の値（置いておく数・合計の大きさ・サーバ全体の同時の送信数・短い時間の送信数・続きが来ないとみなす時間・パスの長さ・入力を溜めておく時間）——design で決める。

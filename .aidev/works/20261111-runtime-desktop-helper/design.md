# Run the existing desktop broker only while soda is running

Use one Windows-supported mechanism: first-time local UAC-approved preparation installs an administrator-protected helper executable and an on-demand SYSTEM Task Scheduler definition, with no service registration. The definition remains; its process exists only while the existing soda lease is live. No boot, login, time, idle or network triggers; execution limit PT0S, DisallowStartIfOnBatteries=false, StopIfGoingOnBatteries=false, RunOnlyIfIdle=false, RunOnlyIfNetworkAvailable=false, MultipleInstances=IGNORE_NEW, restart0. Battery transitions do not terminate it. Task.Run acceptance alone is not broker readiness; the existing authenticated pipe/lease must connect. Normal logged-in desktop capture remains the existing user helper. Signed-out/boot access remains the separate signin purpose and is not provided by this route.

Reuse WindowsDesktopUnlock's existing broker/worker, owner PID+creation-time, active-session/logon checks, pipe peer checks, fixed purpose bits, heartbeat, Shutdown, Job and retained worker handles. Add a SYSTEM-only console hosting entry that calls the same StartService/Shutdown body; Task Scheduler is only the launcher. The SYSTEM process remains in session0; StartWorker continues using the existing active-session CreateProcessAsUser and desktop selection. An elevated administrator process alone is not claimed to access Winlogon/UAC.

Runtime helper name/path/pipe prefix differs from the existing service, so candidate tests do not stop/delete the existing service. A runtime-compiled helper uses actual OS named-pipe server PID, retained Process identity/session0 and the exact same protected executable. Only its SYSTEM-only broker entry creates that fixed broker pipe. Legacy service-compiled helper retains the existing SCM configuration/PID check. No user-writable PID registry, new token acquisition, permission wire, ACK or authorization layer.

Task action directly executes the fixed protected EXE, `--runtime-broker $(Arg0) $(Arg1) $(Arg2)`; Run supplies only decimal owner PID, creation ticks and one existing fixed purpose. No shell. Principal SYSTEM; task ACL SYSTEM/Administrators full and target owner read/execute only. Verify definition principal/action/arguments/triggers before Run. Standard task Run supplies owner information; a PID/start/logon/image mismatch fails the existing broker check. Parallel invocation does not replace an existing running broker.

`prepare-desktop-helper.ps1` is a small local entry around the existing compiler/ACL installer with a RuntimeTask branch before any SCM operation. Initial non-elevated preparation requests UAC, preserving the intended owner SID; ValidateOnly compiles/checks only, without UAC/task registration/SCM/desktop/input. Uninstall removes this task/helper only after it is no longer running. Existing service registration/binary is not modified. New task preparation does not run a broker or grant desktop access.

Bundled DesktopSettings commands select the runtime route with an internal helper flag; explicit legacy commands keep their service route. Existing allowUnlock/allowElevated/virtual permissions are unchanged. Existing setupMessage tells the local user to prepare, save permissions and retry. No new settings mode/field/RPC/remote start button. After preparation, existing provider configure/dispose starts/stops DesktopUnlockLease. EOF/owner exit/heartbeat expiry runs Shutdown and waits for worker retirement; task deletion is not used as termination proof. Definition remains idle after exit. Existing bounded retries can re-run an already prepared task but never request UAC; missing/cancelled preparation leaves normal sharing available. Multiple soda instances retain existing one-owner admission; no automatic takeover or fallback permission widening.

Validation: meaningful C# pure startup/peer/task-plan checks (no COM/desktop in pure mode), old-source failure and byte-exact restoration; real Windows candidate compile/pure before live use; TS Settings/lease lifecycle tests and old-source negative. Independent review before build and deployment. Root alone authorizes eventual service migration and live UAC/Winlogon tests; old registered service remains until new route passes.

Implementation ownership: backend NativeUnlock, windows-helper, existing installer RuntimeTask branch + thin prepare script, Settings/lease/server diagnostics and relevant tests. UI owns Web/TUI/protocol message function/docs. No duplicate edits; build once after integration.

Primary references: Microsoft TaskFolder.RegisterTaskDefinition (TASK_LOGON_SERVICE_ACCOUNT), Security Contexts for Tasks, task Settings.ExecutionTimeLimit; schtasks/delete explicitly does not terminate a running application. Runtime lifetime comes from the existing lease, not task-definition deletion.

# 記録: origin/main で落ちる E2E の直し（e2e-main-failures）

## 背景
2026-10-10、E2E の全体を 1 回流して（別の作業 e2e-fake-agent）、origin/main でも落ちる試験が 4 本見つかった。今日の PR（#122〜#137）の退行の可能性があったので、いつから・何が原因かを突き止めた（使い捨ての worktree で、その 1 本ずつを、過去のコミットで流して）。

## 結論: 製品の退行は無い（試験と文書だけを直した。製品のコードに差分なし）
| 試験 | いつから | 原因 | 直し |
| :- | :- | :- | :- |
| `display-script-drop`「余白を押す」 | 今日の #131（様式 PR6） | 画面の隅を余白として押していたが、クラシックの切り替えのボタンが帯いっぱいに伸びて、そこがボタンになった（意図した変更） | 余白を、サイドバーの中の「ボタン・入力の載っていない点」として探す共通の部品に。サイドバーの空き（区画の下）でも確かめる |
| `new-terminal-cwd` | #70（設定をサーバで共有） | 1 つのサーバの中では、最初のブラウザの値が勝つ（20260927-cli-mode D3 の決定どおり）。試験は、ブラウザごとの値を期待していた | 方針ごとに、別のサーバのテストに分けた |
| `scrollback-copy`「マウスでの選択」 | 作られた 2026-09-20 から、この機械では落ちる | 掴む点が、pane の枠の上の、xterm の外の余白（約 9.5px）に当たる | 掴む基準を `.xterm-screen` に |
| `scrollback-copy`「copy モードで yank」 | （レビューの機械で、main でも落ちた。#138 のプロンプトでは通る） | カーソルの初期位置の前提が、プロンプトの行数に依る | 目印の行へ検索で飛ぶ形に（期待は同じ） |
| `terminal-app`「tab バーの ＋」 | #110（画面の切り替えのボタン） | Tab を 4 回でサイドバーに届く前提が、切り替えのボタンと通知のベルで崩れた | Tab の回数を 16 に（確かめる順と中身は同じ） |

- 文書: `docs/herdr-parity.md`（H36b ほか）・`verification.md`・`tls-setup.md`・`custom-commands.md` の「設定は、ブラウザごと」を、いまの決定（サーバの共有の設定）に直した。

## 軽いレビュー（実装とは別のエージェント）
- 判断: マージしてよい。製品のコードに差分なし。「最初のブラウザの値が勝つ」は、決定（D3）どおり。試験は、弱まっていない。
- 指摘: 同じファイルの copy モードの 1 本が、main でも落ちる（報告から漏れていた）→ 直した。古い文書 → 直した。

## 学び
- 今日は、着地のたびに「関係する E2E」だけを流し、全体は流していなかった。#131 の意図した変更に追従していない試験が 1 本、それより前から落ちていた試験が 3 本、気づかれないまま残っていた。E2E の全体は、1.2 時間かかる（839 件）。

## 監督役の確認
- 差分は、`docs/`・`packages/e2e/`・`.aidev/` だけ。`pnpm typecheck` が通る。直した spec は、実装者が、main（#139）を取り込んだ後に、各 2 回流して通る。

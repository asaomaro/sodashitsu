# 要件: 表示の面の配置と状態（ブラウザ版）— たたみの記憶・帯の上下・帯の行のボタン・パネルの上下左右と D&D・浮いた窓

## 背景 / 課題

表示の面（pane の中のプログラムが `sodactl display` で出すパネルと帯。`docs/display.md`）は、PR1〜PR3（`20261007-soda-extensions`）で、パネルは **pane の右に固定**・帯は **端末の上に固定** で出るようになった。
使ってみて、利用者が次を求めた（2026-10-08。決定済み）。

- パネルをたたんでも、**再読み込みで開いた状態に戻る**（たたみは保存していない。`research.md` F9）。
- パネルが、出るたびに端末の幅を奪う。**初めはたたんでおき、ボタンを押したときだけ開く**出し方が無い。端末の幅を奪わずに見る方法（画面の中に浮く窓）も無い。
- パネルは右にしか置けず、帯は上にしか置けない。帯はたためない。
- たたんだパネルは、幅 24px の縦の見出しになる（端末の幅を、たたんでも 24px 使う）。

## 目的 / ゴール

利用者が、pane ごとに、**表示の面を置く場所（上・下・左・右・浮いた窓）と、開いているか・たたんでいるかを自分で決められ、その決めた状態が、再読み込みの後も同じ画面で保たれている**状態。
たたんだ面・閉じた浮いた窓は、**アプリが描く帯の行のボタン**から、いつでも開ける状態。
そのうえで、**PR3 までの守り（`research.md` G1〜G7）が、どの配置でも 1 つも弱まっていない**状態: 枠の `load` は 1 回のまま・固定のラベルと印が常に見える・浮いた窓が、ほかの pane や端末やアプリの部品の押下とキー入力を横取りできない・
プログラムとスクリプトが、利用者の決めた位置・大きさ・配置を変えられない。

（`.aidev/charter.md` は無い。）

## この作業の範囲の切り方

- **ブラウザ版（この work）と、端末版（`20261008-display-tui`）に分ける**（`decisions.md` D2）。端末版は、いまは面そのものを描かないので、「帯とパネルを描く・操作を返す」から作る。差分が大きく、守るもの（端末のエスケープシーケンス）も違う。
  この work が決める **プロトコルの項目（プログラムの指定）と、共有の設定の 3 項目は、端末版がそのまま使える形**にする。
- この work は、PR を 3 つに分ける（先の PR だけで使える順。`tasks.md`「PR の分け方」）:
  **PR-A** 状態の記憶と既定・帯をたたむ・帯の上下・帯の行のボタン ／ **PR-B** パネルの上下左右と D&D ／ **PR-C** 浮いた窓。

## ユーザーストーリー

- US1: 利用者として、たたんだパネル・帯が、再読み込みの後もたたんだままでいてほしい。なぜなら、要らない面を毎回たたみ直すのは手間だから。（受け入れ: AC1, AC3, AC9）
- US2: 利用者として、新しく出たパネルを、初めは開くか・たたんでおくかを、設定で選びたい。なぜなら、端末の幅を、頼んでいない表示に取られたくない人と、すぐ見たい人がいるから。（受け入れ: AC2, AC7）
- US3: 利用者として、たたんだ面を、いつも同じ場所のボタンから開きたい。そのボタンは、pane のプログラムが似せて描いたものと見分けられてほしい。なぜなら、開く操作の入口が、信頼できない中身に紛れてはならないから。（受け入れ: AC5, AC6, AC-I1, AC-I3）
- US4: 利用者として、帯を、上にも下にも置き、たたみたい。なぜなら、プロンプトの近く（下）に置きたい表示と、上でよい表示があり、要らないときは行を返してほしいから。（受け入れ: AC3, AC4）
- US5: 利用者として、パネルを、pane の上・下・左・右のどこにでも、ドラッグして置きたい。なぜなら、横に長い表（下が向く）と、縦に長い一覧（横が向く）があるから。（受け入れ: AC11〜AC16, AC-I2, AC-I3）
- US6: 利用者として、パネルを、端末の幅を変えずに、画面の中に浮く窓で見たい。窓は、動かせて、大きさを変えられ、ボタンで出し入れできてほしい。なぜなら、端末の列数が変わると、動いているプログラムの表示が崩れるから。（受け入れ: AC17〜AC20, AC-I1〜AC-I5）
- US7: パネルを出すプログラムの作者として、「下に」「浮いた窓で」「初めはたたんで」と、初めの置き方を指定したい。なぜなら、中身の形（横長・縦長・たまに見る）を知っているのは作者だから。ただし、利用者が変えた後は、利用者のものが勝ってよい。（受け入れ: AC7, AC8）
- US8: 利用者として、面をどこに置いても・どう動かしても、スクリプトが動く面の守り（覆い・印・フォーカスの番）が今までどおり効いていてほしい。なぜなら、置き場所を変えただけで、キー入力を取られる危険が増えては困るから。（受け入れ: AC10, AC19, AC21〜AC25）

- 記憶が無いときの既定を選ぶ、**共有の設定 3 つ**（パネルの初めの状態・パネルの既定の置き場所・帯の既定の上下）。
- 帯をたたむ・帯を上か下に置く。
- **帯の行のボタン**（たたんだパネル・たたんだ帯を開く。浮いた窓を開閉する。アプリが描く）。
- パネルを pane の上・下・左・右に置く。同じ側の複数のパネルはタブ。各側の大きさのつまみ。
- パネルの見出しをつかむ D&D と、同じことができるメニュー・キー。
- 浮いた窓（その pane の端末の領域の中。移動・大きさの変更・複数・重なりの順・キーボード）。
- プログラムの指定: `sodactl display set` の `--dock right|left|top|bottom|float`（パネル）・`--edge top|bottom`（帯）・`--collapsed`。機能の問い合わせ。
- 知らせ（トースト）が、どの配置でも、面の固定の部品に重ならないこと。

### 対象外

- **モバイルの画面（幅 767px 以下）**: 変えない。パネルは重ね表示（もともと「ボタンを押すと開く」出し方）、帯は端末の上。配置・たたみ・帯の上下・浮いた窓は効かない（`decisions.md` D12）。

- 浮いた窓の位置と高さを、**プログラムが指定すること**（守りのため、入れない。`--size` は今までどおり、幅〔上下に置いたときは高さ。浮いた窓では幅〕の**初めの値**。窓が 1 回出た後は、`--size` を変えても、窓は動かない）。
- 状態を、共有の設定・サーバに持つこと（別のブラウザ・別の端末へは引き継がない。画面の大きさが違うため）。
- スクリプトの面の状態（スクリプトが持つ値）を、配置の変更・たたむ／開くをまたいで保つこと（今のたたむ・タブの切り替えと同じく、作り直しで消える）。
- `20261007-soda-extensions`・`20261007-ext-host` の文書の変更。

## 機能要件

1. **たたみの記憶**: パネルと帯の、開いている・たたんでいるを、**pane と面の名前（と種類）の組**ごとに、その画面が覚える。再読み込み・再接続・面の出し直し（閉じて、同じ名前で出す）の後も同じ。
2. **既定を選ぶ設定**（共有の設定。設定の画面の節「端末」）:
   - 「表示のパネルの初めの状態」: 開く（既定）／たたむ。**記憶が無い面にだけ**効く。
   - 「表示のパネルの既定の置き場所」: 右（既定）／左／上／下／浮いた窓。
   - 「表示の帯の既定の場所」: 上（既定）／下。
3. **帯をたたむ**: 帯の行のメニューから、たたむ。たたんだ帯は行を使わず、帯の行のボタン（機能要件 5）になる。押すと戻る。
4. **帯の上下**: 帯は、端末の上か下に出る。帯ごとに決まり、上と下に同時にあってよい。替えるのは、帯の行のメニュー・表示のメニュー（機能要件 9）。
5. **帯の行のボタン**: たたんだパネル・たたんだ帯を開くボタンと、浮いた窓を開閉するボタンを、**帯と同じ行の、アプリが描く部分**（左端の印「▍表示」の隣）に並べる。帯の中身（プログラムが描く枠）には入れない。
   出ている帯が無いときは、ボタンだけの細い行（高さ 24px）になる。ボタンが 1 つも無く、帯も無ければ、行は出ない。ボタンには、面の種類の印・**面の名前**（`[A-Za-z0-9_-]` だけ。題は使わない）・スクリプトの面なら印「スクリプト」を出す。
   **浮いた窓の面のボタンは、窓が開いている間も出したまま**（押された見た目になり、押すと閉じる。窓の開閉で、ボタンの行が出たり消えたりして端末の高さが変わる、を起こさない）。
   ボタンの並びは、行の幅の 4 割まで。収まらない分は「ほか N」のボタンにまとめ、押すと表示のメニューが開く。**たたんだパネルの幅 24px の縦の見出しは、やめる**（たたむと、端末は幅をすべて取り戻す）。
6. **パネルの置き場所**: パネルは、pane の上・下・左・右、または浮いた窓に置ける。パネルごとに決まり、別々の側に同時に置ける。同じ側の複数のパネルは、今までどおりタブで切り替える。
   **上・下に置いたパネルは、帯を隠さず、帯と端末の間に置く**（上から: 上の帯 → 上のパネル → 左のパネル・端末・右のパネル → 下のパネル → 下の帯）。上・下のパネルは pane の幅いっぱい、左・右のパネルは、その間の高さ。
7. **大きさ**: 各側のパネルの大きさ（左右は幅・上下は高さ）は、端末との境目のつまみ（ドラッグ・キーボード。今の幅のつまみと同じ決まり: ドラッグの間は案内の線だけ・離したとき 1 回だけ確定・`Esc`・ダブルクリックで戻す）で変えられ、pane と側ごとに覚える。
   **端末は、最低 40 列・10 行を保つ**。収まらないパネルは、自動でたたまれる（帯の行のボタンになる。押せない。理由が出る）。
8. **D&D**: パネルの見出し（固定のラベルのある行。ボタンの上を除く）をつかんで動かすと、その pane の中に、落とせる場所（上・下・左・右・中央＝浮いた窓）が出る。離した場所へ移る。`Esc`・pane の外で離す・ダイアログが開く、で取り消す。
   pane を動かす D&D（pane の名前をつかむ）とは、つかむ場所・落とせる場所の見た目・起きることが別。
9. **表示のメニュー**: D&D・帯の行のボタン・見出しのボタンで出来ることは、すべてメニューでも出来る。面ごとのメニュー（見出し・帯の行の［⋮］から。開く／たたむ・右／左／上／下／浮いた窓に置く〔帯は 上／下 に置く〕・キーで動かす／キーで大きさを変える〔浮いた窓〕・プログラムの指定に戻す・閉じる）と、
   pane の面の一覧のメニュー（新しいキーの操作 `display_menu`。既定 `prefix+shift+i`。面を選ぶと、その面のメニューが開く）。
10. **浮いた窓**: その pane の**端末の領域の中**に重なる窓。見出し（固定のラベル・印・［操作する］ほか、ドックのパネルと同じもの）・題・枠。端末の幅・行数を変えない。
    - 見出しをつかんで動かす。縁と角をつかんで大きさを変える。**窓の全体が、いつも端末の領域の中にある**（外へ出ない。pane の大きさが変わったら、中へ寄せて縮める）。最小 240×120px。最大は端末の領域。
    - 複数の窓を出せる。押した窓・操作を始めた窓が前に出る。**操作中の面の窓は、いつも最前面**（後から出た窓は、その後ろ）。初めの位置は、アプリが決める（右上から、窓ごとに少しずらす）。
    - ［たたむ］か、帯の行のその窓のボタンで閉じる（面は残る）。ボタンを押すと、同じ位置・大きさで開く。
    - **利用者がまだ触っていない浮いた窓は、いつも閉じて始まる**（プログラムの `--dock float` でも、設定の既定でも）。窓が端末の上に出るのは、利用者が開いたときだけ（「ボタンを押すと開く」。プログラムの都合で、端末の上に窓が重ならない）。
    - 位置と大きさは、pane と面の名前ごとに覚える。
    - **帯・帯の行のボタン・ドックのパネル・ほかの pane・tab バー・サイドバー・メニュー・ダイアログ・知らせには、重ならない**（それらが上、または領域が別）。
11. **プログラムの指定**: `sodactl display set` に `--dock right|left|top|bottom|float`（`--kind panel` だけ）・`--edge top|bottom`（`--kind band` だけ）・`--collapsed`（どちらも）。**初めの値**であり、優先は
    **利用者がその画面で決めたもの ＞ プログラムの指定 ＞ 設定の既定**。利用者が、その面を 1 回でも操作する（開く・たたむ・移す・窓を動かす）と、その時点の置き場所とたたみが**まとめて**記憶になり、以後、その面には、指定も設定も効かない。ただし、たたみは「設定が『たたむ』か、プログラムが `--collapsed` を付けたか、置き場所が浮いた窓」なら、たたんで始まる（プログラムは、開かせる指定を持たない）。
    位置・大きさ（浮いた窓）を指定する口は無い。指定は `sodactl display list` に出る。
12. **機能の問い合わせ**: `sodactl display --features` の `sodactl`・`server` の機能に `layout`、出せる画面の数に `collapse`・`dock`・`float`（その機能を出せると名乗った画面の数）が出る。
13. **キーの操作**: `prefix+i`（`focus_display`）は、開いている面（浮いた窓を含む）を先に選び、無ければ、たたんだ面を開いて移る。`prefix+shift+i`（`display_menu`）で、表示のメニュー。どちらも設定の節「キー」で変えられる。
14. **知らせの位置**: 知らせ（トースト）は、面の固定の部品（見出し・帯の行のアプリが描く部分）に重ならない場所に出る（面が上下左右のどこにあっても・浮いた窓がどこにあっても）。

## 非機能要件 / 制約

- **PR3 の守りを弱めない**（`research.md` G1〜G7。AC21〜AC25 と AC10・AC19 が対応）:
  - 枠（iframe）を、DOM の中で動かさない。配置・たたみが変わるときは、枠の部品を外して作り直す（今のたたむ・タブの切り替えと同じ道）。浮いた窓の移動・大きさの変更・重なりの入れ替えは、スタイルだけを変える。
  - 見出し（固定のラベル・印「スクリプト」・［操作する］・［操作を終える］・操作中の文言）は、どの配置でも同じ部品で、枠の外に、欠けずに出る。
  - 枠・プログラムから、配置・たたみ・位置・大きさを変える道を足さない（プログラムの指定は、機能要件 11 の「初めの値」だけ）。
  - 面を開く・動かす・たたむ操作で、アプリは枠へフォーカスを移さない（枠へ入るのは、今までどおり、利用者のクリック〔静的な形式〕・`prefix+i`・［操作する］だけ）。
  - アプリ自身の操作（たたむ・配置替え・窓を閉じる）で、フォーカスを `body` へ落としたままにしない。
  - スクリプトの面の操作中に、利用者が、この作業の部品（見出しのボタン・つかむ場所・帯の行のボタン・つまみ・窓の縁）を押しても、「スクリプトがフォーカスを取った」と数えられない（利用者の押下で、面が閉じたり、pane が冷却に入ったりしない）。
- **端末を作り直さない**: 面の有無・配置で、端末（葉）の DOM の位置を変えない（今の決まり。`research.md` F1）。
- **端末の大きさを送りすぎない**: 配置・たたみ・大きさの確定のたびに、端末の大きさ（`client.view`）は 1 回だけ変わる。ドラッグの間は送らない。浮いた窓の操作では、送らない。
- **古い版との組み合わせ**: 黙って壊れない。古いサーバ＝sodactl が指定を落として、今までどおり出す（結果に、落とした項目が出る）。古い画面（読み込み直していない）＝今までの場所に出る。古い sodactl＝新しい引数を知らない（使い方の誤り）。
- **上限**: 覚える状態は、面ごと 256 件・名前ごと 64 件・pane の側ごと 128 件まで（古い順に捨てる）。もう無い pane の分は、接続のたびに捨てる。壊れた値は捨てる。
- 面の名前・pane の id の形（UUID）に依存しない。
- `third_party/ask-form/`・`/ask-view/*`・`/display-view/*` の応答ヘッダと `sandbox` の値・枠の中のページ（`frame.js`・`script.html`）は変えない。

## 完了条件 (受け入れ基準)

状態の記憶・既定・帯・帯の行のボタン（PR-A）

- [ ] AC1: パネルをたたむ／開くと、再読み込みの後も、同じ pane の同じ名前の面は同じ状態で出る。面を閉じて同じ名前で出し直しても同じ。別のブラウザ（別の `localStorage`）の状態は変わらない。
- [ ] AC2: 設定「表示のパネルの初めの状態」を「たたむ」にすると、**記憶の無い**パネルは、たたんで（帯の行のボタンとして）出る。既に利用者が開いた・たたんだ面の状態は変わらない。設定は、ほかのブラウザにも伝わる（共有の設定）。既定は「開く」（今までどおり）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: たたんだ面・閉じた浮いた窓は、帯の行のボタン（クリック・`Enter`・`Space`）・表示のメニュー・`prefix+i` で開く（`prefix+i` は、開いているパネル〔最後に操作した面から〕→ たたんだパネル → 出ている帯 → たたんだ帯、の順に選び、たたんだ面は開いてから移る）。閉じる（たたむ）のは、見出しの［たたむ］・面のメニュー。開く／たたむで、面は消えない（プログラムへ何も届かない）。枠の中の入力の途中の値と、スクリプトの状態は消える。
  面そのものを閉じるのは、今までどおり［×］（プログラムへ「利用者が閉じた」）。メニューは、項目を選ぶ・`Esc`・外を押す、で閉じる。
- [ ] AC-I2 確定 / 取り消し: D&D・窓の移動・大きさの変更は、離したときに確定し、`Esc`（とダイアログが開いたとき・ポインタの取り消し）で、始める前の状態へ戻る。メニューの項目は、選んだ時点で確定する。キーで動かす／大きさを変えるモードは、`Enter` で確定・`Esc` で元へ戻る。
  どの確定も、「プログラムの指定に戻す」で、記憶ごと取り消せる。
- [ ] AC-I3 キーボードだけで完結するか: 端末から `prefix+shift+i` で表示のメニューを開き、矢印で面を選び、`Enter` で面のメニュー、矢印と `Enter` で「開く」「下に置く」「浮いた窓にする」「キーで動かす」などを実行し、`Esc` で端末へ戻る、がマウス無しで通る。
  D&D・帯の行のボタン・つまみ・窓の移動と大きさの変更で出来ることは、すべてキーボードで出来る。帯の行のボタン・見出しのボタン・つまみには `Tab` で届く。
- [ ] AC-I4 フォーカスの行き先: マウスで帯の行のボタン・見出しのボタンを押しても、フォーカスは動かない（端末にあれば端末のまま）。フォーカスが、その面の見出しのボタン・帯の行のボタンにあって（`Tab` で届いて）操作したときは、開いた → その面の見出しの［たたむ］（浮いた窓の帯の行のボタンは、開閉の後も行にあるので、フォーカスはそのまま）、たたんだ → その面の帯の行のボタン、置き場所を変えた → 移った先の見出しの［⋮］へ移る。
  メニューは、閉じると、開く前の場所（端末・ボタン）へ戻る（メニューを開いたまま、フォーカスを取らない部品を押して閉じたときも）（項目を実行して、その場所が消えたときは、上の行き先。無ければ端末）。枠の中にフォーカスがあるときに表示のメニューを開いたら、戻る先は端末。キーで動かす／大きさを変えるモードを終えると、始める前の場所へ戻る。
  ［操作する］・［操作を終える］は、今までどおり（PR3 の決まり）。フォーカスが枠の中にある面をたたむ・移すと、端末へ戻る。面が出た・更新された・消えたときは、今までどおり動かない。
- [ ] AC-I5 既存の操作を妨げないか: D&D・窓の移動の間のキーは、端末へ流れない（`Esc` は取り消し）。浮いた窓の上のホイールは、窓の中（枠）をスクロールし、端末のスクロールバックを動かさない。窓の外の端末は、今までどおり押せる・選べる・打てる。
  pane の分割の境のドラッグ・pane の D&D・拡大（zoom）・コピーモード・`prefix+i`・`Esc`（枠から端末へ）は、今までどおり動く。浮いた窓の見出しにフォーカスがあるときの `Esc` は、窓を閉じずに、端末へ戻る。窓の題・余白・縁を押しても、フォーカスは端末のまま。

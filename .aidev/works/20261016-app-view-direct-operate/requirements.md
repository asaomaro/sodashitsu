# 20261016-app-view-direct-operate: requirements

アプリタブのメイン画面を、［操作する］なしで操作できるようにする。

## 背景
- script の面の出どころは 3 通り: ①プラグインのアプリのメイン画面（承認した拡張が出す。信用）②画面に描いた外の中身が script として動くもの（プラグインの作りで防ぐ）③pane のプログラムが出した面（信用しない。覆いで守る）。
- 覆い（［操作する］）は主に ③ のための仕組み。sandbox・CSP は操作中も効く。アプリ固有の入力欄からの指示は `soda.action` が覆いに関係なく呼べるので、覆いでは守られていない。→ ① では覆いは手間だけ増やしている。
- 操作中、キーは隔離された枠の中へ直接届き、親は prefix を受け取れない。枠から届く知らせが本当に押されたキーかは、親は見分けられない（偽れる）。

## 要件
- **A**: メイン画面（`tabView.display`・`mobileDisplay` の面。`DisplayInfo.source` が拡張のもの）は、タブを開いた・選んだ時点で**操作中**（覆い・［操作する］なし）。
- **B**: メイン画面では `Esc` で抜ける操作を設けない（`Esc` はアプリが使える）。prefix は枠の中の**中継**（作者の script より先。window の capture）が親へ伝え、親は**壊さない操作だけ**受ける。閉じる等は枠の外のタブ行からマウスで。印「スクリプト」と操作中の表示は残す。
  - 受ける操作: タブの切り替え（次・前・番号）、ワークスペースの切り替え。作業画面⇄アプリ画面は、**既存のキー操作が無い**ので含めない（報告）。閉じる・分割・送る・起動・終了・設定の変更・コマンドの実行は受けない。
  - 中継の知らせは偽れる前提。受けて困る操作は入れない。送りすぎには上限。
- **B-1**: 中継で画面・タブを切り替えても、端末へフォーカスを移さない（タブ行などへ）。
- **B-2**: 枠が固まると中継も止まる。出口は「マウスでタブ行」と既存の「10 秒応答が無ければ閉じる」。docs の限界に書く。
- **C**: パネル・帯・浮いた窓の面と pane のプログラムが出した面は、今どおり［操作する］と `Esc`。メイン画面以外に広げない。
- 端末版は対象外。モバイル Web: A は同じ。B（prefix の中継）はキーボードがあれば同じ動き（キーが来なければ何も起きない）。

# 要件: エージェントの fork（会話を引き継いだエージェントを、別の pane・別の worktree に起こす）

> **下書き（2026-10-09）**。調査（`research.md`）の結果で、できること・できないことを確かめてから、確定する。

## 背景 / 課題

- Sodashitsu は、エージェントを pane に並べ、worktree で作業フォルダを分けられる（workspace のメニューの「新しい worktree」「worktree を開く」）。分けられるのは、**ファイル**だけで、**エージェントの会話の記憶**は、分けられない。別の案を試すときは、新しいエージェントに、同じ調査を、最初からやり直させている。
- 利用者の問い（2026-10-09）: 「fork を Sodashitsu に足す場合、どちらの fork か」。監督役は、リポジトリの fork（GitHub の上の写し）ではなく、**会話（セッション）の fork** を勧め、利用者は「作って」と決めた。

## 目的 / ゴール

動いているエージェントを、**ここまでの会話の記憶を持ったまま**、別の pane に、もう 1 つ起こせる状態。起こす先は、同じフォルダか、新しい worktree（新しいブランチ）を選べる。どこから枝分かれしたかが、グラフで見える。

## ユーザーストーリー

- US1: エージェントに調査をさせた利用者として、その理解を持ったまま、別の案を、並べて試したい。なぜなら、同じ調査を、やり直させたくないから。
- US2: 2 つの案を、互いのファイルを書き換え合わずに試したい。なぜなら、同じフォルダで 2 つのエージェントが書くと、壊し合うから。（新しい worktree で fork）
- US3: どのエージェントが、どこから枝分かれしたかを、後から見たい。（グラフの線）

## スコープ

### 対象
- Claude Code のエージェント（まず、これだけ）。
- ブラウザ版の、pane のメニュー・グラフのノードのメニュー。`sodactl agent fork`。

### 対象外
- リポジトリの fork（GitHub の上の写し）。
- ほかのエージェント（Codex など）。調査で、同じ口があると分かったものは、後の作業の候補。
- 会話の途中の、任意の時点からの fork（fork するのは、いまの時点）。
- fork したエージェントどうしの、結果の比べ・取り込み。
- 端末版（`soda`）のメニュー（`sodactl` は、端末版の中からも使える）。

## 完了条件 (受け入れ基準)

調査（`research.md`。Claude Code 2.1.295 で実測）の結果を反映した。

- [ ] AC1: Claude Code が動いている pane の右クリックのメニューと、グラフのノードのメニューに、「このエージェントを fork」がある。fork できないときは、押せない形で、理由を出す: Claude Code でない／**会話の id が分からない**（フックを入れていない・フックを入れる前に起動したエージェント。「設定の『エージェント連携』でフックを入れて、エージェントを起動し直すと、使えます」）／別のマシンの pane。
- [ ] AC2: 「同じフォルダで fork」を選ぶと、同じ workspace の同じ tab に、新しい pane ができ（基本画面の、分割の既定の向き）、そこで、**元の会話を引き継いだ、別のセッション**の Claude Code が起動する（`claude --resume <会話の id> --fork-session`）。元のエージェントは、止まらず、そのまま続く。元の会話の記録は、書き換わらない。**引き継がれるのは、会話とモデル。権限のモードと、追加したフォルダは、引き継がれない**（確定の前の画面に、そう出す）。
- [ ] AC3: 「新しい worktree で fork」を選ぶと、ブランチ名を決めて（今の「新しい worktree」と同じ決まり。枝は、元の workspace のフォルダの `HEAD` から切る）、新しい worktree と workspace ができ、そこで、元の会話を引き継いだ Claude Code が起動する。確定の前の画面に、次を出す: (a) 作成先 (b) **まだコミットしていない変更は、付いてこない**（変更があるときだけ。変更されたファイルの数つき。サーバが `git status` で数える）(c) 権限のモードなどは、引き継がれない。起動した後、fork したエージェントに、**最初の知らせ**を 1 回送る:「このセッションは、fork されました。作業フォルダは <新しいフォルダ> です。元のフォルダ <元のフォルダ> のファイルは、変更しないでください」（会話の中の絶対のパスが、元のフォルダを指したままなので、元のフォルダを書き換えないように。利用者に見える形で、pane に打ち込む。知らせを送らない選択も、確定の前の画面でできる）。
- [ ] AC4: fork したエージェントのノードは、グラフで、元のノードから「fork」の線で繋がる。**見るだけの線**（指示は流れない・設定の画面を持たない・線の上限に数えない）。ノードに付く注記（どのノードから fork したか）として保存し、再起動の後も残る。元のノードが無くなったら、線は消える（注記は、掃除する）。古い版のサーバ・ブラウザは、注記を無視する（グラフのファイルが、読めなくならない）。fork には、エージェントが起動したエージェントに付く、自動の監督の線・承認の代理の線を、付けない。
- [ ] AC5: fork の操作が送るのは、「どの pane のエージェントを」「同じフォルダか、新しい worktree か」「ブランチ名」「最初の知らせを送るか」だけ。**ブラウザから、起動するコマンドの文字列・会話の id を、受け取らない**（会話の id は、サーバが、その pane の記録から引く。起動のしかたは、サーバの固定の表から）。画面からと、`sodactl`（ログイン済み）から使える。`pane.sock`（ログイン不要の受け口）には、載せない。
- [ ] AC6: `sodactl agent fork <pane> [--worktree <ブランチ>] [--no-note]` で、同じことができる。結果に、新しい pane の id が返る。
- [ ] AC7: 失敗したとき、理由が分かり、半端な状態が残らない: 古い Claude Code（会話の fork に対応していない版）・会話の記録が見つからない（`CLAUDE_CONFIG_DIR` が違う）・worktree を作れない（ブランチ名の重複）・pane を足せない。worktree を作った後に、起動で失敗したときは、作った workspace は残し（中身があるため）、何が残ったかを知らせる。
- [ ] AC8: 文書（`docs/agent-fork.md` を新しく。`docs/sodactl.md`・`docs/agent-graph.md`・`AGENTS.md` の案内）。限界: Claude Code だけ・フックが要る・権限のモードは引き継がれない・長い会話の fork は、起動に時間と費用がかかる・別のマシンの pane は対象外。

## 決めたこと

| # | 事項 | 決定 | 根拠 |
| :- | :- | :- | :- |
| F1 | どちらの fork か | 会話（セッション）の fork | 利用者（2026-10-09） |
| F2 | 対象 | まず Claude Code だけ（Codex には `codex fork <id>` があるが、後の作業） | 調査 |
| F3 | 会話の id の出どころ | フックの報告（`pane.agentSession`）だけ。プロセスの引数・更新の時刻から、推さない | 推すと、別の会話を fork しうる |
| F4 | 別のフォルダからの fork | 記録の写しは、しない（Claude Code が、id で全プロジェクトから探す。v2.1.223 以降） | 調査（実測） |
| F5 | グラフの線 | 新しい線の種類は足さず、ノードの注記（`forkedFrom`）にする | 新しい種類を足すと、古い版が、グラフのファイルを退避して空で起動する |
| F6 | 絶対のパスの問題 | 最初の知らせを、fork したエージェントに送る（既定で送る。やめられる） | 元のフォルダを、書き換えないため |

## 残る問い

- 対話中の実際のプロセス（`-p` ではない）を fork できるかは、`-p` で眠っている最中の fork しか確かめていない。実装のときに、実際の対話のセッションで確かめる。

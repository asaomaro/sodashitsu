# 要件: エージェントの fork（会話を引き継いだエージェントを、別の pane・別の worktree に起こす）

> **下書き（2026-10-09）**。調査（`research.md`）の結果で、できること・できないことを確かめてから、確定する。

## 背景 / 課題

- Sodashitsu は、エージェントを pane に並べ、worktree で作業フォルダを分けられる（workspace のメニューの「新しい worktree」「worktree を開く」）。分けられるのは、**ファイル**だけで、**エージェントの会話の記憶**は、分けられない。別の案を試すときは、新しいエージェントに、同じ調査を、最初からやり直させている。
- 利用者の問い（2026-10-09）: 「fork を Sodashitsu に足す場合、どちらの fork か」。監督役は、リポジトリの fork（GitHub の上の写し）ではなく、**会話（セッション）の fork** を勧め、利用者は「作って」と決めた。

## 目的 / ゴール

動いているエージェントを、**ここまでの会話の記憶を持ったまま**、別の pane に、もう 1 つ起こせる状態。起こす先は、同じフォルダか、新しい worktree（新しいブランチ）を選べる。どこから枝分かれしたかが、グラフで見える。

## ユーザーストーリー

- US1: エージェントに調査をさせた利用者として、その理解を持ったまま、別の案を、並べて試したい。なぜなら、同じ調査を、やり直させたくないから。
- US2: 2 つの案を、互いのファイルを書き換え合わずに試したい。なぜなら、同じフォルダで 2 つのエージェントが書くと、壊し合うから。（新しい worktree で fork）
- US3: どのエージェントが、どこから枝分かれしたかを、後から見たい。（グラフの線）

## スコープ

### 対象
- Claude Code のエージェント（まず、これだけ）。
- ブラウザ版の、pane のメニュー・グラフのノードのメニュー。`sodactl agent fork`。

### 対象外
- リポジトリの fork（GitHub の上の写し）。
- ほかのエージェント（Codex など）。調査で、同じ口があると分かったものは、後の作業の候補。
- 会話の途中の、任意の時点からの fork（fork するのは、いまの時点）。
- fork したエージェントどうしの、結果の比べ・取り込み。
- 端末版（`soda`）のメニュー（`sodactl` は、端末版の中からも使える）。

## 完了条件 (受け入れ基準)（下書き）

- [ ] AC1: Claude Code が動いている pane のメニューと、グラフのノードのメニューに、「このエージェントを fork」がある。fork できないとき（Claude Code でない・会話の id が分からない・古い版）は、項目を出さないか、押せない形で理由を出す。
- [ ] AC2: 「同じフォルダで fork」を選ぶと、同じ workspace の同じ tab に、新しい pane ができ、そこで、**元の会話を引き継いだ、別のセッション**のエージェントが起動する。元のエージェントは、止まらず、そのまま続く。元の会話の記録は、書き換わらない。
- [ ] AC3: 「新しい worktree で fork」を選ぶと、ブランチ名を決めて、新しい worktree と workspace ができ、そこで、元の会話を引き継いだエージェントが起動する。**まだコミットしていない変更は、付いてこない**ことを、確定の前に、はっきり出す（変更があるときだけ。件数つき）。
- [ ] AC4: fork したエージェントのノードは、グラフで、元のノードから「fork」の線で繋がる（見るための線。指示は流れない）。線は保存され、再起動の後も残る。
- [ ] AC5: fork の操作が送るのは、「どの pane のエージェントを」「どこへ」だけ。**ブラウザから、起動するコマンドの文字列を、受け取らない**（起動のしかたは、サーバが、エージェントの種類と、その会話の id から決める）。
- [ ] AC6: `sodactl agent fork <pane> [--worktree <ブランチ>]` で、同じことができる。
- [ ] AC7: 文書（`docs/` の、エージェントの操作の説明・`docs/sodactl.md`）。

## 残る問い（調査で確かめる）

- Claude Code の、会話を引き継いで別のセッションとして始める起動のしかた（引数）と、その制約（動いている最中のセッションを fork できるか・引き継がれる範囲・モデルや権限の設定は引き継がれるか）。
- Sodashitsu が、pane のエージェントの「会話の id」を、いま、どこまで知っているか（フックの報告・`agentSession`）。フックを入れていない利用者では、どうなるか。
- 新しい worktree で fork するとき、会話の記録は、元のフォルダ（プロジェクト）に結びついている。別のフォルダで、引き継げるか。
- ほかのエージェントに、同じ口があるか。

# 要件: グラフを主体にしたワークフロー（グラフの画面で pane を足す・移す・操作する・処理を呼ぶ）

## 背景 / 課題

- いまの連携のグラフ（`docs/agent-graph.md`。20260927-agent-graph）は、基本画面で作った pane を選んで載せ、線で結ぶ・つながりを確かめる、ための画面にとどまる。pane を足す・エージェントを起動する・端末を操作する、は基本画面でしかできず、ノードを押すとグラフの画面が閉じる。
- 利用者の構想（2026-10-08）: グラフの画面を主体にしたワークフローを提供する。見せ方が違うだけで、基本画面と同じ実体（workspace・tab・pane）を扱い、どちらの画面も自由に行き来できる。「ターミナルマルチプレクサ」から「グラフの UI」への、使い方の転換。
- 画面の案は、利用者が採用した（2026-10-08。Artifact「グラフ主体のワークフロー」の 1〜5 枚目。5 枚目が構造の確定版）。

## 目的 / ゴール

グラフの画面だけで、エージェントを使う作業の一巡（pane を足す → エージェントを起動する → 指示する・承認する → 結果を次へ渡す → 置き場所を整える）ができる状態。基本画面で行った変更はグラフに、グラフで行った変更は基本画面に、そのまま現れる。

## 用語

- **グループ**・**worktree グループ**・**「グループなし」**: いまのサイドバーのまとまり（`docs/tui.md`「サイドバーのグループ」。20261004-group-worktree-items）。
- **空間**: グラフの 1 枚の面。グループごと（と「グループなし」）に 1 枚。
- **囲い**: 空間の上で、workspace・worktree グループを表す枠。
- **端末の窓**: グラフの上に重ねて開く、pane の端末。
- **処理のノード**: pane ではないノード。サーバに定義済みの処理を、線をきっかけに呼ぶ。

## ユーザーストーリー

- US1: 複数のエージェントを動かす利用者として、グラフの画面で全体を見たまま、pane を足し、端末を操作したい。なぜなら、基本画面との往復で、全体の把握が途切れるから。（AC-V・AC-T・AC-A）
- US2: workspace が多い利用者として、サイドバーの行から、グラフの上の目的の場所へ動きたい。なぜなら、広い空間から目で探すのは遅いから。（AC-S）
- US3: 作業の置き場所を整える利用者として、グラフの上のドラッグで、pane・worktree グループを移したい。（AC-M）
- US4: 連携を組む利用者として、エージェントの完了をきっかけに、定義済みの処理（テスト・整形・知らせ）を走らせ、その結果を次へ渡したい。（AC-P）

## スコープ

### 対象

- ブラウザ版のデスクトップの、グラフの画面。
- グラフの保存の形（ノード・位置・囲い・空間）と、`sodactl graph` の表示。
- サイドバー（基本画面と同じ部品）の、グラフの画面での動き。

### 対象外

- 端末版（引数なしの `soda`）。グラフの画面は、今までどおりブラウザだけ。
- モバイルの 1 列の画面。今の「見るだけ」の画面のまま（新しい操作は足さない）。
- 別のマシンの pane への、新しい操作（足す・移す・端末の窓）。今までどおり、載せる・線を結ぶ・そのマシンへ移る、だけ。
- tab の枠。tab は、タグで表す（決定 G3）。tab の中の分割の形（左右・上下・比率）は、グラフでは表さない・変えない。
- pane を別の worktree の workspace へ移すこと（#98 の制限のまま）。
- worktree グループの一部だけを、別のグループへ移すこと（今の決まりのまま）。
- 処理のノードのための、新しい定義の書式。呼べるのは、いまある定義（独自コマンド `commands.json`）だけ（決定 G8）。処理の文字列を、ブラウザ・グラフの保存に持たせない。
- 画面の様式（角・余白・文字）。`20261008-ui-style` の仕組みに乗る。

## 完了条件 (受け入れ基準)

### 画面の構造（AC-V）

- [ ] AC-V1: グラフの画面は、グループごとに 1 枚の空間を持つ。「グループなし」も 1 枚。空間の見出しの並びから切り替えられ、並びの順はサイドバーと同じ。
- [ ] AC-V2: 空間には、そのグループの**すべての** workspace が、囲いとして出る。worktree グループは外側の囲いになり、その中に worktree ごとの workspace の囲いが入る。囲いの見出しに、名前・フォルダ（ブランチ）が出る。
- [ ] AC-V3: 囲いの中に、その workspace の**すべての** pane が、ノードとして出る（選んで載せる操作は要らない）。ノードには、今と同じ情報（呼び名・エージェントの名前と種類・状態・サブエージェントの件数）に加えて、tab のタグが出る。
- [ ] AC-V4: workspace の見出しに、その workspace の tab のタグが並ぶ。基本画面で選んでいる tab は、見分けられる。タグを押すと、その tab のノードだけが強く表示される（もう一度押すと戻る）。tab が 1 つだけの workspace では、ノードのタグを省いてよい。
- [ ] AC-V5: ノード・囲いの位置は保存され、ほかのブラウザにすぐ届く。pane・workspace・グループが基本画面で増えた・減った・移ったときは、グラフが再読み込みなしで追従する。新しいノードは、囲いの中の空いた場所に置かれ、既存のノードの位置は動かない。囲いは、中のノードが収まる大きさに保たれる。
- [ ] AC-V6: 線（きっかけ・監督・承認の代理）の働きは、今と同じ。今あるグラフ（ノード・線・位置）は、この作業の後も失われない——線はそのまま残り、ノードは、その pane のある囲いの中に置き直される。
- [ ] AC-V7: 線は、同じ空間のノードどうしで結ぶ。今ある・移動で生じた、別の空間のノードとの線は、消さずに働き続け、ノードの縁に「別のグループの <呼び名>」への印として出る（押すと、その空間のそのノードへ動く）。
- [ ] AC-V8: 上限を見直す。ノードは「すべての pane」になるので、今の 64 を、pane の数の上限に合わせる（値は設計で決める）。超えたときは、理由を示して、足す操作を断る。200 ノード・200 線で、ドラッグ・拡大縮小が引っかからない（設計で、測り方と基準を決める）。

### サイドバーと行き来（AC-S）

- [ ] AC-S1: グラフの画面でも、基本画面と同じサイドバー（workspace・エージェントの一覧）が出る。
- [ ] AC-S2: サイドバーの workspace の行を押すと、その workspace のある空間に切り替わり、囲いが画面に収まる位置へ動いて、囲いが強く表示される。エージェントの行を押すと、同じに、そのノードへ動く。
- [ ] AC-S3: 基本画面とグラフの画面を、サイドバーの切り替え・今のキー（`open_graph`）で行き来できる。行き来しても、選んでいる workspace・tab・pane は保たれる（グラフでノードを選んでから基本画面へ戻ると、その pane にフォーカスがある）。
- [ ] AC-S6: 画面の切り替えは、2 択の入れ替えではなく、**画面の並び**として作る（いまは「基本画面」「グラフ」の 2 つ）。後の作業で、3 つ目以降（プラグインが差し込む、特定の作業に特化した画面。利用者の構想。2026-10-09）を足せる形にする。どの画面も、同じ実体（グループ・workspace・tab・pane）の見せ方であり、切り替えても実体は変わらない。この作業では、3 つ目の画面と、差し込む仕組みは作らない。
- [ ] AC-S4: 空間の全体の中の現在地が分かる（小さな地図）。地図を押す・ドラッグすると、その位置へ動く。
- [ ] AC-S5: 名前で探せる（pane の呼び名・エージェントの名前）。選ぶと、AC-S2 と同じに動く。

### 端末の窓（AC-T）

- [ ] AC-T1: ノードを押す（または選んで `Enter`）と、グラフの上に、その pane の端末の窓が開く。グラフの画面は閉じない。窓の中で、基本画面と同じに、その pane を操作できる（キー・貼り付け・マウス・画像・リンク）。
- [ ] AC-T2: 窓は、動かせ、大きさを変えられ、閉じられる。「基本画面で開く」で、その pane へ移れる。「留める」と、ほかのノードを押しても閉じない。同時に開ける窓の数には、上限がある（値は設計で決める）。
- [ ] AC-T3: 窓にフォーカスがある間、キーはその pane に届く（グラフのキーの操作は働かない）。決まったキーで、グラフへフォーカスを戻せる。`Esc` は、pane に届く（エージェントの操作に使われるため）。
- [ ] AC-T4: pane の大きさ（桁と行）は 1 つ。窓を開いたときの大きさの扱いは、今の「操作を引き取る」仕組み（`pane control`）と同じ決まりに従い、窓を閉じると、基本画面の大きさへ戻る。同じ pane を、基本画面の別のブラウザが見ていても、表示が壊れない。
- [ ] AC-T5: pane が閉じられた・別の空間へ移った、ときは、窓が閉じる。窓を閉じたとき、フォーカスは、そのノードへ戻る。
- [ ] AC-T6: 表示の面（パネル・帯）を持つ pane の窓では、面を出さない（その pane に面があることだけを、見出しの印で示す）。スクリプトの面の守り（フォーカスの戻しと遮断器）を、窓が壊さない。

### 足す（AC-A）

- [ ] AC-A1: 囲いの見出しの「＋」から、その workspace に pane を足せる。種類（シェル・エージェントの種類）と名前を決められる。足した pane は、その workspace で選んでいる tab に、分割して入る（基本画面で見ても、tab の中に収まっている）。
- [ ] AC-A2: エージェントを選んだときは、その pane でエージェントが起動する（`sodactl agent start` と同じ経路）。「監督の線を結ぶ」を選ぶと、選んだノードからの線が、同時に結ばれる。
- [ ] AC-A3: 足した直後に、端末の窓が開く。
- [ ] AC-A4: 空間の空いた場所・ツールバーから、workspace を足せる（基本画面の、workspace を作る・worktree を開く、と同じ入口）。足した workspace は、表示中のグループに入る。
- [ ] AC-A5: ノード・囲いから、閉じる操作ができる（基本画面と同じ確認）。

### 移す（AC-M）

- [ ] AC-M1: ノードを、別の workspace の囲いへドラッグして落とすと、その pane が、その workspace で選んでいる tab へ移る。見出しの tab のタグへ落とすと、その tab へ移る。線は、つながったまま残る。
- [ ] AC-M2: 移せる先は、今の制限と同じ（同じ worktree の workspace どうしだけ。`different_worktree`）。つかんだ時点で、落とせる囲いと落とせない囲いが見分けられ、落とせない囲いには理由が出る。`Esc` で取りやめられる。
- [ ] AC-M3: worktree グループは、ひとかたまりで動く。外側の囲いをつかんで、空間の見出し・サイドバーのグループへ落とす（または「別のグループへ移す」）と、worktree グループ全体が、そのグループへ移る。中の workspace だけを移す操作は、出さない。通常の workspace は、1 つで同じに移せる。
- [ ] AC-M4: 囲いの中でのノードの位置の変更・空間の中での囲いの位置の変更は、今のドラッグと同じ（グリッドに吸い付く・保存される）。位置の変更と、囲いをまたぐ移動は、取り違えない（囲いの外へ出るまでは、位置の変更）。

### 処理のノード（AC-P）

- [ ] AC-P1: 空間に、処理のノードを足せる。足すときに、サーバに定義済みの処理（独自コマンド `commands.json` の、裏で走る種類）から 1 つ選ぶ。ノードには、処理の id と説明が出る。
- [ ] AC-P2: ノードから処理のノードへの線（きっかけ）が動くと、その処理が走る。処理には、きっかけの元の pane の情報（id・場所・状態）が、環境変数で渡る。元の pane の出力を渡すかは、線の設定で選ぶ（既定は渡さない）。
- [ ] AC-P3: 処理のノードには、状態（待ち・実行中・成功・失敗）と、直近の結果（終了コード・時刻）が出る。処理のノードから pane のノードへ、線を結べる——処理が終わったら（成功・失敗を選べる）、その pane に、定めた指示と、処理の出力の末尾を渡す。
- [ ] AC-P4: 安全。グラフの保存・ブラウザとのやり取りが持つのは、処理の id だけ。処理の文字列は、サーバの設定ファイルだけにあり、ブラウザから書き換えられない。定義から消えた id のノードは、走らず、「定義が無い」と出る。処理は、今の線の上限・一時停止・履歴の決まりに従う（連鎖の暴走を止める）。
- [ ] AC-P5: 処理のノードを、手で 1 回走らせられる（確かめのため）。

### 共通

- [ ] AC-X1: `sodactl graph show` に、空間・囲い・処理のノードが出る。今の JSON を読んでいるプログラムが壊れない（項目を足すだけ）。
- [ ] AC-X2: キーだけで、主な操作ができる（空間の切り替え・ノードの選択と移動・端末の窓を開く・足す・移す）。
- [ ] AC-X3: 文書が合っている（`docs/agent-graph.md`・`docs/sodactl.md`・`docs/custom-commands.md`）。

## 非機能・制約

- **差分を小さく切る**（`AGENTS.md`）。5 つの PR に分ける。前の PR だけでも、使える状態にする。
  1. 構造: 空間・囲い・すべての pane・tab のタグ・保存の形の移行・サイドバーからの移動（AC-V・AC-S）
  2. 端末の窓（AC-T）
  3. 足す（AC-A）
  4. 移す（AC-M）
  5. 処理のノード（AC-P）
- 壊れやすい所（タスクごとの独立点検を掛ける）: 保存の形の移行（AC-V6）・位置の計算（AC-V5）・端末の窓の大きさ（AC-T4）・移動の制限（AC-M2）・処理の実行の安全（AC-P4）。
- 表示の面の守りのファイル（`DisplayFrame.vue` ほか）は、変えない。

## 残る問い

- G8 の読み: 「定義済みの処理」に、拡張（`extensions.json` のプログラム）への呼び出し・エージェントへの定型の指示（プロンプトのひな形）を含めるか。含めるなら、PR 5 の中で種類を足す。
- 処理のノードは、どの空間にも置けるか・空間をまたいで共有するか（仮: 空間ごとに置く）。
- 既定の画面を、グラフにする設定を設けるか（G9）。

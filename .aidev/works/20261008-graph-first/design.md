# 設計: グラフを主体にしたワークフロー

要件は `requirements.md`。この設計は、5 つの PR のうち **PR1（構造）を詳しく**、PR2〜PR5 を骨子まで書く。PR2 以降は、PR1 の着地の後に、この文書へ追補する。

## いまの作り（調べた事実）

- グラフの画面は、`App.vue` が `<GraphView />` を、基本画面に重ねるダイアログとして出す（`view.graphOpen`。`#soda-graph-dialog` へ Teleport）。開いている間、サイドバーは隠れる。
- グラフの実体は、サーバの `Graph`（`packages/protocol/src/graph.ts`）: `nodes: {key, x, y}[]`・`links`・`rev`。ノードの鍵は `local:<paneId>` か `<マシンの id>:<paneId>`。更新は `graph.update`（`GraphOp` の列。1 回に 256 個まで）。座標は、1 枚の面の絶対の値（±1,000,000）。
- 上限: ノード 64（`GRAPH_NODES_MAX`）・線 128（`GRAPH_LINKS_MAX`）。
- ノードは、利用者が選んで載せる（`PaneChecklist.vue`）。例外は、エージェントが起動した pane（`AgentLineage`。サーバが、空いた位置に足す）。pane が閉じると、`GraphPaneCleanup` が後始末をする。
- グループ・worktree グループ・「グループなし」は、サーバの状態にある（`packages/protocol/src/model.ts` の `WorkspaceGroup`・`groups`。20261004-group-worktree-items）。
- pane の数そのものの上限は無い（描画の上限 `VIEW_VISIBLE_PANES_MAX` は 4096）。

## 方針

1. **実体を増やさない。** 空間・囲いは、保存しない。グループ・workspace・pane という、いまある実体から、毎回導く。保存するのは、今までどおり、ノードの位置と線だけ。
2. **すべての pane のノードは、サーバが持つ。** 位置がブラウザごとに食い違わないように、ノードを足す・置く・消すのは、サーバが行う。
3. **グラフの画面は、重ねるダイアログから、主な領域の画面に変える。** サイドバーは、そのまま残る。

## データ（PR1）

### ノード

- 手元のすべての pane に、ノード（`local:<paneId>`）がある。サーバは、次の時点でノードを足す。
  - 起動のとき（移行）: ノードの無い pane のすべてに。
  - pane ができたとき（分割・tab・workspace の作成・復元）。
- pane が閉じると、ノードと、その線が消える（今の `GraphPaneCleanup` の動き。確認のダイアログは、グラフから閉じる操作のときだけ）。
- 「pane を載せる」「グラフから外す」は、手元の pane では無くなる（別のマシンの pane では、今のまま）。`graph.update` の `remove_node` は、手元の開いている pane の鍵に対しては断る（`node_required`）。
- `AgentLineage` の「ノードを足す」は、要らなくなる（線を足す動きは残る）。

### 空間と囲い（導く）

- **空間** = グループ 1 つ（と「グループなし」）。ノードの属する空間は、pane → workspace → その workspace の項目が入っているグループ、で決まる。
- **ノードの座標は、属する空間の中の値**として読む。`Graph` の形は変えない（`x`・`y` のまま）。空間が違えば、同じ座標でも重ならない。
- **workspace の囲い** = その workspace のノードの外接の四角に、余白（見出し 44px・周り 24px）を足したもの。保存しない。
- **worktree グループの囲い** = 中の workspace の囲いの外接の四角に、余白（見出し 48px・周り 24px）を足したもの。
- 別のマシンのノードは、「グループなし」の空間に、マシンごとの囲いで出す。

### 置き場所の計算（`packages/protocol/src/graphLayout.ts`。新しい純粋な関数）

サーバとブラウザの両方が使う。入力は、空間のノードの位置と、囲いの構成。

- `frames(space)`: 囲いの四角の一覧を返す。
- `placeNode(space, workspaceId)`: 新しいノードの位置を返す。その workspace の囲いの中で、グリッド（ノード 216×76・間 40）の空いた升。囲いが広がって、ほかの囲いと重なる升は、選ばない（右 → 下の順に、重ならない最も近い升を探す）。既存のノードは、動かさない。
- `placeFrame(space, nodeCount)`: 新しい workspace（最初のノード）の位置。空間の、ほかの囲いと重ならない、左上に最も近い場所。
- `resolveDrop(space, moved)`: ドラッグの結果、囲いどうしが重なるかを判定し、重なるなら、重ならない最も近い位置を返す。

**重ならないことを、不変条件にする**: 同じ空間の workspace の囲いどうし（worktree グループの外の囲いどうしも）は、重ならない。サーバは、`graph.update` の `move_node` の結果がこれを破るとき、断る（`frame_overlap`）。ブラウザは、落とす前に `resolveDrop` で寄せるので、ふつうは断られない。

### 移行（AC-V6。壊れやすい。★）

起動のとき、1 回だけ行う（`Graph` に `layout: 2` の印を足す。無い・1 のときに移行する）。

1. 今あるノード（位置を持つ）は、位置を保ったまま、その pane の空間に属する。
2. ノードの無い pane に、`placeNode` でノードを足す。
3. 今ある位置のままだと囲いが重なる workspace は、その workspace のノードを、まとめて平行移動して、重ならない場所へ移す（workspace の中の相対の位置は保つ）。
4. 線は、触らない。
5. 移行の前の `Graph` を、状態ディレクトリに `graph.v1.bak.json` として残す（1 世代）。

移行の後に、古い版のサーバへ戻すと、ノードが 64 を超えていて読めないことがある。戻すときは、控えを戻す（文書に書く）。

### 上限（AC-V8）

- `GRAPH_NODES_MAX`: 64 → **512**。`GRAPH_LINKS_MAX`: 128 → **512**。`GRAPH_OPS_MAX`: 256 → **1024**（囲いごとの移動で、ノードの数だけ `move_node` を送るため）。
- 手元の pane が 512 を超えるときは、新しい pane にノードを足さない（pane は作れる。グラフには「上限のため、出ていない pane が N 個」と出す）。
- 性能の基準: 200 ノード・200 線で、ノードのドラッグ中のフレームの間隔が、中央値 16ms・最悪 50ms 以内（既存の `GraphView.perf.test.ts`・`perf.integration.test.ts` の流儀で測る）。

### 動いたとき

| できごと | サーバの動き |
| :- | :- |
| pane ができた | `placeNode` で足す |
| pane が別の workspace へ移った | そのノードを、移った先の囲いへ `placeNode` で置き直す。線は残す |
| workspace が別のグループへ移った（worktree グループごとも） | その workspace のノードを、相対の位置を保って、移った先の空間の `placeFrame` の場所へ平行移動する |
| pane・workspace が閉じた | ノードと線を消す |

線の両端が別の空間になったとき、線は消さない（AC-V7）。

## 画面（PR1）

### 画面の並び（AC-S3・AC-S6）

- `view.graphOpen`（真偽）を、`view.screen`（`"base" | "graph"`。後で足せる文字列の並び）に置き換える。画面の定義は、1 か所の一覧（`screens.ts`: id・名前・部品）に持つ。サイドバーの上に、この一覧から切り替えの部品を出す。
- `App.vue` の主な領域は、`view.screen` に応じて、基本画面（tab バーと pane）か、グラフの画面を出す。サイドバー・トースト・ダイアログは、共通。
- `open_graph`（`prefix+a`）は、2 つの画面の入れ替えとして残す。グラフの画面での `Esc` は、今の「1 段ずつ戻る」の最後（画面を閉じる）を、**基本画面へ切り替える**に読み替える。
- 基本画面の pane は、グラフの画面の間も、破棄しない（端末の状態・スクロール位置を保つ。`v-show`）。グラフの画面の間、キー・ホイールは pane に届かない（今と同じ）。
- モバイルの 1 列の画面は、今のまま（`MobileGraphSheet.vue`。重ねる画面のまま。`MobileShell.vue` は変えない）。

### グラフの画面

- 上: ツールバー（今の操作 +「全体を表示」・探す）。その下に、空間の見出しの並び（サイドバーのグループの順）。
- 面: 表示中の空間の、囲い・ノード・線。拡大縮小・移動は、空間ごとに覚える（ブラウザごと。`localStorage`）。
- 囲いの見出し: 名前・フォルダ（ブランチ）・tab のタグ。worktree グループの見出し: 名前・worktree の数。PR1 では、「＋」「別のグループへ移す」・つかんで移す、は出さない（PR3・PR4）。
- ノード: 今の `GraphNode.vue` に、tab のタグを足す。tab が 1 つの workspace では省く。
- 見出しの tab のタグを押すと、その tab のノードを強く、ほかを弱く出す（ブラウザの中だけの状態）。
- 別の空間のノードとの線: ノードの縁に、小さな印（相手の呼び名・線の種類）。押すと、その空間へ切り替えて、相手のノードへ動く。線の設定（`LinkPanel`）は、印からも開ける。
- 小さな地図: 右下。表示中の空間の、囲いの四角と、いま見えている範囲。押す・ドラッグで動く。
- ノードを押したときの動き: PR1 では、今のまま（その pane のある基本画面へ切り替える）。端末の窓は PR2。

### サイドバー（AC-S1・AC-S2・AC-S5）

- `Sidebar.vue` は、どちらの画面でも同じ部品。行を押したときの動きだけを、`view.screen` で分ける。
  - 基本画面: 今のまま。
  - グラフ: workspace の行 → その空間に切り替え、囲いが収まる位置と倍率へ動き、囲いを 1.5 秒、強く出す。エージェントの行 → 同じに、そのノードへ。サーバの「選んでいる workspace・pane」も、今の操作と同じに切り替える（基本画面へ戻ったとき、その pane にいる。AC-S3）。
- グループの見出しを押すと、その空間に切り替わる（畳み・広げは、今のまま、矢印で）。
- 探す: ツールバーの入力。空間をまたいで、pane の呼び名・エージェントの名前・workspace の名前を、部分一致で探す。

### ドラッグ（PR1 の範囲）

- ノードのドラッグ: 位置の変更だけ。離したときに `resolveDrop` で寄せる。ほかの workspace の囲いの上では、「落とせない」見た目にして、離すと元へ戻す（移動は PR4）。
- workspace の囲いの見出しのドラッグ: 中のノードを、まとめて平行移動する（1 回の `graph.update`）。worktree グループの見出しのドラッグ: 中のすべての workspace を、まとめて。

### キー（AC-X2 のうち PR1 の分）

- 空間の切り替え: `[`・`]`。ノードの選択の移動は、今のまま（矢印）。囲いをまたぐ。
- `/` で、探すへ。

## `sodactl`（AC-X1）

- `sodactl graph show --json` に、`spaces`（グループの id・名前・含む workspace）と、ノードごとの `workspaceId`・`tabId` を足す。今の項目は変えない。
- `sodactl graph node add/rm` は、別のマシンの pane では今のまま。手元の pane では、`add` は「すでにある」（成功として返す）、`rm` は断る。

## 互換

- 新しいサーバ + 古いブラウザ（再読み込みの前）: ノードが 1 枚の面に重なって見えることがある。操作は壊れない（`Graph` の形は同じ）。再読み込みで直る。
- 古い `sodactl`: `graph show` は読める。

## PR2〜PR5 の骨子

- **PR2 端末の窓**: グラフの画面の上の層に、窓の部品（動かす・大きさ・留める・閉じる）。中身は、今の `TerminalPane.vue` を、もう 1 つの見え方として出す。大きさは、`pane control` の「操作を引き取る」決まりに乗せる（窓を開いた画面が、その pane の大きさを決める。閉じると、基本画面の大きさへ戻す）。配置 PR-C（浮いた窓）の部品と、枠・つかむ所・重なりの順を共有する。フォーカスを戻すキーは、prefix の後の `Esc`。同時に開ける窓は 4 つまで（仮）。
- **PR3 足す**: 囲いの見出しの「＋」→ 小さなフォーム → `pane.split`（その workspace で選んでいる tab の、最後にフォーカスのあった pane を分割）→ エージェントなら `agent start` と同じ経路 → 監督の線。workspace を足す入口は、今のダイアログ（workspace を作る・worktree を開く）を、そのまま開く。
- **PR4 移す**: ノードを別の囲いへ → `pane.move_to_tab`（落とせる先は、サーバの制限と同じ判定を、ブラウザでも先に見せる）。worktree グループ・workspace の囲いを、空間の見出し・サイドバーのグループへ → 今の、項目をグループへ移す操作。
- **PR5 処理のノード**: ノードの種類を足す（鍵 `proc:<id>`。`Graph.nodes` に、`commandId` を持つ形を足す。`GraphSchema` の変更）。線の先が処理のノードのとき、`GraphEngine` が、独自コマンドの「裏で走る」実行の経路を呼ぶ。結果（終了コード・出力の末尾）を、履歴と、次の線へ渡す。上限・一時停止・連鎖の止め方は、今の線の決まりに乗せる。「定義済みの処理」に、拡張・プロンプトのひな形を含めるかは、利用者の答えを待つ（requirements「残る問い」）。

## PR1 の危険と、点検の掛け方

| 所 | 危険 | 点検 |
| :- | :- | :- |
| 移行 | 今のグラフ（位置・線）を壊す | ★ タスクごとの独立点検。控えを残す。移行の前後で、線の数と、既存のノードの相対の位置が同じことをテストする |
| 置き場所の計算 | 囲いが重なる・ノードが飛ぶ | ★。性質のテスト（乱数の構成で、重ならない・既存の位置が動かない） |
| サーバがノードを足す・消す | 復元・`soda handoff`・pane の移動との順の食い違い | ★ |
| 画面の並びへの置き換え | `view.graphOpen` を見ている所の取りこぼし（`AskDialog.vue` ほか）・フォーカスの戻り先 | 全体の点検。既存のグラフの E2E を、変更なしで通す（開く・閉じるの読み替えを除く） |
| 上限の引き上げ | 性能 | 性能のテスト |

# 要件: soda 拡張の表示の面（ブラウザ版）— pane の横のパネルと上の帯を、pane の中のプログラムから出す

## 背景 / 課題

Claude Code の Mods は、Claude Code の画面にペイン・帯・ボタンを描けるが、Claude Code だけの機能で、Codex・GitHub Copilot CLI などでは使えない
（`research.md` F1・F4）。利用者は「Sodashitsu の側で、Mods でできるような機能を提供できるか」を問い、方針を決めた（`decisions.md` D1〜D11）:
拡張を 3 つの層（表示・観測・割り込み）に分け、**表示の面から**出す（D1・D2）。表示はエージェントに依存せず、検知の対象外のプログラムも含めて、すべての pane で動く。

いまの Sodashitsu で、pane の中のプログラムが利用者の画面に何かを出す道は 3 つしかない。

- 質問のフォーム（`sodactl ask`）: 答えるまで画面に重なるダイアログ。出しっぱなしにする表示（進み具合・要約・差分の一覧）には使えない。
- サイドバーの独自トークン（`report-metadata`）: 80 文字までの短い値。
- 通知: その場かぎりの 1 行。

「作業中ずっと pane の横に出ていて、中身が更新され、ボタンで指示を返せる」表示の置き場所が無い。

## 目的 / ゴール

pane の中のプログラム（エージェント・スクリプト・後の作業で足す拡張のプロセス）が、**ログインなしで**、自分の pane の横の**パネル**と上の**帯**に中身を出し・
更新し・閉じられ、パネルの中の操作（ボタン・入力）を受け取れる状態。その中身が何であっても、**アプリ本体・ほかの pane・認証の情報・利用者のキー入力に触れられない**状態。
あわせて、プログラムが「いま何が使えるか」を聞いて、使えない機能を「未対応」として知れる状態（エラーで止まらない）。

（`.aidev/charter.md` は無い。）

## この作業の範囲の切り方（作業を分けた）

依頼の範囲は「表示の面」「拡張の登録と起動」「機能の問い合わせ」の 3 つだが、1 つの作業にすると差分が数十ファイルを超える見込み（protocol・server・cli・web・静的ページ・E2E・文書で
30〜40 ファイル、拡張の登録・承認・プロセスの管理・設定画面でさらに 20〜25 ファイル）。AGENTS.md「差分を小さく切る」に従い、**要件の時点で 2 つの作業（別の work・別の PR）に分ける**（`decisions.md` D12）。

| 作業 | 中身 | この文書での扱い |
|---|---|---|
| **A: 表示の面（この work）** | パネルと帯・`sodactl display`・受け口（`pane.sock` と `/ws`）・隔離した枠・操作を返す道・機能の問い合わせ | 要件 → 設計 → タスクまで書く |
| **B: 拡張の登録と起動**（`.aidev/works/20261007-ext-host/`） | 設定ファイルへの登録（利用者の設定・承認つきのプロジェクトの設定）・Sodashitsu による起動と停止・落ちたときの扱い・`soda handoff` をまたぐ扱い・標準入出力の NDJSON | 要件の骨子だけ（その work の `requirements.md`）。A が着地してから着手する |

A だけで使える: pane の中のプログラムは `sodactl display` を呼べばよい（`sodactl ask` と同じ形）。B は、A の操作と同じメッセージを、Sodashitsu が起動したプロセスの標準入出力に載せる。
そのため **A で決めるメッセージの型（操作の名前・引数・出来事の行）は、B がそのまま使える形にする**。

## ユーザーストーリー

- US1: pane の中のエージェント（のスキル・フック）として、作業の進み具合や要約を、自分の pane の横のパネルに出して更新したい。なぜなら、端末の出力に流れて消える情報を、
  利用者が作業のあいだ見続けられるから。（受け入れ: AC1, AC2, AC4, AC5, AC24）
- US2: シェルスクリプトの作者として、ビルドの結果などの 1 行を、pane の上の帯に 1 つのコマンドで出したい。なぜなら、長く動くプロセスを書かずに、状態を目立つ場所へ出せるから。
  （受け入れ: AC1, AC3, AC6）
- US3: パネルを出したプログラムとして、パネルの中のボタン・入力欄の操作を受け取りたい。なぜなら、利用者が端末に文字を打たずに、選んで指示を返せるから。（受け入れ: AC10, AC11, AC12, AC13）
- US4: 利用者として、pane のプログラムが出したパネルを、自分の判断でたたむ・閉じることができ、それが Sodashitsu 自身の画面でないと見分けられたい。なぜなら、
  pane のプログラムは信頼できるとは限らず、画面を占められたり、確認画面を装われたりしたくないから。（受け入れ: AC7, AC8, AC9, AC-I1〜AC-I5）
- US5: 利用者として、パネルの中身が、端末に打っているキー・ほかの pane・ログインの情報を読めず、外へ通信もできないと確かでいたい。なぜなら、パネルは質問のフォームと違って
  出しっぱなしで、その横でパスワードも打つから。（受け入れ: AC14, AC15, AC16, AC17, AC18, AC19, AC25, AC28）
- US6: 拡張の作者として、いまのサーバ・sodactl・つながっている画面で、パネル・帯・操作の受け取りのどれが使えるかを聞きたい。なぜなら、使えない環境（古いサーバ・端末版だけ・
  画面なし）で、エラーにせず別の出し方（端末への出力）に切り替えたいから。（受け入れ: AC20, AC21, AC22, AC26, AC27）
- US7: 後の作業（B: 拡張の登録と起動、端末版のパネル、観測、割り込み）の実装者として、いまの操作と出来事の行に、新しい種類を足すだけで済ませたい。なぜなら、型を作り直すと、
  先に書かれた拡張が動かなくなるから。（受け入れ: AC23）

## スコープ

### 対象

- pane ごとの表示の面: **パネル**（pane の横。pane の領域の中に出て、端末はその分せまくなる）と**帯**（pane の上。端末の上に出る低い領域）。
- `sodactl` の新しいコマンド `display`（出す・更新する `set`／閉じる `close`／一覧 `list`／操作を待つ `wait`・`events`／機能の問い合わせ `--features`）。
- 受け口: ログイン不要の `pane.sock`（自分の pane の分だけ）と、ログイン済みの `/ws`（Windows・pane の外・別のマシンのため）。
- 中身の形 3 つ: 文字（`text`）・Markdown（`markdown`）・HTML（`html`。**作者のスクリプトは動かさない**。操作は属性で宣言する）。
- 隔離した枠（sandbox の iframe・専用の静的ページ・専用の応答ヘッダ）と、枠から拡張へ操作を返す道。
- ブラウザ版（デスクトップ・モバイル）の表示・たたむ・閉じる・キーボードの操作。
- 上限（大きさ・数・頻度）と、複数の画面がつながっているときの扱い。
- 文書（`docs/sodactl.md`・新しい `docs/display.md`・`docs/verification.md`・sodactl の skill ファイル・`docs/tui-parity.md`・`AGENTS.md` の案内）。

### 対象外

- **拡張の登録と起動**（設定ファイル・プロジェクトの設定の承認・プロセスの起動と停止・`soda handoff` をまたぐ再起動・標準入出力の NDJSON）: 作業 B（`20261007-ext-host`）。
- **端末版（引数なしの `soda`）のパネルと帯**: 別の作業（D8）。この作業では、端末版は表示の面を出さず、機能の問い合わせに「未対応」と答える。
- **観測のイベント**（ターンの完了・承認待ち・ツール呼び出し）と**割り込み**: 後の作業（D1・D4）。
- **作者のスクリプトが動く HTML**（`sodactl ask` の `view` の HTML の枠と同じもの）: この作業では出さない。出しっぱなしの枠でスクリプトを動かすと、端末へのキー入力のフォーカスを奪って
  読み、枠の遷移で外へ持ち出す道を止められない（`docs/sodactl.md`「成果物（view）」の「枠の中のキー」に書かれた限界と同じもの。US5）。要るかどうかは利用者に確かめる（`decisions.md` D13）。
- **サーバがファイルを読む・外部の URL を取りに行くこと**: しない。中身は `sodactl` が読んで、要求にそのまま載せる（`sodactl ask` の `image`・`view.file` と違い、受け口にサーバの読み出し・外部通信の権限を足さない）。
- 表示の面の保存（`session.json`）: しない。サーバの再起動で消える（`report-metadata` と同じ）。
- 利用者がパネルの幅をドラッグで変えること・パネルを pane の左や下へ移すこと・pane から切り離して別の場所へ出すこと: 後の作業。
- 通知・サイドバーの独自トークンを拡張の面として束ねること: 既存のコマンド（`report-metadata`）のまま。

## 機能要件

1. **出す・更新する**: `sodactl display set <名前> --kind panel|band` が、呼び出し元の pane に、その名前の面を出す。同じ名前でもう一度呼ぶと、中身・題・大きさを置き換える（同じ面の更新）。
   中身は `--text <文字>`・`--markdown-file <パス>`・`--html-file <パス>`・標準入力（`--format text|markdown|html` で形を指す。既定は `text`）の**どれか 1 つ**で渡す（2 つ以上・どれも無いのは使い方の誤り＝終了コード 2）。
   題は `--title <文字>`（省くと名前）、大きさは `--size <px>`（パネルは幅で既定 320、帯は高さで既定 32）。`--ttl-ms` を付けると、時間が来たら消える。`--wait` を付けると、出した後、その面の最初の出来事を待って出す（機能要件 7 の `wait` と同じ）。
2. **閉じる・一覧**: `sodactl display close <名前>`（`--all` で自分の pane の全部）と `sodactl display list`（自分の pane の面の名前・種類・題・大きさ・版）。
3. **対象の pane**: pane の中では呼び出し元の pane（`SODA_PANE_ID`）。`pane.sock` の経路では、**その要求が名乗った pane の面だけ**を扱える（ほかの pane の面を出す・閉じる・読む・待つ操作は無い）。
   `/ws` の経路（ログイン済み）では `--pane <id>` で任意の pane を指せる（ログイン済みの接続は、もともとどの pane にも書ける）。別のマシンの pane は、ほかのコマンドと同じ `--machine <名前|id>` と `--pane` で指す。
4. **パネルの表示**: pane の領域の右側に、アプリが描く見出し（固定のラベル・題・たたむ・閉じる）と、隔離した枠を出す。端末はその分せまくなり、pane の大きさ（列数）が変わる。
   1 つの pane にパネルが複数あれば、見出しのタブで切り替える。たたむと、見出しだけの細い帯になり、端末は元の幅へ戻る。
5. **帯の表示**: pane の端末の上に、高さの決まった領域（既定 32px）を出す。複数あれば縦に積む。右端にアプリが描く閉じるボタンと、出どころの印。
6. **中身の形**:
   - `text`: 文字のまま（`<pre>`）。
   - `markdown`: 整形して出す（見出し・表・コード・チェックリスト）。mermaid の図は**出さない**（コードのまま）。
   - `html`: 作者の HTML と CSS を出す。**`<script>`・`on…=` などのスクリプトは動かない**。外への読み込み（画像・スタイルシート・フォント・`fetch`）は止まる（画像は `data:` だけ）。
7. **操作を返す**: `html`・`markdown` の中の要素に、属性 `data-soda-action="<名前>"` を付けると、押したときにその名前が拡張へ届く。`<form data-soda-action="…">` は、送信したときに
   欄の値（`name` → 値）を添えて届く。届け先は、`sodactl display wait`（1 件を待って出して終わる）と `sodactl display events`（NDJSON を出し続ける）。
   利用者がパネル・帯を閉じたこと・時間が来て消えたこと・pane が閉じたことも、同じ道で届く。
8. **利用者の操作**: パネル・帯は、利用者がいつでも閉じられる（閉じると面は消え、出したプログラムへ知らせが届く）。パネルは、たたむ・戻すができる（その画面だけの状態）。
   pane の右クリックのメニューから、その pane の面をまとめて閉じられる。
   端末にフォーカスがあるとき、キーの操作（新しい操作。既定 `prefix+i`。設定画面の節「キー」で変えられる）で、その pane の面の枠へフォーカスを移せ、`Esc` で端末へ戻れる。パネルのタブは矢印キーで切り替えられる。
9. **出どころの固定の表示**: パネルの見出しと帯の端に、アプリが描く固定のラベル（「pane のプログラムの表示」と分かる文言と名前）を出す。中身・題からは消せない・書き換えられない。
   題は文字として出す（HTML として解釈しない）。
10. **どの画面に出るか**: その pane を動かしているサーバにつながっていて、**「面を出せる」と名乗ったすべての画面**（ブラウザのデスクトップ・モバイル。接続のたびに、出せる種類を添えて名乗る）で、その pane を表示しているときに出る。
    あとからつないだ画面・再読み込みした画面にも出る（面はサーバが持つ）。画面が 1 つも無くても `set` は成功し、つながったら出る。端末版・`sodactl`・軽い接続（別のマシンの要約）は名乗らないので、出ない。
    モバイルの画面（幅 767px 以下。pane を 1 つだけ出す画面）では、パネルは pane の横ではなく、上部のバーのボタンから開く重ね表示にする（端末の幅を奪わない）。帯は端末の上にそのまま出す。
11. **機能の問い合わせ**: `sodactl display --features` が、sodactl の機能・上限と、（つなげれば）サーバの機能・上限・**いま面を出せる画面の数**（パネル・帯・操作の受け取りのそれぞれを出せると名乗った画面の数。0 なら、その機能はいま「未対応」）を、1 行の JSON で返す。
    サーバが古い・つなげない（pane の外でログインもしていない、を含む）ときは `server` が `null`。pane の外でも、ログイン済みでつなげれば `server` は入る。終了コードは常に 0。
12. **使えないときは「未対応」**: サーバが古くて `display` の操作を知らないとき、`sodactl display set`・`close`・`list`・`wait` は、エラーではなく stdout に
    `{"status":"unsupported","reason":"…"}` を出して終了コード 0 で終わる。`events` は、最初の行の代わりに終わりの行（理由が「未対応」）を 1 行出して、終了コード 0 で終わる。
    `set` の結果には、機能要件 11 と同じ「いま面を出せる画面の数」（その種類を出せると名乗った画面の数。その pane を表示しているかは数えない）が入る。出せる画面が 1 つも無いときの `set` は成功し、その数が 0 と入る。
13. **メッセージの型**: 操作の名前・引数・結果と、出来事の行（NDJSON）の形を `packages/protocol` に 1 か所で定義し、`pane.sock`・`/ws`・`sodactl` が同じ定義を使う。
    出来事の行は `type` で種類を表し、読み手は知らない `type`・知らない項目を無視する決まりにする（後の作業が観測・割り込み・端末版の種類を足せる）。
14. **消えるとき**: pane が閉じた・`close`・利用者が閉じた・`--ttl-ms`・サーバの停止と再起動・`soda handoff`（サーバの入れ替え）。同じ名前の `set` は消さずに更新する。
    面はサーバのメモリだけに持つ（`report-metadata` の独自トークンと同じ）ので、**入れ替えで消える**。待っていた `sodactl display events` は、接続が切れたら 5 秒まで繋ぎ直す。
    5 秒のうちに繋がれば（＝入れ替え・すぐの再起動）、「サーバが入れ替わって面が消えた」という 1 行を出して待ち続ける（プログラムは、それを見て出し直せる）。繋がらなければ（＝停止）、終わりの行を出して終了コード 1 で終わる。
    `wait`（`set --wait` を含む）は、同じく 5 秒まで繋ぎ直し、繋がれば「サーバが入れ替わった」の行を出して終了コード 0 で終わる（待っていた面はもう無い）。繋がらなければ `connection_closed`（終了コード 1）。

## 非機能要件 / 制約

- **隔離**（US5。脅威と対策の表は design）:
  - 枠は `allow-same-origin` を付けない sandbox の iframe（不透明 origin）で、専用の静的ページを専用の応答ヘッダ（`default-src 'none'`・スクリプトは静的ページ自身のものだけ）で開く。
    中身は `postMessage` で渡す。アプリ本体の CSP は変えない。
  - 作者のスクリプトは動かない（インラインのスクリプト・イベント属性・`javascript:` の URL）。枠自身を外のページへ移す手段（`<meta refresh>`・フォームの送信・リンク）は取り除くか止める。
  - 中身のリンクは、`http:`・`https:` のものだけ、利用者が押したときに新しいタブで開く（ask の Markdown の枠と同じ。開いた先のタブは元の画面と無関係）。ほかのリンクは行き先を外す。枠の中で別のページへは移らない。
  - 枠からアプリへ届くのは、決まった形の知らせ（操作・端末へフォーカスを返す・prefix のキー）だけで、アプリは**自分が開いた枠からのもの**だけを、形と大きさを確かめて受ける。
  - 枠が、利用者の操作なしに端末からキー入力のフォーカスを奪えない。
- **`pane.sock` に載せる操作の条件**（`docs/sodactl.md`「受け口に操作を足すとき」の 4 つ）を満たす: 対象が呼び出し元の pane に限られる・pane のプログラムがもともと出来ることを超えない・秘密を返さない・量の上限がある。
  `/ws` の handler をそのまま登録しない。受け口に、サーバのファイルの読み出し・外部への通信を足さない。
- **上限**（値は design で確定。`sodactl` の要求〔`set`・`wait`〕が超えたら理由つきの誤り。画面からの操作の頻度と、溜める出来事は、超えた分を捨てる）: 1 つの面の中身 256 KiB・題 80 文字・名前 `[A-Za-z0-9_-]` の 1〜32 文字・1 つの pane にパネル 4 と帯 2・サーバ全体で面 64 と中身の合計 8 MiB・
  1 つの pane の `set` は毎秒 10 回まで（続けて 10 回まで通り、11 回目は誤り）・操作の名前 64 文字と添える値の合計 8 KiB・1 つの画面からの操作は毎秒 20 回まで・1 つの pane で同時に待てる `wait` は 4・溜める出来事は pane ごとに 64 件（あふれたら古いものから捨て、捨てた数を知らせる）。
- **画面を占めすぎない**: `--size` の範囲はパネル 160〜800px・帯 24〜96px（外れた値は使い方の誤り）。そのうえで画面は、表示のときに丸める（誤りにしない）: パネルの幅は pane の幅の半分まで。
  端末が決まった幅（40 列相当）を下回るなら、パネルは自動でたたまれる。帯の高さの合計が pane の高さの 3 分の 1 を超える分は、出さずに「ほか N 件」の印にする。
- **pane を生かし続ける**: 面の処理の誤り・上限の超過・壊れた中身で、pane の入出力・ほかの pane・ほかの画面が止まらない。
- **古い版との組み合わせ**: 黙って壊れない（新旧の表を docs に書く）。古いサーバ＝機能要件 12。古い sodactl＝`display` を知らないので使い方の誤り（終了コード 2。呼び出し側は使えないと判断する）。
  古いブラウザの画面（読み込み直していない）＝名乗らないので面は出ず、出せる画面の数に入らない。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 面は、プログラムの `set` で開く（利用者の操作では開かない）。開いても、いまのフォーカス・表示中の tab・ほかのダイアログは変わらない。閉じるのは、見出し（帯は右端）の［×］（マウスでも、`Tab` で届いて `Enter` でも）・pane の右クリックのメニュー・プログラムの `close`。
  閉じたとき、枠の中の入力の途中の値は捨てられ、プログラムへは「閉じた」だけが届く。たたむ（パネルだけ）は、見出しのボタンか、たたんだ見出しをもう一度押す。
- [ ] AC-I2 確定 / 取り消し: 枠の中のボタン・フォームの送信が確定で、押した時点で 1 件の操作が届く（取り消しは無い。押す前にフォーカスを外へ出せば、何も届かない）。閉じる［×］は確認なしで閉じる
  （プログラムが出し直せる。失われるのは、枠の中の入力の途中の値だけ）。
- [ ] AC-I3 キーボードだけで完結するか: 端末から、キーの操作（既定 `prefix+i`。設定画面で変えられる）でその pane の面の枠へフォーカスを移し、`Tab` で枠の中のボタン・欄を巡り、`Enter`・`Space` で押し、
  `Esc` で端末へ戻る、がマウス無しで通る。パネルのタブは矢印キーで切り替えられる。閉じる・たたむのボタンにも `Tab` で届く。
- [ ] AC-I4 フォーカスの行き先: 面が出た・更新された・消えたとき、フォーカスは動かない（端末にあれば端末のまま）。ただし、フォーカスのある枠が消えたときは、その pane の端末へ戻る。
  キーの操作で入ったときは、枠の中の最初の操作できる要素（無ければ枠そのもの）へ移り、`Esc` で元の pane の端末へ戻る。
- [ ] AC-I5 既存の操作を妨げないか: 枠にフォーカスがある間、枠の中のキーは端末へ流れない。枠から親へ渡るのは `Esc`（端末へ戻る）と prefix のキー（押すと端末へ戻り、続くキーは今までどおりの操作になる）だけ。
  枠の上のホイールは枠の中をスクロールし、端末のスクロールバックを動かさない。面を出しても、pane の分割の境のドラッグ・pane の拡大（zoom）・コピーモードは今までどおり動く。

## 未確定事項 / 確認したいこと

- **作者のスクリプトが動く HTML を許すか**（利用者に確かめる。`decisions.md` D13）: この要件は「許さない」（操作は属性で宣言）で書いた。許す場合は、`sodactl ask` の `view` と同じ限界（キー入力のフォーカスを奪える・枠の遷移で外へ出せる）を、出しっぱなしの枠で受け入れることになる。
- コマンドの名前 `display`（利用者に確かめる。D14）: サーバの中に既に `surface`（`/ws` の RPC の面）という語があるので避けた。`panel` は `pane` と紛らわしいので、識別子の語幹にしない。
- パネルの位置を右に固定すること・幅の既定（320px）・モバイルの出し方: 勧める案で書いた。design で採否の理由を確定する。
- 面を pane の大きさに含めること（端末がせまくなり、列数が変わる）: pane の大きさを決める権限（tab ごとに 1 つの画面が持つ）との関係は、research の追補（R3）で確かめた。権限を持たない画面では、申告する大きさが変わるだけで PTY は変わらない。
- `soda handoff` で面を引き継がないこと（`decisions.md` D15）: 独自トークンと同じ扱いにした。引き継ぐ場合は、引き継ぎの記録（`handoff.json`）に面を足す作業になる。

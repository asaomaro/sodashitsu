# 要件: サイドバー行の独自トークンと、行の並び・色の条件付け（herdr H21 の残り）

## 背景 / 課題

サイドバーの行（spaces 区画の workspace 行・agents 区画のエージェント行）の中身は `packages/web/src/components/Sidebar.vue` に
固定で書かれている（spaces: 1 行目＝状態の印・workspace 名、2 行目＝上流とずれているときだけブランチと ↑↓ の数。agents: 1 行目＝状態の印・
workspace 名・tab 名、2 行目＝付けた名前・エージェントの表示名・「未検証」）。利用者は何を・どの順で・どの色で出すかを変えられず、
外のスクリプトやエージェントのフックが「いま何をしているか」（要約・モデル名・負荷など）を行に載せる手段も無い。

herdr には (1) 行の並びを設定する `[ui.sidebar.agents]`／`[ui.sidebar.spaces]` の `rows`（組み込みのトークン・`$name` の独自トークン・
`fg`/`bold`/`dim` の見た目・最大 16 の順序付きの条件 `rules`）と、(2) 独自トークンの値を外から押し込む `herdr workspace report-metadata`・
`herdr pane report-metadata`（`--source`・`--token NAME=VALUE`・`--clear-token`・`--seq`・`--ttl-ms`）がある
（一次資料: `scratchpad/herdr/docs/versions/0.9.1/website/src/content/docs/configuration.mdx`「Sidebar row layouts」、
`cli-reference.mdx` の `workspace report-metadata`・`pane report-metadata`、`src/metadata_tokens.rs`・`src/app/api_helpers.rs`・
`src/config/sidebar.rs`・`src/config/sidebar/rules.rs`・`src/ui/sidebar/tokens.rs`。decisions D1）。
`docs/herdr-parity.md` の H21 はこの 2 つを「対象外のまま」と記し、backlog `product-roadmap.md` に残している。

## 目的 / ゴール

- 外のスクリプト・エージェントのフックが、`wtmctl` から workspace・pane ごとに名前付きの短い値（独自トークン）を押し込め、
  その値が**接続しているすべてのブラウザ**のサイドバーに、ブラウザを開き直さずに現れる状態。値は herdr と同じ規則で整えられ・
  上限で抑えられ・古い報告に上書きされず・期限で消える。
- 利用者が設定画面から、**このブラウザの**サイドバーの行に何を・どの順で・どの見た目（色・太字・薄字）で出すかと、値に応じた
  条件付きの見た目（一致・含む・始まる・数の大小、隠す）を決められる状態。
- 何も設定していない利用者には、サイドバーの見た目と操作が今までと何も変わらない状態。
- 外から押し込まれた値は、ブラウザの中で**ただの文字列**として描かれ、画面の構造・スクリプト・スタイルに影響しない状態。

## ユーザーストーリー

- US1: エージェントのフックを書く開発者として、pane ごとに「いま何をしているか」の要約やモデル名をサイドバーのエージェント行に出したい。
  なぜなら、どの pane が何を処理しているかを端末を開かずに一覧で見たいから。（受け入れ: AC2, AC3, AC4, AC12, AC13）
- US2: ビルドや監視のスクリプトを書く開発者として、workspace ごとの状態（CI の結果・負荷など）を spaces 行に出し、一定時間で自動で消したい。
  なぜなら、古い値が残って誤解を招くのを防ぎたいから。（受け入れ: AC1, AC3, AC6, AC13）
- US3: 同じ対象に複数のスクリプトから報告する開発者として、遅れて届いた古い報告で新しい値が上書きされないようにしたい。
  なぜなら、並行して動くフックの報告の順は保証されないから。（受け入れ: AC5）
- US4: 利用者として、サイドバーの行に出す項目・順番・色を設定画面から選びたい。なぜなら、自分の作業に要る情報だけを見やすく並べたいから。
  （受け入れ: AC11, AC12, AC13, AC15, AC-I1〜AC-I5）
- US5: 利用者として、値に応じて色を変えたり隠したりしたい（例: 負荷が 80 を超えたら赤、`ok` なら隠す）。なぜなら、注意が要る行だけを目立たせたいから。
  （受け入れ: AC14）
- US6: 何も設定しない利用者として、今までどおりのサイドバーを使い続けたい。なぜなら、見た目が勝手に変わると戸惑うから。（受け入れ: AC10, AC16）
- US7: 運用者として、外から押し込まれた値で画面が壊されたり、認証の無い相手に値を書かれたりしないでほしい。なぜなら、値は全ブラウザに配られるから。
  （受け入れ: AC7, AC9, AC18）
- US8: herdr から移ってきた利用者として、herdr との違いを docs で知りたい。なぜなら、herdr の設定ファイル・コマンドをそのまま使えるか判断したいから。（受け入れ: AC8, AC17）

## スコープ

### 対象

- RPC `workspace.report_metadata`・`pane.report_metadata`（herdr と同じ方式名）と、CLI `wtmctl workspace report-metadata`・`wtmctl pane report-metadata`
  （独自トークンの設定・消去、`--source`・`--seq`・`--ttl-ms`）。値はサーバのメモリに持ち、snapshot と既存の `workspace.updated`・`pane.updated` で配る。
- ブラウザの設定画面（節「表示」）で、spaces 行と agents 行それぞれの行の並び（行・トークンの追加・削除・並べ替え）、トークンごとの見た目、
  最大 16 の条件の編集と、既定へ戻す操作。保存は `wtm.prefs.v1`（このブラウザだけ・ほかの外観の設定と同じ）。
- `Sidebar.vue` の展開時の workspace 行・エージェント行を、設定した並びで描く（設定していなければ今までと同じ）。
- `docs/herdr-parity.md` の H21・`docs/wtmctl.md`・`wtmctl help`・skill ファイル（`packages/cli/skills/wtmctl/SKILL.md`）の更新。

### 対象外（backlog に `[ ]` で残す。decisions D6）

- `machine` トークン（複数ホストの対応が着地してから。別 worktree で進行中）。
- `rows_by_agent`（エージェントの種類ごとの並びの上書き）・`row_gap`・`terminal_title_stripped`。
- `pane report-metadata` の `--title`・`--display-agent`・`--state-label`・`--clear-state-labels`・`--agent`・`--applies-to-source`（表示名・状態名の上書き）。
- 独自トークンの値の永続化（サーバの再起動・`wtm handoff` をまたいで残すこと）。herdr もメモリだけで持つ（decisions D4）。
- 設定ファイル（TOML）からの読み込み・書き出し。本製品には利用者が書く設定ファイルが無い。
- 畳んだサイドバー・手動グループの見出し行・モバイルの pane の一覧（`mobile/PanePicker.vue`）の描き方（herdr も展開した desktop のサイドバーだけ）。
- 隣り合う値の間の ` · ` の区切り文字と、`git_status` の ↑ 緑・↓ 赤の既定の色（今までの見た目を保つ。decisions D3）。

## 機能要件

- 独自トークンの報告は、対象（workspace・pane）・報告元（`source`）・設定する値と消す名前の組・任意の `seq`・任意の `ttlMs` を受け、
  herdr と同じ順で検査して、受け付けたものだけを対象の値に反映する。反映して値が変わったときだけ、全クライアントへ配る。
- 値の整え方・上限・`seq`・期限・報告元の数の上限は herdr と同じ（AC3〜AC6 の数値）。
- 行の並びの設定は、組み込みのトークン（本製品に実在する情報だけ）と `$name` の独自トークンを、行ごとに順に並べたもの。
  トークンごとに見た目（前景色・太字・薄字）と最大 16 の条件を持てる。
- 描くとき、値の無いトークンは消え、トークンが 1 つも残らない行も消える（行が 1 つも残らないときの代わりの描き方は AC12）。条件は先頭から順に見て、最初に当たったものだけが効く。
- 値はすべて文字列の差し込み（テキスト）で描き、HTML・スタイル・URL として解釈しない。色は `#RGB`・`#RRGGBB` に合うものだけを使う。

## 非機能要件 / 制約

- 独自トークンの報告は、認証済みの WebSocket の RPC だけで受け付ける（新しい待ち受け・認証の無い口を作らない）。
- サーバが持つ量は対象ごとに有界（キー 32・報告元 32・値 80 文字・キー名 32 文字・1 回の報告 16 キー）で、対象が閉じたら捨てる。
- 期限の処理はタイマー 1 つで行い、プロセスの終了を妨げない（`unref`）。
- 負荷試験・E2E は行わない（共有マシン。ユーザーの指示）。単体・結合テスト（vitest）と smoke で確かめる。

## 完了条件 (受け入れ基準)

- [ ] AC1: `wtmctl workspace report-metadata <workspaceId> --source <ID> --token NAME=VALUE ... [--clear-token NAME]...` が、その workspace の
  独自トークンを設定・消去して `{}` を出し終了コード 0 で終わる。触れなかったキーはそのまま残る。設定された値は snapshot（`wtmctl snapshot`・
  ブラウザの接続時）の `Workspace.tokens` に載り、変わったときは既存の `workspace.updated` で全クライアントへ配られる（値が 1 つも無ければ `tokens` の項目ごと無い）。
  報告しても値が変わらない（同じ値の設定・無いキーの消去）ときは配らない。
- [ ] AC2: `wtmctl pane report-metadata <paneId> ...`（オプションは AC1 と同じ）が、pane について同じことを行う（`Pane.tokens`・`pane.updated`）。
- [ ] AC3: 値は、前後の空白を除き・制御文字（Unicode の Cc）を除き・先頭から 80 文字（Unicode のコードポイント）までにしてから、もう一度前後の空白を除いたものを
  保存する。結果が空なら、そのキーを消す（`--clear-token` と同じ）。1 回の報告で同じキーを複数回（設定・消去のどちらでも）指定したら、最後の指定だけが残る。
  1 回の報告のキーの数は、そうして残った異なるキー名の数（設定と消去を合わせる）で数える。
- [ ] AC4: 次の報告は何も変えずに失敗する（RPC のエラーの `code`、`wtmctl` は `{"error":{"code","message"}}` を stderr に出して終了コード 1）:
  対象が無い（`not_found`）／`source` が空・80 文字超・`[A-Za-z0-9:._-]` 以外を含む（`invalid_metadata_source`）／`ttlMs` が 1〜86400000 の外
  （`invalid_metadata_ttl`）／設定も消去も無い・17 キー以上・キー名が空・33 文字以上・`[A-Za-z0-9_-]` 以外を含む（`invalid_metadata_token`）／
  反映後のキーが 32 を超える（`metadata_token_limit`）。違反が複数あるときは、この並び（対象 → source → ttlMs → キー → キーの数）の先のものを返す
  （`seq` の古さの判定はキーの検査の後・キーの数の検査の前。AC5）。
- [ ] AC5: `seq` を付けた報告は、同じ `source` から既に受け付けた `seq` 以下なら、成功を返すが何も変えない（配りもしない）。1 つの対象が `seq` 付きで受け付ける
  `source` は 33 個目から `metadata_sequence_source_limit` で断る（消去・期限切れでも枠は戻らない。すでに枠を持つ `source` は受け付け続ける）。`seq` の無い報告は常に受け付ける。
- [ ] AC6: `ttlMs` を付けた報告で設定したキーは、その時間が過ぎると消え、消えたことが配られる。期限はその報告で設定したキーにだけ付き、ほかのキーの期限は変えない。
  同じキーを `ttlMs` 無しで設定し直すと期限は外れる。期限の処理は 1 つのタイマーで行い、そのタイマーはプロセスの終了を妨げず（`unref`）、サーバの終了で止める。
- [ ] AC7: workspace・pane が閉じたら、その独自トークンと `seq` の記録は捨てる。独自トークンは `session.json` に保存しない（再起動・引き継ぎで消える）。
- [ ] AC8: `wtmctl` の引数: `--source` が無い・設定も消去も無いときは使い方つきで終了コード 2。`--token` の値が `=` を含むときは独自トークンの `NAME=VALUE`
  （`=` の前が空なら終了コード 2）、含まないときは今までどおり接続の token として扱う。`--seq`・`--ttl-ms` が 0 以上の整数（安全な整数の範囲）でなければ終了コード 2。
  `wtmctl help`・skill ファイル・`docs/wtmctl.md` に 2 つのコマンドと `--token` の見分け方が載る。
- [ ] AC9: 独自トークンの値に `<img src=x onerror=alert(1)>` や `</span><script>…` を入れても、サイドバーにはその文字列がそのまま文字として出て、要素・属性は増えない。
  前景色の設定は `#RGB`・`#RRGGBB` に合わないものを保存も適用もしない。
- [ ] AC10: 行の並びを設定していない（既定の）ブラウザでは、サイドバーの spaces 行・agents 行の描かれ方（要素・クラス・文字・表示/非表示の条件）が変更前と同じ
  （既存の `Sidebar.test.ts` がそのまま通り、既定の並びと変更前の描画を比べるテストを足す）。
- [ ] AC11: 設定画面の節「表示」で、spaces 行と agents 行それぞれについて、行の追加・削除・並べ替え、行の中のトークンの追加・削除・並べ替えができ、選んだ時点で
  このブラウザに保存され（`wtm.prefs.v1` の `sidebarRows`）、サイドバーにすぐ反映される。組み込みのトークンは spaces が `state_icon`・`state_text`・`workspace`・
  `branch`・`git_status`・`git`、agents が `state_icon`・`state_text`・`workspace`・`tab`・`pane`・`agent`・`name`・`unverified`・`terminal_title`（意味は design）。
  独自トークンは `$` と `[A-Za-z0-9_-]` の 1〜32 文字の名前で足せる（spaces 行は workspace の、agents 行は pane の値を読む）。行は 16・1 行のトークンは 16 まで。
  保存値が壊れていたら、読めない要素だけを捨てて残りを使う。同じブラウザのほかのウィンドウでの変更に追従する。
- [ ] AC12: 設定した並びで描くとき: 値の無いトークンは消え、トークンが 1 つも残らない行も消える。残った最初の行を主の行（今の 1 行目の見た目）、2 行目以降を補足の行
  （今の 2 行目の見た目）として描く。worktree 自動グループの本体の行（開閉の印を持つ workspace 行）の開閉の印は主の行の先頭に置く。行が 1 つも残らなければ、状態の印と workspace 名（agents 行は状態の印と
  workspace 名・tab 名）の主の行を出す（行を押せなくならないため）。畳んだサイドバーと手動グループの見出し行は今までどおり。クリック・右クリック・D&D・navigate の
  選択の見た目は今までどおり。
- [ ] AC13: トークンごとに前景色（`#RGB`・`#RRGGBB`）・太字（既定／入／切）・薄字（既定／入／切）を設定でき、その 1 か所にだけ効く（「既定」は今の見た目のまま、
  「切」はその見た目の既定の太字・薄字を外す）。
- [ ] AC14: 文字の値を持つトークン（`state_icon`・`git_status`・`git` 以外）に、最大 16 の条件を順に付けられる。条件は `equals`・`contains`・`starts_with`
  （`ignore_case` で ASCII の大文字小文字を無視。ASCII 以外は区別する）と `gt`・`lt`（有限の閾値。値が全体で有限の数として読めるときだけ比べる。等しいときは当たらない）の
  どれか 1 つと、前景色・太字・薄字の上書き、隠す（`hide`）を持つ。先頭から見て最初に当たった条件だけが効き、指定した見た目だけを上書きする。`hide` なら
  そのトークンを消す。当たらなければそのトークンの見た目のまま。比べるのは表示で切り詰める前の値全体。
- [ ] AC15: 設定画面の［既定に戻す］で、spaces・agents それぞれの並びを既定へ戻せる（保存値からその区画の設定が消える）。
- [ ] AC16: 既存のテスト（全パッケージの vitest）がそのまま通り、起動確認（`aidev smoke`）が通る。起動確認に、ビルドした `wtmctl` で workspace の独自トークンを
  報告し、snapshot に載ることを足す。
- [ ] AC17: `docs/herdr-parity.md` の H21 が、対応した範囲・herdr との違い・対象外（backlog へ送ったもの）を記している。
- [ ] AC18: 独自トークンの報告は、認証済みの WebSocket の RPC（既存の方式と同じ口）でだけ受け付ける。サーバは新しい待ち受けを作らず、接続の token が無い・
  違う `wtmctl` の報告は、既存のコマンドと同じく認証の失敗で終わって何も変えない。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 並びの編集は設定画面（`prefix+s`・メニュー）の節「表示」の折りたたみ「サイドバーの行（上級者向け）」を開いて使い、もう一度押すと閉じる。
  トークンの見た目と条件は、そのトークンの［詳細］で開閉する（`aria-expanded`）。閉じても値は変わらない（変更は操作した時点で保存済み）。設定画面を閉じても同じ。
- [ ] AC-I2 確定 / 取り消し: 追加・削除・並べ替え・選択肢の変更は選んだ時点で反映・保存する（確定ボタンは無い）。文字の入力（色・条件の値）は
  Enter か入力欄を離れた時点で確定し（独自トークンの名前は足す操作の引数なので、Enter か［追加］で足す。decisions D9）、規則に合わない値は保存せずに理由を出して入力欄に残す。設定画面を閉じたとき（Esc・［閉じる］・外側のクリック）は、
  打ちかけの値のうち規則に合うものを確定し、合わないものは捨てる。［既定に戻す］は同じ場所に出る確認（［戻す］［やめる］）を経て戻し、
  ［やめる］・Esc では何も変えない。
- [ ] AC-I3 キーボードだけで完結するか: 折りたたみを開く→行・トークンを選んで足す・動かす・消す→［詳細］で見た目と条件を変える→閉じる、を Tab・Shift+Tab・
  Enter・Space・矢印（`select` の中）だけで通せる（部品はすべてネイティブの `button`・`select`・`input`）。
- [ ] AC-I4 フォーカスの行き先: 項目（行・トークン・条件）を消したら、同じ位置に繰り上がった項目の［削除］へ、無ければその並びの［追加］へ移る。［既定に戻す］の
  確認を閉じたら［既定に戻す］へ戻る。足した・動かした後は、押したボタンか足した項目に残る（`body` へ落ちない）。
- [ ] AC-I5 既存の操作を妨げないか: 編集の部品の上で打つキー（文字・Enter・矢印）は prefix・直接のキー・navigate の経路へ漏れない（今の設定画面と同じ）。
  Esc は確認が開いていればそれを閉じ、無ければ今までどおり設定画面を閉じる（打ちかけの値の扱いは AC-I2）。

# 要件: 会話の参照が、別のプログラムの報告で、すり替わる・別の pane に付く件の直し

## 背景
2026-10-10 の入れ替えで、2 つの pane の会話が再開されなかった（調査: `resume-investigate-result.md` の内容を、`research.md` として work に写す）。
- 件 B: pane の中で動いた**子の `claude`**（エージェントが、試しに動かしたもの。`SODA_PANE_ID` を引き継ぐ）の `SessionStart` の報告が、その pane の会話の参照を上書きした。受け口（`SessionService.reportAgentSession`）は、誰が報告したかを、何も確かめない。
- 件 A: Codex 0.162 は、フックを、pane の中ではなく、**常駐のプロセス（app-server daemon）**の中で動かす。daemon の環境の `SODA_PANE_ID` は、最初に daemon を起動した pane のもの。だから、どの pane の Codex の報告も、その 1 つの pane 宛てになる（その pane の参照を上書きし、本来の pane には付かない。その pane が閉じた後は、どこにも付かない）。

## 目的
会話の参照が、**その pane の前面で動いているエージェント自身の報告でだけ**、変わる状態。取り違えた報告は、捨てて、ログに残る。取り違えが起きても、本来の参照へ戻れる。

## 完了条件
- [ ] AC1（誰の報告か）: フックのスクリプトは、報告に、**エージェントのプロセスの pid**（`CLAUDE_PID` があればそれ。無ければ、フックの親をたどって分かる範囲で。取れなければ、付けない）を足す。サーバは、`session_start` の報告を受けたとき、その pid が、**その pane の前面のジョブのエージェントのプロセス（か、その pane の PTY の前面のプロセスグループの一員）**であることを確かめ、違えば、参照を変えない（ログに 1 行: pane・種類・会話の id の先頭 8 文字・理由）。pid が付いていない報告（古い版のフック・pid の取れない OS）は、今までどおり受ける。サーバの側で、接続の相手の pid を OS から取れる（`SO_PEERCRED`）なら、報告の中の pid より、そちらを優先して、親をたどる（報告の中の pid は、pane の中のプログラムが好きに書けるので、**これは、安全の境界ではなく、取り違えを防ぐ仕組み**と、文書に書く）。
- [ ] AC2（起動の直後）: エージェントを起動した直後は、報告が、検知より先に届く。**落とさない**: 前面のエージェントが、まだ検知されていないときは、報告を短い間（設計で決める。目安 15 秒）保留し、検知されたときに、pid を確かめて、受けるか捨てるかを決める。保留は、pane ごとに 1 件（新しいものが勝つ）。保留の間にサーバが止まったら、**今までどおり受けた扱い**にして保存する（再開できないより、まし）か、捨てるかを、決めて書く。#122 の決まり（10 秒の猶予・`hasPendingResume`）・fork の作業（matcher の `clear`・`fork`・`compact`。`feature/agent-fork`。まだ main に無い）と、ぶつからない。
- [ ] AC3（同じプロセスの中の替わり）: 同じ `claude` のプロセスの中で、会話が替わる（`/resume`・`/clear`・fork）ときの報告は、pid が同じなので、受ける。
- [ ] AC4（一つ前へ戻れる）: pane ごとに、直近の参照を 3 件まで覚える（保存にも。古い保存は、そのまま読める）。再開に使うのは最新。**再開のコマンドを打ち込んだ後、エージェントが、手が空く前に居なくなった（＝再開の失敗）とき**は、参照を捨てる代わりに、一つ前へ戻す（次の起動で、一つ前を試す。打ち込みを、その場でやり直すことはしない）。全部失敗したら、無し。`sodactl agent get` などに、履歴は出さない（最新だけ）。
- [ ] AC5（ログ）: 参照を捨てた・戻した・報告を捨てた、のログに、会話の id の先頭 8 文字・再開を打ち込んでからの時間・理由。
- [ ] AC6（サブエージェントの数え）: 入れ子の子の `claude` の `SubagentStart` が、親の pane の件数に混ざらない（AC1 と同じ確かめを、サブエージェントの報告にも。pid の無い報告は、今までどおり）。
- [ ] AC7（Codex。**先に調べて、止まって報告**）: Codex 0.162 のフックが、daemon の環境で動くことを、実物で確かめる（費用は最小に。利用者の `~/.codex` は書き換えない——一時の `CODEX_HOME` に、認証だけを読める形で渡せるなら。できなければ、動いている daemon と pane の `codex` の、プロセスの親子・環境を、読むだけで）。そのうえで、**正しい pane に付ける方法**を、案として出す（調査の案 1: フックの入力の `cwd`・時刻と、`kind: codex` で参照の無い・起動したばかりの pane を、サーバが突き合わせる。1 つに決まるときだけ付け、決まらなければ捨ててログ。案 2: pane の `codex` から daemon へ、pane を伝える道があるか）。**この AC は、実装せず、案と、確かめた事実を、結果に書く**（監督役が決める）。AC1 が入れば、Codex の報告は、少なくとも、別の pane を上書きしなくなる（daemon の pid は、どの pane の前面にも居ない）——それを、結合テストで。
- [ ] AC8: 文書（`docs/` の会話の再開の説明: 何の報告で変わるか・捨てる条件・Codex の今の限界）。フックのスクリプトが変わるので、導入済みは「更新が必要」になる（押したときだけ書き換える）。回帰テストには、否定の対照。

## 対象外
- Codex の正しい pane への付け方の実装（AC7 の案を見てから）。Windows での pid の確かめ（付いていなければ、今までどおり受ける）。

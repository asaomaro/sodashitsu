# 要件: 確認の通知を右上に積み、先送りした通知をベルから見返せるようにする

## 背景 / 課題

エージェントが入力待ち・完了になったときの知らせ（20260920-agent-notifications）は、画面の**下・中央**にトーストとして出る
（`packages/web/src/components/Toast.vue` の `.toast-list`: `bottom: 3.5em; left: 50%`）。次の問題がある。

- 端末の入力欄（pane の下端）に**被さり、打とうとしている場所を隠す**。消えない知らせ（`kind: "sticky"`）は利用者が閉じるまで残るので、被さりも残る。
- 消えない知らせを **×で閉じると、その知らせは記録から消える**（`NotificationController.syncToasts` が待ち行列から外す）。
  「いま対処できないので閉じたが、後で見たい」知らせを見返す手段が無い（`prefix+o` の行き先も同時に失う）。
- 出来事が解消した（入力待ちから復帰した・pane が閉じた）あとも、消えない知らせは残り続ける（pane 閉鎖・待ち行列の上限・置き換えのときしか消えない）。

利用者の要望（原文）:
「確認の通知を右上からスタックする形にしてください。現在は画面下部中央部の為、入力エリアに被さり邪魔になっています。また、応答せず閉じた通知の一覧をポップアップで表示して、判断を先送りした通知を後から見れるようにします。ベルアイコンからポップアップを呼び出し、ベルアイコンには通知件数のバッヂを表示してください。可能であるかは分かりませんが、通知の元になったイベントが解消していれば、通知一覧から自動で消える機能も欲しいです。ポップアップ内に通知の一括削除ボタンも配置してください。」

「確認の通知」は、エージェントの入力待ち（blocked）・完了（done）の知らせ（sticky のトースト）と読む。

## 目的 / ゴール

- 知らせが**入力や端末の読み取りを妨げない場所**（右上）に出ていて、複数あっても読める状態。
- **応答せずに閉じた知らせを、あとで一覧で見返せる状態**（ベルの件数で「先送りした件数」が常に分かる）。
- 一覧は**いま意味のある知らせだけ**を持ち、**解消した知らせは自動で消えている**状態。不要になれば一括で空にできる状態。

（charter.md は無い PJ のためスキップ）

## ユーザーストーリー

- US1: 複数のエージェントを回している利用者として、知らせが右上に積まれてほしい。なぜなら、端末の入力欄を隠されずに打ち続けたいから。（AC1〜AC4）
- US2: 席を外していて、戻ってきて×で閉じた利用者として、閉じた知らせをあとで見返したい。なぜなら、その時は対処できなくても判断を先送りしただけで、忘れたくないから。（AC5〜AC8）
- US3: 利用者として、画面のどこからでもベルの件数で先送りした件数を知り、押して一覧を開きたい。なぜなら、一覧の置き場が見えていなければ、あることに気づかないから。（AC9〜AC12）
- US4: 利用者として、すでに片付いた出来事（入力待ちから復帰した・pane を閉じた）は一覧から消えていてほしい。なぜなら、古い知らせが溜まると本当に要る知らせが埋もれるから。（AC13〜AC15）
- US5: 利用者として、一覧をまとめて空にしたい。なぜなら、1 件ずつ消す手間をかけず、要らなくなった分を一度で片付けたいから。（AC16）

## スコープ

### 対象

- Web 版（`packages/web`）のトーストの置き場所と見え方（短い知らせ〔4 秒で消える〕も同じ右上にそろえる）。
- 応答せずに閉じた知らせの履歴（`client-core` に規則、`web` に状態・保存）。
- ベルのアイコン（デスクトップ・モバイル）・件数のバッヂ・ポップアップ（一覧・個別の削除・一括削除）・開くキー。
- 解消した知らせの自動削除。
- docs（`docs/verification.md`・`docs/herdr-parity.md`・`docs/tui-parity.md`・`docs/tui.md` のキー一覧）。

### 対象外

- 端末版（`soda` 引数なし）の画面の作り変え（右上・ベル）。端末版は既存の「知らせの一覧」（未処理の知らせ）があり、キーの割り当ては共有の設定なので、新しい操作を端末版では**その一覧を開く操作に読み替える**だけにする（`docs/tui-parity.md` に書く）。
- 通知の設定（画面内・OS 通知・音）・OS 通知・音・案内（オンボーディング）の仕様変更。
- 履歴のサーバ保存・ほかのブラウザとの共有（理由は design の decisions）。
- 知らせの種類の追加（`blocked` / `done` のまま）。

## 機能要件

1. **トーストの置き場所**: 画面の右上から、縦に積む。端末の入力欄（pane の下端）には被さらない。消えないもの・4 秒で消えるものを同じ置き場に、時間順に並べる。
2. **履歴**: 応答せずに（行き先へ移らず・対処せずに）知らせが外れたとき、**「判断を先送りした通知」として一覧に残す**。上限は 50 件・7 日。保存はこのブラウザ（`localStorage`）。
3. **ベル**: 常に見える場所に置き、履歴の件数をバッヂで出す（0 件は出さない・100 件以上は `99+`）。押すとポップアップが開く。
4. **ポップアップ**: 履歴を新しい順に出す。各行は対象の呼び名・種類（入力待ち／完了）・時刻・［移動］・［×（削除）］。［すべて削除］を置く。
5. **自動削除**: 出来事が解消したら履歴から消える（何で何が消えるかは design の表）。再接続・再読み込みのあとに復活しない。
6. **開くキー**: `prefix+shift+o`（操作 `open_notification_history`）。設定の「キー」で変えられる。

## 非機能要件 / 制約

- 既存の仕様を壊さない: 通知の設定・OS 通知・音・`prefix+o`・未処理の待ち行列の上限 8・見ている pane には出さない・案内。
- 二重に数えない: 履歴と待ち行列は別の置き場で、ベルの件数は履歴だけを数える。`prefix+o`・［移動］・OS 通知のクリックで行った知らせは履歴から消える。
- アニメーションは「動きを減らす」設定（`prefers-reduced-motion`）に従う。
- 実体の id は UUID（AGENTS.md）。履歴は pane の id を持つが、マシンごとに分けて持つ（id がマシンをまたいで衝突するため）。
- 大きな変更の切り分け: 差分を小さくするため、規則は `client-core` の純関数へ、状態は 1 つのストアへ、画面は 2 部品（ベル・ポップアップ）へ分ける。

## 完了条件 (受け入れ基準)

- [ ] AC1: トーストの一覧は画面の**右上**に出る。端末の pane の下端の入力エリアと**矩形が交差しない**（デスクトップ・モバイルの幅の両方。ブラウザの実測）。
- [ ] AC2: 複数のトーストは縦に積まれて**互いに重ならない**。消えない知らせも 4 秒で消える短い知らせも同じ置き場で、時間順（古いものが上・新しいものが下）に並ぶ。上限（消えない知らせは待ち行列と同じ 8 件・短い知らせは 3 件）を超えたら、短い知らせは古いものから外し、全体は高さで切って中でスクロールする。
- [ ] AC3: 他の UI との重なり方が決まっている。タブバーの右端・pane の右上は一時的に隠れてよい（入力欄ではない）。モバイルは上部バーのボタン（設定・連携・キーボード）を**隠さない**位置（バーの下）に出し、上の安全領域（ノッチ）を避ける。ダイアログ・グラフ画面・質問のフォームの上に出す／下に隠れる規則は今までどおり（開いている間は、グラフ画面・質問のフォームの中へ出す）。
- [ ] AC4: 一覧は `aria-live="polite"` の領域で、読み上げに閉じるボタンの名前（`aria-label`）が付く。出る動き（スライドイン）は `prefers-reduced-motion: reduce` では付かない。
- [ ] AC5: 消えない知らせが、行き先へ移らずに外れたとき、履歴に残る。外れ方は次の 3 つ: トーストを×・本体のクリックで閉じた／待ち行列の上限（8 件）を超えて押し出された／トーストを「切」にしていて、そもそもトーストが出ていない（この場合は知らせの時点で入る）。
- [ ] AC6: 履歴は**同じ pane につき最新の 1 件**だけ（古い方は置き換わる）。上限は 50 件、保持は 7 日。超えたら古いものから落とす。件数・7 日の判定は純関数にして、単体テストで総当たりする。
- [ ] AC7: 履歴は**このブラウザの `localStorage`**（`soda.notifyHistory.v1`）に、マシン（`local`・登録したマシン）ごとに保存する。再読み込みしても残る（解消済みのものを除く。AC14）。保存できない環境（プライベートウィンドウ等）でも動く（メモリだけで）。マシンを切り替えたら、そのマシンの履歴に切り替わる。
- [ ] AC8: 履歴に入るのは `blocked`／`done` の知らせだけで、案内・短い知らせ・`prefix+o` の「未処理の知らせはありません」等は入らない。
- [ ] AC9: ベルのアイコン（SVG。絵文字にしない）が、デスクトップではサイドバーの下端（畳んだサイドバーでも見える）、モバイルでは上部バーに出る。履歴の件数をバッヂで出し、0 件は出さない・100 件以上は `99+`。ボタンの `aria-label` に件数が入る（例「通知の一覧（3 件）」）。モバイルでも押せる大きさ（高さ 2rem 以上）。
- [ ] AC10: ベルを押す／`prefix+shift+o` でポップアップ（ダイアログ）が開く。各行は、対象の呼び名・種類・時刻（「3 分前」等）・［移動］・［×］。新しい順。0 件なら「判断を先送りした通知はありません」。
- [ ] AC11: ［移動］（行本体も同じ）でその pane へ移り（`prefix+o` と同じ動き）、ポップアップを閉じ、その行を履歴から消す。対象がもう無ければ、その旨を知らせて行を消す。
- [ ] AC12: ［×］で 1 件消す。消した行の次（無ければ前）の行へフォーカスが移り、0 件になったら［閉じる］へ移る。
- [ ] AC13: 通知の元の出来事が解消したら、履歴から自動で消える。対象と条件は design の表のとおり: pane が閉じた・エージェントが居なくなった／入れ替わった・入力待ちから別の状態へ戻った・完了したエージェントがまた動き出した（working／blocked）・完了を既読にした（その pane を見た）・同じ pane の新しい知らせが来た。
- [ ] AC14: **再接続（スナップショット）・再読み込みのあと**に、解消済みの知らせが履歴に復活しない／残らない（最初のスナップショットで、保存されていた履歴を現在の状態と突き合わせて掃除する）。切断中に起きた解消も、再接続のスナップショットで掃除する。
- [ ] AC15: トーストを閉じた時点で、出来事がすでに解消していれば、履歴に入れない。
- [ ] AC16: ポップアップに［すべて削除］を置く。**2 段階**（1 回目で「n 件をすべて削除しますか？ ［削除する］［やめる］」に変わり、2 回目で確定）。0 件のときは無効。確定したら 0 件になり、バッヂが消える。
- [ ] AC17: 既存の仕様を壊さない: 通知の設定・OS 通知・音・案内・見ている pane には出さない・未処理の待ち行列の上限 8・`prefix+o` の順序と文言。
- [ ] AC18: 二重に数えない。ベルの件数は履歴だけを数える。トーストが出ている間の知らせ（まだ閉じていない）は数えない。`prefix+o`・トーストの［移動］・OS 通知のクリックで行った知らせは、履歴からも消える。
- [ ] AC19: 新しい操作 `open_notification_history`（既定 `prefix+shift+o`）が、キーの割り当て（設定の「キー」・ヘルプの一覧）に載り、既存のキーと衝突しない。端末版は、同じ操作を既存の「知らせの一覧」を開く操作に読み替える。
- [ ] AC20: docs を直す（`docs/verification.md` の手動項目・`docs/herdr-parity.md`・`docs/tui-parity.md`・`docs/tui.md` のキー一覧）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: ベルのボタン・`prefix+shift+o` で開く。Esc・［閉じる］・背景のクリックで閉じる。閉じても履歴は変わらない（行を消したときだけ変わる）。
- [ ] AC-I2 確定 / 取り消し: 行の［移動］は確定（移って閉じる）、［×］は 1 件削除（ポップアップは開いたまま）。［すべて削除］は 2 段階で、［やめる］・Esc（確認の中の Esc は確認だけを取り消す。ポップアップは閉じない）で取り消せる。
- [ ] AC-I3 キーボードだけで完結: 開く（`prefix+shift+o` または Tab でベルへ→Enter）→ ↑↓／Home／End で行を選ぶ → Enter で移動・Delete／Backspace で削除 → Tab で［すべて削除］・［閉じる］→ Esc で閉じる、をマウス無しで通せる。
- [ ] AC-I4 フォーカスの行き先: 開いたら最初の行（無ければ［閉じる］）へ。閉じたら、ベルから開いたならベルへ、キーから開いたなら今フォーカスのある pane の端末へ戻る。［移動］で閉じたときは移った先の pane へ。
- [ ] AC-I5 既存の操作を妨げない: ポップアップは `showModal()` のダイアログで、開いている間のキー・ホイールは背後の端末・`prefix` のキーへ漏れない（既存のダイアログと同じ経路）。トーストの［移動］・×の操作は変えない。

## 未確定事項 / 確認したいこと

- 「確認の通知」を入力待ち・完了の知らせと読んだ（要望の原文からの解釈。依頼元の読みと同じ）。
- 履歴の保存を、このブラウザだけ（`localStorage`）にした。ほかのブラウザ・端末と共有したい場合は別の work（サーバ側の置き場とマシンごとの id の扱いが要る）。
- 履歴は同じ pane につき最新の 1 件にした（入力待ち → 完了のように続く出来事は、新しい方が古い方を解消するため）。件数が少なすぎると感じる場合の上限（50・7 日）は設計で決め、利用者に確認する。

# ブラウザの画面寸法の安定化

利用者のスクリーンショットでは、ページ全体の縦横スクロールバーが出入りし、小刻みに画面が振動する。サイズ変更直後の内容のはみ出しが画面寸法に影響しないようにする。端末・サイドバー・各ビュー内部のスクロール、ログイン画面・切断画面のスクロールを維持する。

## 調査と設計

通常サイズでは利用者の継続的な振動は再現していない。実 Chromium で通常サイズ変更直後に旧表示領域の scrollHeight が一時的に残ること、および低い画面で root.scrollHeight=93px > clientHeight=60px を確認した。ページ全体のスクロールバーによる寸法変化を防ぐため、接続後の .app-shell だけ overflow:clip にする。画面の大きさ、PTYの計測、個別ビューのスクロール方式は変えない。overflow:clip は新たなスクロールコンテナを作らない。

## 受け入れ基準

- Statuslineを持つエージェントペインを実ブラウザで7種類のサイズへ変えても、ページ全体のスクロール範囲が viewport 内に収まり、寸法が安定する。
- ファイル一覧がマウスホイールでスクロールできる。
- 低いログイン画面はスクロールしてボタンに到達できる。
- 既存のstatuslineリサイズ・設定・モバイル表示を維持する。

## 限界

利用者の環境で同じ継続的振動が解消したことの実機確認は未実施。ブラウザ名・倍率を追加確認中。

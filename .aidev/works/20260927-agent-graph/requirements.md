# 要件: エージェントの連携をノードとして画面で設定する（agent-graph）

## 背景 / 課題

- 製品全体のゴール（20260918-web-terminal-multiplexer の requirements）は「複数ホストのエージェントのセッションを、ブラウザの 1 画面で
  状態把握・操作・**相互連携の設定**まで行える状態」。このうち相互連携の設定だけが未着手で、MVP の時点から後続 work
  「ノードによるオーケストレーション」（状態トリガ・出力の受け渡し・監督関係）として予定していた。
- 前提としていた外部操作 API とエージェント自動化（`sodactl agent list / wait / read / prompt --wait / send-keys / start`・skill ファイル）は着地済みで、
  エージェント同士は CLI で連携できる。
- ただし今は、連携させるには利用者がシェルスクリプトを書くか、エージェントに sodactl の使い方と相手の pane ID を毎回教える必要がある。
  - どのエージェントがどれと連携しているかが画面から見えない。
  - 連携が今動いているのか・止まっているのか・何回回ったのかが分からない。
  - 連携を変える・止めるのに、スクリプトやエージェントへの指示を書き直す必要がある。

## 目的 / ゴール

- エージェントの連携（誰が終わったら誰に何を渡すか・誰が誰を監督するか）を、スクリプトを書かずにブラウザの画面でマウスで結ぶだけで設定でき、
  設定した連携が画面を閉じても動き続ける状態。
- 連携の全体像（どの pane がどれと繋がり、今どこが動いていて、何回回ったか）が 1 画面で分かり、止めたいときにすぐ止められる状態。
- 連携が暴走しても（無限の往復など）、上限で必ず止まり、利用者が気づける状態。

## ユーザーストーリー

- US1: 複数のエージェントを並行運用する開発者として、pane をノードとして並べ、線で結んで「A が終わったら B に A の結果を渡して指示する」を設定したい。
  なぜなら 実装→レビュー→修正のような受け渡しを、スクリプトを書かずに、席を外している間も回し続けられるから。（受け入れ: AC1, AC2, AC3, AC4, AC5, AC6）
- US2: 同じ開発者として、1 つのエージェントを監督役にして、配下のエージェントへの指示・待機・結果の取りまとめ・承認待ちへの対応を任せたい。
  なぜなら 決まった流れでは書けない判断（どれに次を頼むか・承認してよいか）をエージェントに任せられるから。（受け入れ: AC7, AC8, AC9）
- US3: 同じ開発者として、連携の全体と、今どの線が動いたか・何回回ったかを一目で見て、必要ならすぐ止めたい。
  なぜなら 連携が意図どおり動いているかを確かめ、暴走や誤りに気づいたらすぐ被害を止められるから。（受け入れ: AC10, AC11, AC12, AC13）
- US4: 複数のマシンでエージェントを動かす開発者として、別のマシンの pane とも線で結びたい。
  なぜなら 役割ごとにマシンを分けても、連携を 1 画面で組めるから。（受け入れ: AC14）
- US5: スクリプトやエージェント自身から連携を組む開発者・AI エージェントとして、画面と同じ連携を sodactl でも作成・一覧・削除・一時停止したい。
  なぜなら 決まった編成を繰り返し作る・エージェントが自分で協力相手を用意する、を自動化できるから。（受け入れ: AC15）

## スコープ

### 対象

- 専用のグラフ画面（ブラウザ）。ノード＝pane（中のエージェントの名前・種類・状態をその場で表示）。ノードから該当の pane へ移動できる。
- 線（連携）の 4 種類:
  - **状態トリガ**: A が指定の状態（done / blocked / idle 等）になったら、B へ決めた prompt を送る。
  - **出力の受け渡し**: トリガのときに A の画面の末尾（結果）を B への prompt に含める。
  - **監督関係**: 監督役のエージェントに配下の pane と使い方（sodactl）を知らせ、配下への指示・待機・読み取りは監督役が行う。
  - **承認待ちの代理**: A が承認待ち（blocked）になったら監督役へ判断の材料を渡す。監督役に返答までさせるか・知らせるだけにするかを線ごとに選ぶ。
- 実行主体: 状態トリガと出力の受け渡しは**サーバが決めたとおりに実行**する（ブラウザを閉じても動く）。監督関係と承認待ちの代理の判断・返答は監督役のエージェントが sodactl で行い、
  サーバは知らせる内容の受け渡しと可視化を担う。
- 暴走の防止: 線ごとの実行回数の上限（超えたら止めて知らせる）、グラフ全体と線ごとの一時停止・再開、実行の履歴の表示。
- 連携の保存: サーバを再起動しても、グラフ（ノードの配置と線の設定・一時停止の状態）が残る。
- 別のマシン（`soda machine` で登録したもの）の pane とも線で結べる。
- sodactl からの連携の作成・一覧・削除・一時停止・再開と、エージェント向けの skill ファイルへの説明の追加。

### 対象外

- ①の端末版（20260927-cli-mode）でのグラフの表示と編集（後続。①の着地が前提）。
- 役割のテンプレート（「実装役」「レビュー役」などの型でグラフを作り、後から pane を割り当てて再利用する）。
- 条件の分岐（出力の内容によって送り先を変える等）・変数・待ち合わせ（A と B の両方が終わったら C）などのワークフロー言語としての機能。
  必要な判断は監督役のエージェントに任せる。
- ノード編集のための外部ライブラリの導入（MVP の decisions D10：自前で実装する）。

## 機能要件

- F1 グラフ画面: キーとサイドバーから開閉できる専用の画面に、pane をノードとして表示する。ノードには pane の呼び名・マシン・エージェントの名前と種類・5 状態を
  その場で表示し、状態の変化は 2 秒以内に反映する。ノードから該当の pane へ移動できる。
- F2 ノードの配置: ノードをマウスで動かせ、配置は保存される。グラフに載せる pane を選べる（すべての pane を自動で載せない）。
- F3 線を結ぶ: ノードから別のノードへマウスでドラッグして線を作り、線の種類と設定（トリガの状態・送る prompt・受け渡す行数・上限・承認待ちの扱い）を決める。
  線を選んで設定を変える・削除できる。向きを持つ（どちらからどちらへ）。
- F4 状態トリガの実行: 線の元の pane のエージェントが指定の状態になったとき、サーバが線の先のエージェントへ prompt を送る。
  先のエージェントが受け付けられない状態（作業中・承認待ち・不在）のときの扱い（待つ・見送る）を持つ。
- F5 出力の受け渡し: トリガのとき、元の pane の画面の末尾の指定行数を prompt に含めて送る。
- F6 監督関係: 監督役のエージェントに、配下の pane（ID・呼び名・マシン）と sodactl での操作方法を知らせる。配下の構成が変わったら知らせ直す。
- F7 承認待ちの代理: 配下のエージェントが承認待ちになったら、監督役へ判断の材料（画面の末尾と対象）を渡す。線の設定が「返答まで任せる」なら監督役が
  sodactl で返答し、「知らせるだけ」なら返答は人が行う。どちらでも人への通常の通知は出る。
- F8 実行の表示と履歴: 線が実行されたこと（いつ・何を送ったか・結果）を線の上と履歴に表示する。
- F9 上限と一時停止: 線ごとの実行回数の上限（既定値あり）を超えたら、その線を止めて利用者に知らせる。グラフ全体・線ごとに一時停止と再開ができ、
  一時停止中はどの線も実行されない。
- F10 保存と復元: グラフ（載せた pane・配置・線とその設定・一時停止の状態）をサーバに保存し、再起動後も復元する。
  pane が閉じられたら、その pane に繋がる線は無効として表示する（黙って消さない）。
- F11 複数ホスト: 登録したマシンの pane もノードにでき、線で結べる。マシンが繋がっていない間の実行の扱い（見送り・知らせる）を持つ。
- F12 sodactl: 線の作成・一覧・削除・一時停止・再開、グラフ全体の一時停止・再開を sodactl から行え、画面と同じ状態を共有する。
  skill ファイル（`sodactl skill`）に連携の使い方を加える。
- F13 同時接続: 複数のブラウザで同じグラフを開いたとき、一方の変更が他方へ即座に反映される。

## 非機能要件 / 制約

- **実行の確かさ**: 状態トリガは、状態の変化 1 回につき高々 1 回だけ実行する（二重に送らない）。送れなかったときは履歴に理由を残す。
- **応答性**: 状態の変化から線の実行開始まで、エージェントの状態の判定の周期を除いて 2 秒以内の目安。
- **規模**: 少なくとも pane 16 個・線 32 本のグラフを、操作が固まらずに表示・編集できる。
- **安全**: 連携は認証を通過した利用者だけが作成・変更できる（画面・sodactl とも既存の認証）。自動で送る prompt と承認の代理は、利用者が線で明示したものだけで、
  既定では上限と一時停止で必ず止められる。
- **対応環境**: ブラウザは既存と同じ（Chrome / Edge 最新版）。モバイルブラウザでは閲覧と一時停止・再開ができればよい（編集はデスクトップ）。
  サーバは既存の 3 環境（Linux / WSL2 / Windows ネイティブ）。ただし `agent start` 等の既存の制約（Windows のサーバで使えない操作）はそのまま引き継ぐ。
- **互換**: 既存の画面・sodactl・サーバの挙動を壊さない。
- **実装の制約**: ノード編集は外部ライブラリを使わず自前で実装する（MVP の decisions D10）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

対象の部品: グラフ画面、ノード、線、線の設定の入力欄、pane をグラフに載せる選択、履歴の表示、一時停止の切り替え。

- [ ] AC-I1 開く / 閉じる: グラフ画面はキー（prefix＋キー）とサイドバーのクリックで開き、同じキー・`Esc`・閉じるボタンで閉じる。
  線の設定と pane の選択は、線・ノードの操作から開き、`Esc` または外側のクリックで閉じる。確定せずに閉じたときは値が変わらない。
- [ ] AC-I2 確定 / 取り消し: 線の設定は確定の操作（`Enter`・保存ボタン）で反映し、`Esc` で取り消して元に戻る。線の削除とグラフからの pane の除去は、
  実行中・一時停止中にかかわらず確認を挟み、取り消せば何も失われない。ドラッグで線を作っている途中の `Esc`・何も無い所での離しは、線を作らずに終わる。
- [ ] AC-I3 キーボードだけで完結するか: ノードの選択・移動、線の作成（元と先をキーで選ぶ）・設定・削除、一時停止・再開、pane への移動、グラフ画面を閉じる、を
  マウスを使わずに最初から最後まで行える。
- [ ] AC-I4 フォーカスの行き先: グラフ画面を開くと直前に選ばれていた pane のノード（載っていなければ先頭のノード）にフォーカスが移る。線の設定を閉じるとその線に戻る。
  グラフ画面を閉じると開く前の pane に戻り、ノードから pane へ移動したらその pane にフォーカスが移る。
- [ ] AC-I5 既存の操作を妨げないか: グラフ画面を開いている間のキー・ホイール・ドラッグは端末の pane へ漏れない。グラフ画面を閉じれば、pane へのキー入力・prefix 操作は
  開く前と同じく届く。グラフ上のホイールはグラフの拡大縮小・移動だけに作用し、ページ全体をスクロールさせない。

## 未確定事項 / 確認したいこと

- 監督役への「知らせる」の手段（prompt として送る・skill ファイルや環境への書き出し・その両方）と、エージェントが作業中のときの知らせ方 → design。
- 状態トリガの「状態になったとき」の判定の単位（`done` の既読との関係・`idle` が続く場合に再発火しないこと）→ design。
- 実行回数の上限の既定値と、上限に達した線の再開の手順 → design。
- pane が別の tab / workspace に移動・サーバの再起動で ID が変わる場合の線の追従 → research（既存の pane ID の寿命の確認）。
- 別のマシンの pane を元・先にするときの実行の場所（手元の `soda serve` が中継する前提）と、中継が切れている間に起きた状態の変化の扱い → research・design。
- 送る prompt の中で受け渡す出力を差し込む位置の書き方 → design。
- グラフ画面で確立した操作パターン（ノードエディタの一般的な操作：ドラッグでの接続・ズーム・選択）→ research。

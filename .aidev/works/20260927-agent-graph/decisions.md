# 判断の記録（20260927-agent-graph）

## D1 設計の方針（design の前にユーザーが選んだ）

- **背景**: research の申し送り 8 点のうち、有力な案が複数ある論点を、design を書く前にユーザーに示した（2026-09-28。例「impl が終わったら reviewer に結果を渡す」で説明）。
- **決定**:
  1. 先のエージェントが作業中（working）なら**手が空くまで待つ**（最大 30 分。超えたら見送って履歴に残す）。待つ間に同じ線がもう一度動いたら新しい 1 件だけを送る。線ごとに「見送る」に切り替えられる。
  2. 状態トリガの元の状態は**「完了した」「承認待ちになった」の 2 つ**。完了は作業から手が空いた 1 回ごと（`(instanceId, completionSeq)` の増加。ブラウザの完了の通知と同じ判定）、承認待ちは 1 秒続いたら。
  3. 出力の受け渡しは**トリガの設定の選択肢**（元の画面の末尾 N 行を prompt の `{output}` の位置へ、無ければ末尾へ）。線の種類は「トリガ・監督・承認の代理」の 3 つ。
  4. 線ごとの実行回数の上限は**既定 10 回**。達したらその線を一時停止して知らせ、利用者が再開すると 0 に戻る（1〜100 で変えられる）。
  5. 監督役への知らせは、線を結んだとき・配下が変わったときに、**監督役の手が空いていれば短い prompt で送る**（作業中なら手が空くまで待ち、続く変化は 1 回にまとめる）。
  6. 別のマシンの pane の線で、中継が切れている間に起きた変化は**見送って履歴に残す**（繋ぎ直しても後から送らない）。
  7. グラフは **session（`soda serve`）に 1 つ**。
  8. 端末版でグラフ画面を開く操作は**「ブラウザで開けます」と知らせる**（操作表は共有のまま）。
- **理由・代替案**: 1 は「見送る」だと往復の連携が作業中の一瞬に落ちて止まり、「割り込む」は作業中のエージェントを乱す。2 の「手が空いた（idle）」も選べる案は、起動直後・承認の後の idle で誤って動く。3 の「線の種類として分ける」は単独では動かない線ができる。4 の「時間あたり」は往復が長く続く使い方で止まり方が読めない。5 の「取りに行くだけ」は監督役が気づかない。6 の「繋がったら送る」は時間のたった指示が突然届く。7 の複数のグラフは要件の範囲を超える。8 の「端末版に載せない印」は操作表に新しい仕組みを足すことになる。
- **影響**: design はこの方針で書く。

## D2 承認の代理の既定は「知らせるだけ」

- **背景**: 承認の代理で「返答まで任せる」は、人の承認をエージェントに任せることになる。
- **決定**: 新しい承認の代理の線の既定は `notify`（知らせるだけ）。`delegate` を選ぶと設定のパネルに注意を出す。
- **理由・代替案**: 既定を `delegate` にすると、線を引いただけで承認が自動になる。

- **背景**: requirements〜tasks はユーザーとの対話で承認した（2026-09-28）。tasks の承認のときにユーザーが「自律で PR・merge まで」を選んだ。

## D4 01-graph-core の実装での読み替え

- **決定**:
  1. protocol の graph の型は `packages/protocol/src/graph.ts` にまとめた（model.ts・messages.ts は参照だけ）。
  2. `graph.update` の操作は add_node・move_node・remove_node（線も消す）・rekey_node（stale のノードを選び直して印を外す）・add_link・update_link・remove_link の 7 つ。count・paused は操作で変えられない。まとめて当てる処理は client-core の `graph/ops.ts`（architecture の表に無かったモジュール）。
  3. 線の番号の続き `nextLinkId` を `graph.json` に保存する（消した線の id を再利用しない）。
  4. 全体の再開は線の count と paused を変えない。count を 0 に戻すのは線ごとの再開だけ（design の「resume は count を 0 に戻す」を線ごとに限定）。
  5. 検証の失敗は専用のコードを足さず `invalid_params`（web は保存の前に同じ validate を使う）。
  6. design に無かった既定値: 承認の代理の行数 40・トリガの prompt の既定の文。
  7. geometry の export 名に `graph` を付けた（`snapToGrid` 等との衝突を避ける）。
  8. グラフ画面を「同じ prefix＋キー」で閉じるのは 03 で足す（01 は Esc と閉じるボタン）。
  9. web の vitest の worker のヒープの上限を 4GB に上げた（`SettingsDialog.test.ts` が 1 件ごとに約 21MB を残し、操作が 1 つ増えて既定の 2GB を超えた。漏れそのものは backlog）。
  10. グラフ画面（`showModal()` の top layer）を開いている間は、トーストと再接続の表示を App.vue の `<Teleport :disabled="!graphOpen">` でその dialog の中へ出す（`popover="manual"` は top layer の中の重なりが「後から出したものが上」なので、グラフ画面を後から開くとまた隠れ、出し直しの管理が要るため採らない）。
- **影響**: 02 以降はこの形に合わせる。

# Native H.264の送信待ち改善

ユーザーのsr-pcの画像では1920×1200、30fps上限、描画4.6fps。最大解像度指定が幅1280より優先する。単一フレームの描画ACK待ちは取得・圧縮・通信・描画を直列化するため、上限30fpsでも到達できない。

ブラウザがv1に加えv2サブプロトコルを提示し、B RPC capabilityとhelper readyが全て対応する場合だけwindow=3へ上げる。未対応の相手へ新規option/ready/stream/ACK計測値を送らない。既定window=1。

helper、B、A、ブラウザで最大3枚のFIFOを維持し、描画済みの先頭ACKだけで枠を空ける。重複ACKは無視し、未到着先頭を飛ばすACKは拒否する。H264参照フレームは破棄しない。最古の未ACK期限、既存の512KiBの送出バッファ上限、停止と画像への復帰を維持。画像snapshot、入力の鮮度、認証画面のguardは変更しない。

取得、CPU NV12変換、MF encoder待ち込みの圧縮、B送信→描画ACK、ブラウザ受信→復号描画の直近値を約1秒間隔で表示する。有限0..60000ms、枚数0..3。幅上限が最大解像度指定で上書きされることを表示する。

GPU内NV12変換、zero-copy、動的bitrateは今回の範囲外。

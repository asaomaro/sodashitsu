# 要件: 操作できる所の見え方を良くする（サイズ変更・D&D・サイドバーの区画）

## 背景 / 課題

利用者が実際の画面を見て、次を指摘した。

- サイドバーとビューの間・pane の間は、ドラッグで大きさを変えられるが、**操作できることの表現が控えめで分かりづらい**。サイドバーの境目は幅 6px の透明な帯で、マウスを乗せても何も変わらない。pane の間の境目も、マウスを乗せたとき・ドラッグ中の変化が無い（research.md「F1」「F2」）。
- workspace・pane・タブの D&D は、**操作できるのか、今ドラッグできているのかが分かりづらい**。掴んだものの見た目が変わらず、ドラッグの像も無く、workspace の落とし先は行の枠だけで、どこに入るのかが分からない。タブは、ブラウザ版ではドラッグで並べ替えられない（research.md「F5」）。
- ブラウザ版のサイドバーの「spaces」と「agents」は、1 つのスクロールの中に積んであるだけで、**境目をドラッグして大きさを変えられない**（端末版はできる。research.md「F3」「F4」）。
- 「spaces」と「agents」を、**それぞれ折りたためない**（VS Code のサイドバーの区画のように、見出しを押して展開・折りたたみをしたい）。

## 目的 / ゴール

- 利用者が、大きさを変えられる境目を、マウスを乗せた時点で見分けられ、ドラッグしている間は「今動かしている」と分かる状態。
- 利用者が、ドラッグできるものを見分けられ、ドラッグ中は「何を掴んでいるか」「どこに入るか」「そこに落とせるか」が分かる状態。
- 利用者が、ブラウザ版のサイドバーで、spaces と agents の高さの配分を自分で決められ、使わない方を畳める状態。

charter ゴール: `.aidev/charter.md` は無い（紐づける charter はない）。

## ユーザーストーリー

- US1: Sodashitsu の利用者として、大きさを変えられる境目を見て分かりたい。なぜなら、今は探さないと見つからないから。（受け入れ: AC1, AC2, AC3）
- US2: 同じ利用者として、D&D の間、掴んでいるものと入る場所を見たい。なぜなら、落とすまで結果が分からないと、操作に自信が持てないから。（受け入れ: AC4, AC5, AC6, AC7, AC8）
- US3: 同じ利用者として、spaces と agents の高さを決め、片方を畳みたい。なぜなら、workspace が多いときとエージェントが多いときで、見たい方が違うから。（受け入れ: AC9, AC10, AC11, AC12, AC13）
- 動きの抑制・既存の操作・文書の AC（AC14, AC15, AC16）は、制約由来の基準。

## スコープ

### 対象

- **境目の表現**（ブラウザ版）: サイドバーとビューの間・pane の間・（新しく作る）spaces と agents の間。マウスを乗せたとき・フォーカスがあるとき・ドラッグ中の見た目。サイドバーの境目のキーボード操作。
- **D&D の表現**（ブラウザ版）: workspace の行（とグループ）・pane・タブ。掴めることの表示、掴んでいるものの表示、ドラッグの像、入る位置の表示、落とせない所の表示。
- **タブのドラッグでの並べ替え**（ブラウザ版。今は無い）。
- **サイドバーの区画**: ブラウザ版で、区画ごとのスクロール・境目のドラッグ・区画の折りたたみ。端末版で、区画の折りたたみ（境目のドラッグは既にある）。
- 文書（`docs/herdr-parity.md`・`docs/tui-parity.md`・`docs/tui.md`・`docs/verification.md`）。

### 対象外

- D&D でできることを増やすこと（タブの並べ替えを除く）。workspace の移動の決まり（項目単位・グループへの出し入れ）は `group-worktree-items` が決めたまま。
- モバイルの 1 列レイアウト（`MobileShell`）と、タッチでの D&D（長押しで掴む等）。
- 端末版の D&D の表現（文字の画面で、別の作業）。
- 連携のグラフの画面の中のドラッグ（ノード・線）。
- 配色のテーマそのものの変更（既存の色の変数を使う）。

## 機能要件

### 境目（サイズ変更）

- F1: 3 種類の境目（サイドバーとビュー・pane の間・spaces と agents）は、**同じ見た目の決まり**を持つ。通常は今の細い線。マウスを乗せると（少し待ってから）強調の色の太い線になり、ドラッグ中はその線が出たままになる。カーソルは今と同じ（左右・上下の矢印）。
- F2: 当たり判定は、見える線より広い（境目の両側に数 px）。pane の間の境目は、設定で枠を細くしても掴める幅を保つ。
- F3: ドラッグ中は、マウスが境目から外れても線の強調とカーソルが変わらない。ドラッグ中に、下の端末の文字が選択されたり、ほかの要素の hover が反応したりしない。
- F4: サイドバーの境目は、キーボードでも動かせる（フォーカスして左右の矢印。`Home`／`End` で最小・最大、`Enter` で既定の幅）。読み上げに、境目であること・今の幅が伝わる。spaces と agents の境目も同じ（上下の矢印）。pane の間は今のまま。
- F5: ダブルクリックで既定に戻す動きを、3 種類で揃える（サイドバーは既定の幅〔今のまま〕、pane の間は半分ずつ、spaces と agents は中身の高さに合わせた自動の配分）。

### D&D

- F6: ドラッグできるもの（workspace の行・グループの見出し・pane の名前・タブ）は、マウスを乗せると掴めることが分かる（カーソルと、行・タブの hover の見た目）。
- F7: ドラッグが始まると（閾値を超えたら）、**掴んだものが元の場所で薄くなり**、**ポインタに付いて動く像**（掴んだものの名前と、状態のアイコン。グループを掴んだときは件数）が出る。
- F8: workspace の行とタブの並べ替えでは、**入る位置に線**が出る（行と行の間・タブとタブの間）。グループの中へ入るときは、グループの範囲が分かる表示になる。線は、落としたときに実際に入る位置と一致する。
- F9: pane のドラッグでは、今の表示（縁は分割・中央は入れ替え）を保ったうえで、落としたらどうなるかを言葉でも示す（像か落とし先に「左に分割」「入れ替え」「新しいタブへ」など）。
- F10: 落とせない所にいる間は、像が「落とせない」見た目になり、線・面は出ない。そこで離すと、何も起きずに元へ戻る。`Esc` で取り消すと、像が消えて元へ戻る（今のまま）。
- F11: サイドバーやタブの一覧の端までドラッグすると、一覧が自動でスクロールする。
- F12: ブラウザ版で、タブをドラッグして並べ替えられる（同じ workspace の中。結果はキーの `move_tab_previous/next` を繰り返したのと同じ）。

### サイドバーの区画

- F13: ブラウザ版のサイドバーは、spaces と agents が**区画ごとにスクロール**する。見出しと、spaces の下のボタン（＋新規・メニュー）、いちばん下の畳むボタンは、スクロールしても見えたまま。
- F14: spaces と agents の境目をドラッグして、高さの配分を変えられる。どちらの区画も、見出しと 2 行分より小さくならない。配分は端末ごとに保存され、読み込み直しても同じ。ウィンドウの高さが変わっても、配分の比が保たれる。
- F15: 配分を一度も変えていない間は、spaces は中身の高さ（多すぎれば上限まで）、agents は残り、という自動の配分になる（端末版と同じ考え方）。
- F16: 区画の見出しを押すと、その区画が**折りたたまれる**（見出しだけになる）。もう一度押すと開く。見出しに、開閉の印（▸／▾）が付く。両方を畳むこともできる。片方を畳むと、もう片方が空いた高さを使う。畳んでいる間、境目のドラッグはできない。
- F17: 畳んだ区画の見出しには、件数（workspace の数・エージェントの数）と、agents では注意の要る状態（入力待ち・承認待ち）があることが分かる印が出る。
- F18: 並び順のボタン（見出しの右）は、今までどおり押せる（押しても区画は開閉しない）。
- F19: 折りたたみの状態は端末ごとに保存され、読み込み直しても同じ。
- F20: サイドバー全体を畳んだ状態（アイコンだけの細い表示）では、区画の見出し・境目・折りたたみは出ない（今のまま、アイコンが 1 列に並ぶ）。区画を畳んでいた場合の扱いは design で決める。
- F21: 端末版でも、区画の見出しの行を押すと（または操作で）その区画を折りたためる。状態は手元に保存される。

### 動き

- F22: 色・太さの変化と、像・線の出入りには、短い動き（0.1〜0.2 秒程度）を付けてよい。OS で「動きを減らす」が有効なときは、動きを付けない（変化は即座）。

## 非機能要件 / 制約

- ドラッグ中の処理で、端末の描画や入力が遅くならない（ポインタの移動ごとの計算は 1 回の描画につき 1 回まで）。
- 境目・線・像の色は、既存のテーマの色の変数から取り、8 つのテーマすべてで背景と見分けられる（文字でない部品のコントラスト 3:1）。
- 既存のキー操作・既存の保存された設定（サイドバーの幅）は変えない。
- **実装は、`group-worktree-items` が main に入った後に、その上で行う**（サイドバーの行と D&D を作り直しているため。research.md「設計判断に効く点」3）。設計までは先に進めてよいが、design は、その作業の design（項目単位の移動・グループの見出し・グループなし）を前提にする。
- `settings-side-menu`・`subagent-display` とは、触るファイルが重なる（`Sidebar.vue` のエージェントの行）。重なる所は、後から入る方が合わせる。

## 完了条件 (受け入れ基準)

- [ ] AC1: サイドバーとビューの境目・pane の間の境目・spaces と agents の境目にマウスを乗せると、強調の色の線が出る。離すと消える。3 つとも同じ色・同じ太さ。
- [ ] AC2: 境目をドラッグしている間、ポインタが境目から外れても線の強調が続き、離すと消える。ドラッグの間、端末の文字は選択されない。
- [ ] AC3: サイドバーの境目に `Tab` でフォーカスして、左右の矢印で幅が変わり、`Home`／`End` で最小・最大、`Enter` で既定の幅になる。境目は、名前と今の値を持つ区切り（separator）として読み上げに出る。
- [ ] AC4: workspace の行をドラッグすると、元の行が薄くなり、ポインタに付いて動く像に、その workspace の名前が出る。離すか `Esc` で、像が消えて行の見た目が戻る。
- [ ] AC5: workspace の行をドラッグ中、行と行の間に入る位置の線が 1 本だけ出て、離すと、その位置に入る（線の位置と結果が一致する）。グループの中に入る位置では、グループの中であることが分かる表示になる。
- [ ] AC6: 落とせない所（サイドバーの外・自分自身の位置）では、線が出ず、像が「落とせない」見た目になり、離しても順は変わらない。
- [ ] AC7: pane の名前をドラッグすると、像に pane の名前が出て、落とし先（pane の縁・中央・タブ・workspace の行）に応じて、落としたらどうなるかの言葉が出る。
- [ ] AC8: ブラウザ版でタブをドラッグすると、タブとタブの間に線が出て、離すとその位置へ並べ替わる。読み込み直しても、ほかの画面でも、その順になっている。
- [ ] AC9: workspace とエージェントがどちらも区画に収まらない数のとき、spaces と agents がそれぞれスクロールし、見出し・［＋ 新規］・畳むボタンは見えたまま。
- [ ] AC10: spaces と agents の境目をドラッグすると高さの配分が変わり、読み込み直しても同じ配分で出る。どちらの区画も、見出しと 2 行分より小さくならない。上下の矢印でも変えられる。
- [ ] AC11: 「spaces」の見出しを押すと spaces が見出しだけになり、agents が空いた高さを使う。もう一度押すと元の配分に戻る。「agents」も同じ。両方を畳める。読み込み直しても状態が同じ。
- [ ] AC12: 畳んだ区画の見出しに件数が出る。agents を畳んでいる間に、入力待ち・承認待ちのエージェントがあると、見出しに印が出る。
- [ ] AC13: 端末版で、区画の見出しの行をクリックすると、その区画が見出しだけになり、もう一度で戻る。`soda` を起動し直しても状態が同じ。
- [ ] AC14: OS の「動きを減らす」が有効なとき、境目・像・線に動き（transition・animation）が付かない。
- [ ] AC15: 既存の操作が変わらない: サイドバーの幅のドラッグとダブルクリック・pane の間の矢印キー・workspace と pane の D&D の結果・並び順のボタン・サイドバー全体を畳む操作。保存済みのサイドバーの幅がそのまま使われる。
- [ ] AC16: `docs/herdr-parity.md`・`docs/tui-parity.md`（H19b の web 版の欄を含む）・`docs/tui.md`・`docs/verification.md` に、境目・D&D の表現・区画の大きさと折りたたみ・タブの並べ替えが書かれ、実機でだけ確かめられること（8 つのテーマでの見え方・タッチ・動きを減らす設定）が、自動テストの範囲と分けて書かれている。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 区画の折りたたみは、見出しのクリックと、見出しにフォーカスして `Enter`／`Space` で切り替わる。見出しは、開閉の状態（`aria-expanded`）を持つボタンとして読み上げに出る。
- [ ] AC-I2 確定 / 取り消し: 境目のドラッグ・D&D は、離した時点で確定し、`Esc` で取り消すと、始める前の状態に戻る（境目のドラッグも `Esc` で元の大きさに戻る）。
- [ ] AC-I3 キーボードだけで完結するか: サイドバーの幅・区画の高さ・区画の折りたたみは、キーボードだけで操作できる。並べ替えは、既存の操作（`move_workspace_*`・`move_tab_*`）で代替できる。
- [ ] AC-I4 フォーカスの行き先: 境目のドラッグ・D&D の後、フォーカスは始める前の所（端末）に残る。区画を畳んだとき、中にあったフォーカスは見出しへ移る。
- [ ] AC-I5 既存の操作を妨げないか: ドラッグ中のポインタの動き・キーが、端末へ漏れない。ダイアログが開いたら、ドラッグはその場で終わる（今のまま）。区画の見出しのクリックが、並び順のボタンを押したことにならない（逆も）。

## 未確定事項 / 確認したいこと

- 区画の折りたたみに、既定のキーを割り当てるか（今の案: 操作 `toggle_spaces_section`・`toggle_agents_section` を足し、既定のキーは無し。設定で割り当てられる）。
- サイドバー全体を畳んだとき（アイコンの 1 列）に、畳んだ区画のアイコンを出すか隠すか（今の案: 区画の折りたたみは無視して、今までどおり全部出す）。
- 像・線の見た目の細部は、design で画面の見本を作って決める（利用者に見てもらう）。

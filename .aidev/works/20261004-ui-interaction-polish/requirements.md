# 要件: 操作できる所の見え方を良くする（サイズ変更・D&D・サイドバーの区画）

## 背景 / 課題

利用者が実際の画面を見て、次を指摘した。

- サイドバーとビューの間・pane の間は、ドラッグで大きさを変えられるが、**操作できることの表現が控えめで分かりづらい**。サイドバーの境目は幅 6px の透明な帯で、マウスを乗せても何も変わらない。pane の間の境目も、マウスを乗せたとき・ドラッグ中の変化が無い（research.md の事実 F1・F2。以下、research.md の番号は「調査 Fn」と書き、この文書の機能要件 Fn と区別する）。
- workspace・pane・タブの D&D は、**操作できるのか、今ドラッグできているのかが分かりづらい**。掴んだものの見た目が変わらず、ドラッグの像も無く、workspace の落とし先は行の枠だけで、どこに入るのかが分からない。タブは、ブラウザ版ではドラッグで並べ替えられない（調査 F5）。
- ブラウザ版のサイドバーの「spaces」と「agents」は、1 つのスクロールの中に積んであるだけで、**境目をドラッグして大きさを変えられない**（端末版はできる。調査 F3・F4）。
- 「spaces」と「agents」を、**それぞれ折りたためない**（VS Code のサイドバーの区画のように、見出しを押して展開・折りたたみをしたい）。端末版（引数なしの `soda`）にも、区画の折りたたみは無い。

## 目的 / ゴール

- 利用者が、大きさを変えられる境目を、マウスを乗せた時点で見分けられ、ドラッグしている間は「今動かしている」と分かる状態。
- 利用者が、ドラッグできるものを見分けられ、ドラッグ中は「何を掴んでいるか」「どこに入るか」「そこに落とせるか」が分かる状態。
- 利用者が、ブラウザ版のサイドバーで、spaces と agents の高さの配分を自分で決められる状態。
- 利用者が、ブラウザ版でも端末版でも、spaces と agents のうち使わない方を畳める状態。

charter ゴール: `.aidev/charter.md` は無い（紐づける charter はない）。

## ユーザーストーリー

- US1: Sodashitsu の利用者として、大きさを変えられる境目を見て分かりたい。なぜなら、今は探さないと見つからないから。（受け入れ: AC1, AC2, AC3, AC17）
- US2: 同じ利用者として、D&D の間、掴んでいるものと入る場所を見たい。なぜなら、落とすまで結果が分からないと、操作に自信が持てないから。（受け入れ: AC4, AC5, AC6, AC7, AC8, AC18, AC19）
- US3: 同じ利用者として、spaces と agents の高さを決め、片方を畳みたい。なぜなら、workspace が多いときとエージェントが多いときで、見たい方が違うから。（受け入れ: AC9, AC10, AC11, AC12, AC13, AC20, AC21）
- 動きの抑制・既存の操作・文書の AC（AC14, AC15, AC16）は、制約由来の基準。

## スコープ

### 対象

- **境目の表現**（ブラウザ版）: サイドバーとビューの間・pane の間・（新しく作る）spaces と agents の間。マウスを乗せたとき・フォーカスがあるとき・ドラッグ中の見た目。サイドバーの境目と、spaces と agents の境目のキーボード操作。
- **D&D の表現**（ブラウザ版）: workspace の行（とグループ）・pane・タブ。掴めることの表示、掴んでいるものの表示、ドラッグの像、入る位置の表示、落とせない所の表示。
- **タブのドラッグでの並べ替え**（ブラウザ版。今は無い）。
- **サイドバーの区画**: ブラウザ版で、区画ごとのスクロール・境目のドラッグ・区画の折りたたみ。端末版で、区画の折りたたみ（境目のドラッグは既にある）。
- 文書（`docs/herdr-parity.md`・`docs/tui-parity.md`・`docs/tui.md`・`docs/verification.md`）。

### 対象外

- D&D でできることを増やすこと（タブの並べ替えを除く）。workspace の移動の決まり（項目単位・グループへの出し入れ）は `group-worktree-items` が決めたまま。
- モバイルの 1 列レイアウト（`MobileShell`）と、タッチでの D&D（長押しで掴む等）。境目のサイズ変更は、今もタッチで動くので（`touch-action: none`）、それを壊さないことだけを実機で確かめる。
- 端末版の D&D の表現（文字の画面で、別の作業）。
- 連携のグラフの画面の中のドラッグ（ノード・線）。
- 配色のテーマそのものの変更（既存の色の変数を使う）。

## 機能要件

用語: **この機器に保存**＝そのブラウザの localStorage（ブラウザ版）、または手元の `tui-state.json`（端末版）。ほかの機器・ほかのブラウザとは共有しない（サイドバーの幅と同じ扱い）。「端末」は、pane の中の端末の画面を指す。

### 境目（サイズ変更）

- F1: 3 種類の境目（サイドバーとビュー・pane の間・spaces と agents）は、**同じ見た目の決まり**を持つ。通常は今の細い線（サイドバーは右の罫線、pane の間は今の色の帯、spaces と agents は区切りの罫線）。マウスを乗せて 0.15 秒たつと、強調の色（テーマの強調色）の太さ 3px の線が重なって出る（すぐ通り過ぎただけでは出ない）。キーボードのフォーカスがあるとき・ドラッグ中も、同じ線が出る。カーソルは今と同じ（左右・上下の矢印）。
- F2: 当たり判定は、見える線より広い: 境目を中心に幅 8px 以上。pane の間は、設定で枠を細く（2px）しても、当たり判定は 8px を保つ。
- F3: ドラッグ中は、ポインタが境目から外れても線の強調とカーソルが変わらない。ドラッグ中に、端末の文字が選択されたり、ほかの要素（行・ボタン・ほかの境目）の hover の見た目が出たりしない。
- F4: サイドバーの境目と、spaces と agents の境目は、キーボードでも動かせる: `Tab` でフォーカスして、矢印（サイドバーは左右、区画は上下）で 1 段ずつ、`Home`／`End` で最小・最大、`Enter` で既定（F5 と同じ）。読み上げには、名前と今の値を持つ区切り（`role="separator"`）として出る。pane の間は今のまま（矢印で 2% ずつ）。マウスで掴んだときは、境目にフォーカスを移さない（フォーカスは始める前の所に残る）。
- F5: ダブルクリックで既定に戻す動きを、3 種類で揃える。サイドバーは既定の幅（今ある動き）。pane の間は半分ずつ（**新しい動き**。今はダブルクリックで何も起きない）。spaces と agents は自動の配分（F15。保存した配分を消して、「一度も変えていない」状態に戻す）。
- F6: 境目のドラッグ中に `Esc` を押すと、始める前の大きさに戻る（**新しい動き**。今は取り消せない）。ダイアログが開いたときは、今までどおり、その時点の大きさで確定して終わる。

### D&D

- F7: ドラッグできるもの（workspace の行・グループの見出し・pane の名前・タブ）は、マウスを乗せると掴めることが分かる: カーソルが「掴める」形（grab）になり、行・タブは hover の背景になる。
- F8: ドラッグが始まると（ポインタが 6px 動いたら。今の閾値のまま）、**掴んだものが元の場所で薄くなり**（不透明度 0.4 程度）、**ポインタに付いて動く像**が出る。像の中身: workspace は状態のアイコンと名前、グループの見出しは名前と件数、pane は名前、タブは名前。
- F9: workspace の行・グループ・タブの並べ替えでは、**入る位置に線**が 1 本出る（行と行の間・タブとタブの間）。グループの中へ入る位置では、線がグループの字下げの位置から始まり、そのグループの見出しが強調される。線は、落としたときに実際に入る位置と一致する。
- F10: pane のドラッグでは、今の表示（縁は分割・中央は入れ替え）を保ったうえで、落としたらどうなるかを像に言葉で出す。言葉は落とし先で決まる: pane の左右上下の縁＝「左に分割」「右に分割」「上に分割」「下に分割」／pane の中央＝「入れ替え」／タブ＝「このタブへ移す」／workspace の行＝「新しいタブへ移す」。
- F11: 落とせない所にいる間は、像に「落とせない」印（禁止の記号）が付いて薄くなり、線・面は出ない。そこで離すと、何も起きずに元へ戻る。落とせない所: workspace・グループ＝サイドバーの一覧の外と、動かしても順が変わらない位置／タブ＝そのタブバーの外（別の workspace へは運べない）と、順が変わらない位置／pane＝落とし先（pane・タブ・workspace の行）でない所と、自分自身・自分のいるタブ。`Esc` で取り消すと、像が消えて元へ戻る（今ある動き）。ダイアログが開いたときは、取り消しになる（今ある動き）。
- F12: 一覧の端（上下 24px。タブバーは左右）へドラッグしたままにすると、その一覧が自動でスクロールする。
- F13: ブラウザ版で、タブをドラッグして並べ替えられる（同じ workspace の中。結果はキーの `move_tab_previous/next` を繰り返したのと同じで、ほかの画面にも伝わる）。

### サイドバーの区画

- F14: ブラウザ版のサイドバーは、spaces と agents が**区画ごとにスクロール**する。区画の見出し・spaces の下のボタン（＋ 新規・メニュー）・いちばん下の畳むボタンは、スクロールしても見えたまま。
- F15: 配分を一度も変えていない間は、自動の配分: spaces は中身の高さ（ただし、agents に見出しと 2 行分を残す所まで）、agents は残り。
- F16: spaces と agents の境目をドラッグして、高さの配分を変えられる。どちらの区画も、見出しと 2 行分より小さくならない。配分は比としてこの機器に保存され、読み込み直しても同じ。ウィンドウの高さが変わると、比を保って配り直す（最小を割るときは、最小の方を優先する）。
- F17: 区画の見出しを押すと、その区画が**折りたたまれる**（見出しだけになる）。もう一度押すと開く。見出しに、開閉の印（開＝▾・閉＝▸）が付く。片方を畳むと、もう片方が空いた高さを使う。両方を畳むと、見出しが上に 2 つ並び、下は空く。どちらかを畳んでいる間、境目は出ない（ドラッグもフォーカスもできない）。開き直すと、畳む前の配分に戻る。
- F18: 畳んだ区画の見出しには、件数（spaces は workspace の数、agents はエージェントの数）が出る。agents を畳んでいる間、入力待ち・承認待ちのエージェントが 1 つ以上あれば、見出しにその状態のアイコン（エージェントの行と同じもの）が出る。
- F19: 並び順のボタン（見出しの右）は、今までどおり押せる（押しても区画は開閉しない）。
- F20: 折りたたみの状態はこの機器に保存され、読み込み直しても同じ。
- F21: サイドバー全体を畳んだ状態（アイコンだけの細い表示）では、区画の見出し・境目は出ず、区画の折りたたみの状態に関わらず、今までどおり全部のアイコンが 1 列に並ぶ。サイドバーを開き直すと、区画の折りたたみの状態は元のまま。
- F22: 端末版でも、区画の見出しの行（spaces の見出しと、「Agents」の区切りの行）をクリックすると、その区画を折りたためる。動きは F17・F18 と同じ（印・件数・状態の印・片方が空きを使う・両方畳める・畳んでいる間は境目のドラッグができない）。状態はこの機器に保存される。区切りの行は、今はドラッグの掴み手でもあるので、動かさずに離したときだけ折りたたみにする。
- F23: 操作 `toggle_spaces_section`・`toggle_agents_section` を、ブラウザ版と端末版の両方に足す（既定のキーなし。設定で割り当てられる）。

### 動き

- F24: 色・太さの変化と、像・線の出入りには、短い動き（0.1〜0.2 秒）を付ける。OS で「動きを減らす」が有効なときは、動きを付けない（変化は即座。F1 の 0.15 秒の待ちは残す）。

## 非機能要件 / 制約

- ドラッグ中の処理で、端末の描画や入力が遅くならない（ポインタの移動ごとの計算は 1 回の描画につき 1 回まで）。
- 境目・線・像の色は、既存のテーマの色の変数から取り、8 つのテーマすべてで背景と見分けられる（文字でない部品のコントラスト 3:1）。
- 既存のキー操作・既存の保存された設定（サイドバーの幅）は変えない。
- **実装は、`group-worktree-items` が main に入った後に、その上で行う**（サイドバーの行と D&D を作り直しているため。research.md「設計判断に効く点」3）。設計までは先に進めてよいが、design は、その作業の design（項目単位の移動・グループの見出し・グループなし）を前提にする。
- `settings-side-menu`・`subagent-display` とは、触るファイルが重なる（`Sidebar.vue` のエージェントの行）。重なる所は、後から入る方が合わせる。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 区画の折りたたみは、見出しのクリックと、見出しにフォーカスして `Enter`／`Space` で切り替わる。見出しは、開閉の状態（`aria-expanded`）を持つボタンとして読み上げに出る。
- [ ] AC-I2 確定 / 取り消し: 境目のドラッグ・D&D は、離した時点で確定する。`Esc` で取り消すと、始める前の状態に戻る（境目のドラッグは F6、D&D は F11）。
- [ ] AC-I3 キーボードだけで完結するか: サイドバーの幅・区画の高さ・区画の折りたたみは、キーボードだけで操作できる。並べ替えは、既存の操作（`move_workspace_*`・`move_tab_*`）で代替できる。
- [ ] AC-I4 フォーカスの行き先: マウスでの境目のドラッグ・D&D の後、フォーカスは始める前の所（端末）に残る（F4）。区画を畳んだとき、中にあったフォーカスはその区画の見出しへ移る。
- [ ] AC-I5 既存の操作を妨げないか: ドラッグ中のポインタの動き・キーが、端末へ漏れない。ダイアログが開いたら、境目のドラッグはその時点で確定し、D&D は取り消しになる（今ある動き。F6・F11）。区画の見出しのクリックが、並び順のボタンを押したことにならない（逆も）。

## 未確定事項 / 確認したいこと

- 像・線・境目の見た目の細部（色の濃さ・像の形）は、design で画面の見本を作って決める（利用者に見てもらう）。
- 区画の折りたたみの操作に既定のキーは付けない、とした（F23）。付けたい場合は利用者の判断。

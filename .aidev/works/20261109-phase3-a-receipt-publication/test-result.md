# A receipt publication race

C# Receiver.Receipt uses CreateNew+FileShare.Read, then writes JSON and Flush(true). The path can be observed empty/partial. Old actual receiver-armed/baseline-ready/receiver-result callbacks were evaluated against generated real files before changing runtime; all three failed with SyntaxError. This reproduces a source defect, not proof that A8's75ms-after-armed failure was exactly this cause. Timing disproves a90s timeout for that attempt. A6 remains separately unresolved.

JS-only readPublishedAReceipt now returns undefined on SyntaxError or ENOENT, allowing only the caller's existing until/expiry to retry. It is used for server-ready, receiver-armed, baseline-ready, receiver-result polls and the final cleanup result read. No new timers, waits, deadline reset, identity fallback or automatic approval/retry of a job. Fully parsed values return unchanged for original identity/proof guards; complete invalid identity still fails. EACCES/EPERM, EBUSY and other IO errors throw immediately. C#8/native3 binaries unchanged, no recompile needed.

Fixed enum failureClass: syntax_error/io_missing/io_access/io_busy/other. The final catch classifies the thrown error without persisting it. Diagnostic failureEvidence keeps receiptLastErrorClass and capped receiptTransientReads; this is a historical last read error, not an assertion of the final cause (a later timeout remains failureClass other). No raw errors, code strings, paths, identities or receipt payloads are logged. Existing stages/90s receiver wait/240s overall approval/guards/cleanup requirements unchanged; incomplete cleanup receipt remains unconfirmed rather than success.

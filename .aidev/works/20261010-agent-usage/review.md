## PR2（Claude Code のステータスラインの包み: 導入・外す・受け口）
### 独立レビュー（差分全体。実装とは別のエージェント。実際に包みを動かして）
- 判断（1 回目）: このままではマージしない。確かめられたこと: 導入 → 外すで、設定のファイルが 1 バイトも違わず戻る（16 通りの形）・包みの出力が、直接の実行とバイトまで同じ（ANSI・OSC 8・5 MB・終了コード・stderr）・設定を書くのは、押したときだけ・偽の報告でできるのは、表示の数字を偽ることだけ。
  - 止める: SIGTERM で、直接の子だけ止まり、孫（`sh -c` の下の子）が残る → 元を新しいプロセスグループで起動し、取り消しはグループへ（1 秒で SIGKILL）。
  - 直す: 横のファイルが無いと、外すが書式を整形し直す → 引数にも、元の値の文字列を入れる。CRLF の設定に、LF の行を足す → ファイルの改行に合わせる。待っているだけの Claude Code に、2 分で「届いていません」→ 検出の後に動いたものだけ・文言は「まだ報告がありません」。
- 再レビュー（差分だけ）: まだマージしない。**直しで入った退行**: 元のコマンドが 8 KiB を超えると、引数に元を載せず、包みが横のファイルへ進まないので、ステータスラインが空になる → 引数から取れなければ、横のファイルへ進む（結合と、否定の対照）。外すの信じる順を、包みと同じ（引数が先）に。空のオブジェクトの設定の戻し。
- **この最後の直しには、再々レビューを掛けていない**（1 か所の直しで、再現の結合と否定の対照つき。監督役の判断）。
- main（#135）の取り込みで、型・`sodactl agent usage` の表・文書が衝突 → 両方を残し、Claude Code と Codex の枠を、同じ表・同じ列の決まりに。

### 監督役の確認（main を #135 まで取り込んだ後。自分で）
- `pnpm build`・`pnpm typecheck`・起動確認・`handoffSmoke`・`stopSmoke`: 通る。
- `pnpm test` の全体: 10288 件中 1 件失敗（`packages/tui` の `TuiApp.subagents.test.ts`「一覧を開いている間は、経過時間が進む」。この PR は `packages/tui` に触れていない。負荷の平均 20 の中）。**そのファイルだけを 2 回流し直して、14 件すべて通る。**

### 残すこと（文書の限界に書いた）
- 包みは、ステータスラインの更新のたびに、Node を 1 回起動する（測定: 直接 1〜3 ms・包み 41〜58 ms）。
- 包み自体が SIGKILL で殺されたときは、元の子が残りうる。元のコマンドは、制御端末を持たない（`/dev/tty` を開くコマンドは動かない）。
- アカウントの鍵は、報告が言うまま（pane の中のプログラムが、別のアカウントの枠の数字を偽れる。表示だけ。ログに残す）。
- 「まだ報告がありません」は、ほかの pane の報告があると、出ない。制限は Pro・Max だけ。アイドルの間は、値が古い（`updatedAt`）。プロジェクトの設定・管理された設定が `statusLine` を上書きしていると、包みは呼ばれない。
- **実物の Claude Code では、確かめていない**（ステータスラインのコマンドの環境に `CLAUDE_PID` が入るか・stdin を閉じるか・取り消しのシグナル）。利用者が導入したときが、実物での最初の確認。

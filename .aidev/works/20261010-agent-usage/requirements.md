# 要件: エージェントの利用状況（PR1: サーバ・記録から読む・`agent.usage`・`sodactl agent usage`）

調査は `research.md`（2026-10-10。出どころつき）。全体の要件と、PR1 の範囲。PR1 は Claude Code の側まで（AC4 の Codex は次）。


### 目的
起動しているエージェントの利用状況を、Sodashitsu で見られる: セッションごと（モデル・トークン・コスト・コンテキストの使用率）と、アカウント全体（制限の枠の使用率と、リセットの時刻）。ダッシュボード（3 つ目の画面）と、pane の情報ボタン。対象は、最初は Claude Code・Codex・GitHub Copilot CLI。ほかの種類は、取り方（アダプタ）を足せる形。

### 決めたこと（監督役。調査の「決めること」への答え）
1. コストの単価の表は、製品が持たない。コストは、報告（Claude のステータスライン。PR2）か、記録の `cost-state` があるときだけ。無ければ、無い（画面は「—」）。Codex のコストは、無い。
2. Claude の記録の `cost-state`（未文書）は、使う。読めない・形が違うなら、黙って無い扱い（落ちない）。
3. （PR2）包みの控えは、横のファイルと、command の引数の両方。
4. 記録からのトークンの合計は、**「記録に残る分」**（`basis: "transcript"`）として出す。確定した累計とは言わない。`cost-state` があれば、そちらの累計（`basis: "cumulative"`）を優先し、その後の記録の分を足す。
5. （PR2）包みで `refreshInterval` は足さない。古い値は `updatedAt` で示す。
6. アカウントの鍵は、設定のフォルダの根（`CLAUDE_CONFIG_DIR`／`~/.claude`、`CODEX_HOME`／`~/.codex`）と、マシンの id から作る。画面の名前の既定は、種類の名前（同じ種類で 2 つ以上あるときだけ、根のフォルダ名を添える）。
7. （PR3）モバイルは、重ねるダイアログ。
9. サブエージェントのトークンは、pane の合計に含め、内訳（主・サブエージェント）を持つ。
10. （PR3）`view.screen` の追加に伴う一般化は、PR3 に含める。
- Copilot CLI は PR5（実機の確かめの許可を、利用者に確認中）。PR1 では、アダプタの枠が、種類を足せる形になっていればよい。

### 切り方
PR1 サーバ（記録だけ）→ PR2 ステータスラインの包み → PR3 ダッシュボード → PR4 情報ボタン → PR5 Copilot CLI。

### PR1 の完了条件
- [ ] AC1（共通の形）: 調査の 5 の `AgentUsage`・`AccountUsage` を、protocol の型に（無い項目は無い。`updatedAt`／`asOf` は必ず。`basis`・`source`）。種類ごとのアダプタの枠（`claude`・`codex`。知らない種類は、何も返さない）。
- [ ] AC2（読み口の安全。**独立点検あり**）: #126 の `SubagentTranscript.ts` の I/O（根の下の実体・通常のファイル・リンク 1 つ・`O_NOFOLLOW`・`O_NONBLOCK`・開いた fd で確かめ直す・読む量と待ちの上限・ログに場所と中身を出さない）を、共通の部品に切り出して、サブエージェントの窓と、この機能の両方が使う（**サブエージェントの窓の動きは変えない**。既存の試験が通る）。入力は pane の id だけ。場所は、サーバが決める: Claude は、フックの報告の `transcript_path`（`session` の報告にも載せる。フックのスクリプトが変わる＝導入済みは「更新が必要」）を、根の下・名前が `<会話の id>.jsonl` で確かめて使い、無ければ、根の下を、会話の id の名前で探す（上限つき）。Codex は、`fix/codex-multi-pane`（もうすぐ main に入る）の `lookupCodexRecord` があれば、それに揃える（無ければ、同じ決まりで: `sessions` の下を、新しい日付から・上限つき）。**codex-multi-pane と、同じファイル・同じ関数を、別々に作らない**（着地の順は、あちらが先。あなたは、あちらが入ったら取り込む。それまでは、Codex の記録の探索を、差し替えやすい 1 つの関数に閉じる）。
- [ ] AC3（Claude の集計。**独立点検あり**）: `assistant` の行の `usage` を、`message.id` で 1 回に数える。サブエージェントの記録（`<id>/subagents/agent-*.jsonl`）を含め、内訳を持つ。モデル（最後の主の応答）。コンテキストの使用率（最後の主の応答の `usage` から。窓の大きさが分からなければ、率は無い・トークン数だけ）。`cost-state` の最後の行（`totalCostUSD`・`modelUsage`）。**増分**（前回の位置から。初回は、分割して走査。上限 64 MiB——超えたら、末尾だけ読んで「一部」の印）。壊れた行・途中の行・巨大な行で、落ちない。サーバの主スレッドを、長く止めない（1 回の処理の上限。大きな記録は、数回に分ける）。
- [ ] AC4（Codex の集計）: 記録の末尾から、最後の `token_count`（`total_token_usage`＝累計・`last_token_usage`・`model_context_window`・`rate_limits`）と、最後の `turn_context` の `model`。制限の枠のラベルは `window_minutes` から（300→「5 時間」・10080→「週」・ほかは「N 分」）。`primary`・`secondary` の、ある方だけ。アカウント全体は、`sessions` の中で、いちばん新しい記録の、最後の `token_count`（pane との対応が無くても出る）。

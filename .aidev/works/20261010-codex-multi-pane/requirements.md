# requirements: codex-multi-pane


## 背景
Codex 0.162 は、フックを常駐の daemon の中で動かす。報告の `paneId` は、daemon を起動した pane のもので、会話を動かしている pane のものではない（#128 の調査）。#128 で、「pane に前面の codex が居て、サーバ全体で codex が 1 つだけで、cwd が一致」のときだけ受けるようにした。**2 つ以上の pane で Codex を使うと、どの pane にも参照が付かず、再起動の後、再開されない。**利用者は、同じフォルダ（`/workspaces/yukkuri-work`）で、Codex の pane を 2 つ使っている。

## 目的
Codex の pane が、いくつあっても（同じフォルダでも）、それぞれの pane の会話の参照が、正しく付き、再起動の後、`codex resume <id>` で、それぞれ再開される。**間違った pane に付けるくらいなら、付けない**（#128 の方針のまま）。

## 手がかり（監督役の案。確かめて、使えるものを組み合わせる）
1. **pane の `codex`（TUI）の引数**: 復元で `codex resume <id>` を打ち込んだ pane・利用者が `codex resume <id>` と打った pane は、前面のプロセスの引数（`/proc/<pid>/cmdline`）に、会話の id がある。サーバは、前面のジョブの引数を、すでに読んでいる（`ForegroundJob`）。**引数に id があれば、それが、その pane の会話**（daemon の報告を待たない）。`codex resume`（id なし。選ぶ画面）・`codex resume --last`・ただの `codex` は、これでは分からない。
2. **最初のターンの時刻**: `SessionStart` は、TUI の起動ではなく、**最初の入力を送ったとき**に出る（調査の事実 3）。サーバは、その瞬間に、どの pane の codex が「手が空いている → 動いている」に変わったか・どの pane に入力（Enter）が届いたかを、知っている。**報告が届いた時刻の直前（設計で決める。目安 3 秒）に、動き始めた codex の pane が、1 つだけで、cwd が一致し、まだ参照が無い（か、引数の id と矛盾しない）**なら、その pane に付ける。2 つ以上が同時なら、付けない。
3. **終了のときの画面**: TUI は、終わるとき、画面に `codex resume <thread id>` と出す（調査の案 4）。pane の画面の末尾（mirror）から、codex が居なくなった直後に拾う。kill・サーバが先に止まる、では得られないので、補助。
4. **会話の記録のファイル**: `~/.codex/sessions/YYYY/MM/DD/rollout-…-<id>.jsonl` の先頭に `cwd` と id・開始の時刻がある。**候補の検算**に使える（付けようとしている id の記録が、実在して、cwd が一致するか）。読むだけ。場所は `CODEX_HOME`（サーバの環境。無ければ `~/.codex`）の下だけ・id は UUID の形だけ・先頭の 1 行（上限つき）だけ。
5. 調査の案 2（daemon の接続と thread の突き合わせ）は、Codex の内部の API に頼るので、**使わない**。

## 完了条件
- [ ] AC1（先に確かめる）: 手がかり 1〜4 が、実物の Codex で成り立つかを確かめ、`research.md` に事実として書く（引数に id が出る形・`SessionStart` の時刻と、画面の判定の変化の時刻の差・終了の文言の正確な形・記録の先頭の形）。**実物を動かすときの決まり**: 一時の `CODEX_HOME`（認証は、読める形の複製を置き、終わったら消す）・**最初の画面を読んでから、打つ**・更新の問いには「しない」（Skip）を選ぶ・`npm -g` などの全体の置き場を変える操作はしない・会話は 1〜2 往復の短いもの・**利用者の daemon（動いているもの）には繋がない／止めない**（一時の `CODEX_HOME` なら別の daemon になる、と調査にある。そうならないなら、実物は動かさず、動いている利用者の Codex のプロセスと記録を、読むだけで）。確かめられなかった手がかりは、使わない。
- [ ] AC2: 手がかりを組み合わせて、pane ごとに、会話の参照を付ける。優先の順（引数 → 時刻の一致 → 終了の文言）と、矛盾したときの扱い（引数が最優先。時刻の一致で付けたものを、後から引数・終了の文言が打ち消したら、直す）を、設計で決めて `decisions.md` に。**付ける前に、手がかり 4 で検算**（記録が無い・cwd が違うなら、付けない）。
- [ ] AC3（取り違えない）: 同じ cwd の 2 つの Codex の pane で、(a) 片方ずつ、最初の入力を送る → それぞれに、正しい id (b) ほぼ同時（目安の窓の中）に送る → どちらにも付けない（後で、終了の文言・次の起動の引数で付く）(c) Sodashitsu の外（別の端末・VS Code）で動いた Codex の会話は、どの pane にも付かない (d) pane の codex を終えて、同じ pane で別の会話を始める → 新しい id に替わる（#128 の履歴に、前のものが残る）。結合テスト（偽の codex と、偽の daemon の報告で）。否定の対照。
- [ ] AC4（復元）: 再起動の後、参照のある Codex の pane すべてに、`codex resume <id>` が打ち込まれる。復元した直後は、引数に id があるので、参照は、そのまま保たれる（`SessionStart` が来なくても、捨てられない・替わらない）。#122・#128 の決まり（猶予・保留・一つ前へ戻す・再開の失敗）と、ぶつからない。
- [ ] AC5: Codex の pane が 1 つの場合（#128 の道）も、今までどおり。ログに、どの手がかりで付けたか（`source: argv / first-turn / exit-text`）・付けなかった理由。会話の id は、先頭 8 文字だけ。
- [ ] AC6: 文書（Codex の限界の節を、書き換える: 付く条件・付かない場合・`sodactl` の「自分の pane」が、Codex の中では別の pane を指しうる件は、**この作業の対象外**として、限界に書く）。

## 対象外
- Codex の中の `sodactl --current` が別の pane を指す件。Codex の daemon の内部の API。Claude Code の側の仕組みの変更。

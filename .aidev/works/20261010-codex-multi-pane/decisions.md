# decisions: codex-multi-pane

## D1 付ける順序と、矛盾したときの扱い（AC2）
手がかりは、その pane の会話の参照を、次の順で付ける・直す。
1. **引数（`argv`）**: 前面の `codex` の引数に `resume <UUID>` があれば、検出（`instanceId`）ごとに 1 回だけ、その pane の参照にする。`codex resume <id>` の起動は、利用者が会話を指定した（復元・手で打った）ことそのもので、daemon の報告を待たない。
2. **最初の入力の時刻（`first-turn`）**: daemon の報告（シェルの子孫でない `codex` の報告）の直前 6 秒に、最初の入力（Enter）が PTY に書かれた `codex` の pane が、cwd 一致・参照なしで **1 つだけ**のとき、その pane。報告の `paneId` は使わない（daemon を起動した pane のもので、閉じていることもある）。
3. **`sole-codex`**: 前面の `codex` がサーバ全体で 1 つだけで、cwd が一致するとき、その pane（#128 の道を残す）。
4. **終了の文言（`exit-text`）**: `codex` が居なくなった直後、画面の `To reconnect, run:`／`To continue this session, run:` の次の行の `codex resume <id>`。**これは、それまでの参照を直す**（前の参照は履歴の一つ前に積む）。
- **矛盾**: 引数が最優先（検出の時点で付く）。終了の文言は、検算を通ったものに限り、時刻の一致で付いた参照・引数の参照も直す。時刻の一致で付けた参照を、引数が後から打ち消すことは無い（引数は検出の時点）。アプリの中で `/resume` で替わった会話は、あとの終了の文言が直す。
- **検算（手がかり 4）**: 2・3・4（終了の文言）は、付ける前に会話の記録を調べる（D6 で、終了の文言も検算に改めた）。記録が無い（短い間隔で 6 回やり直す）・cwd が違う・cwd が読めない・`originator` が `codex-tui` でない・（2・4 は）確かめられない、なら付けない。引数は、検算しない（`codex` 自身が読んで起動する。無ければ `codex` が終わり、再開の失敗として#122 の仕組みが扱う）。

## D2 最初の入力の時刻は、PTY への書き込みで取る
- 実測（research.md）: Enter から報告まで約 0.4 秒。画面の判定の周期（500〜1000ms）では、報告の時点で「動き始めた」を観測していないことがある。サーバは、利用者の入力・`agent prompt` などの全てを `TerminalHost` の書き込みで通すので、**改行を含む入力が最後に書かれた時刻**（`lastSubmitAt`）を覚える。判定の変化より、正確で、取りこぼしが無い。
- 窓は 6 秒（実測 0.4 秒の 15 倍）。同じ窓に 2 つの pane の入力があれば付けない（取り違えるより、付けない）。キーを打っただけ（改行なし）は、時刻にしない。

## D3 付けられなかった報告は捨てる（保留しない）
- 入力の時刻は、報告が届いた時点で決まる（あとから変わらない）ので、保留して待つ意味が無い。付けなかった報告は、ログ（`agent report ignored`。理由・会話 id の先頭 8 文字）に残し、あとの終了の文言・次の起動の引数で付く。
- 記録の検算の再試行だけは、非同期で待つ（待つ間に pane・前面の `codex`・参照が変わっていたら付けない）。

## D4 ログ
- 付けたとき: `agent session attached`（`source`: `hook`〔シェルの子孫の報告〕・`argv`・`first-turn`・`sole-codex`・`exit-text`、会話 id の先頭 8 文字）。付けなかったとき: `agent report ignored`（理由）。

## D5 対象外・限界
- Codex の中の `sodactl --current` が別の pane を指す件（daemon の環境）。
- 付かない場合: 最初の入力がほぼ同時、`/cd` で cwd が変わった、`CODEX_HOME` が違って記録が見つからない、`codex resume`（id なし）や `--last` で始めて同時に最初の入力。あとで終了の文言・次の起動の引数で付くことがある。

## D6 独立レビューの指摘（1〜7）への対応

- **指摘 1（終了の文言の検算）**: D1 の前提「終了の文言は TUI が出したものだから検算しない」は誤り。画面には、pane の中のプログラムなら誰でも文言を出せる。終了の文言の id も、記録の実在・cwd 一致・`originator` で検算してから付ける。合わなければ付けず、直前の参照は残す（ログ `exit text not used`）。
- **指摘 2（Sodashitsu の外の Codex）**: 記録の先頭の `originator` を見る。利用者の記録 124 件の値: `codex-tui`（109。うち 3 件は `source: vscode`）・`codex_exec`（10）・`codex_cli_rs`（3）・`codex_chatgpt_android_remote`（2）。**`source` は pane の TUI でも `vscode` になる**（環境の `TERM_PROGRAM`）ので使えない。pane の TUI は `codex-tui` なので、**`codex-tui` だけを受ける**（古い版の `codex_cli_rs` は付かない。安全側）。`originator` は先頭の 480 バイト付近にあり、8 KiB の中。
- **指摘 3（記録の読み取りの守り）**: `O_NOFOLLOW | O_NONBLOCK`・`fstat` で通常のファイル（リンク 1 つ）・読みの 1 秒の時間切れ（#126 の `SubagentTranscript` と同じ作り）。日付のフォルダは、通常のディレクトリだけを新しい順に歩き、見つかったら止める（上限 400）。再試行は、最近の 3 日だけ見る（`attempt` を渡す）。
- **指摘 4（記録が無いと `sole-codex` も付かない）**: 仕様どおりの安全側。文書の限界に書いた（確かめられない〔`sessions` が無い〕ときだけ付く）。
- **指摘 5（参照のある pane）**: 参照のある pane も、最初の入力の時刻の候補にする（引数で付いた pane が `/new` で替えたとき、新しい会話に付く。前の参照は一つ前）。報告の id が、ほかの pane の今の参照と同じなら付けない。1 回の入力から出る報告は 1 つなので、報告に結んだ入力は、別の報告の候補にしない（連続して始めた 2 つの pane を、窓の中でも別々に付けるため）。報告が検出より先に届く（起動直後の `/resume`）順序は、通常の起動では起きにくい（最初の入力は検出の後）。限界に書いた。
- **指摘 6（窓）**: 窓（6 秒）の中の別の入力（`sodactl agent prompt` など）が 1 つだけあり、本物の最初の入力が窓の外、という取り違えの余地は残る（実測 0.4 秒からの推定。記録の検算・`originator`・cwd が、別の会話を除く）。限界に書いた。
- **指摘 7（確認済み）**: 閉じかけの pane・検知の揺れは、毎回数え直す・待つ間に見直す。変更なし。

## D7 再レビューの指摘（A〜E）への対応

- **A・C（検算の間の状態の変化）**: 検算（await）の前に、その pane の `{ 前面のエージェントの instanceId（無ければ null）, 今の参照の会話の id }` を控え、後で同じときだけ付ける（違えば付けず、ログ `the pane changed while the record was checked`）。終了の文言・最初の入力の時刻・1 つだけの codex の全部で同じ控えを使う。終了の文言は、終わった（消えようとしている）エージェントの instanceId を控え、後で、居ない（または同じ instanceId）で、参照が同じなときだけ付ける。
- **B（別の pane の会話が、参照のある pane に付く）**: 検算で記録の**先頭の行の `timestamp`**（会話の始まり。記録は最初のターンで作られるので、新しい会話ではその Enter の時刻に近い。実測: Enter が 0・報告が +407 ms・先頭の行の時刻が +21 ms）を読む。
  - (i) 報告の `source` が `startup`・`clear`（新しい会話）のとき: 候補の pane の最後の入力（Enter）の時刻に対し、**始まりが −2 秒〜+5 秒**のときだけ付ける（参照の有無に関わらず。読めない・入力の時刻が無い、なら付けない）。別の pane の会話は、その pane の Enter より前に始まっているので外れる。
  - (ii) `resume`・`fork`・`compact`・`source` が無い（古いフック）のとき: 前からある会話で、始まりが古いので時刻では結べない。**参照の無い pane だけ**を候補にする（前の決まりに戻す。`codex resume`〔id なし〕・`--last` が当たる）。
  - 1 つだけの codex（`sole-codex`）でも、**すでに参照のある pane を付け替えるとき**は、(i) の時刻の条件を掛ける（外の Codex の会話で上書きしない。`resume` は古いので付け替わらない）。参照の無い pane は、今までどおり（時刻を見ない。最初の入力が無い起動の形〔`codex "…"`〕でも付く）。
- **E**: 記録の探索の全体（日付のフォルダの歩きを含む）を 2 秒の時間切れで包む。時間切れは「見つからない」（確かめられない〔undefined〕にはしない。`sole-codex` を検算なしで通さないため）。
- **D**: 先頭の行が 64 KiB に収まって JSON として読めるときは、それで読む（`payload.id`・`cwd`・`originator`・行の `timestamp`）。読めない・収まらないときは、先頭の 8 KiB を正規表現で読む（今までどおり）。会話の中の文字列に釣られない。

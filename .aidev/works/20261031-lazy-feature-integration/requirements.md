# 要件（未完了の依頼を再開）

ユーザーの依頼は、統合可能な機能用の独立実行ファイルを廃止してsoda本体に取り込み、機能を有効にするまで実装を読み込まず、不要なプロセス・メモリを使わない設計にすること。単なる起動・停止の管理や、子プロセスを起動しないことだけでは完了ではない。

- sodaの配布物と内部entryに集約し、利用者が各機能用exeを探して手動配置・登録する手間をなくす。新しい独立installerを追加する方向にしない。
- 有効化時/選択した操作時だけ実装をdynamic importし生成。薄い設定・認可・保存状態の境界は先に置けるが、未使用の機能実装を常時生成しない。
- 必要なOSプロセスの分離と、別exeファイルの必要性を混同しない。権限・session・STA・PID認証・実closeまでの物理slotを保つ。
- 無効化/終了/handoff時に生成済みruntimeの停止とデータ解放を行う。未生成の機能には停止操作でimportを発生させない。
- 更新のpreflight、CLIの終了コード、既存の保存/認可/対象固定を壊さない。
- 独立最終レビューと、未有効時の実module評価0を観測する回帰を行う。生成試験で実screen/audio/input、OS service/driver/trustを操作しない。

デスクトップアシスタントと配布統合を優先。リモートデスクトップ残件、最後にsr-pc接続復旧まで継続する。macOS audio WIPは別worktreeに保全しており、完了とは扱わない。

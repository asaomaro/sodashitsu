# Native desktop implementation inventory

Baseline: `a29196e6`. This inventory covers the Windows capture/input/helper/runtime transport and the native resource, protected-worker and drag lifecycle; sign-in/boot and TypeScript transport are separate coordinated work. Phase 1 below removes the obsolete SCM broker and separates validation programs. Remaining rows explicitly identify follow-up work; this phase does not claim that all custom lifecycle machinery has been replaced.

## Comparison evidence

Read official upstream source at fixed commits; no upstream implementation has been copied:

- [R1 RustDesk portable service, 95cca3f661f635b3cc85c04935fe8d96d8f432ef](https://github.com/rustdesk/rustdesk/blob/95cca3f661f635b3cc85c04935fe8d96d8f432ef/src/server/portable_service.rs): IPC-token validation and protected shared-memory path setup (61–193, 277–336), capture recreation when the desktop changes (697–715), authenticated IPC with ping/pong and exit on channel closure or lost responses (728–815), startup timeout and runtime token ownership (908–994). This supports authenticated bounded channels and connection-scoped retirement; it does not prescribe our exact timeout values or a Windows Task.
- [R2 RustDesk Windows platform, same commit](https://github.com/rustdesk/rustdesk/blob/95cca3f661f635b3cc85c04935fe8d96d8f432ef/src/platform/windows.rs): `is_process_running_as_system` and `get_process_executable_path` (2643–2693) inspect OS tokens/process image using limited process-query access. This supports real OS peer identity checks.
- [R3 RustDesk input dispatch, 2fe026917dbdc0f715a8ce299da5eaf4e016587e](https://github.com/rustdesk/rustdesk/blob/2fe026917dbdc0f715a8ce299da5eaf4e016587e/src/server/connection.rs#L3197): mouse and key dispatch check input permission. The inspected callbacks do not condition ordinary user input on a rendered-image age. This comparison is confined to those callbacks.
- [F1 FreeRDP shadow input, fba7d19ac85f834700328ed445b8949087de6ccd](https://github.com/FreeRDP/FreeRDP/blob/fba7d19ac85f834700328ed445b8949087de6ccd/server/shadow/shadow_input.c): tracks keys per client, releases recorded keys (87 onward), and checks `mayInteract` before keyboard input (154 onward). It supports per-client held-input cleanup rather than a machine-wide permanent failure latch.
- [F2 FreeRDP cliprdr, same commit](https://github.com/FreeRDP/FreeRDP/blob/fba7d19ac85f834700328ed445b8949087de6ccd/channels/cliprdr/client/cliprdr_main.c): declares `FileGroupDescriptorW`/`FileContents` (39–40), bounds packet lengths (57–93) and negotiates streaming file clipboard capabilities (107–156). This is evidence for standard streamed-file formats, not evidence that our custom crash journal is needed.

Classifications: **standard** = an established OS/application pattern implemented for this language/runtime; **adaptor** = translation needed between Sodashitsu's existing permission/JSON/process model and that pattern; **obsolete** = remove, with phase stated; **better exception** requires demonstrated evidence. There are no claimed better exceptions.

## Phase 1 boundary and validation

Phase 1 changes no wire records, current permission defaults, active Windows process, Task/service registration or installed executable. The old stopped service is not read or held as a source fallback; deletion of the deployed registration is a separate operational action and has not been performed. Normal sharing launches no SYSTEM helper. Enabling privileged features still requires the already documented one-time administrator preparation.

Source-only Windows compilation and generated checks are pending the designated operator; Linux checks are recorded separately. Independent review is required before integration. This is not an all-clear for the follow-up rows above.

## Phase 2: ordinary resource completion and source ownership

The phase 2 snapshot removes `WindowsResourceFence`, its generated tests/validator, all Host resource epochs/fence/terminal records and the broker `SodaDesktopProtectedOutput` retirement parser/timer. Shipping and role-loading input lists no longer reference the deleted source. Host release retries its own held keys/buttons after an input failure and retains unsuccessful entries until source termination; it cannot acknowledge failed cleanup. Direct OS-desktop admission applies to normal cleanup as well as protected cleanup.

Control commands/replies carry a monotonically increasing **existing-source command sequence**, with `{type:"control",enabled,seq}` produced after release. Clipboard completion uses the existing generation; microphone stop completion uses the existing stream id (including a requested id that is already stopped). The TS counterpart must match the current physical source and exact command sequence/generation/stream id; enqueueing a stop or seeing an unmatched old completion does not permit another helper to acquire ownership. No terminal resource receipt or new UUID is introduced.

The native pointer ACK and Explorer selection request/result now contain the applied x/y/window/PID and existing selection nonce, with no epoch. Their TS consumer binds the witness to the actual source process and submitted input sequence and clears it after later input/control. A fresh helper has no old witness map. OLE/worker authority and source ownership checks remain; they are not replaced by another GUID.

WinEvent/checkpoint, routing debounce, NativeDragSlot journal and remaining shipping Memory delegates are still explicit follow-ups, not retained better exceptions.

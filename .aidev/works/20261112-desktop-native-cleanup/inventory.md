# Native desktop implementation inventory

Baseline: `a29196e6`. This inventory covers the Windows capture/input/helper/runtime transport and the native resource, protected-worker and drag lifecycle; sign-in/boot and TypeScript transport are separate coordinated work. Phase 1 below removes the obsolete SCM broker and separates validation programs. Rows record the removal phase or the retained standard/adaptor boundary; the final closure below states the current source disposition.

## Comparison evidence

Read official upstream source at fixed commits; no upstream implementation has been copied:

- [R1 RustDesk portable service, 95cca3f661f635b3cc85c04935fe8d96d8f432ef](https://github.com/rustdesk/rustdesk/blob/95cca3f661f635b3cc85c04935fe8d96d8f432ef/src/server/portable_service.rs): IPC-token validation and protected shared-memory path setup (61–193, 277–336), capture recreation when the desktop changes (697–715), authenticated IPC with ping/pong and exit on channel closure or lost responses (728–815), startup timeout and runtime token ownership (908–994). This supports authenticated bounded channels and connection-scoped retirement; it does not prescribe our exact timeout values or a Windows Task.
- [R2 RustDesk Windows platform, same commit](https://github.com/rustdesk/rustdesk/blob/95cca3f661f635b3cc85c04935fe8d96d8f432ef/src/platform/windows.rs): `is_process_running_as_system` and `get_process_executable_path` (2643–2693) inspect OS tokens/process image using limited process-query access. This supports real OS peer identity checks.
- [R3 RustDesk input dispatch, 2fe026917dbdc0f715a8ce299da5eaf4e016587e](https://github.com/rustdesk/rustdesk/blob/2fe026917dbdc0f715a8ce299da5eaf4e016587e/src/server/connection.rs#L3197): mouse and key dispatch check input permission. The inspected callbacks do not condition ordinary user input on a rendered-image age. This comparison is confined to those callbacks.
- [F1 FreeRDP shadow input, fba7d19ac85f834700328ed445b8949087de6ccd](https://github.com/FreeRDP/FreeRDP/blob/fba7d19ac85f834700328ed445b8949087de6ccd/server/shadow/shadow_input.c): tracks keys per client, releases recorded keys (87 onward), and checks `mayInteract` before keyboard input (154 onward). It supports per-client held-input cleanup rather than a machine-wide permanent failure latch.
- [F2 FreeRDP cliprdr, same commit](https://github.com/FreeRDP/FreeRDP/blob/fba7d19ac85f834700328ed445b8949087de6ccd/channels/cliprdr/client/cliprdr_main.c): declares `FileGroupDescriptorW`/`FileContents` (39–40), bounds packet lengths (57–93) and negotiates streaming file clipboard capabilities (107–156). This is evidence for standard streamed-file formats, not evidence that our custom crash journal is needed.

Classifications: **standard** = an established OS/application pattern implemented for this language/runtime; **adaptor** = translation needed between Sodashitsu's existing permission/JSON/process model and that pattern; **obsolete** = remove, with phase stated; **better exception** requires demonstrated evidence. There are no claimed better exceptions.

## Phase 1 boundary and validation

Phase 1 changes no wire records, current permission defaults, active Windows process, Task/service registration or installed executable. The old stopped service is not read or held as a source fallback; deletion of the deployed registration is a separate operational action and has not been performed. Normal sharing launches no SYSTEM helper. Enabling privileged features still requires the already documented one-time administrator preparation.

Source-only Windows compilation and generated checks are pending the designated operator; Linux checks are recorded separately. Independent review is required before integration. This is not an all-clear for the follow-up rows above.

## Phase 2: ordinary resource completion and source ownership

The phase 2 snapshot removes `WindowsResourceFence`, its generated tests/validator, all Host resource epochs/fence/terminal records and the broker `SodaDesktopProtectedOutput` retirement parser/timer. Shipping and role-loading input lists no longer reference the deleted source. Host release retries its own held keys/buttons after an input failure and retains unsuccessful entries until source termination; it cannot acknowledge failed cleanup. Direct OS-desktop admission applies to normal cleanup as well as protected cleanup.

Control commands/replies carry a monotonically increasing **existing-source command sequence**, with `{type:"control",enabled,seq}` produced after release. Clipboard completion uses the existing generation; microphone stop completion uses the existing stream id (including a requested id that is already stopped). The TS counterpart must match the current physical source and exact command sequence/generation/stream id; enqueueing a stop or seeing an unmatched old completion does not permit another helper to acquire ownership. No terminal resource receipt or new UUID is introduced.

The native pointer ACK and Explorer selection request/result now contain the applied x/y/window/PID and existing selection nonce, with no epoch. Their TS consumer binds the witness to the actual source process and submitted input sequence and clears it after later input/control. A fresh helper has no old witness map. OLE/worker authority and source ownership checks remain; they are not replaced by another GUID.

At the phase 2 boundary those items were follow-ups. Phases 3 and final slot/test-seam phase below remove all four.

## Phase 3: direct desktop admission

Removed the entire native protected observer (WinEvent hook, private atom/window, observer thread, generated marker tokens, synchronous checkpoints and observer timeout revocation), `DesktopEpoch`, `Guard`/capture tickets and Host capture/publish callback layer. The authenticated immutable worker scope still checks actual SYSTEM identity, owner/logon, session/active session, retained broker/worker PID plus creation time, lock state and input/thread desktop. The same direct `AllowedDesktop` guard is rechecked at OS input and after waiting for queued output. No epoch, replacement GUID, replacement observer or new retry/timer was introduced. As with R1's capture recreation, observing a changed source ends the current source; this implementation does not claim to prove every unobserved away-and-back transition.

Startup `SelectSource` now reads the actual session/desktop once and routes normal, secure or transition. Its 80 attempts, four-sample stability state and 25 ms sleeps are gone. The privileged worker still independently authenticates its OS source before using it.

At the phase 3 boundary, the standalone `WindowsProtectedEpoch.cs` file remained only because sign-in source/builds still consume it in their independently owned phase. All native helper/preparation/protected validator/role-loading references are removed. Its final physical deletion is assigned to the sign-in cleanup once those consumers disappear. The runtime asset entry is not removed prematurely while those consumers remain.

## Human input and media flow-control cleanup

Ordinary input may omit `expiresAt`; an explicit provided deadline is still validated. Clipboard parsing likewise tolerates an omitted deadline and enforces it when present (the current ordinary clipboard producer may still provide its bounded OS-operation deadline). Removed the duplicate six-second input/clipboard admission gates beneath the existing eight-second helper liveness watchdog. The privileged broker's separate authenticated owner lease is unchanged.

Removed protected native video publication's one-second age/reversed-age gate and its otherwise unused start timestamp: congestion at the stdout gate could terminate an otherwise live stream. Also removed the native video's 2.5-second ACK-age termination and the profile transaction's three-second age termination. The ordered one/three-frame credit queue, generation/base-sequence checks, held IDR bounds, actual codec failures, current OS source, stop state and physical source lifecycle remain. The queue is now a standard `Queue<long>` with no per-frame age records; the profile has no age field. This follows the inspected R1 capture/flow-control distinction; it is not a claim that every upstream backend has identical timing behavior.


## Final slot and release-assembly phase (source frozen for review)

`WindowsNativeDragSlot` no longer reads/writes a DPAPI journal, pins parent directories, records a prior PID, waits for a previous process, or supplies a generated recovery test. It acquires the existing per-user OS mutex with a zero-wait admission and releases it in the same synchronous STA worker scope. The worker disposes the data object, cancels the lease, disposes the pump, and finishes OLE before disposing the slot. Neither background reader nor watchdog receives the slot. The server independently retains the actual child until its close event; mutex release is not process-exit proof. Abandoned ownership is handled by the OS mutex. This is **standard** synchronization, with no better-than-upstream exception.

All six `Memory*` injection fields live exclusively in repo-only HostChecks. Their callers are compiled only with explicit `SODA_DESKTOP_TEST`; release compilation contains neither fields nor injection branches. Generated virtual-display checks likewise moved to a repo-only partial. Public helper/preparation `-ValidateOnly` remains production compilation and never requires Checks sources or defines the test symbol. Developer validators explicitly compile their test partials; no silent file-existence fallback or warning suppression is used.

Rich clipboard now accepts the caller's existing three-second request deadline and removes its independent five-second idle/sixty-second transaction lifetime. Permission generation, cancellation, clipboard sequence, bounded chunks/queue, offsets and each actual operation deadline remain. These are the existing source/OS operation contract, not a replacement transaction clock.

## Final snapshot and native lifecycle closure

The exact coordinated schema is optional `keyframe.snapshotIds` / full JPEG `info.snapshotIds`, each 1–64 UUIDs (transport snapshots 3946684d/ba23d3b6). Host retains a bounded pending set, copies it immediately before the actual OS capture, forces that requested capture to full JPEG, and puts only those capture-local IDs on its full-frame metadata. Input/keyframe invalidation or discarded preparation does not remove pending IDs. Only successful full publication retires the exact captured IDs; newer requests remain. Existing source/frame ACK flow control is unchanged. There is no new clock, epoch, hidden witness, or correlation for ordinary human frames.

The ordinary JPEG scheduler no longer rejects a prepared frame solely because it waited 200 ms for ACK. Actual input revision still invalidates pixels and current OS source/Stopping is rechecked at publication. Existing bounded one-prepared/one-unacknowledged frames, FPS pacing and explicit agent snapshot/digest permission remain.

Removed duplicate five-second heartbeat and fifteen-minute whole-job expiry from NativeDragWorker, DragLease and DragDataPump. DragLease now checks only its actual permission/cancellation and removes the unused clock callback, clock rollback state, birth time and last beat. Worker stdio EOF/write failure aborts the job; the server retains actual child close; OS authority/gesture admission and OLE completion/cancellation still govern its lifetime. The pump retains its actual five-second pending-file response budget and monotonic clock because it measures a bounded asynchronous IO operation. Worker startup, explicit gesture 750 ms, finite init/drain/cancel waits and force-exit after failed cleanup are operation budgets, not an ordinary live-job age limit. No new timer or framework was added. The existing beat packet validates the current source/scope without creating or extending a separate lifetime.

All native-owned capture/input/selection/drag, privileged Task preparation/IPC, temporary display, codec/media and user-role families have a standard/adaptor disposition in the table above. There are **zero unresolved native-owned custom-layer dispositions and zero “better” exceptions** at this source snapshot. Sign-in/Boot replacement and transport consumers belong to their separately reviewed source phases; installation migration and combined Windows validation are operational work still outstanding. This is not authorization to alter an installed service/task.

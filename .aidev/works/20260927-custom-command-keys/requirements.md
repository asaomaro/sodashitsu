# 要件: 独自コマンドのキー（herdr の `[[keys.command]]`）

## 背景 / 課題

- herdr には、設定ファイル（`config.toml`）の `[[keys.command]]` に書いたコマンドを、キー 1 つで走らせる仕組みがある
  （一次資料の確認結果は下記「herdr の挙動（一次資料）」）。lazygit を浮いた端末で開く・ビルドを裏で走らせる・
  htop を一時的な拡大 pane で開く、といった「よく使うコマンドへの 1 打」を利用者が自分で足せる。
- 本製品にはこの仕組みが無い。`docs/herdr-parity.md` の H12（ポップアップ端末・独自コマンドのキー割り当て）は
  「後続」のまま。backlog（`.aidev/backlog/product-roadmap.md:54`）に「サーバで任意のコマンドを走らせる仕組みと、
  その権限の設計が要る」とある。
- 本製品はブラウザから操作する。**ブラウザが送った文字列をサーバがシェルで実行する口**を作ると、ブラウザ側の
  不具合・なりすまし（XSS・盗まれた Cookie 等）がそのままサーバでの任意コマンドの実行になる。コマンドの中身は
  サーバの持ち主だけが書ける場所に置き、ブラウザは「どれを走らせるか」だけを選べる形にしたい。

### 利用者の決定（この work の前提。decisions.md D1）

1. **コマンドの定義はサーバ側の設定ファイルだけ**に書く（サーバの持ち主が書く。状態ディレクトリに置き、0600 を推奨、
   読み直せる）。herdr の `config.toml` と同じ位置づけ。ブラウザはコマンドを **id で呼ぶだけ**で、コマンドの文字列は
   ブラウザからサーバへ一切渡らない。
2. **キーの割り当ては既存のブラウザの設定画面（節「キー」）で行う**（ブラウザごと。既存の 34 操作と同じ仕組み。
   20260921-keybinding-customization ほか）。
3. 種類は `popup`（タブの上に浮かぶ端末。終わるまで全ての入力を受ける。幅・高さはセル数か %）・`pane`（一時的な
   拡大表示の pane。終われば閉じる。20260926-edit-scrollback の仕組みを使ってよい）・`shell`（裏で走らせる）。
   **`plugin_action` は対象外**（本製品にプラグインの仕組みが無い）→ backlog に残す。
4. 考慮すること：コマンドへの環境変数（herdr の `HERDR_ACTIVE_PANE_ID` に当たる `WTM_ACTIVE_PANE_ID`・作業場所）、
   名前付き session（session ごとの状態ディレクトリの設定）、Windows。
5. 安全：設定を厳しく検証する（形・大きさの上限）、呼び出しの要求は認証済みのクライアントだけ、id を検証する、
   注入をさせない（コマンドの文字列は持ち主が書いたとおりにシェルへ渡す——それは意図どおり——が、ブラウザから来た
   値をそこへ差し込まない）。
6. popup の UI は相互作用の受け入れ基準（AC-I1〜AC-I5）を持つ。
7. 追加の機能は backlog の `[ ]` 行に回す。

## 目的 / ゴール

- サーバの持ち主が、サーバの状態ディレクトリの設定ファイルに書いたコマンドを、ブラウザから設定画面で割り当てたキー
  1 つで popup・一時的な拡大 pane・裏での実行のいずれかとして走らせられる状態。
- ブラウザから送られた値がコマンドの文字列に混ざる経路が無く、設定ファイルが壊れていても・（Unix で）他人が書き換えられる
  状態でも、サーバが知らないコマンドを走らせない状態。
- 利用者が、独自コマンドのキーを既存の設定画面の節「キー」で他の操作と同じ手順で割り当て・確認できる状態。
- `docs/herdr-parity.md` の H12 が実態（対応したこと・herdr との違い）に合っている状態。

（`.aidev/charter.md` はこの PJ に無いので、charter ゴールへの紐づけは省く。）

## ユーザーストーリー

- US1: ブラウザで作業する開発者として、lazygit のような対話的なツールを、今の tab のレイアウトを崩さずに浮いた
  端末でさっと開き、終えたら元の画面に戻りたい。なぜなら pane を分割・拡大して開くと、戻すたびにレイアウトの
  操作が要るから。（受け入れ: AC4, AC5, AC6, AC-I1〜AC-I5）
- US2: 同じ開発者として、ビルドやテストのような「結果は別の場所で見る」コマンドを、キー 1 つで裏で走らせたい。
  なぜなら毎回 pane に打ち込むのは手間で、画面も散らかるから。（受け入れ: AC7）
- US3: 同じ開発者として、htop のような全画面のツールを一時的な拡大 pane で開き、終えたら元の pane と拡大表示の
  状態に戻りたい。なぜなら scrollback の編集（`prefix+e`）と同じ感覚で使いたいから。（受け入れ: AC8）
- US4: サーバの運用者として、サーバで走るコマンドは自分が設定ファイルに書いたものだけであってほしい。なぜなら
  ブラウザ（別の機器・別の人の手元にありうる）から任意の文字列を実行できる口は、Cookie の盗難や画面の不具合が
  そのままサーバの乗っ取りになるから。（受け入れ: AC1, AC2, AC3, AC9, AC10, AC11）
- US5: キー割り当てを自分用に変えている利用者として、独自コマンドのキーも既存の設定画面で割り当て、キー一覧で
  確かめたい。なぜなら操作ごとに設定の場所が違うと覚えられないから。（受け入れ: AC12, AC13, AC14）
- US6: herdr から移ってきた利用者として、herdr の `[[keys.command]]` と同じ考え方（種類・大きさの書き方・環境変数）で
  書きたい。なぜなら覚え直しを少なくしたいから。（受け入れ: AC1, AC15, AC16）

## スコープ

### 対象

- サーバの状態ディレクトリ（名前付き session ではその session の状態ディレクトリ）に置く独自コマンドの設定ファイル
  の読み込み・厳しい検証・読み直し。
- ブラウザがコマンドの一覧（コマンドの文字列を含まない）を受け取り、id で走らせる要求。読み直しの要求。
- 種類 `popup`・`pane`・`shell` の実行。コマンドへの環境変数と作業場所。
- popup の画面（浮いた端末・閉じる手段）。
- 設定画面の節「キー」への独自コマンドの行の追加（割り当ての追加・変更・削除）、キー一覧（`prefix+?`）への表示、
  キーを押したときの実行。
- `reload_config`（`prefix+shift+r`）で、ブラウザの設定に加えて独自コマンドの設定も読み直す。
- docs（`docs/herdr-parity.md` の H12、利用者向けの設定ファイルの説明）と backlog の更新。

### 対象外

- `plugin_action`（本製品にプラグインの仕組みが無い）→ backlog。
- 設定ファイルにキーを書くこと（キーはブラウザごとの設定画面で割り当てる。利用者の決定 2）。設定ファイルに
  「既定のキー」を書ける拡張 → backlog。
- ブラウザの設定画面からコマンドの定義を書く・変える（利用者の決定 1。コマンドの文字列はブラウザから渡さない）。
- popup を他のブラウザ（同じ session を開いている別の画面）にも出す・切断や再読み込みをまたいで popup を保つ・
  ウィンドウの大きさの変化に popup の端末の大きさを追従させる → backlog。
- 外部操作の CLI（`wtmctl`）から独自コマンドを走らせるサブコマンド（要求としては使える）→ backlog。
- 更新時の引き継ぎ（`wtm handoff`）で popup・`pane` 種のコマンドの「閉じたら戻す」対応を引き継ぐこと → backlog
  （`pane` 種の pane 自体は普通の pane として引き継がれる）。
- 設定ファイルの変更を監視して自動で読み直すこと（読み直しは明示の操作）→ backlog。
- 選択中の文字列をコマンドへ渡す（herdr の plugin_action の selection）。

## 機能要件

- F1: 設定ファイルは状態ディレクトリの 1 つの JSON のファイル（依存を増やさずに厳しく検証できる形。名前は design で決める）。サーバの起動時に読み、ブラウザからの読み直しの要求
  （`reload_config` から送る）で読み直す。ファイルが無ければ独自コマンドは 0 件（エラーではない）。
- F2: 1 件のコマンドは、id（持ち主が付ける。ブラウザのキー割り当てを保存するときの鍵になるので、読み直しても
  変わらない）・種類・コマンドの文字列・任意の説明・popup だけ幅と高さ、からなる。
- F3: 検証は厳しく行い、1 つでも規則に合わない所があれば**ファイル全体を採らない**（独自コマンドは 0 件とし、
  理由をサーバのログと一覧の応答に出す。読み直しでは直前に採っていた一覧を捨てる）。規則：大きさの上限・件数の
  上限・文字列の長さの上限・知らない項目の拒否・id の文字の規則と重複の拒否・種類は 3 つのどれか・幅と高さの範囲・
  popup 以外への幅と高さの拒否・空のコマンドの拒否・制御文字（改行を除く）を含むコマンドの拒否・JSON として読めないファイルの拒否。
- F4: Unix では、設定ファイルがシンボリックリンク・通常のファイルでない・サーバを動かしているユーザー以外の持ち物・
  グループかその他が書き込める、のいずれかなら採らない（他人がコマンドを差し込めるため）。Windows ではこの持ち主・権限の検査をしない（ACL を読む手段が
  依存無しには無い。状態ディレクトリが利用者ごとの `%LOCALAPPDATA%` の下にあることに頼る。docs に書く）。
- F5: ブラウザに渡す一覧には、id・種類・説明・（popup の）幅と高さだけを入れ、コマンドの文字列を入れない。
- F6: 走らせる要求は、コマンドの id と、そのブラウザでフォーカス中の pane の id（と popup では端末の大きさ。pane の領域の大きさを
  知っているのはブラウザなので、幅・高さの指定から端末の列数・行数を決めるのはブラウザ）だけを受け取る。それ以外の項目は取り除かれ
  使われない（既存の要求と同じ）。サーバはその id の定義から文字列を取り、ブラウザから来た値をコマンドの文字列に差し込まない。
  知らない id は失敗。要求は認証済みの WebSocket の接続でだけ受ける（既存の仕組み）。
- F7: コマンドは Unix では `/bin/sh -c`（`shell` は herdr と同じくログインシェルの `-lc`）、Windows では `%ComSpec%`
  （無ければ `cmd.exe`）の `/d /c` に文字列をそのまま渡して走らせる。
- F8: コマンドの環境は、pane と同じサーバの環境（`WTMCTL_TOKEN` 等を落としたもの）に、`WTM_ACTIVE_WORKSPACE_ID`・
  `WTM_ACTIVE_TAB_ID`・`WTM_ACTIVE_PANE_ID`・`WTM_ACTIVE_PANE_CWD`・`WTM_COMMAND_ID` を足したもの。作業場所は
  フォーカス中の pane の場所（ディレクトリとして在れば。無ければサーバの既定の場所）。`WTMCTL_URL`・`WTMCTL_TOKEN` は入れない。`pane` 種の pane はその pane の
  `WTM_PANE_ID` を持ち、`popup`・`shell` は `WTM_PANE_ID` を持たない（herdr と同じ）。
- F9: `popup`：そのブラウザの画面に、tab のレイアウトを変えずに浮いた端末を開く。大きさは幅・高さ（省略は半分・
  数はセル・`"80%"` は pane の領域の割合）。開いている間はその端末が全てのキー入力を受け、コマンドが終わると閉じる。
  1 つのブラウザで同時に 1 つだけ。画面の閉じるボタン（マウス）でも閉じられる（コマンドを止める）。popup を開いたブラウザが
  切断したら、サーバが止まるときも、その popup のコマンドを止める。popup はセッションの保存に入らない。popup を求められるのはブラウザの接続だけ（`wtmctl` 等の外部の接続からは
  失敗させる。見せる画面が無いため）。コマンドが 0 以外の終了コードで終わったら（起動できなかった等）、閉じた後にトーストで
  終了コードを知らせる。開くと popup の端末へ
  フォーカスが移り、閉じると開く前の pane へ戻る。popup の上のホイールは popup の端末にだけ効く。
- F10: `pane`：フォーカス中の pane を分割した新しい pane でコマンドを走らせ、拡大表示にして焦点を移す。コマンドが
  終わる（か pane を閉じる）と pane が閉じ、焦点と拡大表示の状態が開く前に戻る（scrollback の編集と同じ）。
- F11: `shell`：入出力を捨てて裏で走らせる。サーバは結果を待たない。同時に走る数に上限を置く。
- F12: 失敗（知らない id・起動できない・popup が既に開いている等）はブラウザにトーストで知らせる。成功した `shell` は
  短いトーストで「走らせた」ことを知らせる。
- F13: 設定画面の節「キー」に群「独自コマンド」を足し、各コマンドを 1 行（名前は説明、無ければ id）として、既存の操作と
  同じ手順で prefix の後・直接のキーを追加・変更・削除できる。既定のキーは無い。保存はブラウザごと。一覧に無い
  （設定ファイルから消えた）コマンドの割り当ては保存に残すが効かない。独自コマンドが 0 件なら群は出さず、設定ファイルの
  置き場所の案内を出す。
- F14: キー一覧（`prefix+?`）に、割り当てのある独自コマンドを群「独自コマンド」として出す。
- F15: `reload_config` は、今の働き（ブラウザの設定の読み直し）に加え、サーバに独自コマンドの読み直しを求め、
  結果を全てのブラウザの一覧に反映する。設定ファイルに問題があればトーストで知らせる。

## 非機能要件 / 制約

- 安全：コマンドの文字列はサーバの設定ファイルだけから来る。ブラウザから受け取るのは id（規則で検証）・pane の id・
  popup の端末の大きさ（整数の範囲で検証）だけで、どれもコマンドの文字列・引数に入らない（環境変数の値に入るのは
  サーバのモデルから引いた値だけ）。要求は認証済みの WebSocket でだけ受ける（既存の仕組み）。
- 互換：既存の要求・イベントの形を変えない（足すだけ）。既存のキー割り当て・保存の形（`wtm.prefs.v1` の `keys`）を
  壊さない——独自コマンドの割り当ては別の項目として足す。
- 並行作業：他の work（sidebar-row-tokens・multi-host-machines）が同じ `packages/web`・`packages/server` を触りうるので、
  差分は追加に寄せる。
- 検証は vitest・`pnpm -s typecheck`・`pnpm -s build`・`aidev smoke`。E2E（playwright）と負荷の試験は走らせない
  （利用者の方針）。
- プロジェクト規約：足した挙動には回帰テストを書き、足した箇所を 1 つずつ壊してテストが落ちることを確かめる
  （`.aidev/conventions/regression-negative-control.md`）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 状態ディレクトリの設定ファイルに書いた独自コマンド（id・種類・コマンド・説明・popup の幅と高さ）が、サーバの起動時に
  読み込まれ、ブラウザへの一覧に id・種類・説明・幅と高さだけが載り、コマンドの文字列は載らない。名前付き session ではその
  session の状態ディレクトリのファイルを読む。ファイルが無ければ 0 件で、エラーにならない。
- [ ] AC2: F3 の規則のどれか 1 つに反するファイル（読み直しで採られなかった場合は、直前に採っていた一覧も捨てる）（大きすぎる・件数が多すぎる・長すぎる・知らない項目・id の規則違反や重複・
  知らない種類・幅高さの範囲外・popup 以外の幅高さ・空のコマンド・制御文字・JSON として読めない）は全体が採られず、独自コマンドは
  0 件になり、理由（どの項目か。コマンドの文字列は含めない）がサーバのログと一覧の応答に出る。
- [ ] AC3: Unix で、設定ファイルがシンボリックリンク・通常のファイルでない・別のユーザーの持ち物・グループかその他が書き込める
  のいずれかなら採られない（AC2 と同じ扱い）。
- [ ] AC4: `popup` のコマンドのキーを押すと、そのブラウザの画面に tab のレイアウトを変えない浮いた端末が開き、コマンドがその
  端末で動く（出力が見え、入力が届く）。大きさは幅・高さの指定（省略は pane の領域の半分・数はセル・% は割合）に従う。
- [ ] AC5: popup のコマンドが終わると popup が閉じる。閉じるボタンで閉じるとコマンドが止まる。popup を開いたブラウザが切断すると
  コマンドが止まる。サーバの停止でも止まる。popup はセッションの保存に入らない。
- [ ] AC6: 1 つのブラウザで popup が開いている間に別の popup のコマンドを走らせると失敗し、トーストが出る（2 つ目は開かない）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

popup（浮いた端末）について。

- [ ] AC-I1 開く / 閉じる: popup のコマンドに割り当てたキー（設定画面で割り当てたもの）で開く。コマンドの終了、または popup の見出しの
  閉じるボタン（マウス）で閉じる。コマンドが 0 以外の終了コードで終わったら（起動できなかった等）トーストで知らせる。閉じるとコマンドは止まり、popup の中身は残らない（次に開くと新しく走る）。
- [ ] AC-I2 確定 / 取り消し: 確定の操作は無い（端末なので、入力はそのままコマンドへ届く）。取り消しに当たるのは閉じるボタン（コマンドを
  止める）。Esc は popup の中のコマンドへ届き、popup を閉じない（herdr と同じ）。
- [ ] AC-I3 キーボードだけで完結するか: 開く（割り当てたキー）→ 使う（端末へ入力）→ 閉じる（コマンドを終える。例: lazygit の `q`・
  シェルの `exit`）をマウス無しで通せる。Tab・Shift+Tab も端末へ届くので、キーボードで閉じるボタンへは移らない（閉じるボタンは
  マウス用の逃げ道。キーボードではコマンドの終了で閉じる。herdr と同じ）。
- [ ] AC-I4 フォーカスの行き先: 開くと popup の端末へフォーカスが移り、閉じると開く前にフォーカスしていた pane の端末へ戻る。
- [ ] AC-I5 既存の操作を妨げないか: popup が開いている間、キー（prefix・直接のキー・Esc を含む）は popup の端末にだけ届き、下の pane・
  prefix・既存の操作・ブラウザのダイアログへ漏れない。popup の上のホイールは popup の端末のスクロールにだけ効き、下の pane へ漏れない。
  下の pane の表示・出力は popup の間も続く（レイアウトは変わらない）。

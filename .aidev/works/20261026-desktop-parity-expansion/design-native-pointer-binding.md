# Native pointer and release binding

An input ACK measures successful injection, not Explorer selection processing. The future selection worker must still validate current normal desktop/user, physical point, foreground window/process, stable selected filesystem items and locally approved file-root snapshots. No browser field or transport/render ACK establishes this proof.

The Windows helper opts into nativePointerProof only for a normal non-virtual resource-managed source. A successful newly inserted LMB down with no other held key/button captures physical coordinates using the existing AbsolutePointer pixel calculation, root window/PID from WindowFromPoint/GetAncestor and the current control resource epoch. Duplicate down/up/move, failed/expired input, disabled/secure/virtual/unmanaged/modifier/invalid targets cannot create proof. Seq admission, native input and immutable witness capture share Gate; all ACK IO stays outside it. UTC is read after acquiring Gate.

Structured helper ACKs and a bounded private ASCII prefix carry metadata. DesktopInputAcks retains64 submitted input slots, distinguishes live down/cancelled down/other inputs, validates negotiated witness schema, and invokes the private witness callback before its normal ACK callback. Cancellation removes pointer authority while preserving the normal input receipt. B retains a witness only for the same physical resource channel, current owner/control epoch and newest accepted input sequence. Metadata is stripped before public viewer ACK/ready messages.

Shared capture rewrites physical sequence numbers back to the submitting member only. Other viewers and late ACKs cannot acquire proof through matching local counters. Any input attempt, release, control change or stop invalidates pending candidates and stored metadata synchronously. A's rejected-input paths send native_pointer_cancel to B, which invalidates metadata without forwarding anything to the OS helper. B performs the same invalidation before its own input eligibility checks; sealed input therefore has the same B-side fence.

releaseConfirmed resolves id+original control epoch only after the exact physical helper cleanup ACK AND successful enqueue/send return. A synchronous ACK followed by failed send/throw/dispose cannot release the next owner or resolve success. Timeout, source death without terminal cleanup proof, clock reversal/exception and disposal reject pending completion. Normal release remains fire-and-forget for existing callers. The future native file operation must bind its gesture and source to this receipt and recheck share/file authority after completion.

Current scope is input binding only. No public native file request, B selection executable adapter, local gateway, manual/managed helper command, real Explorer drop or new UI is connected by this phase. Native/Linux/macOS platform configure does not receive Windows-only witness options.

Primary references read: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput and https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-windowfrompoint . Microsoft documents inserted input events; it does not promise target application processing or selection completion.

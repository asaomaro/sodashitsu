# Browser-PC native helper gateway

This phase implements the browser-PC native process host, loopback gateway, managed discovery RPC and reusable browser bridge. Remote desktop gesture/controller integration, manual CLI command and actual Explorer target operation remain for the next phase. Splitting these avoids combining their additional UI/CLI files with this security/state/protocol change. Old-version compatibility is not required by the user.

A managed helper is a separate fixed Node child. Its parent IPC transports only a descriptor and stop request; no file bytes, secret, arbitrary command or source path. Only a direct authenticated WebSocket's admitted browserOrigin can start it; a bridge or sameMachine claim alone cannot. owner/client and viewer UUID scope cleanup, maximum8 children per server/2 per owner, duplicate ready rejection and actual retained-child close prevent ownership loss. A spawned child remains owned if authentication throws or its owner leaves during fork. It is never replaced before close; shutdown sends stop and retains a finite60s force-kill timer for that exact child.

Before browser proof the child only serves a random exact-Host IPv4 loopback page. It expires unclaimed after30s and compiles no Windows code. The page allows one MessagePort from the exact parent window, origin and helper id, then opens its own-origin WebSocket and consumes a constant-time-checked one-use secret. Secret exists only in fixed no-store local HTML, not the URL, descriptor or public RPC. Host/origin/address/path limits, strict JSON/UTF8, bounded messages and no CORS prevent the public relay from serving this proof for a different browser PC. A remote/helper locator alone is not co-location proof.

The browser bridge loads only the admitted random localhost origin, matches the actual iframe WindowProxy/origin/id, and retains the authenticated MessagePort. Initial local frame proof expires3s; fixed compile/preflight readiness expires60s. A1s heartbeat and local5s response deadline close lost connections, including silent port loss. Local helper Host expiry propagates through Gateway.done and ends the managed child; keeping a WS open does not renew5s idle or15m absolute lifetime. Preparation is an owned promise; shutdown waits it, a host returned after reentrant shutdown is closed before binary cleanup, and factory exceptions cannot leave a late host.

Fixed trusted launch paths compile only packaged native sources in a new current-user protected directory. COPY and B selection use exact preflight arguments that return before any desktop/input/slot/OLE call. Preflight completes before a binary becomes available. This warms first execution without extending a gesture. No-input short-lived commands may close their unused stdin early; submitted private request bytes still require successful I/O. Both paths require bounded output, final monotonic deadline and normal process exit. Cleanup removes only retained-identity generated binaries and empty directories, never arbitrary recursive paths.

The helper arm timestamps the original gesture before B selection/cleanup. Native ready reports its process clock, sampled before the host receives it; the host adds only remaining original750ms minus10ms. The C# final admission and startup watchdog enforce that absolute native deadline as well as the original per-begin bound. The Node host validates metadata totals before spawn, binds nonce/request/index/offset/length, retains at most16 pending reads/4096 registered request ids and bounds pipe queues. C# Pump reuses one UUID per file across contiguous chunks: the host permits exactly index/nextOffset progression, rejects concurrent duplicates/gaps/reuse after end. The later browser controller must allocate a fresh B native_read request UUID for each chunk, preserving the C# correlation id separately; B rejects replayed read UUIDs.

A host retains its native process until actual close even after abort. finished alone is insufficient; COPY success requires finished plus clean output, matching live job, no cancellation, exit0 and no signal. Reentrant cancellation from running/read callbacks is checked before every subsequent stdout record. Existing Windows user/PC native slot remains a separate exact Windows process-exit fence across helper instances, including WSL interoperability. Native worker teardown or idle failure never claims a saved destination or deletes source/target files. The actual RDP plain/sealed browser-controller byte path and actual OLE destinations are not proven by this phase's isolated bridge tests.

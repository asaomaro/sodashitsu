# Independent Windows monitor capture/encoding

Current Windows normal desktop only. User does not require old-code compatibility, so new independent mode requires current relay/provider/helper capability and explicit independentMonitors proof; no legacy fallback or permission inheritance. Existing single/cohort mode remains available. No real OS capture/input/audio/clipboard operation during generated tests; actual multi-device verification remains separate.

## Sources and windows

Add independentMonitors start/feature capability. Require sharedDesktop/sharedMonitors/monitors, local allowMonitors, explicit monitorDevice (single monitor ID or all discovery view); forbid protected/virtual/display resize/nativePlatform combinations. Provider permits up to8 viewers and at most8 live-or-retiring physical helpers. Recheck the physical budget atomically immediately before spawn, so pending relay sockets cannot exceed the bound. Map by requested monitor ID; same-monitor viewers must match the complete fixed capture/cohort options, different monitors may use distinct quality/native settings. Each physical monitor cohort has its own DesktopSharedCapture/native encoder/ACK/backpressure; all discovery is an intentional separate aggregate cohort, not the source for single-monitor windows. No capture or encoder object is reused across monitor IDs. Retiring helpers count until actual child close.

UI explicit independent mode reconnects with all for initial discovery when no ID is chosen. New monitor windows carry only machine/label/ID/settings/mode, never grants or credentials; connect directly to that monitor and do not crop an aggregate. Normal auth/E2E/new input/clipboard/mic consent applies. Each window can set its own capture settings; same-monitor cohort still requires matching settings. Topology fingerprint (all monitor IDs/physical bounds/primary/scale, excluding selected bounds) must match across sources; mismatch/change stops all independent sources and invalidates old coordinates.

## One PC-wide interactive owner

Independent helpers target the same OS global keyboard, clipboard and microphone. Introduce one provider-wide owner PER resource (member+source identity): control, clipboard and microphone. Different windows may own different resources, preserving existing clipboard/microphone use while switching monitor input. A new owner of a resource waits for that resource's cleanup ACK. Audio reception/files/viewing are independent. A busy grant is denied, never steals the previous window or implicitly enables consent elsewhere.

All DesktopProvider interactive entry points (human WS, private endpoint/agent recipient, existing single/cohort and independent mode) use the SAME provider-wide resource arbiter and fault latch. A physical DesktopResourceChannel wraps every spawned helper and strips/validates private native cleanup ACKs before existing raw/shared consumers; shared virtual subscriptions retain the underlying physical channel identity. No mode or endpoint bypasses the resource gate. Local member/control/mic/clipboard flags and routes are revoked before dropping the final resource. On resource release/detach, send a unique private resource_fence UUID to the SAME physical helper after queued old work. Reject new input/clipboard/mic commands during cleanup. A matching source+UUID resource_fence_ack alone returns owner to idle. Viewer messages cannot carry these private commands/ACKs. Duplicates/stale/foreign ACKs never release a new owner. Last subscriber retirement waits for fence completion before ending helper stdin, so cleanup output is not discarded.

Native config resourceFences=true is requested for all helpers and ready proof is mandatory before any interactive grant. Unsupported helpers remain view-only; no legacy interaction fallback. DesktopResourceChannel defers physical stdin end while a cleanup fence is pending; its private ACK parser continues after viewer/shared-subscriber teardown, so ACK cannot be lost. Existing forced-shutdown grace is extended only for pending cleanup (bounded6s vs fence5s). Control/release in this mode use strict key/button release: success means SendInput succeeded for every remotely held token and input desktop authority is still current for every held key/button up. Failure latches and never produces a success ACK. resource_fence serializes with fast input/control queue, sets Control=false, strictly releases all held keys/buttons, revokes clipboard generation and joins/disposes rich clipboard worker, stops microphone input worker, checks input-desktop authority before every held key/button up; clipboard/mic cleanup needs no capture freshness, and known-neutral cleanup may ACK even after topology changes. Each fence affects only its requested resource. On final process cleanup, terminal ACKs name the current per-resource ownership epochs and freeze future writes; matching terminal proof plus process close can retire an owner. System audio reception is not an interactive grant and continues. No best-effort Release may erase failed held state and then allow an ACK; strict-mode failure must remain terminal even through later cleanup.

The affected resource remains blocked while its fence is pending. At5s timeout/malformed proof/helper death before ACK, latch a provider-wide interactive fault, revoke sessions and stop all desktop sources. Never treat process exit alone as released key evidence. Do not automatically reset fault on viewer reconnect, mode toggle or agent/endpoint entry. Reject all new desktop starts under fault; only a new provider/server generation clears it (ordinary configure/mode toggles preserve the fault), with an operator-facing error. Existing non-independent/independent modes also remain admission-exclusive until live+retiring helpers from the prior mode drain, even though both use the same arbiter. This is conservative failure behavior, not a claim that failed OS input can be proven released. A lock/desktop change may therefore require source-side recovery. No automatic retries or elevation are added.

# End-to-end encrypted agent recipient: public integration

Complete the E2E agent route using the protected CLI identity, recipient/scope-bound AgentAccess and provider-private backplane. Existing plaintext session/mcp/model remains opt-in by legacy43-character grants; encrypted grant prefix never falls back or enters Root RPC.

## Provider and opaque Root

- Add endpointAgent hint bit4 to existing128-bit feature mask. Old implementations ignore unknown bits. Only a new viewer advertising this hint receives sealed agent_endpoint_available with B-approved agent fingerprints/labels (role agent only). No plaintext Root peer enumeration. New Web hides encrypted agent UI until this response; old B gets no unsupported requests.
- New strict sealed viewer messages agent_endpoint_grant(enabled, recipient when enabled) and agent_endpoint_peers. Service intercepts only on primary viewer contexts with negotiated hint, open private root and correct agent lane/kind1; never forwards these into legacy parser. Unsupported/malformed packets close; unauthorized recipient returns a sanitized sealed error and keeps viewing. Per-context at most one pending credential/list operation and at most one start per second; cancellation bypasses busy/rate guard, increments grant revision synchronously and revokes the existing root grant. Pending old work cannot mint/revoke a newer grant.
- Grant uses the actual store.endpoint(fp,agent) permit and combines its revision-active closure with viewer/source/process lifetime and grant revision. Await all credential/public fingerprint work BEFORE synchronous root.grantAgent. Recheck lifetime after awaits. Context stores one hashed-ticket metadata record: scope, recipient, permit, grant revision and monotonic expiry<=30s. Replace/revoke/close deletes it. Only up to8 viewer contexts -> bounded lookup.
- Grant code prefix soda-e2e-agent-v1. + canonical base64url strict JSON: version1, machineId, canonical Root HTTP(S)/loopback origin, provider public fingerprint, recipient fingerprint, opaque private scope, one-use ticket, expiresAt. No cookie/private route/session ID or key. Code only leaves B through sealed viewer response.
- Root DesktopEndpointRelay currently explicitly restricts hello.role viewer. Permit agent roots only when no parent/attachment/binding; agent cannot open viewer children. Root remains opaque and authenticates normal Root session/origin. Provider Service role branch uses Store.endpoint(fp,agent), source/process epoch and existing quotas, maximum8 agent roots; no capture/start/children/private viewer root created by an agent. Trust alone gives only handshake. Initial attach must arrive within monotonic10s after handshake (timer plus checks).
- Agent application records: kind1 on agent lane only, strict bounded finite RPC envelopes. First method attach with ticket+scope. Look up hashed-ticket metadata, compare recipient, exact public machine and relay origin against grant's viewer context, scope, TTL, active permit/revision/viewer epoch BEFORE consuming. Create plane.agent(fp,scope,active) and pass only original strict ticket params to its private RPC. Later observe/act/release only; no general RPC, no clipboard/file/audio/mic/capture-start. Clone borrowed record data before awaits. Wrong scope/recipient cannot consume the rightful grant. Attach success removes metadata; lease remains bound to permit/viewer owner.
- B agent trust revoke/retrust closes matching agent contexts and revokes matching viewer grants immediately; viewer/source/topology/handoff/root close also cancel pending observations/actions. Node-local onOwnerRevoked cancels pending operations. Agent disconnect releases its lease/input while leaving the human viewer alive.
- Extend internal close reason released/stopped so release can seal its finite response before authenticated EOF/drain; revocations remain immediate. Reject new app packets during ending. Final response and terminal ACK use existing ordered Wire/drain semantics.

## CLI and Web

- Browser-safe grant codec in client-core/protocol validates prefix/size/canonical base64url/strict fields/canonical safe origin. No secret in logs/errors. Receiving a code is not trusting its embedded provider fingerprint.
- CLI session/mcp/model add --endpoint-fingerprint and --identity-dir. Encrypted prefix requires independent explicit64hex provider pin, matching code origin/--url and recipient/local initialized identity fingerprint, all checked before authentication/routing. Missing key/pin or expired/invalid code fails closed. Initialize is never implicit. These flags with a legacy grant reject to avoid suggesting encryption where none is used.
- Node transport restores local protected identity with DesktopEndpointStore, owns it for one CLI process scope and closes/settles on all exits. CLI exposes no rotate/trust/policy mutations; parallel initialize preserves the same key. active() combines store permit and CLI abort epoch; it is not a filesystem/process watcher. Manual external key-file edits are not an instant revocation mechanism: use B peer revoke or terminate the CLI. No new global stale lock scheme.
- Only normal Root cookie authenticates /desktop-e2e (read cache or login); no /ws or desktop.agent.* Root plaintext RPC for encrypted sessions. Retry a cached-cookie HTTP401 only before handshake/application/attach; never retry uncertain act. Bind login/connecting transport cancellation to SIGINT/SIGTERM and bounded shutdown. Do not leak grant/pin/lease/input/image in Root-readable JSON, query/header or fallback.
- Node Wire role agent/provider, independent provider pin, normal ordered/rekeyed encryption, strict lane/kind/response schema and one pending RPC, finite sizes/IDs/timeouts/monotonic deadlines, structured server_busy for observe. Store/wire/socket/timers close on errors. No automatic action replay. Support authenticated EOF after final release response.
- Extract a structural DesktopAgentConnection interface so existing DesktopAgentSession and new encrypted session share NDJSON/MCP/model runner. Existing model screenshot waits retain server_busy code; uncertain act closes. Model still requires explicit OPENAI_API_KEY and existing approval behavior; screenshot leaves for model only when that command is invoked.
- Web encrypted agent section appears only with sealed feature proof, selects a B-approved fingerprint, refreshes candidates and sends grant/cancel. Displays encrypted prefixed code, not legacy ticket; never auto-trusts or auto-initializes CLI keys. Old/un-encrypted UI remains compatible. Reset on reconnect/revoke/topology and keep raw Ctrl+Space unchanged.

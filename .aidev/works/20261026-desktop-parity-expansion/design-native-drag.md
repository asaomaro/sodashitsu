# Native Explorer drag — implementation plan

Implement remote Windows Explorer selection → local Windows Explorer copy through a native OLE source. The current browser DownloadURL tile remains an explicitly separate experimental path. A browser alone cannot provide the Windows IDataObject lifecycle; a browser-PC helper is required. Reuse the existing short-lived localhost iframe proof to establish that the helper is on the browser PC; a server hostname/IP is not proof. The helper is optional, visibly enabled, owner/origin/share/generation bound, and is never started on a different remote machine as a substitute.

## Data and authority

Use the existing separate file grant and locally approved fileRoot. Normal Windows only: no protected/signin/virtual/native Linux/Mac mode. A capture/control grant alone cannot read Explorer files. Remote selection metadata is obtained through a fixed trusted helper action, not arbitrary client paths: selected non-elevated Explorer list item under the current remote pointer, current console/default desktop, foreground window/PID/current user, selected filesystem entries, finite count/bytes. Reject non-filesystem, outside-root, symlink/reparse/hardlink, changed file/parent/selection and unsupported names. No arbitrary Shell execution or command. Selection offers are opaque short-lived tickets, bound to that file grant and input sequence, and are invalidated by disconnect/revoke/source change. Full source identities/SHA and bounded positional chunk reads use existing safe file primitives.

The viewer opts into native drag. On an eligible held pointer gesture, delay forwarding movement until selection eligibility is known; this avoids moving remote files before the local native drag starts. Release remote buttons before handing over through a new correlated drag-release receipt: ordinary viewer release is fire-and-forget and is NOT proof. Bind the request/receipt to gesture UUID and the active source/control generation. The trusted helper must finish all held key/button releases and confirm the actual native send counts; failed send or missing ACK refuses drag. Reuse the existing resource-fence mechanism only if it supplies that exact correlation and completion evidence; input/render ACK or websocket send completion are never substitutes. If there is no eligible Explorer list item, resume normal remote movement. If local proof, grant or release acknowledgement fails, refuse native drag. A late response after physical button release cannot start another gesture.

The local helper runs a fixed packaged executable under the interactive current user, outside SYSTEM/elevation. It independently verifies default desktop/current session, real left button held and a short fresh user gesture. OleInitialize/DoDragDrop starts COPY only; never MOVE or LINK. IDataObject exposes FILEGROUPDESCRIPTORW/FILECONTENTS with bounded names/metadata; IStream reads are finite and identity/authority checked. IDataObjectAsyncCapability keeps the native object alive until the drop target finishes asynchronous extraction. Source data is fetched lazily after the gesture/drop and fully SHA verified before native stream publication; no automatic plaintext file exposure or system clipboard replacement. Bound total data100MiB, entries1000, concurrent native drag1, requests/inflight/seek sizes and pending verification memory. Localhost co-location proof is distinct from helper IPC authentication. Bind each connection to owner/origin/gesture/source-generation with one-use cryptographic capability; GetData/Read recheck the live authority, not just helper startup. Gesture admission750ms, selection offer1500ms, each chunk/request5s, heartbeat idle5s, verification and async extraction within an absolute15min operation deadline that no heartbeat extends. At deadline irrevocably cancel, discard old completion and await all in-flight reads plus verified native process exit; keep the PC-wide slot until exit proof, even if target never calls EndOperation. Cancellation/heartbeat expiry aborts streams and waits for native termination; no retained grant/code survives restart. Target-side files remain controlled by Explorer; do not remove arbitrary target paths.

## Bounded delivery phases

1. Native data-object/stream/async/cancellation and framed private IPC kernel, generated Windows validation only. Taskcheck and independent final review required; this alone is not a usable direct drag feature.
2. Trusted B Explorer selection + approved-root/identity source lease and chunk route; fake native selection/OS metadata tests. Taskcheck required.
3. Browser gesture/controller + local proof/managed/manual helper + CLI/UI/normal and sealed paths; browser received frames/DOM verify activation/fallback/revoke. Taskcheck required.
4. Real browser/Windows Explorer copy and cancel validation on available devices. Ask for any required concrete disruptive action only after preparing the exact result. No implicit system clipboard/service/driver/trust modification.

## Kernel versus host obligations

The kernel fetch delegate must be a finite cancellable adapter: each registered chunk request has5s timeout, full verification stays within the15min absolute operation. The packet codec validates syntax/nonce/sequence/manifest and byte bounds; it does not authorize/register request IDs or enforce blocking pipe-read deadlines. The host must reject unknown/completed request IDs, bind scope to its registration, cancel pending I/O, and keep the PC-wide slot until actual native process exit. WaitIdle(false) and DoDragDrop returning are never cleanup proof. These adapters are not yet implemented by the N1 kernel-only change.

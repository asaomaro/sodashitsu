# Recipient-bound agent grants: private foundation

This phase adds private recipient binding to DesktopAgentAccess and a finite private RPC owner used by the provider-side backplane. No public endpoint/CLI/UI transport is activated yet.

An optional binding contains authenticated recipient fingerprint and an active() closure combining the actual Store.endpoint(agent) permit revision, provider viewer/source epoch, origin and public machine. The binding object is copied when granted. Grant rejects inactive binding; attach requires exact recipient match and valid binding BEFORE consuming the ticket. Legacy unbound attach accepts no recipient. Invalid/revoked binding destroys its ticket/lease, and same fingerprint re-trust cannot revive it. Recheck on observe/refresh and each before/after async act; tick/occupied also purge invalid binding. Revoke releases held inputs immediately. Existing unbound behavior remains compatible.

A private Node owner wrapper receives exactly attach/observe/act/release with existing DesktopMethods schemas, byte limits and one pending operation. It takes already-authenticated recipient and an outer active closure, owns one random owner ID, and can attach only once to a bound grant. No general RPC/capture/start/child access; no root/server websocket registration. Operation deadlines (observe10s, act60s, other10s, lifetime<=120s) close owner, revoke via clientGone and release inputs. Delayed results never publish; no act retry. Strict sequential positive safe integer request IDs (<=16 digits), duplicate/out-of-order rejection, <=4MiB response, request<=64KiB. Revocation/lifetime is checked before and after awaits. Closing rejects pending requests promptly; unabortable capture/helper work may complete but has no authority to send another input or publish a result.

Tests use generated frames and fake input only: wrong/legacy recipient not consuming a ticket, exact recipient success, invalid permit/retrust, pending refresh/act revocation, owner close/deadline/duplicate/size/schema and release. Negative controls remove binding/lifetime guards and must fail. Fragile binding and private wrapper taskcheck and final independent cross review required. All OS capture/input remain untouched.

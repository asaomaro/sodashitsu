# Provider-private viewer/agent backplane

Connect the recipient-bound internal agent owner to the existing private provider backplane, without activating a public role/CLI/UI route yet.

Each private root has a fresh opaque43-character agent scope (independent from cookie/session/private route ID). root.grantAgent(recipientPermit) selects exactly its own one ready/allowInput/nonsecure viewer from Relay after root/provider epoch checks. Grant copies recipient fingerprint, revision-active closure and root's opaque scope. No observer can mint a grant for another root. root.revokeAgent() revokes only its viewer. Legacy grant/attach remain unscoped; a scoped grant requires exact scope as well as recipient. Scope mismatch must not consume the rightful ticket.

plane.agent(fp,scope,active) accepts only an existing active root scope, combines root/provider/plane lifetime and caller's authenticated-agent lifetime, and creates a finite DesktopEndpointAgentRpc with that scope. Track at most8 owners total; completed/timeout/close owners remove themselves. Closing a root synchronously closes only its agent owners after native/helper ownership is cancelled; plane.close closes all owners. Scope never authorizes own capture/start/general RPC/other lanes. It is additional binding; the one-use viewer ticket, trusted recipient and private authenticated transport are still required.

AgentAccess gains optional recipient.scope, copied/validated; attachRecipient adds private scope argument. Rpc gains optional scope/onClose options, checked before use; close callback is best effort and must not prevent pending rejection or grant cleanup. Existing scope-less internal tests remain valid. No public RPC method, HTTP path, Root metadata or feature advertisement is added.

Tests use the existing generated synthetic helper only: ready/input ceiling, exact root grant, wrong recipient/scope no ticket consumption, attach/observe/raw key/lease release, root takeover/revoke/close/provider epoch, two roots isolation, owner cap/reclaim, callback throws. Source regressions and guarded negatives must fail on removed scope/root ownership guards. Taskcheck and final independent review required before merge. Actual encrypted role routing, code/UI and CLI transport remain next phase.

Provider-local AgentAccess onOwnerRevoked notification is required so human takeover/secure transition also promptly rejects pending RPC/capture, even when root stays alive. RPC subscribes only its own random owner; close unsubscribes before clientGone. Grant authority/maps are deleted before notifications, cleanup exceptions do not stop remaining callbacks. Successful explicit release suppresses self-cancellation until its finite release response is prepared, then closes normally. No public event/API is exposed.

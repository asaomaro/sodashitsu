# 7B4g: explicit dedicated-service installation and maintenance

The ordinary server and legacy unlock service are independent. No installer or SCM mutation is run during implementation/CI; the first real installation requires a complete reviewed artifact and explicit operator installation approval. ValidateOnly compiles and inspects generated/local release data only, never target state or privileges.

## Initial installation

An explicit elevated local primary-administrator tool accepts owner SID, a local source release directory and an exact reviewed raw signin-package.json SHA256. No destination, service name, executable/arguments, credentials, trust/certificate registration or startup command can be supplied. Actual owner must be a user. Service name/Program Files and ProgramData slot are the existing fixed owner-derived paths.

Acquire and retain the owner mutex before inspecting service/code/data absence, through staging, publication and final Manual policy verification. Before any registration, require service absent, fixed code directory absent and owner data slot absent. Reject preexisting/unsafe/reparse/hardlink targets and never repair ACLs, adopt foreign contents, erase data or reset keys/trust. Verify every existing ancestor; create missing fixed ancestors/slot using protected SYSTEM/Administrators ACLs and retain their identities. Source files need not be administrator-owned: no source program is executed; exact reviewed manifest, closed relative entries, bounded regular single-link/no-follow files, same identity and streaming hash bind every copied byte. Reject extra/unexpected source entries. Source inventory/hashes are not permission to run a different manifest.

Copy into a fresh private stage under the fixed Program Files parent with CreateNew/no overwrite, flush, recheck identity/hash and current authority. Pin/verify secure copies, capture the stage directory identity, then close stage-only file/directory verification handles under the retained private parent before rename. Atomically publish without replacement and reopen/recheck the same directory identity and complete manifest at the fixed path. Runtime verification retains its existing no-write/no-delete sharing; no runtime lease is weakened for staging. No Node/Host/Worker is executed. Code verification is read-only and pins the entire closed package.

Create only fixed private runtime/admin/runs directories and the immutable one-byte 'S' quiescence barrier. No enrollment/identity/trust/required marker is initialized. Under owner mutex and exclusive immutable barrier, publish installer initial state bound to actual package SHA/barrier identity and fresh UUID. Initial means no child has run in this package generation, not absence of a receipt guessed from missing files.

A private install.transition marker binds owner/install UUID/reviewed package and records the attempted installation. Partial files/stages/marker remain recovery; no unconditional rollback/deletion. RunStorage rejects this marker. Register only the fixed LocalSystem own-process service, initially DISABLED, error control NORMAL, no dependencies/recovery actions/triggers, no interactive/desktop flag, and SYSTEM/Administrators-only control DACL. Inspect the actual disabled configuration and protected package. Remove only the verified marker, then switch only start type to DEMAND and inspect the actual manual policy. Do not start the service. A crash after marker removal and before enabling leaves a disabled service requiring explicit verified maintenance.

No System execution occurs until a later explicit controller start intent; no certificate/driver installation, key/trust generation or user input/capture is part of installation. All operator tools remain repository/revision-bound and are documented; runtime package remains the closed SYSTEM asset set.

## Upgrade and recovery (subsequent small delivery)

An upgrade requires the old reviewed package and known initial/independently observed stopped run, empty administrative journal, owner mutex and same exclusive barrier. Disable the verified manual service BEFORE writing the upgrade marker: previous controller revisions then refuse policy and Services cannot start it during partial maintenance. Hold exclusive barrier throughout; never stop/kill an unverified process or change an unexpected service. Stage/verify new package before changing the fixed package name. Under Disable+exclusive+marker, close the old package verification handles before archive rename, then verify/re-pin the archived identity and the new fixed package; no share-delete relaxation of runtime leases.

A private, closed, purpose-bound marker binds old/new manifests, owner/install UUID, old stopped evidence and exact archive/stage names. Preserve old code and run journal in fixed-parent private archives; never delete identity/trust/enrollment/runtime. Publish new code and a fresh package-generation initial state only under this recorded clean boundary. Verify all new package/data/service facts. Clear the marker before restoring manual start; no automatic normal run or admin replay.

Recovery must inspect and verify every residue and actual disabled/manual SCM state against the explicit manifests. It may finish a completely known maintenance transition, or restore a verified disabled installation with valid generation proof. Unknown partial objects remain quarantined for explicit operator handling; no guessing from STOPPED, missing records or unretained PIDs. General runtime crash with no independent completion is not clean evidence. Reboot proof or another separately reviewed clean boundary is required for any destructive reset; no reset flag or automatic lost-result replay.

## Verification

Test actual ordinary temp-file inventories, fixed mapping, byte/identity pinning, copy/flush/rename, collision/refusal, partial publication and revocation; use a fake SCM interface for registration/start-mode/DACL sequencing. Do not invoke native create/change/delete/start/stop in CI. Compile native wrappers and validate generated structures/policies. Revert actual source guards and require intended assertions/byte restoration. Use separate independent design/source/fix/records review. Preserve dirty root edits with all-file preflight; native-only changes reuse unchanged JS validation.

Primary API references: CreateServiceW, ChangeServiceConfigW, SetSecurityInfo/SetServiceObjectSecurity and QueryServiceConfig. Use fixed own-process/manual/LocalSystem policy and no optional recovery/interactive flags. Registration is a future operator action, not implicit authorization from generated tests.

# 7B4c4: one-shot start intent and exact clean-stop receipt

The fixed barrier proves only that nobody holds the installation's read leases. SCM STOPPED and process exit alone cannot establish that the most recent native job was clean. A previous clean receipt must not survive an untracked later run and be mistaken for the most recent run.

## Controlled run journal

Add a dedicated local run journal, separate from the six administrative-operation journal and from enrollment/trust. Before every normal/admin service start, the elevated controller owns the verified owner mutex, verified service configuration, verified package and exclusive unchanged barrier. It writes one private, bounded, machine-DPAPI-protected start intent containing ownerSid, fresh UUIDv4 runId, package manifest SHA256, barrier identity digest, issuedAt/expiresAt (admission only, max5min) and normal/admin mode. Admin mode additionally binds the actual private administrative pending nonce and cipher digest; normal mode requires the administrative journal to be empty. Paths are fixed owner-slot files; no CLI/env credentials or arbitrary paths.

Native Host must consume exactly one valid start intent before creating any Node child: private ACL/ancestors, fixed regular single-link file, owner/package/barrier match, atomic pending→claimed nonreplace rename, final identity/deadline checks. No pending intent, any claimed/receipt/ack ambiguity or malformed data means no Node launch. Host checks normal/admin journal conditions against the actual private files while retaining its barrier read lease; legitimate controller writes require exclusive barrier access and therefore cannot change that branch during the run. This also makes an out-of-band Services GUI start unable to replay an old completed intent. Failed package verification before intent consumption cannot create a child.

The durable latest intent/run record remains until an explicit controller transition. The old stop receipt is never accepted for a new pending/claimed runId. Admission expiry does not extend or replace native presence epochs, viewer consent or readonly policy leases; it only bounds creation of this run. There is no automatic re-run after crash or unknown result. A controller stop/status recovery may inspect records but must not rewrite ACLs, erase keys/trust or infer success from missing files.

## Finite observation handshake before child launch

A short admin run must not finish before the controller obtains its actual process handle. After consuming intent, Host publishes a private runId/package/barrier-bound started record with its own PID and native creation FILETIME, then waits at most10s (and within intent admission expiry) for a matching observation ACK. Until then it launches no Node child and cannot publish a normal clean-child receipt. Stop/timeout/invalid ACK is a nonclean no-child outcome.

Controller holds the owner mutex, opens the exact SCM service PID with query/synchronize rights, verifies image/System/session/creation and the started record, and retains that process handle. Only then it atomically publishes a private bounded ACK bound to runId and the started-record digest. Host validates actual ACK identity/digest/domain before child launch. No fast-polling assumption or post-exit PID lookup substitutes for this handshake. Early Host exit/PID reuse before observation means recovery; no child was authorized by ACK.

The observation ACK is the single narrow write permitted while Host holds its barrier read lease. Its helper may publish only the fixed run-observation file with the closed owner/runId/started-digest schema, after verified mutex/process-handle observation. It grants no administrative mutation permit, cannot accept a generic path/payload, and cannot write the admin journal, identity/trust, enrollment, start intents or stop evidence. All those mutations still require separately verified exclusive quiescence. Publish/consume ACK is guarded again immediately before child creation/resume; a stopped/dead/expired/unconfirmed run cannot proceed.

## Completion

Host pins its own process ID and native creation FILETIME (decimal string, not a JS number), runId, package manifest digest and barrier identity while retaining its verified leases. It emits one bounded private stop receipt only after exact Node exit0 and all-descendant Job Active0 are confirmed within the cooperative-stop budget. Forced termination, failed cleanup, package/scope failure or unconfirmed child completion never creates a clean receipt. The receipt does not claim the host process has already exited or its own barrier read lease is released. Clean stop is resource cleanup, not administrative operation success: an incomplete admin result can still accompany a clean stop and must never be rewritten as success. A run stopped before any Node child starts receives no normal clean-child receipt; recovery/initial-state handling remains explicit.

Controller independently waits for the exact pinned service process/creation instance to exit with0, SCM STOPPED with clean exit facts and the matching receipt. It then acquires exclusive access to the same pre-pinned immutable barrier. Only the combination authorizes management; the protected receipt alone is not sufficient. Receipt matches the current claimed runId/owner/package/barrier/PID/creation instance; old/nonmatching receipts cannot authorize a new run.

A never-started installation has an installer-created, package/barrier-bound initial journal state. An already-stopped service without exact successful controlled-run evidence enters explicit recovery. Host receipt plus SCM state alone is never enough. To retain evidence across controller invocations, the controller may persist a distinct private observed-stop record only while it retains the exact process handle and has independently observed exit0, matching SCM/Host receipt and exclusive same-barrier ownership. This record binds current runId, PID/creation, Host receipt digest, package and barrier; a later start intent invalidates it. If the first controller dies before recording independent observation, a later controller must recover explicitly, not guess from PID/FILETIME or a Host receipt. No automatic normal delegation follows an admin-only completion. The operator/controller explicitly prepares a fresh normal start after administrative request/result acknowledgment and cleanup.

## Explicit generation transition

Run artifacts occupy a separate fixed namespace (intent.pending/intent.claimed, started, observation, stopped, stop-observed, initial and transition). Host admits only a single matching pending intent with no other run artifacts or transition marker. Preparing a new generation requires initial or independently observed stopped evidence plus exclusive barrier ownership. Controller writes a private transition marker binding the old evidence and new intent digest, removes only verified old-generation objects, publishes the new pending intent, and removes the transition marker last. Every partial/unknown transition remains recovery; missing all artifacts is not a never-started proof. This is conservative crash detection, not a power-loss transaction claim.

Before admin start, the real six-operation request is durably pending and matches the new start intent. A crash between the journals is explicit recovery; it never authorizes normal fallback or automatic mutation replay. During a live run, only the narrow observation ACK can be written without exclusive barrier ownership. Host publishes only its own started/stopped records; controller publishes observation/observed-stop and generation transitions with distinct purposes and role-specific fixed paths.

## Persistence/security

Use distinct DPAPI purpose/domain for run intent and receipt, owner+runId entropy, closed canonical UTF8 schemas, bounded cipher/JSON and unknown-field rejection. Machine DPAPI does not isolate users; private SYSTEM/Administrators ACLs and verified ancestors/regular files are mandatory. Local elevated administrators are trusted controller principals; this is not a defense against malicious SYSTEM/administrator rewriting code/data.

CreateNew staged files, flush before atomic publish, retain original file identity during transitions, reject hardlinks/reparse points and leave ambiguous stages for explicit recovery. Never claim disk/power-loss transactional durability beyond the documented flush/rename behavior. No generic write helper or remote RPC can construct a start intent or receipt.

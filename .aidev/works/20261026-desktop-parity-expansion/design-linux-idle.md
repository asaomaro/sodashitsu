# Linux damage-only stream continuity

The Portal helper currently stops after1.5s without a new sample, which breaks producers that publish only on damage. Do not relabel cached pixels as newly captured. PipeWire's current gstpipewiresrc keepalive copies the last buffer and adjusts timestamps; it remains disabled. Source: https://github.com/PipeWire/pipewire/blob/master/src/gst/gstpipewiresrc.c (read2026-10-30), especially keepalive property and create/update_time. Portal session lifetime: https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Session.html . No third-party code copied.

Introduce a small typed `platform_idle` notice for Linux only: backend, exact last image sequence and strictly increasing heartbeat counter. Emit at most twice per second only after an actual first image, no pending image ACK, quiet source, active fixed logind/Portal scope and PLAYING pipeline. Continue existing immediate scope/Portal/EOS/error/owner/size invalidation and owner heartbeat expiry. No image bytes, new capture sequence, sourceInputSeq advancement or captured timestamp is synthesized. Notice is liveness, never evidence that old pixels are current.

The1000ms interval starts at receipt. PLAYING is pipeline liveness, not proof of unchanged screen contents. Idle status must be labelled awaiting a new image. Experimental local opt-in stays required. Source/relay/browser discard legitimate notices overtaken by the separate image socket or awaiting its ACK; they consume monotonic counters without refreshing proof. Wrong schemas/backends remain faults. Final source writer rechecks the entire scope plus the final owner deadline after its native pipeline query, as that query may itself cross a deadline.

Provider validates configured Linux mode, ready state, exact current image sequence/no pending ACK and monotonic counter; a notice permits only existing human viewer input for1000ms. Relay applies the same validation and only its human-input branch may use this short liveness proof. Agent input/observe/capture fences retain the existing real-frame freshness2s and post-input sequence floor. New real frame clears idle display/proof. No new permissions or operation replay; encrypted endpoint transport carries the notice on its existing control lane. The browser displays static/awaiting a new image rather than advancing frame counters/FPS. Missing notices, scope change, pipeline failure or existing deadlines refuse input as before.

Independent design review boundaries: only A's admitted human-viewer branch adds a private `platformIdleInput:true` marker (removed before B's strict public input schema parse). Browser-supplied markers are rejected by that strict public schema. B requires both this marker and its own current idle proof; marker-free/private-agent requests retain the real-frame2s gate. All agent branches, including private endpoint agents, never add this marker. Idle notices use the same writer/commit revision RLock as actual frames and recheck scope/Portal/PLAYING/no pending ACK/exact sequence before any byte and before final newline. Queue delay, input mutation, new capture, lock or Portal loss cannot publish an old idle notice. A partial record invalidated by scope is terminal, consistent with existing frame output.

Tests: generated Python scope/pipeline/quiet/ACK/counter/expiry/revocation; Node protocol/provider/relay tests ensuring human-only extension and agent refusal; real browser DOM/received notices/plain+encrypted with synthetic source. No OS picker/input is invoked. Actual Linux Portal and macOS devices unavailable per user. Fragile taskcheck and whole independent review required, plus actual-source regression negative controls and frozen build/typecheck/tests/browser/CI/clean smoke/root merge review.

Remaining after this slice: native Linux/macOS audio/microphone/clipboard/multi-monitor/GPU support and actual platform validation; signed Windows driver/service deployment and unsupported recovery states remain separate. This does not complete all platform parity.

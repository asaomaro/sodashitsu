# 7B4: local administration and installation (implementation plan)

Goal: prepare the dedicated SYSTEM identity, viewer trust and protected enrollment using explicit local administrator operations, then stage/install the reviewed fixed package. No remote RPC, repository server as SYSTEM, arbitrary executable/path, automatic desktop operation, certificate trust changes or automatic use of real user keys is added.

## Local administration boundary

The existing native service remains the only SYSTEM launcher and keeps its fixed owner/package/runtime/Job checks. Add a fixed worker `--context` operation that emits only verified owner/package/runtime metadata and final stop proof, without creating a Winlogon worker, capture/input or a signed-out claim. A context-only Node reader must never make presence.active() true or enable delegation.

At dedicated main startup, obtain this SYSTEM context, then inspect only a fixed private admin mailbox under its owner-hash runtime. The mailbox is local-admin/SYSTEM-only, strict, bounded, nonce/owner/expiry bound and consumed before execution. Accepted operations are status, identity initialize, viewer trust/revoke, enrollment set/disable. No generic invocation, shell, file paths, module names, agent or desktop commands. Node validates the private path/handle and complete schema. Normal remote handlers never read or write this mailbox.

Administration constructs only the dedicated store; initialize/trust/revoke are reachable exclusively through this protected startup branch. System identity uses CurrentUser DPAPI under SYSTEM. A fixed writer helper stores the enrollment at the existing known owner slot, machine/purpose/owner-bound encryption and private ACL, using a create-new stage and atomic replacement. No raw token/private key is returned. Results contain only public status/provider fingerprint/revision or a fixed failure.

A local elevated PowerShell controller acquires an owner-bound mutex, stops only the dedicated signin service and waits for its native Job teardown, writes the private request, starts the fixed service, waits for its nonce-matched result and completed stop, and removes the temporary mailbox. It does not stop generic soda/proxy or the existing unlock service. Protected paths cannot be changed through request fields. A successful administration-only main may exit 0; native host must confirm its exit code and all descendants before reporting a clean service stop.

Read-only status/key management can work while the human is logged in; it must not require a positive signed-out probe. An absent mailbox follows normal readonly presence cycles. A malformed/expired mailbox fails closed and never falls through to normal network startup. Do not initialize missing keys automatically on the normal path.

## Installer boundary

Installer input is an explicit reviewed manifest SHA-256 and staging directory. Revalidate the closed asset list, hashes, sizes, regular-file/link constraints and installed fixed owner slot. Copy only into a new protected Program Files package; verify installed bytes/ACL before registering a fixed LocalSystem service. Create private owner-slot/runtime directories without repairing unsafe existing ACL/reparse objects. No execution from the repository or unprotected staging. Existing installation/upgrade must be explicit; never overwrite live package handles or keys.

Add only necessary fixed package assets (for example the enrollment writer), updating JS/C# manifest validators together. Build/ValidateOnly paths must not register/start services, write Program Files, change trust or run privileged Main. Initial installation does not configure real enrollment or capture/input. Service enabling/start remains an explicit operator action after initialization/trust/enrollment.

## Required verification

Independent taskcheck: context-only cannot grant presence; mailbox/nonce/path/ACL/role; readonly-vs-admin dispatch; credential limits/atomic writes; package and service lifecycle. Generated clocks/ACL/facts/crypto/temporary files and fake service/process/store sinks, intended product-source negatives with exact restore, actual Windows compile/ABI and CI. Dedicated bundle loading and real Root/browser tests remain in scope. No actual service/credential/trust/desktop action before the complete reviewed artifact and operator authorization.

Potential release constraints: configured Root TLS must remain verified (no rejectUnauthorized=false); private CA support, if needed, must be an explicit enrollment-bound public CA input, never an OS trust-store mutation. Signed driver distribution and real hardware validation remain separate external dependencies.

## Architecture review decisions: SCM, journal and token handling

Before every stop/start, controller verifies the existing SCM service's literal quoted fixed compiled-owner executable (no extra args/env expansion), LocalSystem account, own-process/noninteractive type and owner/namespace. Its configuration DACL permits changes/start/stop only to SYSTEM and Administrators (others may query only); owner must be SYSTEM/Administrators. Recovery command/failure actions must not execute another program or silently restart. Reject a mismatched service without stopping, starting or repairing it. Installer registers this exact configuration and validates it again. Controller uses the same owner mutex as install/upgrade; existing mutex name collisions require owner/DACL inspection, never ACL repair/takeover.

A stop receipt is more than SCM STOPPED: pin the service PID/creation identity before stop, wait for that exact process and require normal exit, in addition to the native host's mandatory all-descendant Job-zero confirmation. Add a precreated private immutable owner-slot quiescence file: native host/broker/worker and Node hold a read lease for their whole lifetime. Controller must acquire exclusive access to the same file identity after process exit before managing data. Never delete/replace/reset this barrier to obtain access. Unknown/nonzero termination or failure to establish quiescence is an explicit recovery condition, not automatic management/start. First install has no prior process and still requires the exclusive barrier. Release it only before the new start, while retaining the validated owner controller mutex. Native startup remains independently package/ACL verified.

Token input is secure interactive input or a private pipe; no token argument, environment variable, transcript/debug output or public result. The admin payload is encrypted using machine DPAPI with a DISTINCT admin purpose/owner/nonce entropy and also private SYSTEM/Administrators ACLs. Do not claim machine DPAPI isolates an unprivileged user who has obtained ciphertext; confidentiality relies on the private storage boundary as well. No plaintext token is written to a staging/mailbox file. Bound ciphertext and decrypted UTF-8/schema sizes, retain/compare file identity while claiming, zero owned plaintext byte buffers, and do not claim guaranteed erasure of JS strings or SSD data.

Pending→claimed is a durable atomic transition before any mutation, with nonce and request-cipher digest. Result is durable/atomic and bound to the same owner/nonce/digest. The presence/network branch is never entered in a startup that detected any admin pending/claimed/result/ack state, even if the request expires, fails, is cancelled or has already been consumed. Every awaited step and persistence boundary rechecks the operation deadline/owner/cancellation. Unfinished claimed state remains administrative-only/fail-closed across restart. Unknown results are never auto-replayed.

Controller clears a completed journal only after matching result plus exact-instance clean exit/quiescence. Write/flush its nonce-matched acknowledgment before removing claimed/result files; remove acknowledgment last, so a cleanup crash cannot be mistaken for an unclaimed normal startup. An unresolved/indeterminate claim requires explicit operator recovery. Recovery may read public status, but must not replay the unknown mutation, erase/reinitialize keys, repair ACLs, or enable normal networking automatically. Clearing an indeterminate journal is a separate deliberate nonce-bound decision after status review. A new mutation uses a fresh nonce. Known failed operations report failure and do not silently restart normal sharing.

The installer precreates the private barrier and protects all ancestors. Build/ValidateOnly and generated recovery tests use temporary ordinary files/fake process/service/store facts; actual SCM/process/ACL/key operations remain deferred until the complete reviewed artifact and operator authorization.

## Delivery slices and identity registration

Implement and review the readonly context transport first, without enabling administration or changing normal startup. It emits verified fixed-slot metadata and a complete native stop proof; its public active() always returns false and metadata is withheld until confirmed clean exit. No signed-out pulse, desktop process, capture/input, key/trust operation or network connection is reachable through this purpose. The following slices add the journal and finite admin engine, then native persistence/controller/installer. None may be advertised as an installed signin feature before the complete path is verified.

The SYSTEM endpoint has a different dedicated provider identity from the human user's normal desktop endpoint. Require a separately created Root machine invitation/entry, for example `sr-pc（サインイン）`; do not reuse the normal machine id/token or silently replace its viewer pin. Operator instructions must include separate identity/trust verification. This preserves the existing one-provider-per-machine pin rule. SAS remains outside this minimal signin implementation and is not advertised as supported.

An already-stopped service requires a retained exact-instance clean-stop receipt or sufficient SCM exit facts together with exclusive access to the unchanged barrier. If no exact successful-stop evidence is available, enter explicit recovery; STOPPED alone never authorizes a mutation. Initial never-started installation has its own installer-created receipt and barrier identity.

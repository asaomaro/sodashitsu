# Native drag worker and process boundary

The worker is a fixed, one-operation STA executable, launched only by the future authenticated browser-PC gateway. It accepts no command-line parameters; its inherited private stdin starts with a64-hex nonce plus LF and the N1 framed begin/entry/seal/beat/bytes/end/cancel protocol. A nonce alone does not prove browser ownership/co-location. The parent must authorize origin/owner/viewer/gesture/source-generation with a one-use capability and prove B's real input release before starting this process. Those public adapters are not yet connected.

`DragDataPump` registers each generated request and permits only its exact file index, offset, bounded chunk length and complete End. Requests have an independent5s deadline that heartbeat cannot extend; heartbeat idle5s and absolute15min remain terminal. Each file can be fetched once, pending16, manifest total100MiB/1000. Data passes the existing full-file SHA verification before IStream publication. Packet/rejected/pending bytes are wiped; fetch completion drains independently. The send callback is a bounded nonblocking enqueue, never a direct pipe write.

The real backend checks the active console/default input and thread desktop, normal current user, and held left button. The same final admission function used by generated tests runs the final OS checks, then the host's original750ms/Abort fence, then the OLE call without another callback between fence and dispatch. DoDragDrop allows COPY only; async extraction waits for EndOperation. Terminal cancellation or failed EndOperation cannot become success (`CopyCompleted`). Source content is virtual and read-only; no target filesystem path, source deletion, or system clipboard replacement exists here.

A background reader owns bounded N1 framing; a separate bounded32-item output queue owns serialization/writes. Independent watchdog covers startup/manifest/heartbeat/absolute lifetime and pending request expiration. It cancels data and forces its own process exit after5s of stalled cleanup, including blocked native callbacks or pipe I/O. Normal success waits data drain and output completion. The parent must still require actual child close with exit0 before reporting native completion; a `finished` message alone is insufficient.

`NativeDragSlot` admits one worker for the same Windows user across helper instances/sessions. Only the current console is supported by the real backend; mixed Windows users are not a supported broker configuration. A per-user Global mutex serializes admission, but mutex release/abandonment is not exit proof. Private user-only directory ACLs, held non-reparse/non-delete-shared ancestor handles, single-link regular journal checks and current-user DPAPI protect a PID+creation-time record. A subsequent admission opens a read-only query/synchronize process handle and waits for that exact process to exit; PID reuse with a different creation time proves the recorded original exited. Access/identity/record uncertainty refuses admission. It never kills an old PID. The record remains after worker teardown, including forced process exit. Missing/corrupt existing private state refuses admission. Runtime mutex/state acquisition occurs only in the standalone worker; do not call it inline from a long-lived PowerShell/server process.

Tests create only new private disposable directories, generated bytes and owned console processes. They do not change existing directory ACLs, services, drivers, system trust, user input, clipboard contents or real desktop/OLE state. Actual desktop/token/console/Global-slot/OLE/Explorer paths are compiled but remain unverified on a real interactive device.

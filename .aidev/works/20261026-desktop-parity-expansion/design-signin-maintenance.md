# Explicit dedicated service maintenance

No real installed state/SCM is mutated during implementation/tests. Public mutation remains an explicit local elevated operator command against fixed owner paths and reviewed manifest SHA(s), with owner mutex, primary administrator/actual user owner, retained package/parent identity and exclusive immutable barrier. No process start/stop/kill, keys/trust deletion, ACL repair or replay is part of maintenance.

## First delivery: finish fully committed initial registration

Only recover the narrow initial-installer crash boundary after all package/data/initial record writes completed. Fixed service must already exist, be DISABLED, pass the complete disabled policy and be SCM STOPPED with exit0 or never-started1077 and specific0. No arbitrary existing service adoption. Hold owner mutex, full installed package with exact reviewed manifest, fixed private parent/directories, exclusive barrier and validated package/barrier-bound journal initial state. Admin/runtime directories must both be empty (initial installation only). Closed slot inventory is exactly admin,runtime,runs,quiescence.lock; any install.transition marker/residue rejects this first recovery command. Thus a missing marker never alone proves completion: intact DPAPI initial generation, exact package and immutable barrier, private empty runtime/admin and disabled service policy all independently required. The tool never creates an initial record, deletes a marker or fixes partial files.

Recheck all evidence immediately before setting only start type to Manual; inspect exact manual policy and same STOPPED status after. This is not a recovery path for any started/claimed/stopped/unknown journal or partial registration, and never treats SCM STOPPED alone as a clean boundary. No automatic start follows. Generated fixture includes exact DPAPI initial record, ordinary temp files/native identity, actual exclusive barrier and fake SCM only. Negative controls target initial state, exact disabled/not running policy, closed slot inventory and final authority/marker checks. Actual native recovery SCM change remains untested.

## Subsequent upgrade delivery

Upgrade requires old reviewed package and initial/independently observed stopped run, empty admin, exclusive barrier and owner mutex. Stage and verify new reviewed bytes before disabling old manual service. Disable service before any durable maintenance marker; old controllers then refuse. Keep disabled through all rename/state transitions. Record closed purpose-bound owner/old/new package/generation/barrier IDs and exact random archive names, preserve old code/run journal, never touch runtime/identity/trust/enrollment. Close only old package/journal handles before archive moves while private parents+exclusive barrier remain held, reopen and bind same captured identities. Verify new fixed package and initialize a fresh run generation only from the recorded clean boundary. Clear exact known marker then restore Manual, never start. General unknown process crash is not made clean by missing PID/SCM STOPPED; broader partial upgrade recovery requires explicit fully verified transition handling and must remain separate from initial recovery.

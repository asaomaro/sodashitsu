# Durable folder continuation

Persist explicitly saved folder upload/ZIP download across server-process restart/handoff. No old-version migration and no power-loss guarantee. Keep fresh manual file grant, same root/settings binding, finite15min last operation,8 jobs per registry (browser8combined),100MiB/1000entries/depth32. Completed output/user files are never removed on abort.

Use a separate private encrypted DesktopTransferStore namespace `desktop-folder-transfers`, with the existing DPAPI-user/Unix owner key protection and bounded2MiB plaintext (folder manifest plus per-entry identities cannot fit the single-file45KiB bound;1000 completed entries with all bounded identities exceed1MiB). The single-file default remains unchanged. Both namespaces participate in synchronous freeze, settings/endpoint generation invalidation, bind, drain, rollback and close; wait for all even when one fails.

DesktopFolders exports strict bounded continuation snapshots and restore/suspend/verified-discard operations. Upload records include approved root identity, created destination/each directory identity, declared file bytes, accepted offset/prefix snapshots, committed file SHA+inode identity, and a prepublication per-file committing intent. Before each file publication persist its final exact temporary snapshot and expected SHA; recover an already published original inode via FileTransfer.published, or reopen the exact unpublished temporary. Persist only after IO sync, before ACK. Restore reconstructs mutable state/counters from verified file state, never adopts an arbitrary path, same-content replacement or unknown temporary. All completed/partially-completed files and empty directories are preserved correctly; abort only removes verified owned temporary files and verified owned empty directories.

Download records retain generated scratch directory/archive identity under the private folder-store namespace, exact SHA/size, original source directory/file identities and metadata checks. The archive is a private completed snapshot; restore verifies the same source tree, same archive FD/name/parent and full SHA, then seeks only to an allowed browser-confirmed chunk boundary. No arbitrary tmp path is adopted/deleted. Replaced or modified source/archive/parent is rejected. Freeze pauses both group/stream timers before provider epoch changes; queues/loaders fully drain before releasing StateDirLock. Rollback cold reloads; stale callbacks cannot mutate/delete retained data.

Verification: restart upload with multiple files/empty dirs and partial stream, download prefix/exact ZIP, final receipt, data and publication child-process exit boundaries, root/parent/source/archive/completed/temp replacement, corrupt/missing key/generation/zero bytes, expiry, cancel/revoke/settings OFF→ON, concurrent owners, pending-write freeze/rollback/old timers, all-job close errors. Browser actual DOM and received frames prove restart/manual grant/continuation for normal and encrypted paths. Product-source runtime negative controls with byte restoration and positive rerun.

# 要件: ブラウザ版の tab バーで、tab をドラッグで並べ替える

## 背景 / 課題

- 端末版は tab をドラッグで並べ替えられる（`docs/tui.md`「マウス」、`docs/tui-parity.md` の H04m・M12）。ブラウザ版はキー（`move_tab_previous`・`move_tab_next`。既定のキーなし）でしか並べ替えられず、マウスで使う人には手段が無いのと同じになっている（`docs/tui-parity.md` の H04m・M12 の Web の列が「無し」）。
- 前の作業 `20261004-ui-interaction-polish` が、利用者の指摘「タブは、ブラウザ版ではドラッグで並べ替えられない」を `split-dnd.md` の F13・AC8 として切り出したままになっている。この作業は、そのうち **tab の並べ替え**だけを取り上げる（F13 と、それに要る最小の見せ方）。workspace・pane を含む D&D 全体の表現の作り直し（ポインタに付いて動く像・掴める形のカーソル・禁止の印。F7・F8 の像・F10・F11 の印）は、取り上げない。

## 目的 / ゴール

ブラウザ版（デスクトップ）で、マウスだけで tab の順を直せる状態。つかんだ tab がどこに入るかが離す前に分かり、今ある操作（クリックでの切り替え・右クリックのメニュー・ホイール・pane の名前を tab へ落とす移動）はどれも今までどおり働く状態。

## スコープ

### 対象
- ブラウザ版のデスクトップの画面の tab バー（`TabBar.vue`）。同じ workspace の tab の間での並べ替え。

### 対象外
- 別の workspace への tab の移動（後の作業の候補）。
- モバイルの 1 列の画面（tab バーを持たない）と、タッチでのドラッグ（AC9）。
- ポインタに付いて動く像・掴める形のカーソル・「落とせない」印など、D&D 全体の表現の作り直し（`20261004-ui-interaction-polish/split-dnd.md` の残り）。
- サーバ・protocol の変更（AC8）。1 回で目的の位置へ動かす RPC（`tab.move_to` のようなもの）は足さない（後の作業の候補）。
- 端末版の変更。

## 完了条件 (受け入れ基準)

- [ ] AC1: tab バーの tab をマウスの左ボタンでつかんで動かし、別の位置で離すと、その tab がその位置へ並べ替わる。隣へ・2 つ以上離れた位置へ・先頭へ・末尾へ、前向きにも後ろ向きにも動かせる。画面の tab の順と、サーバの持つ順（再読み込みした後の順）が一致する。
- [ ] AC2: ドラッグ中、離したときに入る位置（tab と tab の間・先頭の前・末尾の後）に線が 1 本だけ出て、つかんだ tab は元の場所で薄くなる。線の位置と、離した結果は一致する。離しても順が変わらない位置（つかんだ tab の前後の境目）と、tab バーの外では、線は出ない。離す・取り消すと、線と薄さは消える。
- [ ] AC3: tab が多くて tab の列があふれているとき、ドラッグしたままポインタを列の左右の端（24px）へ寄せると、列がその向きへ自動でスクロールし、最初は見えていなかった位置へ落とせる。
- [ ] AC4: tab バーの位置の設定が「下」でも、AC1・AC2 が同じに働く。
- [ ] AC5: 並べ替えは、同じサーバにつながっているほかの画面（別のブラウザ）に、再読み込みなしで反映される。
- [ ] AC6: ドラッグ中に画面の外から状態が変わっても壊れない。つかんだ tab が閉じられた・tab が 1 個になって tab バーが隠れた・表示中の workspace が切り替わった・ダイアログ（グラフ画面・質問のフォームを含む）が開いた、のどれでも、ドラッグは取り消しになり（何も送らない）、線・薄さ・キーの受け口が残らない。tab の数や順だけが変わったときは、ドラッグは続き、離した時点の順で入る位置を決める。
- [ ] AC7: pane の名前のドラッグと取り違えない。pane の名前を tab へ落とすと今までどおりその tab へ pane が移り（`pane.move_to_tab`）、tab の順は変わらず、入る位置の線も出ない。tab のドラッグ中は、pane の落とし先の強調（tab の破線の枠・pane の縁と中央・サイドバーの行）は出ず、pane の上・サイドバーの上で離しても何も起きない。
- [ ] AC8: サーバ・protocol は変えない。ブラウザが送るのは既存の `tab.move`（動かす数だけ）と、確定の後の `tab.focus` だけで、取り消し・順が変わらない位置で離したときは `tab.move` を 1 つも送らない。`tab.move` を持つ今までのサーバでそのまま動く。
- [ ] AC9: タッチのポインタでは、tab のドラッグは始まらない（タップでの切り替え・tab の列の横スクロールは今までどおり）。モバイルの 1 列の画面は tab バーを持たないので、何も変わらない。
- [ ] AC10: 文書が合っている。`docs/tui-parity.md` の H04m・M12 の Web の列が「あり」になり、`docs/herdr-parity.md` の H04 に、ブラウザ版の tab のドラッグ（使う RPC・同じ workspace の中だけ）が書かれ、`docs/verification.md` に手で確かめる項目がある。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開始 / 終了: ドラッグは、tab の上で左ボタンを押したまま 6px 以上動かしたときに始まる（pane の名前・workspace の行と同じ閾値）。右ボタン・中ボタン、「＋」のボタン、右端の帯からは始まらない。離す・取り消すと終わる。
- [ ] AC-I2 確定 / 取り消し: 線が出ている位置で離すと確定する。`Esc`・tab バーの外で離す・順が変わらない位置で離す・ポインタの取り消し（`pointercancel`）は取り消しで、順も、選ばれている tab も変わらない。`Esc` で取り消した後にボタンを離しても、tab は切り替わらない。
- [ ] AC-I3 キーボードだけで完結するか: 同じ並べ替えは、既存のキー操作 `move_tab_previous`・`move_tab_next`（既定のキーなし。設定で割り当てる）だけでできる。この作業でキー操作は足さず、変えない。tab のボタンに Tab キーで止まって Enter・Space で切り替える操作も今までどおり。
- [ ] AC-I4 フォーカスの行き先: 確定すると、つかんだ tab が選ばれ（表示が切り替わり）、その tab のフォーカス中の pane の端末にフォーカスが移る。取り消すと、選ばれている tab は変わらず、選ばれている pane の端末へフォーカスが戻る（tab のボタンに残らない）。
- [ ] AC-I5 既存の操作を妨げないか: 6px 未満で離したときは今までどおりのクリック（tab の切り替え。`tab.focus` を 1 回）で、ドラッグの後に切り替えが二重に起きない。右クリックのメニュー・tab バー上のホイールでの切り替え・「＋」・tab が 1 個のときの自動非表示は今までどおり。ドラッグ中のキーは端末へ届かない（`Esc` を含む）。

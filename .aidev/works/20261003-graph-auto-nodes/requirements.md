# 要件: エージェントが起動したエージェントを連携のグラフに自動で載せる

## 背景 / 課題

pane の中のエージェント（Claude Code 等）に「sodactl で別のエージェントを起動して操作して」と頼むと、そのエージェントは同じ workspace に pane を作り（`sodactl pane split` 等）、
そこにエージェントを起動して（`sodactl agent start`、または pane に `claude` 等を打ち込んで）、`agent prompt`／`agent wait`／`agent read` で操作する。
このとき起動された側の pane は、**連携のグラフ（`docs/agent-graph.md` 「pane を載せる（ノード）」）に載らない**。グラフに載せるのは利用者が「pane を載せる」で選んだものだけ（すべての pane を自動では載せない）だからである。
利用者はグラフ画面で「誰が誰を起動し、誰が誰に指示しているか」を見たいのに、エージェントが自分で作った連携は画面に出ず、状態（作業中・承認待ち）も一覧できない。
承認待ちで止まった子がいても、グラフから気づけない（ブラウザのサイドバーには出るが、親子の関係と線による知らせは無い）。

## 目的 / ゴール

- エージェントが起動した別のエージェントの pane が、利用者が何もしなくても連携のグラフにノードとして載っており、「親が子を監督している」関係が線で見える状態。
- 子が承認待ちになったとき、親（起動した側）に知らせる線が最初から引かれている状態。
- 利用者が手で載せたノード・線・配置は、自動の処理に変えられない状態。利用者が外した子は、同じ子について加え直されない（親は、新しい子が現れたときに限って加え直されうる）。

charter ゴール: `.aidev/charter.md` は無い（紐づける charter はない）。

## ユーザーストーリー

- US1: Sodashitsu の利用者として、エージェントに頼んで別のエージェントを起動させたとき、起動された側がグラフに自動で出てほしい。なぜなら、手で pane を載せ直さなくても、誰が何をしているか・誰が止まっているかを一画面で見渡せるから。（受け入れ: AC1, AC2, AC3, AC4, AC9, AC10, AC11）
- US2: 同じ利用者として、起動した側から起動された側への「監督」の線と、承認待ちを親に知らせる線も自動で引かれてほしい。なぜなら、親エージェントが子の状態を知る手段（監督役への知らせ・承認待ちの通知）を、線を引く手間なしで使えるから。（受け入れ: AC5, AC6, AC12）
- US3: 同じ利用者として、自動で載ったものを外したり動かしたりしても、あとで勝手に戻されたり乱されたりしないでほしい。なぜなら、グラフは利用者が整える画面だから。（受け入れ: AC7, AC8）
- 互換性・文書の AC（AC13, AC14）は特定のストーリーに紐づかない制約由来の基準。

## スコープ

### 対象

- **自動で載せる条件**: pane の中から `sodactl` で作られた pane（`pane split` 等）で、エージェントが**検出された**とき。エージェントの起動方法は問わない（`sodactl agent start`、または打ち込み）。
  - 既存の pane（手で作った pane を含む）に、pane の中の `sodactl agent start` でエージェントを起動した場合も対象にする（作った人が別でも、`agent start` を打った pane が起動した側）。
- 載せるもの: 起動された pane のノード、起動した側（親）の pane のノード（グラフに無ければ）、親が子を**監督**する線（子→親）、承認待ちを親に**知らせるだけ**の承認の代理の線（子→親）。
- 親も子も**手元のサーバ（local）の pane** のときだけ。
- 載せたこと、載せなかった理由（重複・別の監督役・上限・親が無効・競合の失敗）のサーバのログへの記録。
- 文書の更新（`docs/agent-graph.md`・`docs/sodactl.md`・`packages/cli/skills/sodactl/SKILL.md`・`docs/verification.md`）。

### 対象外

- 利用者が手で操作して作った pane・手で起動したエージェントの自動載せ（呼び出し元の pane が分からないため）。
- 別のマシン（`--machine`）の pane の自動載せ。
- トリガの線の自動作成（文面を決めるのは人）。承認の代理の「返答まで任せる」の自動設定。
- pane が閉じたときのノード・線の自動掃除（既存の仕様のまま。閉じた pane は「無効なノード」として残る）。
- グラフ画面の見た目の変更（自動で載ったものに印を付ける等）。
- 端末版（引数なしの `soda`）の変更。

## 機能要件

- F1: pane の中から実行された `sodactl` が、新しい pane を作る操作（`pane split`、`workspace create`、`tab create`）と `agent start` で、**呼び出し元の pane の ID** をサーバへ知らせる（`SODA_PANE_ID` があり、接続先が `SODA_SERVER_URL` と一致して既存の `selfPaneId` が確認できたときだけ。`--machine` 指定では送らない）。
- F2: サーバは、呼び出し元から作られた pane を「誰が作ったか」と結びつけて覚える（メモリだけ。サーバの再起動で消える）。`agent start` は、対象の pane の「起動した側」を、`agent start` を打った pane で記録する（作った人がいても、打った人を優先する。**エージェントを起動した側が親**）。作った人は、`agent start` が無いとき（打ち込みで起動したとき）の親になる。
- F3: その pane でエージェントが検出されたら（1 つの pane につき 1 回だけ）、グラフへ次を**まとめて 1 回の更新で**加える。
  - 子のノード（無ければ）、親のノード（無ければ）。
  - 子→親の「監督」の線、子→親の「承認の代理」の線（知らせるだけ・行数 40・上限 10。AC6）。
- F3 の「1 回だけ」は、pane ごとに最初に検出されたときの 1 回。エージェントが終了して別のエージェントが現れても、入れ替わっても 2 回目は載せない。
- F4: すでにある線・ノードは変えない。重複する線、1 つの配下に 2 つ目の監督役になる線は引かない（その線だけスキップして理由をログに記録する）。加えた結果がノード 64・線 128 を超えるときは何も加えず、理由をログに記録する。
- F5: グラフの更新が競合（`rev_conflict`）したら取り直して最大 3 回やり直す。やり直しても失敗したら諦めてログに記録する（ほかの処理を止めない）。
- F6: 親の pane が閉じていた・グラフで無効（stale）なら、親のノードも線も加えない（子だけも載せない）。ログに記録する。
- F7: 子が検出される前に子の pane が閉じたら、何もしない（ログも出さない）。
- F8: 自動で加えたノードの配置は、既存の「pane を載せる」と同じ規則（`addMissingNodeOps`）にそろえる。
- F9: 追加したことは、ほかのブラウザ・`sodactl graph show` にも既存の `graph.changed` で届く（新しい配信は足さない）。

## 非機能要件 / 制約

- 呼び出し元の pane の名乗りは、認証済みの接続（ログイン済み、または `pane.sock`）でのみ受ける。名乗りは**グラフに載せる関係の記録**にだけ使い、権限の判断には使わない（他の pane への操作の許可を広げない）。
- 古い `sodactl` は新しい項目を送らない・古いサーバは新しい項目を無視する（互換性。片方だけ古くても既存の動きは変わらない）。
- 自動載せが失敗しても、`pane split`・`agent start` 等の本来の処理を失敗させない。自動載せは非同期に行い、本来の処理の応答を待たせない（検証は設計・レビューで、コードが応答の後で動くことを確かめる）。
- グラフの操作は既存の直列の更新（`GraphStore.update`）を通す。`GraphEngine` の動作は変えない。
- 親ごとの監督役への知らせ（既存）は、線が足されると既存の規則で出る（子が増えるたびに親へ知らせが出る。変えない）。
- Windows のサーバでも動く（`pane.sock` や `/proc` に依存しない。検証は設計・レビューで、依存が無いことを確かめる）。

## 完了条件 (受け入れ基準)

- [ ] AC1: pane の中から `sodactl pane split` で作った pane に `sodactl agent start` でエージェントを起動し、検出されると、子と親（グラフに無ければ）のノードが加わる。`workspace create`・`tab create` で作った pane でも同じ（F1）。1 つの pane では 2 回目の検出（入れ替わり）で重ねて加えない（F3）。
- [ ] AC2: `pane split` で作った pane に、`agent start` を使わず `claude` 等の起動コマンドを打ち込んでエージェントが検出されたときも、同じように加わる。
- [ ] AC3: 作った人とは別の pane が既存の pane に `agent start` したときは、`agent start` を打った pane が親になる。
- [ ] AC4: 呼び出し元が分からない（手で作った pane に手で起動した・`--machine` 指定・古い `sodactl`）ときは、何も加わらない。手で作った pane でも、pane の中の `sodactl agent start` で起動したときは AC3 のとおり加わる。
- [ ] AC5: 子→親の「監督」の線が 1 本加わる。親には、`docs/agent-graph.md`「いつ動くか」の監督役への知らせの規則で、監督の知らせが出る。
- [ ] AC6: 子→親の「承認の代理」の線が、知らせるだけ（`notify`）・行数 40・上限 10 で 1 本加わる。子が承認待ちになると、`docs/agent-graph.md`「いつ動くか」の承認待ちの規則で、親へ知らせが出る。
- [ ] AC7: 利用者が子のノードを外した後に、同じ子に対して加え直されない。親のノードを外した後は、**別の子が新しく検出されたときに**親が加え直される（同じ子では加え直さない）。
- [ ] AC8: すでにあるノードの配置・線の設定・一時停止の状態は変わらない。同じ線がすでにあるときは重複させず、同じ配下の別の監督役の線があるときは、その種類の線を引かず（ノードは加える）、理由をログに記録する。新しいノードの配置は「pane を載せる」と同じ規則（F8）。
- [ ] AC9: 加えた結果がノード 64・線 128 を超えるとき、何も加えず（部分的にも加えない）理由をログに記録する。`pane split`・`agent start` は成功する。
- [ ] AC10: 親が閉じている・無効のときは何も加えず、ログに記録する。子が検出される前に閉じたときも何も加えない。
- [ ] AC11: グラフの更新が競合しても、取り直して（最大 3 回）加わる。それでも失敗したらログに記録して諦める。更新の失敗が `pane split`・`agent start` の結果に影響しない。
- [ ] AC12: ほかのブラウザ・`sodactl graph show` に追加が届く（rev が 1 つ進む。何も加えない場合は進まない）。
- [ ] AC13: 古い `sodactl`（新しい項目を送らない）と新しいサーバ、新しい `sodactl` と古いサーバ（項目を無視）の組み合わせで、`pane split`・`agent start` 等が従来と同じ結果（成功・エラー・出力）になる。
- [ ] AC14: `docs/agent-graph.md`・`docs/sodactl.md`・`packages/cli/skills/sodactl/SKILL.md`・`docs/verification.md` に、自動で載る条件・載らない条件・外し方・上限の扱いが書かれている。

## 未確定事項 / 確認したいこと

- 呼び出し元の名乗りを載せる RPC の項目名（`callerPaneId` 案）と、どの RPC に載せるか（`pane.split`・`workspace.create`・`tab.create`・`agent.start`）。design で決める。
- 「作った人」を覚える入れ物をどこに置くか（`SessionService` の pane ごとの状態か、グラフ側の新しい部品か）と、エージェント検出のフック位置。design で決める。
- 「1 回だけ」（F3）の印をどこに置くか（置き場所だけを design で決める）。
- 利用者が外したものを覚えておく印は持たない。外した子が戻らないのは「pane ごとに 1 回だけ載せる」（F3）による（外した判断の記憶ではない）。親だけは新しい子のたびに加え直される（AC7）。実際に煩わしければ別の work で印を足す。
- 閉じた pane の自動掃除が無いので、エージェントを何度も起動すると閉じた子のノードが残り上限を圧迫する。この work では扱わず（対象外）、上限に達したときは記録するだけにする。

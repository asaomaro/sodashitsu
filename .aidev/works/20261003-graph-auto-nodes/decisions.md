# 判断の記録: 20261003-graph-auto-nodes

## D1: 親の決め方・載せる契機（requirements の対象を実装に落とした判断）

- **契機はエージェントの検出**（`pane.agent_status_changed`）。起動の方法（`agent start`・打ち込み）に依らず、作った pane・`agent start` した pane のどちらでも拾う。
- **親 = `agent start` を打った pane > pane を作った pane**。エージェントを起動した側が親、という利用者の指示（「エージェントが起動したエージェントを連携ノードで見たい」）に沿う。
- **載せるもの**は利用者の選択（AskUserQuestion）どおり: ノード＋監督の線＋承認の代理の線（知らせるだけ）。親がグラフに無ければ親も載せる。
- 自動で載せたものに**印は付けない**（画面は変えない）。外した子は pane 単位の「1 回だけ」で戻らない。親は次の新しい子のとき戻る（許容）。
- 閉じた pane のノードの自動掃除は**この work の対象外**（既存の仕様のまま。上限に当たると warn で出す）。
- 実装の判断: ノードだけ足して線が 0 本になる場合を許す（別の監督役が居る子も画面に見せる）／相互の監督を作らない（逆向きの同種の線がある線は引かない）／競合は最大 3 回。

## D2: 検証できない名乗りの扱い

`callerPaneId` はログイン済みの接続が自由に名乗れ、サーバは pane の実在と子との同一性しか検査しない。権限は増えない（ログイン済みの接続は `agent prompt` を直接打てる）ので受け入れ、`docs/agent-graph.md` に経路になりうることと外し方を明記した（review ラウンド 1）。

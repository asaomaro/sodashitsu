# 端末版の性能の測定（AC17）

requirements の非機能要件（キー入力から反映まで追加遅延 p95 50ms 以内の目安・pane 16 個・状態反映 2 秒以内・大量出力の pane があっても
他の pane と画面の操作が固まらない）を、端末版で測る。

```sh
pnpm build
node packages/tui/dist/bench/latency.js          # 人が読む形
node packages/tui/dist/bench/latency.js --json   # 1 行の JSON
```

ビルドした `soda serve` を一時の状態ディレクトリ・空いているポートで起動し、`runTui` を偽の外側の端末（出力を溜めて headless の端末へ流す）で繋ぐ。
全体で十数秒。共有のマシンで重くしないよう、繰り返しや長い負荷はかけない（1 回だけ走らせる）。Linux / WSL2 向け。

| 項目 | 測り方 | 目安 |
|---|---|---|
| (a) 1 pane の打鍵 | `cat` の動く焦点の pane へ 1 文字打つ → その文字を含むフレームが外側の端末へ書かれるまで（30 回）。比較に、同じ pane へ WS の INPUT を直接送って OUTPUT の echo が返るまで（素の往復）も測り、p95 の差を「端末版が足した遅延」とする | 足した遅延 p95 ≤ 50ms |
| (d) 大量出力の隣 | 隣の pane で `seq 1 400000`（約 3MB）が流れている間に (a) と同じ打鍵 | 打鍵の p95 ≤ 50ms（固まらない） |
| (b) 16 pane | 4×4 に割って全 pane に 1 行ずつ出した状態で (a) と同じ打鍵、と外側の端末の大きさを変えてから全体を描き直したフレームが書かれるまで | 打鍵の p95 ≤ 50ms |
| (c) エージェントの反映 | `PATH` の先頭に置いた偽の `claude`（`sleep` の写し）を別の pane で起動 → サイドバーに「Agents」が出るまで、Ctrl+C → 消えるまで | 2 秒以内 |

## 測らないもの（手で測る）

- **本物のエージェントの 5 状態の遷移**（working → idle・blocked・done）: 画面の規則（manifest）で決まるので、偽のプロセスでは起きない。
  Claude Code 等を pane で動かし、`sodactl pane watch`（または Web 版）と端末版を並べて、状態の記号が変わる時刻の差を目で見る
  （サーバの判定の周期は出力のある pane で 500ms・無い pane で 1 秒。端末版の描画は最短 16ms 間隔）。
- **実物の端末エミュレータの描画時間**: この測定は端末版が外側の端末へ書き終えるまで。外側の端末（Windows Terminal 等）が画面に出すまでの時間は含まない。
- **SSH 越し**: 往復の時間が足される。端末版の処理の分は上の値と同じ。

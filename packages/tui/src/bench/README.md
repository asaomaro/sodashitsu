# 端末版の性能の測定（AC17）

requirements の非機能要件（キー入力から反映まで追加遅延 p95 50ms 以内の目安・pane 16 個・状態反映 2 秒以内・大量出力の pane があっても
他の pane と画面の操作が固まらない）を、端末版で測る。

```sh
pnpm build
node packages/tui/dist/bench/latency.js          # 人が読む形
node packages/tui/dist/bench/latency.js --json   # 1 行の JSON（場面ごとの typing・raw・added の統計、violations、pass）
```

終了コードは、目安をすべて満たせば 0、外れたら 1（外れた項目を出す）、測れなかったら 2。

ビルドした `soda serve` を一時の状態ディレクトリ・空いているポートで起動し（ポートを取られていたら替えてやり直す）、`runTui` を偽の外側の端末
（書かれた列をその場で headless の端末へ流す）で繋ぐ。全体で十数秒。共有のマシンで重くしないよう、1 回だけ走らせる。
**負荷の高いマシンでは値が大きく出る**（測る側と端末版が同じプロセスで動くため）。ほかの重い処理が走っていないときに測る。Linux / WSL2 向け。

## 打鍵の 1 標本

同じ pane（`cat`）について、次の 2 つを続けて測る。

- **素の往復**: WS の外部クライアントから INPUT を直接送り、OUTPUT の echo が返るまで（どのクライアントでも払う分）。
- **端末版**: 焦点の pane へ 1 文字打ち、**その pane のカーソルの位置のセルにその文字が描かれ、カーソルが 1 つ進んだ**フレームが書かれるまで
  （画面のほかの場所の描画では止まらない）。
- **足した遅延** = 端末版 − 素の往復（標本ごと）。

各場面で 65 標本を取り、最初の 5 標本は暖機として捨てる（60 標本の統計）。

| 項目 | 測り方 | 目安 |
|---|---|---|
| (a) 1 pane | 上の標本 | 足した遅延の p95 ≤ 50ms |
| (d) 大量出力の最中 | 隣の pane で 8 秒のあいだ `seq` を出し続けさせ（`seq 1 20000` の繰り返し）、**静まりを待たずに**続けて打つ。標本の 9 割以上が流れている間に取れたことを確かめる | 打鍵の p95 ≤ 50ms |
| (b) 16 pane | 4×4 に割って全 pane に 1 行ずつ出した状態で打つ。外側の端末の大きさを変えてから、全体を描き直した（`CSI 2J` を含む）フレームが書かれるまでも測る（目安なし） | 打鍵の p95 ≤ 50ms |
| (c) エージェントの反映 | `PATH` の先頭に置いた偽の `claude`（`sleep` の写し）を別の pane で起動 → サイドバーに「Agents」が出るまで、Ctrl+C → 消えるまで | どちらも 2000ms 以内 |

## 測らないもの（手で測る）

- **本物のエージェントの 5 状態の遷移**（working → idle・blocked・done）: 画面の規則（manifest）で決まるので、偽のプロセスでは起きない。
  Claude Code 等を pane で動かし、`sodactl pane watch`（または Web 版）と端末版を並べて、状態の記号が変わる時刻の差を目で見る
  （サーバの判定の周期は出力のある pane で 500ms・無い pane で 1 秒。端末版の描画は最短 16ms 間隔）。
- **実物の端末エミュレータの描画時間**: この測定は端末版が外側の端末へ書き終えるまで。外側の端末（Windows Terminal 等）が画面に出すまでの時間は含まない。
- **SSH 越し**: 往復の時間が足される。端末版の処理の分は上の値と同じ。
